依頼は LEDGER 0388（音と演出が合っていない所を洗って直す）。導入の電源（0387）は [[intro-tv-reveal]]。

## 測り方

- 走行: `py -3.11 tools/twin-verify.py --tag <名前>`（`--fast` を付けない。実時間でないと音の時刻が意味を持たない）。`eye.mp4` に Unity の音が入る（30fps）
- 音の頭: `ev=sfx` の tau の前後で、焼いた音源（`Assets/Resources/Sound/*.wav`）の 10ms 包絡（log）を動画の音へ相互相関で当てる。⚠ tau → 動画の秒の写し（`tau + 0.035 - OFF`）は 1 走行の中で約 0.2 秒伸び、OFF は走行ごとに違う（20261115_200544 は 2.0〜2.2、20261115_203951 は 1.07）。写しで決めると一撃ごとに外れる
- ⚠ 相関は劇伴の下の小さい一撃（鈴 -28 LUFS）や、窓に別の一撃が入る所（電源の 1 秒後の鈴）で r 0.6 前後になり、外れた所を掴む。そのときは画の縁（電源なら管の縁が光るコマ = 音の頭 + 0.03 秒）から頭を決める
- 乱れは相関より、同じ窓の中で高域（3〜12kHz・5ms）の 20ms 跳ねと画のコマ間差の最大を探して差を取る方が安定した（写しの誤差が消える）
- 画: 同じ窓で 320x180 の灰色のコマ間差。⚠ 動画は 30fps なので画の時刻は ±17ms の粒。音の頭との差が 35ms 前後なら予約の遅れ（`SfxPlayer.ScheduleLeadSec`）の範囲
- 使ったスクリプトはセッションの scratchpad（`av_xcorr.py` / `sheet.py`）で、リポジトリには入れていない。要るなら tools へ起こす

## 踏んだ罠

- 全体の dB は劇伴に埋もれる。砂嵐のような帯の広い音は 3〜12kHz の帯で見る
- 素朴な立ち上がり検出（10ms 実効値の跳ね）は劇伴と重なった一撃で外れる。相関に変えた
- 1 か所 `py` の文字列置換で `"            }\n"` を探したら、深い字下げの `"                }\n"` の中に当たって閉じ括弧が 1 つ残った（コンパイルで分かった）。字下げで区切りを探さない
