**分かったこと**

- cam1 は等立体角で f=325px（幅 735）、左右 140 度・上下 89 度・対角 173 度。直線の当てはめと、部屋の線の直交条件で独立に解いて一致した
- 魚眼の式の種類は直線の残差では区別できない（0.34〜0.37px）。画角は対角 170 度前後でどれも同じなので、式の選択に意味を持たせない
- C の無人画像は `tools/twin/rig.json` のピンホールで f=288（幅 640）。左右 96 度・対角 108 度。中央の倍率は cam1 とほぼ同じで、違いは外側の有無
- **本編の `_CrtLensWarp` は正の値で糸巻き（外側ほど拡大）で、cam1 の樽型と逆向き。** 0296 の「外側に行くにつれ引き延ばされる」をこの向きで実装し、0303 で本人が 0.155 を採用した。負の値へ振っても式の形が違い、映像の外を読む
- 画面を埋めたまま外側を縮めるには中央を拡大するしかない。線の曲がりは cam1 +13.8% に対し、中央 ×1.52 で +5.1%、×2.00 で +7.4%、×3.06 で +9.7%。cam1 と同じにすると ×8.4

**罠**

- `cv2.imwrite` は日本語パスへ書けず、**例外を出さず False を返す**。Drive へ書くときは `imencode` + `tofile`
- 残差を「角度 × f」で比べると短い焦点距離ほど得をして、ピンホールが魚眼に勝つ。画像へ投影し直した画素距離で比べる
- レンズの中心を自由にすると枠の外へ逃げて全光線が平行になり、残差が 0 に見える。探索範囲を枠の中へ縛る
- ツインの C を全周で撮ると、スマホ本体とレンズの筒が 75 度より外を塞ぐ。`clip_start=0.04` で抜く。比較の画では C の右側の近い面も変わるので、向きの照合は左半分だけで行う
- ツインの壁の材質は実際の部屋と違う（剥げた塗装）。外側の形と範囲を見る用途に限り、色を抜いて使う

**未確認**: 本編シェーダ・人が映る場面・HMD。実装するなら C の区間だけ切り替える。合成と録画マスクは共通の論理 UV を通るので一緒に動く見込み（未検証）。
