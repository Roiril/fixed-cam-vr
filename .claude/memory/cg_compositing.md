CG 人形を実写映像へなじませる基盤は 2026-07-27 に作り直した。契約の正本は
[.claude/plans/2026-07-27_cg-compositing-rebuild.md] と [.claude/rules/streaming.md] の「合成の作り直し」節。
ここには**触る前に知らないと事故る前提**だけ書く。

## 触る前に知るべきこと

- **像空間の対応付けが命**。CG は必ずライブ映像と同じ contain-fit 枠（`_CgScale`）でサンプルし、
  RT はソース映像の実寸、画角は**水平**（`hfovDeg`）が正。この 3 つのどれかを崩すと、姿勢を
  完璧に測っても人形は合わない（作り直しの起点がまさにこれ）
- **卓と Unity で同じ数値を出す箇所が 2 つある**。どちらも期待値を両側にハードコードして突き合わせてある:
  - 投影: `calib.test.mjs`「投影は Unity と同じ画素を出す」⇔ `CgProjectionTests.Projection_MatchesPinholeFormula`
  - 色温度: `room-model.test.mjs`「kelvinToRgb は Unity と同じ値」⇔ `CgProjectionTests.Kelvin_MatchesConsoleFormula`
  **片方だけ直すと沈黙して食い違う**（卓では合うのに実機が違う、という最悪の症状になる）
- **卓は CG 人形を描かない**。輪郭プロキシ（半透明の線）だけ。写実に見せた瞬間に
  「著作者が卓を信じて Unity 確認を飛ばす」が始まる
- レンズ歪みは**除算モデル** `r_u = r_d/(1+k1 r_d²)`。順・逆に解析解があるので卓の順投影とシェーダの
  逆変換が厳密に一致する。多項式に変えると画面端で食い違い、較正の検証自体が成立しなくなる

## 較正 UI を触る前に（2026-07-29 の立て直し）

- **判断は [`calib-session.js`]、描画とイベントは [`calib-ui.js`]**。状態遷移（開く / フレームを
  取り直す / 解く / 保存）を書き換えるときは **`calib-session.test.mjs` を先に直す**。
  ここが空白だった間に実バグが 5 件たまった（解像度変化で固定画角を捨てない・映像前に開くと点が
  復元されない・壁の高さの後変更が届かない・失敗直後に古い線が残る・卓と実機で有効判定が違う）
- **「打てる実測点があるか」が合わない原因の第一位**。既定値の壁・定数のタイル格子から作った点は
  現場の床に目印が無い。候補点と検証線は `SOURCE_MEASURED` / `SOURCE_ASSUMED` を持ち、
  推測は候補から畳み、線は点線で描く。**測っていない幾何を実測のように出さない**
- **画角の供給源は `lenses[]`（show.json トップレベル）> そのカメラの前回の解**。
  Unity は lenses を読まない（卓だけの概念）。サーバは `_STATE_KEYS` に足すだけ
- **`rmsPx` は精度ではない**（当てはまり）。実際のずれは `leaveOneOutError` が 1 点伏せて測り、
  `calib.accuracyM` に焼く。バッジ・本番前チェック・レンズの素性判定が同じ数字を使う
- **プレート（保存した映像）で較正できる**。読み込みは `fetch` + `createImageBitmap` — `<img>` の
  `load`/`decode` は非表示ウィンドウで永久に解決しない。寸法が配信と違っても**縦横比が同じなら
  `rescaleCalib` で内部行列を比例で移せる**（違えば移さない＝クロップで嘘の較正を作らない）
- **カメラを跨いで持ち越してはいけない状態が 2 つある**: `liveSize`（そのカメラの配信実寸。
  別カメラの値へ移すと嘘の較正が「較正済み」として焼かれる）と、await を跨ぐ処理の着地
  （`gen` を open/close で ++ して照合する。しないと B のパネルに A の絵と点が載る）

## 実測で決まった運用制約（変えると精度が落ちる）

| 事実 | 数値 | 帰結 |
|---|---|---|
| 焦点距離を既知にすると精度が一桁変わる | クリック誤差 1.5px で、f も推定すると位置 **27cm** / f 固定なら **2cm** | **画角は一度だけ丁寧に測って固定、置き場所は現場で毎回** |
| 歪みを無視すると高さが 4 割狂う | 広角 k1=0.18 でカメラ高 1.5m → 0.91m | k1 を後回しにできない |
| f 未知のまま k1 を解くと縮退する | 5 点で f 430→300 の偽解 | f 未知なら点 6 個以上 / f 固定なら 4 点で可 |

## 「CG っぽい」の原因は、陰影より先に**時間**（2026-08-06）

見た目を合わせ込む前に、この 3 つが効く。詳細は [.claude/rules/streaming.md] の「なじませ 2」節。

- **人形は実写のフレームが進んだ時だけ描く**（`ShowCgLayer.RenderIfDue`）。仮想カメラは
  `enabled=false` にして手動 `Render()`。**自動描画に戻すと 90Hz で回って、人形と腕だけが滑らかに動く**
  — 実写は 15〜30fps なので、動いている最中に一目で合成だと分かる。陰影を直しても消えない差
- **人間用の定数を人形へ流用しない**。接地影の下限 0.15m は成人 1.6m 前提で、
  全高 0.40m の人形では背丈の 3/4 の黒い円盤になっていた（下限は 0.03m へ）
- **`shadowSoftM` は投影シャドウでは「高さによる濃さの減衰」**（縁をぼかす場所が無いため）。
  足元が濃く頭の影が薄い＝実際の半影と同じで、硬い縁が目立つ範囲が接地点の近くへ縮む
- 人形の明るさは `MjpegScreen.SourceLuma`（post 前の生の平均輝度）へ寄せる。
  **主光源と環境光へ同じ倍率**（片方だけだと材質が変わって見える）

## 壊れやすい所

- **影のステンシルを外すと影が「濃い斑」になる**（腕と胴の投影が重なって二重に暗くなる）。
  そのため RT の depth は **24**（depth24 + stencil8）。16 に戻すと沈黙して化ける
- **premultiplied の rgb/a を別々に触らない**。ぼかしも色収差も rgb > a の画素を作ると縁が壊れる
- **素材カット（clip / still）に人形は出ない**（パースが原理的に合わないため）。`rec` は出る
- **HMD 位置合わせが未完了だと人形を出さない**。course→world が identity に落ちて別の場所に立つため

## なじませを触る前に（2026-08-07 に詰めた）

- **「CG に見える」の判断は、数値と絵を必ず並べて見る**。目視だけでは人形の彩度が周囲の 3〜4 倍
  あることを誰も指摘できず、逆に数値を全部そろえたら**絵から人形が消えた**。合成プレビューが
  カットごとに `blend doll/around: luma … sat … grain …` をキャプションとログへ出す
- **人形の明るさは「画に出た後の・立つ場所の」明るさへ寄せる**。全画面平均だと、黒いカーテンが
  画の大半を占める絵で明るい床に立つ人形が暗くなりすぎる（実測で局所は全画面平均の 26〜68%）。
  自動露出（`CameraFeelFx`）が持ち上げたぶんも差し引く（生の輝度へ寄せると二重補正）
- **彩度は post では絶対に埋まらない**（乗算なので比が保存される）。実写だけが受けている
  JPEG 4:2:0 のクロマ半解像度と暗所のカラーノイズ抑制を、CG 層だけに掛ける（`_CgChromaBlur` /
  `_CgChromaGain`。post には触らない＝ FS_POST 4 箇所の手作業同期に入れない）
- **陰影は albedo に比例させない**。影側に `_LightColor` が掛からないと暗い部位ほど陰影が消え、
  「切り抜きを貼った」ように見える（これが最大の原因だった）。リムも光源に比例させる
- **足元が枠外なら、合成の精度をいくら上げても浮いて見える**（床との接点も影の落ち先も画に無い）。
  プレビューが名指しで警告する。直すのは立ち位置か画角＝**演出の管轄**

### まだ残っている 2 つの穴（直すなら）

- **ホールド / 焼き付き（`hold` / `burn`）が CG に掛からない**。実写だけ止まって人形は動き続ける。
  `burn` の「動いたものの跡だけが残る」に対し、唯一の動体である人形にだけ跡が残らない。
  現行 show.json では未使用。直すなら `CameraFeelLogic.Frozen` を `ShowCgLayer.RenderIfDue` のゲートに
- **rec / plate カットで CG がライブ基準のまま**。`RenderIfDue` の刻みも `LumaGain` も `ResolveCalib` も
  `registry.GetActive()` を見るが、3 周目の録画・無人プレートは `_OverlayTex` に入る
  ＝ **人形が一番効く場面で刻みと明るさが表示中の画と別クロック**。ライブが落ちていれば較正が
  外れて概算 pose へ黙って降格もする
