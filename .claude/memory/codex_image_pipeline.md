## 三行で

**異変（何を足すか）は場所に依らない。場所は当日 1 ファイル。伝送（何が失われるか）は機械が計算する。**
**判断は「実機の経路を最後まで通した画」でする** — 素材の中で見えている欠点の半分は体験者に届かない。
**プロンプトで動かせたのは 2 つだけ**（視線となじませ規則）。それ以外は回ごとの振れ幅に埋もれる。

## 2. ⭐ どこで何を測るか（3 段階の測り直しで決めた）

**素材の中で見えている欠点の半分は体験者に届かない。** 測る場所を間違えると、
届かないものを何周も追うことになる（実際に彩度で 4 周やった）。

| 測るもの | どこで | なぜ |
|---|---|---|
| 接地の影・遠近・背景の保存・面積・塊の数 | **生成直後**（`judge.py`） | 届いた画では塊が融合して測れない |
| 縁の鋭さ・粒・細かさ | 生成直後（参考） | **届いた画では差が出ない**（mip が実写も素材も同じだけなます） |
| 彩度・明るさ・暗部 | **post 後**（`posted.py`） | post が均す |
| **継ぎ目の段差** ＋ **読みやすさ** | **届いた画**（`deliver.py` が両方） | 隣に実写が並んだ瞬間にしか出ない／粒に埋もれないか |

⚠⚠ **継ぎ目と読みやすさは逆を向く**（人形を明るくすると読みやすくなるが継ぎ目が悪化する）。
**必ず 1 コマンドで両方見る** — 別々に測ると片方だけ良くして満足できてしまう。
実測で、いちばん読みやすい素材の継ぎ目が 1.6 → **4.0（線ちょうど）**まで上がった。

### 実機の経路（post だけではない）

    素材 → contain-fit（4:3 を 16:9 の枠へ）→ **mip で痩せる**（周回の劣化）
         → **色差をさらに 1 段落とす**（4:2:0）→ グレア → マスクでライブと混ぜる
         → post（レンズ→センサ→ISP）→ **夜間モード**

`ScreenComposite.shader` が正本。`screen.py` が**リニア空間**で再現する
（sRGB のまま計算した数値は丸ごと嘘になる）。

⚠⚠ **帰りの A（生成素材が出る唯一の場所）は完全な無彩。** `_Mono` は解像度の劣化と同じ進みで、
進み 1.0 ＝ 彩度 0。輝度の重みも赤へ寄る（0.52）ので**赤い着物は暗くならず明るく写る**。
⇒ **彩度の作り込みは本番の画に 1 ビットも出ない。**

⚠⚠ **継ぎ目は素材の中を見ても絶対に出てこない。** 実測で、現行の帰りの A は
**左半分だけブースがあった頃の部屋**から作られていて、右の無人プレート（解いた後）と繋がっていなかった
（段差 **6.7** ＝ 線 4.0 の外。同じ日のプレートから作り直すと 1.6〜2.2）。**当日は自動で直る**ので直していない。
手順として「**素材を作り直したら `screen.py` で継ぎ目を測る**」を残す。

⚠ **沈められるのは 帰りの A で 50%・1 周目で 35% まで**（素材 3 本の最悪値。帰りの A は 3 本とも 50%）。
⚠⚠ **1 周目の旧値 10% は 3.5 倍ゆるかった** — 粒を枠の画素ごとの白色雑音で振っていたため
（実機はソース画素の格子で刻む）。`compose.py` は 0.35 + 0.15 × 進み。

## 3. プロンプトで動いたもの / 動かなかったもの

**動いた（2 つだけ）**

- **視線**: 届いた画の**顔の粒**（面積あたり）が レンズ **2.22** / ばらばら 1.14 / 別の一点 0.54（§4.5）。
  ⚠ 08-17 に記録した左右対称度 0.66 / 0.06 / -0.16 は **2 条件とも壁を測っていた**
  （3 走行とも背景を塗り直されていて、`heads.py` の探す範囲＝種との差が画面全体になった。
  いまは 35% の門で止まる）。**結論は変わらないが、あの数値は根拠にならない**
  ⭐ **「常に体験者を見る」を成立させる向きは 1 つしかない — レンズを見ること**
  （見る人がどこへ動いてもその人を見ているように見える）。体験者の実際の立ち位置を見させると、
  画面の中では**あさっての方を向いた人形**になる
  ⚠⚠ **2026-09-04（0135）にユーザーが「全部カメラを見ているのは不自然すぎる」と判定した。**
  計測（レンズ向きがいちばん届く）は変わらないが、指定は**3 分の 1 がレンズ・残りは横顔と斜め・
  後ろ向きは 2〜3 体まで**へ。横顔も明るい楕円として届くので数えられる。消えるのは後ろ向きだけ。
  8/23 の採用は**全員がレンズを見た同じ顔・同じ大きさの 22 体が隅に固まった集合写真**で、
  数は届いたが陳列に見えた。散らし方（奥から手前・同じ姿勢 3 体以上禁止・複製に見せない）も同時に足した
- **なじませ規則**: 同じ種・同じ部屋で旧プロンプトと並べて、接地の影 **-0.12 → 2.45**、
  遠近 **0.07 → 0.57**

**動かなかった（全部、回ごとの振れ幅に埋もれた）**

| 試した手 | 結果 |
|---|---|
| 種をぼかして渡す（`--blur`） | 効かない |
| 参照画像を渡さない（`--no-refs`） | 1 枚目 79・2/3 枚目 51 ＝ 決め手なし |
| 参照に「意匠だけの見本です」と添える | **むしろ下がった**（43 対 基準 55）⇒ 取り下げ |
| 「手前に大きいものを / 何体かは隠れている」 | はみ出しが 0.01% → 4〜28% ⇒ 取り下げ |
| 出す周の伝送を節にする（`--lap`） | 20.5 と 9.1（節なし 9.2）＝ **n=2 では見えない** |

⚠⚠ **当日の枚数は 3 では足りない**（2026-08-18・`yield.py`）。手元の 25 走行を今の計器で
測り直すと、全部の門を要求して通るのは **4%（9 割ほしいなら 57 枚）**。
落ちている上位 3 つ（彩度 80% / 置かない側 76% / 寸法 64%）は**この cue では届かない**ので、
外すと **28%（8 枚）**。⇒ **届かない欠陥のために 7 倍焼いていた。**
合否は動かさず、`judge.py` が「届かない門」を名指しする形にしてある。

⭐ **歩留まり（背景を保つか）は場所で決まり、プロンプトでは動かない。**
事務室 76/94（n=3）・灰色のカーテンの部屋 51/60（n=19・27〜79 と振れる）。
**理由は分かっていない**（「平らな面が多い部屋ほど描き直される」は測ったら逆だった）。
⇒ **枚数で解く**（`autorun.ps1` が 3 枚並列で焼いて良い順に並べる）。

⚠⚠ **「1 枚良かった」を根拠に採用しない。** この日 3 回踏んだ（参照なしの 79 / `--blur` の 36 /
`--lap` の 20.5）。どれも 2 枚目で元へ戻った。条件を比べるなら `stats.py` で中央値を見る。

## 4. 罠（どれも実害つき）

- ⚠⚠ **「前の感じにして」と言われたら、焼く前に `tools/web-compositor/atelier-index.md` を読む**
  （2026-08-23・赤入れ 1 回分）。**採用された素材のプロンプトがそこに残っている。**
  異変ファイル（`anomaly/*.md`）はそれを写して作られているので、**要約した行が画から消えている**。
  実例: 手形の異変から「壁一面」「向きを徹底的にばらす」「垂れた筋」
  「色味ではなく暗さで見せる」が落ちていて、8 個の均一なスタンプになっていた。
  書き戻したら 30 個・読みやすさ 9.0 → 13.5。**プロンプトの当たり外れではないので、回しても直らない**
- ⚠⚠ **post の仕事をプロンプトにやらせない**（3 度目）。異変に「着物は褪せて写る」と書いたら
  post 後の彩度が 0.53 まで落ちた（背景より色が無い）。**何かを直したくなったら、まず
  `posted.py` で「post を通しても残るのか」を測る**
- ⚠⚠ **薄い異変ほどプログラムで作られる。** 布の顔染みを頼んだら Codex が**ガウス関数で明暗を計算する
  PowerShell**（`make_stain.ps1`）を書いて画素へ掛け算していた。クロマキー合成（2026-08-16）と同じ型。
  `prompt/99-output.md` で名指しで禁じてある（「入力画像を直接編集して」とだけ書くと、
  **その編集をスクリプトでやってよいと読まれる**）
- ⚠ **症状を束ねて 1 つの原因を作らない。** 寸法が 1448 になる／背景を描き直す／スクリプトで作る、は
  **互いに独立した回ごとのばらつき**。一度「同じ 1 行が原因」と書いて外した
- ⚠⚠ **異なる異変を同時に焼くと、絵が走行の間で入れ替わる**（2026-09-04 実測・4 つ目の落ち方）。
  `autorun.ps1` を 3 本同時に走らせたら、手形の走行（B の壁）が**幕の顔**を出し、染みの走行が
  それを縮めて自分の出力にし、手形の絵は誰にも拾われず `~/.codex/generated_images/<exec>/` に残った。
  8/23 にも 1 組あった（`195736_3` 人形 と `195755_3` 染み が byte 一致。runs.md の
  「人形が 1 体も描かれなかった回」の正体）。生成物のフォルダは exec ごとに別なのに、
  **同時に走る exec の間で生成の結果が入れ替わる**（機序は Codex 側で、こちらからは見えない）。
  ⇒ **別の異変は 1 本ずつ**。同じ異変の N 枚並列は**重複**する（4 枚中 2 枚が同じ絵・同日）。
  `autorun.ps1` が鍵で直列化し、md5 の重複を 1 枚ずつ焼き直す
  ⇒ 迷子の絵は `generated_images` の**どの走行の log にも出ないフォルダ**にある。中身を見て戻せる
- ⚠⚠ **境目の跨ぎは place では減らない**（2026-09-04・R033）。`left-40` で跨がないのは 4/11、
  `left-35` に狭めても 0/4。群れは範囲と同じ幅で描かれて外へ出る。
  ⇒ `despill.py` で**跨いだ塊だけ種へ戻す**（右端の 1〜3 体・足した所の 6〜13%）。4 枚とも跨ぎ 0、
  届いた顔はほぼ全部残り、縁は届いた画で見えない。autorun が半分マスクの place で自動で当てる
- ⭐ **手形（1 周目 B）は当日に焼かない。壁ごと切り出して当日のプレートへ貼り直す**（0137・`refit.py`）。
  ユーザー判定は「手形だけでなく壁ごと。当日そこに壁が無くても血の壁があるように」。マスクは壁の四角形
  （B は `0,0,240,14,240,306,0,335`）、明るさは床の平均で倍率合わせ、ずれは縁の位相相関（同じ壁が無ければ 0）。
  ⚠ 画角が違うと壁の板が床から浮く（8/16 のプレートで実測）— 当日の画角合わせが前提
- ⭐ **暗い幕の上の染みは、黒い染みだけでは届かない**（同日・R030/R031）。黒い目と口を描いた版は post 後に
  ほぼ消え、「染まらず残った淡い面」で顔を作った版は届いてからも顔に読める。周りを大きく暗く、
  顔の面は元の布の明るさのまま
- ⚠ **面を持たない場所では、その異変は成立しない。** `compose.py` が「この場所に布の面が無い」と
  言って止まる（黙って画面全体へ広げない）
- ⚠ **寸法違いは致命ではない。** `judge.py` が `out_fit.png` を書くので素材にはそれを使う

## 5. 計器を信じる前に

**08-17 に 6 件、08-18 に 4 件**（枠への収め方 / 黒帯を粒に数える / 粒の刻み / 縁を段差の無い所で測る）。
**10 件のうち、実際の生成物を見ていて出たものは 1 件も無い。**

⚠⚠ **染みを `deliver.py` の読みやすさで選ぶと順序が逆に出る**（2026-08-18 追加・08-23 実測）。
読みやすさは**塊ごとの中央値**なので、**顔を作るために塊を分けるほど必ず下がる**。
実測（0113）: 大きな一塊 **7.3** ＞ 目 2 つ＋口の 3 塊 **5.9** で、**顔に見えたのは 5.9 の方だけ**
（7.3 は布の影にしか見えない）。⇒ **顔らしさは塊の位置関係で決まり、塊ごとの指標には出ない。**
染み系は `delivered.png` を並べて目で選ぶ。

⚠⚠ **これは染みだけの話ではない。人形でも同じ形で出た**（2026-08-23 19:57）。
`judge`（NG 2）・継ぎ目（-0.0）・読みやすさ（8.1）の**3 つが揃って指した 1 枚**が、
届いた画では**顔が数個しか読めない**（採ったのは NG 3 / 継ぎ目 3.8 / 読みやすさ 7.4 の方で、
そちらは顔が 20 個以上読めた）。機序は同じ — 暗くて弱い塊は**検出されないので分母に入らない**。
⇒ **数が本体の異変は、最後に `delivered.png` を並べて目で選ぶ。**
⚠ 生成直後の画では分からない（落とした方が整って綺麗に見えていた）。差が出るのは伝送の後だけ。

⭐ **恒等の入力を通す**（素材＝プレートそのもの）。差を測る物差しなら 0 が出るはず。
**継ぎ目の段差で 5.1 出た** ＝ 差ではなく「その列にもともとある構造」を測っていた。
⭐ **単調に動くはずのものを掃引する**（`limit.py`）。単調でなければそこに欠陥がある。
⭐⭐ **同じ量の実装が 2 つ以上あるなら、値を突き合わせる**（2026-08-18）。
`screen.py` の枠への収め方が **cover / contain 反転**していて、届いた画を
**1.33 倍に拡大して上下 12.5% ずつ切り落として**いた。恒等の入力は**原理的にこれを出せない**
（素材にも実写にも同じ変形が掛かるので差が 0 のまま）。正本は `MjpegScreen.cs:258` と
`compose.py:75` の 2 か所にあり、**プロンプトへ書いていた「3.2 画素」の方が正しかった**。
⚠ 直したら次の欠陥が出た — **黒帯（分散 0）を「いちばん平らな所」として粒に数えていた**
（1.39 → 0.47 ＝ 読みやすさが 2 倍に嵩上げ）。届いた画を測る道具は
`screen.frame_inside()` で切ってから測る。
⭐⭐ **さらにその奥に、粒の刻み方の違いがあった。** 実機はソース画素の格子で刻む
（帰りの A で枠の 4.8 画素）のに、枠の画素ごとに白色雑音を振っていた。**定数は 1 つも
間違っていなかったのに、刻み方 1 つで粒が 4.5 倍・沈められる下限が 3.5 倍動いた。**
⇒ 粒は代用（3x3 高域）で測らず、**同じ画を別の乱数でもう 1 枚描いて差を取る**。


- **縁を勾配の生の大きさで測っていた** → 50 階調の段差を 1 画素で切っても種の強い縁より小さく出て、
  貼り付けを 1 度も捕まえられなかった。**勾配をその場の明暗差で割る**（1 画素なら約 0.5）
- **接地の影の帯に物の画素が混ざっていた** → 影が無いのに「直下が 11.8 暗い」と符号が反転
- **読みやすさを「その領域のばらつき」で測っていた** → 融合した塊の中の**背景の構造**を測っていて、
  素材を 10% まで薄めても 32 → 24 にしか落ちなかった
- **薄める倍率ごとに領域を取り直していた** → 100% が 70% より低く出た
- **細かさの比を中央値で割っていた** → 実写側が真っ暗な幕だと中央値 0 で比が 2 億に化けた

⭐ **単調に動くはずのものを掃引すると、計器の欠陥が出る**（`limit.py`）。
⭐ **計器そのものは生成を待たずに試せる**（`selftest.py`。種から偽物を 3 つ作って通す）。
⚠⚠ **嘘をつく計器は載せない。** 接地の影を届いた画で測る案は、影のある素材で 0.02・
無い素材で 0.20 と**順序が逆に出た**ので消した。

## 6. 生成 AI に渡すのは「少し暗くしただけの環境」（2026-08-16 に確定）

種を明るいまま渡すと**モデルは暗い画を一度も描かない**（種 122.9 に対し体験者が見るのは 48.2）。
ユーザー指摘「明るい部屋で生成された人形はホラーっぽくなくリアルでもなく CG っぽい」
（`canon/LEDGER.md` 0050）。

    プレート → dim（**露出だけ**）→ 生成 → undim → captures/ へ → 実機で post

⚠ **監視カメラらしさ（彩度・ヴィネット・コントラスト）を種へ焼かない。** それは post の役目で、
種に入れると**モデルが「直すべき粗」と読んで画を作り替える**（`gen-tone.py` の既定が露出だけなのはこのため）。
⚠ **左右で指示を分けない。** 全体に「足す以外はしない」と 1 つ約束させ、
置かない側は「そこには置かないで」とだけ言う。
⚠ **「1 画素も変えない」は効く**（実測で 83.0 → 83.0 の完全一致）。抽象的な「明るさを変えないで」は効かない。
⚠ **絶対的な明るさをプロンプトで狙わない**（数字で頼むと 0.64 → 0.88 → 1.75 と振れる）。

## 7. 差分マスクが使える条件

冒頭にあった「種と生成の差分がそのままマスクになる」（2026-07-29 実測・差の 2.5%・マスク面積 1.5%）は、
**モデルが背景を触らなかったときの話**。背景まで塗り直された出力では差分は主題と背景を分けられない。
**まず背景を触らせないプロンプトにするのが先**で、差分マスクはその後。

⚠ マスクは**枠空間 16:9**（実機は contain-fit を通さない）。詳細は [[material_flow]]。
