## 三行で

**異変（何を足すか）は場所に依らない。場所は当日 1 ファイル。伝送（何が失われるか）は機械が計算する。**
**判断は「実機の経路を最後まで通した画」でする** — 素材の中で見えている欠点の半分は体験者に届かない。
**プロンプトで動かせたのは 2 つだけ**（視線となじませ規則）。それ以外は回ごとの振れ幅に埋もれる。

| 層 | 実体 | いつ書くか |

| 伝送 | `compose.py --lap N` | 出す周が決まったら（機械が計算） |

展示当日は明るさも周りの物も違うので、**手で書いた文面に部屋の事情が混ざるとその日そこが全部嘘になる**

## 2. ⭐ どこで何を測るか（3 段階の測り直しで決めた）

**素材の中で見えている欠点の半分は体験者に届かない。** 測る場所を間違えると、
届かないものを何周も追うことになる（実際に彩度で 4 周やった）。

| 測るもの | どこで | なぜ |
|---|---|---|
| 接地の影・遠近・背景の保存・面積・塊の数 | **生成直後**（`judge.py`） | 届いた画では塊が融合して測れない |
| 縁の鋭さ・粒・細かさ | 生成直後（参考） | **届いた画では差が出ない**（mip が実写も素材も同じだけなます） |
| 彩度・明るさ・暗部 | **post 後**（`posted.py`） | post が均す |
| **継ぎ目の段差** ＋ **読みやすさ** | **届いた画**（`deliver.py` が両方） | 隣に実写が並んだ瞬間にしか出ない／粒に埋もれないか |

⚠⚠ **継ぎ目と読みやすさは逆を向く**（人形を明るくすると読みやすくなるが継ぎ目が悪化する）。
**必ず 1 コマンドで両方見る** — 別々に測ると片方だけ良くして満足できてしまう。
実測で「いちばん読みやすい素材」が継ぎ目で落ちた。

### 実機の経路（post だけではない）

    素材 → contain-fit（4:3 を 16:9 の枠へ）→ **mip で痩せる**（周回の劣化）
         → **色差をさらに 1 段落とす**（4:2:0）→ グレア → マスクでライブと混ぜる
         → post（レンズ→センサ→ISP）→ **夜間モード**

`ScreenComposite.shader` が正本。`screen.py` が**リニア空間**で再現する
（sRGB のまま計算した数値は丸ごと嘘になる）。

⚠⚠ **帰りの A（生成素材が出る唯一の場所）は完全な無彩。** `_Mono` は解像度の劣化と同じ進みで、
進み 1.0 ＝ 彩度 0。輝度の重みも赤へ寄る（0.52）ので**赤い着物は暗くならず明るく写る**。
⇒ **彩度の作り込みは本番の画に 1 ビットも出ない。**

⚠⚠ **継ぎ目は素材の中を見ても絶対に出てこない。** 実測で、現行の帰りの A は
**左半分だけブースがあった頃の部屋**から作られていて、右の無人プレート（解いた後）と繋がっていなかった
（段差 13.8。同じ日のプレートから作り直すと 6.7）。**当日は自動で直る**ので直していない。
手順として「**素材を作り直したら `screen.py` で継ぎ目を測る**」を残す。

⚠ **読みやすさの余裕は 1.8 倍しかない**（帰りの A で 9.2 対 検出限界 5）。
周りとの明暗差を **6 割**より落とすと粒に埋もれる（1 周目なら 1 割まで見つかる）。
**3 周目以降はこれ以上暗くしない。**

## 3. プロンプトで動いたもの / 動かなかったもの

**動いた（2 つだけ）**

- **視線**: 「レンズを見る」で左右対称度 0.66・「ばらばら」0.06・「別の一点」-0.16。
  ⭐ **「常に体験者を見る」を成立させる向きは 1 つしかない — レンズを見ること**
  （見る人がどこへ動いてもその人を見ているように見える）。体験者の実際の立ち位置を見させると、
  画面の中では**あさっての方を向いた人形**になる
- **なじませ規則**: 同じ種・同じ部屋で旧プロンプトと並べて、接地の影 **-0.12 → 2.45**、
  遠近 **0.07 → 0.57**

**動かなかった（全部、回ごとの振れ幅に埋もれた）**

| 試した手 | 結果 |
|---|---|
| 種をぼかして渡す（`--blur`） | 効かない |
| 参照画像を渡さない（`--no-refs`） | 1 枚目 79・2/3 枚目 51 ＝ 決め手なし |
| 参照に「意匠だけの見本です」と添える | **むしろ下がった**（43 対 基準 55）⇒ 取り下げ |
| 「手前に大きいものを / 何体かは隠れている」 | はみ出しが 0.01% → 4〜28% ⇒ 取り下げ |
| 出す周の伝送を節にする（`--lap`） | 20.5 と 9.1（節なし 9.2）＝ **n=2 では見えない** |

⭐ **歩留まり（背景を保つか）は場所で決まり、プロンプトでは動かない。**
事務室 76/94（n=3）・灰色のカーテンの部屋 51/60（n=19・27〜79 と振れる）。
**理由は分かっていない**（「平らな面が多い部屋ほど描き直される」は測ったら逆だった）。
⇒ **枚数で解く**（`autorun.ps1` が 3 枚並列で焼いて良い順に並べる）。

⚠⚠ **「1 枚良かった」を根拠に採用しない。** この日 3 回踏んだ（参照なしの 79 / `--blur` の 36 /
`--lap` の 20.5）。どれも 2 枚目で元へ戻った。条件を比べるなら `stats.py` で中央値を見る。

## 4. 罠（どれも実害つき）

- ⚠⚠ **post の仕事をプロンプトにやらせない**（3 度目）。異変に「着物は褪せて写る」と書いたら
  post 後の彩度が 0.53 まで落ちた（背景より色が無い）。**何かを直したくなったら、まず
  `posted.py` で「post を通しても残るのか」を測る**
- ⚠⚠ **薄い異変ほどプログラムで作られる。** 布の顔染みを頼んだら Codex が**ガウス関数で明暗を計算する
  PowerShell**（`make_stain.ps1`）を書いて画素へ掛け算していた。クロマキー合成（2026-08-16）と同じ型。
  `prompt/99-output.md` で名指しで禁じてある（「入力画像を直接編集して」とだけ書くと、
  **その編集をスクリプトでやってよいと読まれる**）
- ⚠ **症状を束ねて 1 つの原因を作らない。** 寸法が 1448 になる／背景を描き直す／スクリプトで作る、は
  **互いに独立した回ごとのばらつき**。一度「同じ 1 行が原因」と書いて外した
- ⚠ **面を持たない場所では、その異変は成立しない。** `compose.py` が「この場所に布の面が無い」と
  言って止まる（黙って画面全体へ広げない）
- ⚠ **寸法違いは致命ではない。** `judge.py` が `out_fit.png` を書くので素材にはそれを使う

## 5. 計器を信じる前に

**この日、計器のバグを 6 件見つけた。4 件は掃引か恒等の入力が暴いた（実際の生成物では 1 件も出なかった）。**

⭐ **恒等の入力を通す**（素材＝プレートそのもの）。差を測る物差しなら 0 が出るはず。
**継ぎ目の段差で 5.1 出た** ＝ 差ではなく「その列にもともとある構造」を測っていた。
⭐ **単調に動くはずのものを掃引する**（`limit.py`）。単調でなければそこに欠陥がある。


- **縁を勾配の生の大きさで測っていた** → 50 階調の段差を 1 画素で切っても種の強い縁より小さく出て、
  貼り付けを 1 度も捕まえられなかった。**勾配をその場の明暗差で割る**（1 画素なら約 0.5）
- **接地の影の帯に物の画素が混ざっていた** → 影が無いのに「直下が 11.8 暗い」と符号が反転
- **読みやすさを「その領域のばらつき」で測っていた** → 融合した塊の中の**背景の構造**を測っていて、
  素材を 10% まで薄めても 32 → 24 にしか落ちなかった
- **薄める倍率ごとに領域を取り直していた** → 100% が 70% より低く出た
- **細かさの比を中央値で割っていた** → 実写側が真っ暗な幕だと中央値 0 で比が 2 億に化けた

⭐ **単調に動くはずのものを掃引すると、計器の欠陥が出る**（`limit.py`）。
⭐ **計器そのものは生成を待たずに試せる**（`selftest.py`。種から偽物を 3 つ作って通す）。
⚠⚠ **嘘をつく計器は載せない。** 接地の影を届いた画で測る案は、影のある素材で 0.02・
無い素材で 0.20 と**順序が逆に出た**ので消した。

## 6. 生成 AI に渡すのは「少し暗くしただけの環境」（2026-08-16 に確定）

種を明るいまま渡すと**モデルは暗い画を一度も描かない**（種 122.9 に対し体験者が見るのは 48.2）。
ユーザー指摘「明るい部屋で生成された人形はホラーっぽくなくリアルでもなく CG っぽい」
（`canon/LEDGER.md` 0050）。

    プレート → dim（**露出だけ**）→ 生成 → undim → captures/ へ → 実機で post

⚠ **監視カメラらしさ（彩度・ヴィネット・コントラスト）を種へ焼かない。** それは post の役目で、
種に入れると**モデルが「直すべき粗」と読んで画を作り替える**（`gen-tone.py` の既定が露出だけなのはこのため）。
⚠ **左右で指示を分けない。** 全体に「足す以外はしない」と 1 つ約束させ、
置かない側は「そこには置かないで」とだけ言う。
⚠ **「1 画素も変えない」は効く**（実測で 83.0 → 83.0 の完全一致）。抽象的な「明るさを変えないで」は効かない。
⚠ **絶対的な明るさをプロンプトで狙わない**（数字で頼むと 0.64 → 0.88 → 1.75 と振れる）。

## 7. 差分マスクが使える条件

冒頭にあった「種と生成の差分がそのままマスクになる」（2026-07-29 実測・差の 2.5%・マスク面積 1.5%）は、
**モデルが背景を触らなかったときの話**。背景まで塗り直された出力では差分は主題と背景を分けられない。
**まず背景を触らせないプロンプトにするのが先**で、差分マスクはその後。

⚠ マスクは**枠空間 16:9**（実機は contain-fit を通さない）。詳細は [[material_flow]]。
