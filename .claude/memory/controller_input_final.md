# コントローラ割り当ての最終形（2026-07-23 ユーザー宣言）

**右手のみ・4 入力（A / B / グリップ2秒 / トリガー2秒）× 2 モード（NORMAL / REG）が正義。これ以上の機能追加は今のところ不要。**

- 割り当ての実体: `Assets/Scripts/OvrBridge/OvrControllerBridge.cs`（NORMAL: A=カメラ手動送り Next / B=ステータストグル / グリップ2秒=ランリセット / トリガー2秒=位置合わせ入場。REG: A=点サンプル / B=確定 / トリガー2秒=キャンセル）
- **Why:** コントローラはスタッフ専用。操作を覚える負荷を最小にするため入力面を凍結する
- **How to apply:** 「グリップ単押しで cue 緊急停止を追加」等の新割り当て提案はしない（2026-07-23 に提案して却下済み）。cue 張り付き等の脱出手段が必要な場合は、既存 4 入力の意味の中で解決するか Web 卓側で対応する。`ToggleActiveCameraCue` は現在未配線のデッドコード（2026-07-20 の入力再設計で cue 試射撤去時の取り残し）
- スタッフ向けの操作ガイドはコントローラ上方の追従パネル（ControllerGuidePanel）に出す（2026-07-23〜）。
  **⚠ 2026-08-07 に「常時表示」をやめた** — 出るのは右 B でステータスを表示している間と位置合わせ中だけ。
  読み手はスタッフでも、パネルが浮くのはコントローラの位置＝体験者の視界の中で、文字が見えていた。
  門は `StatusHud.StaffViewing` 1 つで、HMD 内の文字面（導入の合図・黒の上の 1 行・この早見表）が全部そこを見る。
  切り分けの入口も変わった: 「押しても振動しない」→ **まず右 B**（出れば繋がっている）

## ⚠⚠ 2026-09-03: 体験者（左）はどのボタンを押してもいい

ユーザー宣言「体験者が押すボタン、X/Y だけじゃなく、どのボタンを押してもいいようにしてほしい。
これは、言語選択も報告も全部含めて」（`canon/LEDGER.md` 0128）。

読むのは **X / Y / 人差し指のトリガー / 握り / スティックの押し込み**の 5 つ
（`OvrControllerBridge.LeftAnyButtons`）。**読まないものが 2 つある**:

- **スティックの倒し** — ボタンではなく、歩いているあいだ親指が乗っているだけで倒れるので、
  1 秒握れば報告になる以上「倒しっぱなし」が報告に化ける
- ⚠⚠ **左のメニュー（`RawButton.Start`）** — 2026-09-03 に**一度入れて同日に外した**。
  `docs/onsite-checklist.md` が現場の事実として「Quest 側の予約で、押されると体験が中断する」と
  書いているのに、同じボタンを報告に割り当てて**「押すな」と「押していい」を両方書いていた**
  （並行セッションが指摘）。**届くかは実機で未確認**だが、予約なら入れても無意味、
  部分的に届くなら**言語が変わると同時にシステムの面が出る**（いちばん悪い）。
  手で握って押せるものは 5 つで尽きているので、外しても「どれを押してもいい」は成立する

- ⚠⚠ **まとめたマスクで `GetDown` を呼ばない。** `OVRInput.GetResolvedButtonDown` は
  **前フレームにマスクのどれかが押されていたら問答無用で false**（`OVRInput.cs` の実装）。
  握りに指を掛けたまま X を押す持ち方は普通なので、まとめて渡すと
  **言語が一度も切り替わらない現場ができる**（しかも握っている人にだけ起きる）。1 つずつ聞く
- ⚠ **マスクは一覧から導出する**（`OrAll`）。手で書くと片方だけ足して
  「握りでは報告できるのに言語が変わらない」が起きる
- ⚠ **言語を選んだ手を、そのまま報告として数えない**（`_markNeedsRelease`）。
  押したまま注意書きが閉じられると**本編の 1 秒後に身に覚えの無い報告が 1 件立つ**。
  ⚠ このラッチはランリセットでも落とさない（落とすと出し直した注意書きで同じことが起きる）
- **0050 の芯は変わっていない**（被った体験者に手元が見えないので、どれを押しても同じ）。
  変わったのは「同じ」の範囲が 2 つから左のボタン全部になったこと

## ⚠ 2026-09-03: 注意書きの中だけ、左のボタンが言語の切り替えになる

**入力は増えていない。** 左で読むのは同じ集合のままで、**体験前の注意書きが出ている段だけ**
意味が「異変の報告」から「次の言語へ」に変わる（日本語 → English → Français → 日本語）。
2026-08-12 に A の意味が 1 つ減ったのと同じ形で、**新しいボタンも新しい長押しも足していない**
（2026-07-23 の凍結は生きている）。

- 門は **`TitleNotice.IsShowing`**（段ではなく「面が画に出ているか」）。面が組めていない現場で
  見えない切り替えを起こさない
- ⚠ **そのあいだ報告のゲージは進めない。** 進めると**言語を選んだだけで異変の報告が 1 件立つ**
- 振動は `LeftMark`（受理の 1 発）を使い回している。左が受け取る振動は
  受理 / 長押しのランプ / 連絡の 2 連の 3 つのままで、**4 つ目を作っていない**
- 詳細と罠は [[show-language]]

## ⚠ 2026-08-15: 左は体験者のもの（X / Y だけ）

右（スタッフ）と左（体験者）は完全に分かれている。**左で読むのは X と Y の 2 秒長押しだけ**で、
スティック・トリガー・グリップ・A/B は 1 ビットも読まない。どちらを押しても同じ
（被った体験者に手元が見えないため・`canon/LEDGER.md` 0050）。

- ⚠ **`Button.Three` / `Button.Four` を `Controller.LTouch` と組み合わせない。** LTouch の仮想マップは
  どちらも `None` なので**永遠に false**。2026-08-15 まで記録ボタンがこの形で、**実機で一度も
  発火していなかった**。物理ボタンを名指しする `RawButton.X | RawButton.Y` を使う
- 左が受け取る振動は 3 つ: 報告の受理（`LeftMark`）/ 長押し中のランプ（`SetLeftHoldProgress`）/
  **AIエージェントからの連絡**（`LeftNotify`・2 連）。右の長押しランプとは混ぜない
- 左コントローラは人形の左腕も動かす（素手が取れないとき `OvrHandTrackingBridge` が姿勢で代える）

## ⚠⚠ 2026-08-16: 「繋がっている」と「位置が取れている」は別（実機で踏んだ）

`OVRInput.IsControllerConnected` は**電源が入っていれば true**。カメラから見えていないと姿勢は
無効になり、`OVRCameraRig.UpdateAnchors` が**アンカーをトラッキング原点（床の中心）へ置く**
（有効なコントローラが 1 つも無いと `GetLocalControllerPosition(Controller.None)` ＝ ゼロ）。

⇒ **手元の面が足元の遠くに小さく出る**（ユーザー報告）。位置合わせ中は早見表が唯一の操作説明なので、
そのまま作業が止まる。**接続だけで判定しない** — `GetControllerPositionValid` も見て、
位置が取れないあいだは面を出さない（`SetControllerState(connected, positionValid)`）。

- 人形の左腕（`OvrHandTrackingBridge.TryReadController`）は最初から両方見ていた。**そこだけ正しかった**
- 接続・再接続そのものは毎フレーム push しているので、**途中で電源を入れても繋がる**
  （アンカーの GameObject はリグに常設なので参照も切れない）
- 観測は `ev=sum` の `ctrlL=` / `ctrlR=`（`<繋がっている>/<位置が取れている>`）。
  **画にも音にも出ない**ので、実機ログのここが唯一の手掛かり
