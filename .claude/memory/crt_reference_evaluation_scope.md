2026-10-31。0294の完了条件は「家具とか部屋ではなくそれ以外」。0295でプロジェクトの無人画像を映し、元参照との加工感を比較する指示を受領した。
途中でエージェントが「筐体だけの一致で映像加工の差を埋めない」を追加し、評価者が筐体除外と解釈した。ユーザーは筐体を除外していないためadvisor手続きで訂正した。

- 完成用の比較は枠・ガラス・映像の加工感を含む。部屋と家具の内容・配置・撮影構図は除外。
- 新規評価者へ元参照と実描画の2枚のみ。目標点、過去の点数、実装、生成方法を知らせない。
- 加工の原因を2枚から断定させない。床の縞と横棒の白黒線は元写真にもあり、指摘を修正へ変換する前に同入力の対照や元写真で裏取る。
- 家具や模様を採点から除くことを、その上の色縁やにじみを無視する免責へ広げない。
- 旧点数は補正しない。28版の旧評価86%、映像だけの診断73%、訂正後の校正84%は同じhashの別条件の結果。73→84は実装改善ではない。
- 同じ画像の再採点を改善ループとして繰り返さない。今回の84%は評価範囲訂正の一度だけの校正。新候補ごとに範囲を変えない。

固定した評価文と逐語、校正画像/hashはDriveの`2026-10-30_crt-reference/evaluation-scope-20261031.json`と`scope-calibration-01/`。
`evidence-index.py`はC#診断manifestの`captures[]`/`photos[].capture`/`ablations[]`を正規化して画像/sourceの実在とSHA256を検査する。実験ごとのenumを推測しない（Candidateのconditionは`integrated`）。不明な形を読む前に実際のkeyと1行を確認し、画像が無ければ代用しない。
