2026-10-30にユーザーが言語化から作った4案を却下した（LEDGER0294）。
このスクリーンは参照画像を直接画像生成へ入力し、筐体のRGBAと反射マップを作る。
「黒い枠」「ガラス」等へ要約して手続きの形を描き直す方式へ戻さない。
これはこの参照スクリーンでの判定。すべての画像作業で言語化を禁止する一般則ではない。

再生成と検証: `tools/screen-reference/README.md`。
画像・反復・評価記録: `G:\マイドライブ\shubie\reports\2026-10-30_crt-reference\`。
評価は新規エージェントへ2枚だけ。前の評価・実装情報・目標点は知らせない。
ユーザー指定の完了条件は、室内と家具を除く辛口の類似度96%以上。
点数はその評価者の主観的判断であり、画像測定の誤差率ではない。

実装は `CrtReferenceScreen` と `ScreenComposite`。著作とCG・マスクは論理16:9。
物理筐体は1280:1030。素材の開口から論理の中央4:3へ全層共通で写し、黒帯を表示しない。
色収差も実写範囲内へclampする。黒帯をRGB別に読むとシアンの直線が開口へ出る。
導入の到着矩形は物理開口。論理containの0.75をさらに掛けると二重に幅が縮む。
筐体の透過はRGB混合のためだけに使い、最終alphaは1を維持する。

フレームは非POTの1398×1125。インポートはNPOT None・非圧縮。
Frameは開口alphaだけを使う。枠のRGBはCaseColor.jpg（ユーザーの元参照のバイトコピー）から読む。
FrameとCaseColorはsRGB、ReflectanceとGlassはlinear。ランタイムはResourcesから読み、描画へ実際に使う。
NormalとGradeもlinear。NormalはDefaultのRGB画像として読み、自前で[-1,1]へ展開する。UnityのNormalMap importerへ変えない。
Glassは元参照の室内を50%グレー映像へ画像生成で置換した透過むらの素材。
テクスチャ設定は参照素材だけ明示的に行う。新しいAssetPostprocessorで全画像の再importを誘発したため、
全体のcallbackを増やす方式は採らなかった。

初回の枠抽出は右上に照明の残骸が残り、画像生成へ再入力してその塊だけ除去した。
画像生成の出力を完成予想図として合格させず、必ず本番シェーダのPNGを評価へ渡す。
`menu crt-reference`は実写A-C・夜間モード・視点による反射を描画し、元ファイルと材質のhashも保存する。

07では元の枠RGBへ替え、枠の形と質感は非常によく一致すると判定されたが総合82%。
10では色ずれのUV移動量を局所コントラストで変えた結果、細かい輪郭の段差が出た。
位置を局所ごとに動かさず、一定位置で読んだ色の混合量を変える側へ直した。

ガラス透過をカメラISPより前へ置くと、明暗曲線が画面端を再び明るくした。物理ガラスはISP後、OSD後、筐体RGB前へ置く。
法線の光路長吸収と反射マップのFresnel反射もここへ掛け、夜間でも物理ガラスは残す。
低周波の元参照RGB(mip8)を照明gainへ使う部分は、材質の計測でなく画像由来の演出候補。通常映像の加工とともに夜間で弱める。

`CrtReferenceValidation`は実写/録画mask/CGの別解像度入力で位置を照合する。最大中心差0.195px、面積比0.9958、電源断RGB0。
ShaderのisSupportedや描画前のGetShaderMessagesだけでは、描画時に発生するエラーを拾えなかった。
`CrtReferencePreview`は描画後にもエラーを調べ、Python側は全面マゼンタと黒出力を拒否する。通る実描画と落ちる2例で校正済み。
23版のAPKはbuild成功、VR category/focusawareと主画面shader compileを検品。既存11ファイルを退避しbuild後hash不変を確認した。
buildのfont鮮度判定は診断/コメント等のC#変更にも反応した。今回HMD文言は変えていないため-Forceを使用し、既存フォントは変更していない。

同一22の再評価は79/82/86（元88を含め79〜88）。全material property（LiveTex以外）と入力640×480 RGB24を揃えたA/B対照でも94。
点数の幅と入力写真の影響があり、1〜3点差で実装の改善を断定しない。閾値を補正したり、達成判定の対象を勝手に狭めたりしない。
25は約5×4へ落とした入力を共通ISPで処理し、その明暗を除いて参照fieldを掛けた。82で白飛びを指摘され無効化。
共通ISPへ移しただけの対照（局所補整0）は22とRGB差0。これを新しい改善として採点しない。

28では失敗したPalette/core/局所正規化/微細粒/空間PSFを撤去。runtime素材は6点。参照fieldは室内照明を別室へ固定するためruntime0、診断の除去比較だけに残す。
RGB位置差は元参照の推定値そのもの。最高点を理由に22を採用した設定ではない。28の独立判定86で96未達。
28APKは146,108,414bytes。描画manifestとshader/CRT設定hash一致、既存11ファイル不変、2288テスト通過。APK/検証/全39枚の判定HTMLは同じDriveフォルダ。
Gradeはgrade-fit.jsonのlookup全256値からバイト一致で再生成できる。fit-grade.pyの再fitはsource/guide明示が必須。各回更新されるA_ungradedを14時点の画像と取り違えない。
