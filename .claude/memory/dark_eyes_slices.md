# 闇の目を「版」で描く（0238）を触る前に

契約は `rules/streaming.md`「見え — 壊れた画像データでできた目」。ここは**次に触る人が踏みそうな罠**と、2 周（R055 → R056）で分かったこと。
参考画像は `tools/eyes-ref/dejime.jpg`、Codex が描いた個体は `tools/eyes-ref/gen/glitch_*.png`、版は `Assets/Resources/Eyes/EyeGlitch.png`。
照合の数値は `canon/ROUNDS.md` R055 / R056、比較の絵は `logs/eyes-look/`。

## 1. ⚠⚠ 手続きで描いた帯は「チープ」だった（R055 → 0238）

R055 は版画の白目を「帯 × 1 色の横長セル・同心の環」へ手続きで置き換えた。5 回焼いて数値（色の割合・彩度・内側の闇）は
参考に並んだが、ユーザー判定は「整然としすぎ・質感とデジタル感がチープ」。
参考の「デジタル感」の正体は**写真が壊れた画像データ**（JPEG の 8×8 マクロブロック・行のずれ・ブロックの複製・
落ちた矩形・1〜2 画素の色ノイズ）で、**規則正しい格子と平らな 1 色のセルはその正反対**。
⇒ 中身は焼いた版にし、シェーダは包絡で切ってずらして引くだけにした（R056）。

⚠ **「点灯した画素の色の割合」は目に読めるか・チープかを 1 ビットも決めない。** 判定は絵で、数値は並べる材料（`reference/why.md`）。

## 2. 版の作り

- **Codex に参考を添えて同じ画風で描かせる**（`skills/codex`・プロンプトは `image-prompt-standards.md` §7 のとおり
  「見本の目を複製するのではない。取るのは画風・粒・色の配分・壊れ方」）。1 枚 60〜90 秒。4 個体を並列で描かせた。
  個体差は言葉で（半分閉じた細い目 / 見開いた丸い目 / 虹彩の大きさ / 赤の斑の場所）
- `tools/make-eye-glitch.py`: 黒の地を alpha 0（輝度 0.10 未満・2px の開き）→ 目の箱（行の点灯数が最大の 12% を超える行）を
  タイルの中央へ・横 0.92・縦はその `--ratio`（既定 0.60）倍に引き伸ばす → 2×2 の 2048² RGBA。rgb は alpha を掛けてある
- ⚠ `--ratio` はシェーダの `TEX_RATIO` と対。Codex の目は 0.51〜0.55 なので伸ばすのは 2 割まで（0.66 だと B が 1.3 倍に伸びた）
- 4 個体に満たないときは `datamosh()` で化けさせて埋める（左右反転も混ぜる）。**同じ画素を 2 度置かない**
- 取り込みは `EyeGlitchImporter`（mip 必須・Clamp・ASTC 6x6・2048）。mip が無いと遠い目がモアレになる

## 3. シェーダ（`AnomalyEyes.shader`）

- 瞼の包絡（`pu` / `lidU` / `lidD` / `up` / `dn` / 笑い / 瞬き）は 0076〜0085 の式そのまま。**ただし版を切らない**（0239・R057）—
  包絡が与えるのは**中心線 `mid`**（目尻の傾き・笑いの曲がり）と**縦の潰し率 `squash`**（中央の丈で測る）だけ。
  `v = 0.5 + (p.y − mid) / squash · Kv`。閉じる ＝ 行が中心線へ潰れて 1 本の線、笑い ＝ 中心線が上へ曲がって三日月
  - ⚠⚠ **切ると破綻する。** 閉じる途中に手続きの綺麗な弧の縁が現れ、開き切っても版の縁と包絡の縁の 2 種類が混ざる
    （0239「破綻」の正体の 1 つ）。見える形は常に版の alpha
- 目の箱 → 版の箱: `t.x = 0.5 + 0.5·TEX_EYE_W·q.x / SHAPE_SCALE`（q は帯ごとにずらした x）。個体は `seed` から 4 つのタイルと左右反転
- **視線は眼球が瞼の下で回る形**: 目の楕円の 0.55 まで版ごと平行移動、輪郭（1.0）で止まる、間は薄れる。動く量はタイルの 0.10 まで。
  ⚠⚠ **薄れは 5 段に量子化する** — 滑らかだと白目の伸びが動きぼかしに見える（輪郭から放射する筋）。段にすると
  「ブロックが飛んだ」形で壊れた画像データの語彙に乗る。⚠ 「虹彩の周りだけ」（半径の円で薄れる）は動いた先の縁で渦を巻く。
  ⚠ **版ごと滑らせる**（旧・gaze を uv に足すだけ）と輪郭も動き、目玉ではなく目そのものが漂う（0239 のもう 1 つの正体）
- **帯のずれは僅か**（`SHEAR_HOLD` 0.03）。版が既に壊れているので、開きかけの散らばり（0.55）と視線の縁の刻み直しにだけ効く
- ⚠⚠ **mip の段は、ずらす前・歪める前の uv の微分で選ぶ**（`SAMPLE_TEXTURE2D_GRAD`）。帯ごとに uv が跳ぶので、素直に引くと帯の継ぎ目で
  微分が発散して 1 画素の線に別の段が混ざる
- 上下の柱: 版に描いてある柱（タイルの余白）と、目の箱の縁の行を縦に引き伸ばした柱を max で合流。柱の候補は目の横幅あたり 14 本。
  潰し率で一緒に潰れる（閉じると柱も中心線へ寄る）
- **fps は塗る面積で決まる。** quad の縦の余白 `RiftExtend` 1.5 のとき 89 個で 34〜35 fps（版を引く前に捨てても戻らない）。
  版の柱は目の丈の ±0.67 にしか無いので 0.8 へ（面積は半分 → 48 fps）。横も `ShapeScale` 0.74 → 0.90（版画の暈の余白は要らない・
  quad ≒ 版のタイル・さらに −32%）。⚠ `ShapeScale` と `SHAPE_SCALE`、`RiftExtend` と `RIFT_EXTEND` は対

## 4. 対で直す値

- `AnomalyEyesMesh.RiftExtend`（1.5）⇔ シェーダ `RIFT_EXTEND`。片方だけ直すと目が縦に潰れる／伸びる
- `make-eye-glitch.py --ratio` ⇔ `TEX_RATIO`／`EYE_W` ⇔ `TEX_EYE_W`／`COLS × ROWS` ⇔ `TEX_COLS × TEX_ROWS`
- `AnomalyEyes.DefaultColor`（白）⇔ `Main.unity` の `[Eyes]` の `color`。**シーンの値が実物**（`gain` と同じ罠・`menu scene` は書き戻さない）
- `DefaultGain` 0.7 ⇔ シーンの `gain`。0.5（0076 の版画の白目で「明るすぎる」と下げた値）から上げた —
  版の目は輪郭の内側の 4 割が闇で、白の面が無い。判定は `canon/OPEN.md`

## 5. 観測

- `eyes=` の **8 つ目 ＝ 版を掴めたか**（`AnomalyEyes.TextureLoaded`）。版はシェーダの既定が黒なので、
  掴めていないと組めていて数も進むのに 1 画素も出ない。`analyze-xp-log.py` が 0 を FAIL にする
- プレビューは `menu eyes -Set scale=2`（Quest の片眼の密度）。既定の 960×540 では 1〜2 画素の粒が溶けて別物に見える
- ⚠⚠ **実機の生録画（`_raw.mp4`）のコマは、画の中の時計（OSD）で探す。** `xp-evidence` の対応も `record_started − app_started` も、
  生 mp4 を cv2 のコマ番号 ÷ fps で引くと 8 秒ずれた（4 周目 A が出た）。目は視界の周縁なので `_eye.mp4`（中央の切り出し）には
  半分しか写らない（`rules/visual-verification.md` §11）。左眼は `f[:, :w//2]`
- ⚠⚠ **版を引く前に捨てる**（`need` の早期 discard）。quad は目より縦に 1.5 倍長く、目の外の画素が過半。そこで版を 2 回引くと
  89 個が開いた 2 秒で **34 fps** まで落ちた（走行 `20260919_192053`・旧の帯は 58 fps）

## 6. 触らなかったもの（理由つき）

- **段の尺と曲線**（0076 / 0094 / 0138）: ユーザー判定。`frames.tsv` の stage / big / field / open は旧版と全 349 行一致
- **視線の飛び方**（0084）: 帯の刻み直しをこの縁に乗せた。別の時計で刻み直すと群れ全体が常にちらつく（0076「動かすものは 1 つ」）
- **暈**: 0077 で 2 巡とも「残っている」と言われたので無い
- 目の縦横比 0.50〜0.80・虹彩の頭打ち（R055 で入れた）: 包絡の形として残す。虹彩の大きさ自体は版が持つ
