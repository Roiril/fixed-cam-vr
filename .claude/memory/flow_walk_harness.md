2026-10-17。ユーザー依頼「アプリ起動～スタッフセッティング～体験者タブレット～～～リセットまでのフローを、シュビー視点で見直して…直してほしい。まずは必要なハーネスから」「体験者が体験中以外のフローで」。

**道具**: `node tools/visitor-ui/flow-walk.cjs`（使い方は `tools/visitor-ui/README.md`「一巡を通しで撮る」）。
代役 `staff-mock-server.cjs` を空きポートで立て、headless Chrome（1097×686・タッチ）で本番の `index.html` を押して回る。
画面ごとに PNG・見えている文字・押せるボタン・スタッフ画面の開閉の呼び出し元を絵コンテ HTML に並べる。
`a.expect()` が外れると終了コード 1。`--web-root` で直す前の版を同じ代役で歩ける（校正に使った）。
Quest 側は `StaffSetupPreview`（18 画面）を `menu raw:` で焼いて並べる。

**単体の試験では見えず、通しで初めて出たもの**: 回収の長押しを離した指の click が、リセット完了で同じ位置に現れた
「来場者の画面にする」へ入り、2 人目以降だけ来場者の画面へ勝手に飛んでいた。`verify-runtime.cjs` は要素ごとに
dispatch するので、画面の切り替わりをまたぐ指は再現できない。
**Why:** 長押しは成立した時点で画面が変わるのに、指はまだ画面にある。**How to apply:** 長押しで画面を切り替える
ボタンを足すときは `bindHold` を通す（成立後は指を離して 0.4 秒経つまでページ全体の click を捨てる）。
確かめるのは flow-walk の `next-reset` の期待。

直した 7 点（判断と根拠）:
1. 上の誤タップ（`guardClicksAfterHold`）
2. 反映の画面の「博士の説明を始める」ボタンを画面から外した。LEDGER 0204「画面タップでいいならボタンは不要」に反して 10-11 に復活していた。`resultContinueBtn` は `visually-gone` で残す（実機試験が押す）
3. スタッフ画面の「タブレットをスタッフにお渡しください」帯は、アプリが自分で開いたときだけ。長押しで開いたなら読み手はもう受け取ったスタッフ。出すと確認画面が縦にはみ出していた
4. 最初の準備の「対処」は本文（位置合わせの手順）を繰り返さず、並行して直せるカメラ・素材の異常を指す
5. 装着の準備の呼び名を「クエスト」に揃えた（「Meta Quest」と「クエスト内」が 1 画面に混在）。ユーザー自身が 0203 / 0256 で「クエストに反映」と呼んでいる。「くだ／さい」で折れていたので `word-break: auto-phrase`
6. 返却待ちの 3 行目「スタッフの確認をお待ちください。」を外した（上の 2 行と同じことを言う）。中断・通信断のときだけ 1 行足す
7. スタッフの「最初からやり直す（長押し）」→「設定と説明をやり直す（長押し）」（何が最初に戻るのか分からなかった）。Quest の「準備ができました」から、本文と同じ「次の体験者の準備はタブレットで行います」を外した

⚠ 長押しの直後に次を押す試験は、離してから 0.5 秒待つ（0.4 秒以内の click は本番が捨てる）。
タブレットの instrumentation `holdVisitorButton` がこれで落ちた（2026-10-17 の実機導入）。

実機（2026-10-17）: タブレット APK と Quest α へ導入し、端末から取り出した APK の SHA-256 が一致。
instrumentation 5 種類（requireQuest 27 / equipment 9 / staffFinish 152 / visitorFocus 111 / staffFlow 40）が合格。
staffFlow は β が応答せず、β 固定を α に差し替えて流した（リポジトリの試験は β のまま）。
**手で押す確認（離しても飛ばない・反映画面にボタンが無い）と Quest の 2 行表示は未確認**。
α が「位置合わせをやり直してください」で止まり、回収画面まで進めなかったため。β には未導入。

2026-10-19 追試: Quest β でも staffFlow 40 項目合格（リポジトリの β 固定のまま）。⚠ Quest が本編の終了状態だと
通知音の確認で落ちる（試聴を止める正しい挙動）ので、**Quest のアプリを起動し直してから流す**。
手で押す確認はまだ。自動走行（`ShowWalkDebugDriver`）はスタッフ用準備を `UseAutomation` で飛ばすので、
タブレットのスタッフの段（リセット → 来場者 → 確認 → 回収）は自動では進まない。**人が HMD で位置合わせを 1 回確定する**のが前提。
タブレット本番 APK は WebView のデバッグ口を開けていない（`debuggable` 依存）。押す確認は screencap で座標を読み `adb shell input` で行う。
