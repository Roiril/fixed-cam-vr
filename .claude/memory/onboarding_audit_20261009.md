# 起動から HMD 引き渡しまでの改善（2026-10-09）

ユーザー依頼: 起動 → スタッフ設定 → 体験者がタブレットで設定 → スタッフ確認 → HMD 引き渡し。画面を撮り、特殊ケースも含め、見つける → 改善 → 再確認で進める。

## 変更

- 新しいスタッフ準備 API がある場合、タブレットの新しい受付は `staffSetup.stage=settings` と最新の Quest 更新を要求する。リセット完了待ちは入口を無効にする。同じページで送った設定の編集と再送は保持する。
- 新しい順序は説明10文 → スタッフへ返す → Quest のスタッフ確認応答 → 既存の装着前2文 → 装着手順。説明10/10と装着2/2は別に示す。旧 API とスタッフ説明確認モードは12文を連続して進める。
- スタッフ確認済みは画面復元の未確認通知で取り消さない。スタッフ欄を閉じた後は停止し、「この文を再生」で同じ文を再生する。
- `wear1` では次と前を無効にして前章へ戻さない。自動再生終了でも返却待ちへ戻らない。`wear1` から `wear2` への移動を返却判定に含めない。
- シーン更新と表示言語の変更でも接続名と更新停止表示を保持する。
- スタッフ欄には Quest で反映を確認した言語とホラー軽減を常設する。確認可能になったら、その2項目の確認を指示する。
- カメラ異常と位置確認の異常を通常の説明待ちより先に案内する。装着前に異常が出た場合は装着手順を隠す。説明と位置合わせを保持して復旧を待つ。
- 体験者のリセットで「ヘッドセットが再起動しました」と表示しない。新しい体験者は新しい選択へ進む。
- 位置合わせの A やり直しは A を離してから新しい押下を待つ。やり直しを押した場所で点1を記録しない。
- 点採取で A を早く離した場合と誤差超過は理由を主案内へ出す。誤差の cm と合格基準は保持する。
- HMD の案内はタブレットの実際のボタン名を使う。カメラ復旧では問題のあるスマホ名を示す。

## 実機の注意

Quest β は `2G0YC1ZF7S06BW`。Redmi Pad SE は `122d7871`。検証時は同じ展示 Wi-Fi。
β の時計は PC と一致していない。導入版は `lastUpdateTime` の新旧で判定せず、端末から回収した APK の SHA256 とビルド済み APK を比較する。
初回の `HEADSET_CAMERA` 許可ダイアログは HMD に出る。導入で実景を撮影する既存の機能が要求する。位置合わせと引き渡しの物理操作は机上の状態再現だけで合格にしない。

最終通常版は両端末へ導入済み。端末から回収した APK の SHA256 が一致した。tablet APK 内の HTML も現在のソースと一致した。最終再導入後の Quest は TableDuo が稼働していた。廻リ視のプロセスは確認できず、許可画面だけが残っていた。別アプリを終了せず起動再試行を止めた。以前の起動時の tick 47→237 は最終再導入前の証拠として分ける。検証 APK は `INSTALL_FAILED_USER_RESTRICTED` で停止し、ビルド成功だけを確認した。

開始前からスタッフ準備の依存一式が未追跡だった。今回の変更だけのコミットでは依存を欠く。別セッションの変更をまとめず、今回の差分と動く作業ツリーを保持する方針を advisor に諮って採用した。
