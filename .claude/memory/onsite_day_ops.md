旧 `onsite.html` / `shoot.html` / `runbook.html` は転送だけ。以下の 2026-09-04 の記録にある画面の配置と操作は経緯であり、案内には使わない。

### 作り直したときに決めたこと

- **見出しが「開場できます」に届く形にした。** 旧画面は β の deviceId が空・β のタブレットが未登録というだけで、1 度も ready にならなかった
  （`summarize` が 7 台を数えていた）。届かない見出しは読まれなくなる。⇒ 予備の機は登録の `"standby": true` で判定から外す。
  登録の無い側のタブレットは数えない。**注意（熱・露出が自動・反映待ち）は開場を止めない**
- **原因でまとめる。** 卓に届かない・卓の PC が `.10` を失った、のとき赤を 6 個並べない。機器の行は「分かりません」にする
- **灯は生の値だけ。** 1 時間で切れる人の確認を灯に混ぜると、開場して 1 時間後に灯が黄色へ戻る
- **素材の門は日付で止めない。** 旧画面は「無人の写真 3 枚が今日の日付」を要求し、2 日目に毎朝撮り直しを強いた。
  日付は会場と照明の一致を証明しない。⇒ 採用中の写真といまの映像を重ねて人が見る。その確認は素材の版・日付・カメラの傾きの判定が変わると外れる
- **サーバには事実だけ足した。** Quest 行の `run`（体験の段・周・経過）と `facts`（位置合わせ・左右コントローラ・音）は行の status に混ぜない。
  右コントローラが机で寝ているだけで行が要確認になるのを避ける。重みは画面側が体験の段で変える
- **状態が変わった記録はブラウザで作らない。** 画面を閉じているあいだ poll が止まり、見る端末ごとに中身が違う。⇒ `watch` の記録の末尾を `/ops/status.watch.events` で配る
- **画面から呼べる復旧は 1 台ずつの `/ops/restart` と `fix panel` だけ。** `fix cameras` は端末の照合も 90 秒の間隔も見ない
- **体験者 1 人ごとの流れは画面に持たない。** 正本は博士タブレットのスタッフ画面。二重に持つとずれる
- 流用した判定は `ops-shoot-model.js` / `shoot-model.js` / `ops-library-preview.js`（録画の帰属・回収・必要な長さ）。表示は全部書き直した

### ⚠⚠ カメラが 1 台届かないだけで `/ops/status` が落ちていた（2026-11-15 に直した）

届かない端末への `adb connect` は、日本語 Windows では UTF-8 の失敗文を返す。`subprocess.run(text=True)` は既定の cp932 で読むので
読み取りスレッドが `UnicodeDecodeError` で落ち、`stdout` が `None` になる。そのまま `.lower()` を呼んで `/ops/status` が空の応答を返していた。
画面は「状態を取得できません」と出す。**いちばん画面が要る場面（カメラが落ちた）でだけ画面が死ぬ**形だった。
テストは `runner` を差し替えていたので通っていた。見つけたのは、作り直した画面を実機のカメラ 2 台（B が不在）へ向けたとき。
⇒ `operations._ADB_TEXT`（`encoding='utf-8', errors='replace'`）と `(stdout or '')`。`onsite.py` と `quest-fleet.py` は元から UTF-8 で読んでいた。
⇒ 画面が「卓に届いていません」と出たら、`curl -s -m 20 http://127.0.0.1:8099/ops/status` を直接叩く。空なら卓の中の例外（`logs/onsite/desk.log`）。

## 1. 層を 3 つに分けた理由

**シュビーを運用の層に置かない。** Claude は Anthropic への回線が要るので、
**会場の外向き回線が死んだ瞬間に消える**。だから当日の操作は LAN だけで閉じる層に置き、
シュビーは「判断が要るときの修理役」に退けた。

| 層 | 実体 | 落ちる条件 |
|---|---|---|
| 機械が勝手に | `onsite.py watch`（監視と復旧）／ログオン自動起動 | PC が落ちる |
| 人が画面から | `http://192.168.10.10:8099/`（卓の PC は localhost） | LAN が落ちる |
| シュビー | `py -3.11 tools/onsite.py <cmd>` | **外向き回線が落ちる** |

⚠ 3 つとも**同じ HTTP API を叩く**ので、どこから操作しても結果は同じ。ここを分けると
「卓では直したのにパネルに出ない」が生まれる。

## 2. ⚠ 卓の「✅ 本番前チェック」と `onsite.py check` は別物（統合しない）

卓のはブラウザの中にあり、**ブラウザが見えるものしか見えない**（`show.json` ＋ heartbeat ＋ `/diag`）。
`onsite.py check` が見るのは**その外側**で、重なりが無い:

- 端末に入っている APK が焼いたものと同じか（古い機は「実装が効いていない」の顔で出る）
- 端末キャッシュ・電池・熱・Wi-Fi の相手
- **無線 adb が開いているか**（閉じていると当日 1 手も打てない）
- 露出 / AWB ロック・レンズの画角・名乗った cameraId
- 傾きと較正の差
- **卓が 2 つ立っていないか**

⚠ `preflightRows()` は `app.js` の 434 行・グローバル 9 個に依存している。**本番直前に共通化しない。**
壊すと卓 UI が丸ごと死ぬ。分けたまま両方を回すのが正しい。

## 3. ⚠⚠ 古い heartbeat で判定させない（作っている最中に踏んだ）

卓の `/unity/status` は**最後に受け取った heartbeat を何時間でも返す**。最初の実装は
Quest が 1 台も起動していないのに「音 OK / コントローラ NG」を出した — **4 時間前の値**だった。
⇒ `ageSec <= 6.0` のサンプルだけ採る。0 件なら「見ていない」と言う（`skip`）。

⭐ 同じ理由で、**2 台のうち片方だけ欠けている状態は 1 回読んでも分からない**。
heartbeat に端末 ID が無く（`ShowControlClient.cs` の `Hb` に無い）、`_unity_status` は
1 スロットを 2 台が交互に上書きする。⇒ **20 秒の窓の最悪値**で見る（欠けている機の番が来た瞬間に落ちる）。
⭐ **2026-09-11 から heartbeat は `deviceId` を名乗る**（0185・[[visitor_tablet]]）。卓は `_unity_devices` に
機ごとに持ち分け、`GET /unity/devices` で出す（`localIp` / `titleStage` / タブレットの口が開いているか も載る）。
`/unity/status` と `onsite.py check` は従来のまま（1 スロット・20 秒の窓）なので、機ごとに見たいなら `/unity/devices` を読む。
⚠ タブレットの設定そのものは卓を通らない（0187。Quest 自身の :8090 へ直接）。

## 6. ログオン自動起動（2026-09-04 に入れた）

`tools/onsite-autostart.cmd` のショートカットを `shell:startup` へ置いた（`mawarimi-desk.lnk`）。
**外すのはそのショートカットを消すだけ**で、他は何も書き換えていない。

- **冪等が必須**。`onsite.py serve` は `:8099` が開いていれば何もしない。
  ⚠ 卓が 2 つ立つと互いの `show.json` を巻き戻し合う（[[show_json_is_live_config]]）
- ⚠⚠ **`.cmd` は ASCII だけで書く。** cmd.exe は ANSI コードページ（cp932）で読むので、
  UTF-8 の日本語を `rem` に書くと**化けた断片がコマンドとして実行される**（実際に踏んだ）。
  説明は `.md` 側に置く
- ⚠ **発火するのはログオン時だけ。** この機体は `AutoAdminLogon=0`（自動ログオン off・
  **変えていない**）なので、無人再起動でサインイン画面に止まると卓は戻らない。誰かが 1 度サインインする

## 7. ⚠ 自動復旧で Wi-Fi には触らない

`watch` が打つ手は 2 つだけ — **画面を起こす**（`KEYCODE_WAKEUP` → `dismiss-keyguard`）と
**配信アプリを起こし直す**（`force-stop` → `am start`）。順番が要る（Doze 中に `am start` だけ
すると Activity が resume されず、**フレーム 0 のまま HTTP だけ生きる**）。

⚠⚠ **Wi-Fi の入れ直しは 1 度もやらない。** 保存済みの別 AP が選ばれて全台が移る
（2026-08-30 に実演済み）。しかも画面には何も出ない。`onsite.py` はこの操作を持っていない。

⚠ **続けて 2 巡回（`--sec` ごと）止まって見えたときだけ**撃つ。1 回目は記録だけで、間に 1 回でも
映像が進めば数え直す。体験の最中なら、起こし直しは体験者が見ているカメラを 5〜10 秒の砂嵐にする。
⚠ 1 台につき **90 秒に 1 回まで**。卓の `/ops/restart` と同じ `Logs/onsite/restart-ledger.json` を見るので、
同じスマホを両方から数秒差で起こさない（再起動ループを作らない）。
⚠ 未修正（2026-11-14 の運用監査）: 記録の読み書きはプロセスをまたいで原子的でない。watch と卓がミリ秒差で
同じ台を判定すると、両方が起こし直しうる。起きるのは 1 回きりで、その次の判定から 90 秒の間隔に戻る。
