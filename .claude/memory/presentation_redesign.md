# 導入と通信画面の再構築

2026-09-13。依頼は `canon/LEDGER.md` 0207〜0213。具体的な見た目は `canon/OPEN.md` の案であり未判定。

## 変更範囲

導入の描画と通信画面の表示を再実装する。開始条件と通知の時系列は変更しない。共有設定には触れない。

導入は 0208 で割れる演出へ戻した。0209 では中央を無傷で残していた窓を廃止した。
0211 では実景を透かす穴から、静止画像を運ぶ立体メッシュへ変更する。
`IntroPassthroughCapture` が既存 MRUK の左右 `PassthroughCameraAccess` を準備する。
`IntroVeil.FrozenFrameProvider` は取得時の画像と撮影射影を受け渡す。Streaming は OVR を参照しない。
割れ始めに画像を GPU で左右1枚ずつ複製する。撮影時の頭位置へ開始位置を固定する。
変形前の頂点から撮影画像の座標を求めるため、移動中も同じ景色が同じ破片へ残る。
MRUK 201 の Android GPU 画像は Update 内の Blit では前回描画のものになる。
撮影姿勢も前回描画に対応するものを保持して組み合わせる。最新時刻の姿勢を付けない。
Editor の PCA は Update 内で CPU 画像を Apply するため、こちらは最新姿勢を使う。

静止画像は厚みのある破片の表へ貼る。裏と側面は暗くする。
基底 Quad で既存の深度を消す。破片の深度を先に描き、その手前の面だけへ色を描く。
静止画像の経路は compositor alpha を閉じたまま保ち、RGB だけでカメラ映像へ混合する。
撮影不能時だけ旧 alpha 窓へ戻す。`shatStyle=frozen` / `shatFrozen` / `shatCopies` で区別し、
旧窓の描画を「フリーズできた」と判定しない。

カメラ取得には `horizonos.permission.HEADSET_CAMERA` が必要。
権限は fixedcam の生成マニフェストだけへ加える。共有の OculusProjectConfig は変更しない。
実景画像はメモリ内でだけ保持し、演出の終了で解放する。保存と送信はしない。
Meta PCA の画角は compositor のパススルー全域を覆わない。撮影時刻も表示と完全一致は保証されない。
取得できない外周は引き延ばさず暗くする。実機で投影と色の継ぎ目を確認する必要がある。

破砕中の基底 Quad は現実を透かさない。中央を含む全域を同じ破片メッシュが描く。
四辺から閉じるマスクで先に破片を切り落とさない。
破砕中の隙間は黒にする。基底 Quad は alpha と RGB を別々に掛ける。
映像混合が始まるまでは先描きされた管の燐光も消す。燐光が残ると中央の隙間だけが茶色になり、
完成前からスクリーンの矩形が見える。混合開始後は RGB を維持し、混合量は破片だけへ渡す。

0212 の参考画像では尖った大小の破片を採用する。金色の輪と火花は移さない。
`IntroFractureMesh` は角度の空間へ不均一に211点を置く。共有する辺を持つ386枚の三角片を作る。
細長い片を混ぜる。24個の大区分は割れ始めの順序だけに使う。
メッシュ生成の乱数は固定種の System.Random。Unity の乱数へ影響しない。

`IntroFracture.shader` は左上寄りの起点から順に開く。中央も三角片へ分離する。
.12〜.42 で各片が外へ広がる。大きい片は手前へ出す。小さい片は奥へ送る。
中央が空く時間を挟む。0213で、.43以降は時計回りの渦を描いて戻る。
到着は小片.79〜大片.82。スクリーン中心からの距離は開始位置から対応位置へ単調に補間する。
角度は開始位置と対応位置の符号付き最短差から1周引く。回転を巻き戻さず対応位置へ収める。
奥行きは従来の曲線を使う。各片の傾きも残す。終端の位置を対応位置へ厳密に一致させる。
撮影した左右画像の平均 UV をスクリーン内の対応点へ写す。撮影範囲外を引き伸ばさない。
大きな三角片の初期投影には撮影射影の分母も補間する。収束とともに平面の画像座標へ移す。
撮影範囲外は深度にも書き込まない。透明な片が後ろの写真を隠すことを避ける。
開始位置は撮影時の頭を中心とする半径 1.6m の面。途中は傾いて曲線を渡る。
スクリーンの実平面の奥行きも使う。
局所変形は中間だけに加える。終端では共有頂点が一致し、同じ片が矩形全体を隙間なく敷き詰める。
中央を除外する fragment の分岐は持たない。.82〜.88 は完成した実景の面を見せる。

映像への混合は .88〜.98。2.5 秒の段なら 2.20〜2.45 秒。音の `Shatter` は .02 で発火する。
`ScreenOn` は live が .999 へ達した時に発火する。1.70 秒の割れる音の後に約 .70 秒の間がある。
音源は0208で作った広がり→短粒化→中心収束を継続する。

`shatter` は音と画の共通の進み。実際に描画へ配った最大値は `ShatterPeak`。組めた破片数は `ShatterPieces`。テレメトリは `shatStyle=frozen` で旧形式と区別する。新しいシェーダを追加する場合は Always Included Shaders に明示登録する。

通信面は元の文字列で配置を確定する。欠落と位置ずれは文字メッシュに適用する。ラテン文字を全角の文字化けへ置き換えて折り返しが変わる経路を避ける。`CorruptionFor` の回復と解除は既存の値を読む。

本文と赤い残像の GameObject は active のまま保つ。表示だけを MeshRenderer.enabled で切り替える。TMP の OnEnable が頂点の濃度を上書きして全文を出す経路を作らない。

## 検証の入口

`tools/unity.ps1 menu intro` と `menu comms-preview` は本体と同じ描画を使う。比較前の画像は `Logs/design-rebuild-20260913/before/`。日本語のほか英語とフランス語も `menu text-audit -Set lang=...` で確認する。

Editor の代理パススルーは実機の見えを保証しない。Quest の装着時の立体感と現実との合成は実機で別途確認する。

`menu intro -Set frames=1` は各コマの実状態を `clean/frames/frames.tsv` へ保存する。実 `SoundCueLogic` に通して得た発火は同じ場所の `audio-cues.tsv` へ保存する。動画の音はその判定時刻へ DSP の 35ms を足して重ねる。実機の 3D 音響と毎回の音程の揺らぎはこの確認用動画には含めない。
