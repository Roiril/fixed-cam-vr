2026-10-07 調査。台車（Pololu Romi シャーシ）の USB の先は **Romi 純正の 32U4 基板ではなく ESP32**。

- USB-UART は **CP2102N（VID 10C4 / PID EA60）**。この PC では初接続時に **ドライバ未導入（コード 28）** で COM が出なかった。Silicon Labs の CP210x Universal Windows Driver 11.6.0.420（Microsoft 署名・WHQL）を入れて **COM17** になった。基板を挿し直すと番号が変わりうる
- ⚠ **Silicon Labs の zip は curl だと CDN が 403 を返す**（Akamai）。アプリ内ブラウザで公式ページを開き、そのページ上の `fetch` で取得して `<a download>` で保存すると取れる（Downloads に `.tmp` 名で落ちる。PK で始まるか見て zip として使う）。インストールは管理者権限が要り、`Start-Process -Verb RunAs` の UAC で `pnputil /add-driver silabser.inf /install`
- チップは **ESP32-D0WD-V3 rev3.1**（40MHz・4MB フラッシュ・MAC 8c:94:df:52:b3:00）。4MB 標準のパーティション（app0/app1/otadata/spiffs/coredump）
- 中身は **Arduino-ESP32 の自作スケッチ「Romi / Joy-Con 2 control v3」**（BLE 機器名 `jc2-romi`、NimBLE-Arduino）。Joy-Con 2 の SYNC を押して BLE 接続し、スティックの入力を左右モーターの PWM に変換する。起動直後は `[DISARMED]` で、**スティックが中立になって初めて armed** になる。`duty limit` と `SPEED_LIMIT` で速度を絞る。ボタンとスティックの較正（中心 2048 の既定）あり
- **ピン配置（元スケッチの逆アセンブルから確定・実機で確認済み）**: side0 = **左**車輪 DIR=GPIO18 / PWM=GPIO19、side1 = **右**車輪 DIR=GPIO16 / PWM=GPIO17、AUX=GPIO2（起動時 LOW・用途未確定）。PWM は 20kHz・10bit。**左右とも同じ dir で同じ向きに回る**（dir=0 → 手前、dir=1 → 奥。左右の反転補正は不要）。モーター電源（電池）は入っていて 30% で回る
- **付いていないもの（実測）**: エンコーダ（候補 18 ピンを駆動中に監視して変化なし）、I2C 機器（8 組のピンで 0 件）、バッテリ分圧（ADC は全て浮き電位）。**現状は完全な開ループ**
- ビルド元は別の PC の `Documents\Arduino`（NimBLE-Arduino 使用）で、元ソースはこの PC に無い。**元ファームの全フラッシュは `output/romi/esp32-flash-backup-20261007.bin`（4MB・git 管理外）にバックアップ済み**。復元は `esptool.py --port COMxx write_flash 0x0 <bin>`
- 今は **診断・制御ファーム `tools/romi/diag/`（diag.ino + net.h + webui.h・`romi-diag-4`）が焼いてある**（元の Joy-Con 操作は動かない）。シリアル操作は `py -3.11 tools/romi/rc.py "info" "g s 1 40 30 0" ...`（`g` は目標指定の走行。`help` で一覧）。ビルドは Arduino IDE 同梱の arduino-cli、FQBN `esp32:esp32:esp32`（ESP32 コア 3.3.8）。**PlatformIO の ESP32 は Arduino コア 2.x で `ledcAttach` が無いので使えない**
- **ネットワーク（診断ファーム v4・2026-10-07 に堅牢化）**: Romi は**開発用ルーターの 2.4GHz `kougaku-lab-exp-g`（ch6）に参加**する（Quest・タブレット・PC の有線 LAN 192.168.10.x と同じネットワーク）。**IP は静的 `192.168.10.51`**（展示網の割り当て規則: PC .10 / カメラ .21-.23 / Quest .31 .32 / タブレット .41 / **Romi .51**。ゲートウェイと DNS は .1）、名前は **`http://romi.local/`**。
  - **堅牢化は他機器（Quest・配信スマホ）の方針に合わせた**（実装は `tools/romi/diag/net.h`）: ①切断は指数バックオフで再接続（1→2→4→8→16→30 秒・つながればリセット）②20 秒結果が出なければ無線を張り直す ③**UDP :8830 の発見 `fixedcam-discovery/1` に `role:"cart" id:"R"` で参加**（probe へ unicast 応答・5 秒毎に broadcast announce・別 show トークンは無視。Quest と PC 卓は role が camera / show-server 以外を無視するので影響なし）④60 秒つながらなければ非常用 AP `ROMI-DIAG` を足し、復旧して 15 秒で畳む ⑤10 分つながらず走行中でなければ再起動 ⑥ループが 30 秒止まれば WDT で再起動。`/info`（uuid・RSSI・切断回数・理由）と `/health` あり
  - **実測（2026-10-07）**: 強制切断 → **1.2 秒で同じ IP に復旧**。つながらない状況 → バックオフが設計どおり進み **60.2 秒で非常用 AP が上がり（Quest の走査で −33 dBm・ch6・WPA2 を確認）**、網が戻ると自動で LAN に復帰して AP を畳んだ（最悪 30 秒＝バックオフ上限）。試験は `py -3.11 tools/romi/nettest.py discovery|kick|outage|restore` と、ファームの `wifi fake <ssid>` / `wifi unfake`（RAM 上だけ偽 SSID にする。NVS は触らない）
  - ⚠ **PC の Wi-Fi は 2.4GHz が見えない**ので、PC の `netsh wlan` で ESP32 の AP を探しても出ない。Quest の `adb shell cmd wifi start-scan` → `list-scan-results` で見る（**最初の 1 回は古いキャッシュで出ないことがある。数回走査し直す**）
  - ⚠ ESP32 の切断イベントは 1 回の失敗で 2 回届く。そのまま数えるとバックオフの段が倍速で進む（`!netUp && !netAttempting` なら無視して直した）
  - 参加情報（SSID・パスワード）は **ESP32 の NVS にだけ**ある（ソース・git・memory に載せない）。入れ直すときは `ROMI_WIFI_SSID` / `ROMI_WIFI_PASS` を環境変数に置いて `py -3.11 tools/romi/set-wifi.py`（パスワードはユーザーに聞く。応答に値は出ない）。シリアルで `wifi status` / `wifi scan` / `wifi set` / `wifi clear` / `wifi kick` / `reboot`。**ESP32 は 5GHz を使えない**ので、5GHz 専用の SSID（`kougaku-lab-A` や `kougaku-lab-exp-a`）には入れない。PC の Wi-Fi 一覧には 2.4GHz 側が出なかったので、**ESP32 自身に `wifi scan` させて SSID を見つけた**。LAN 内の誰でも `/run` を叩ける（認証なし）ので、展示本番では要対策
- **操作画面（ジョイスティック・2026-10-07）**: `http://192.168.10.51/` を開くと**スクロール無しの操作画面**（ジョイスティック・速度 3 段の切替ボタン・設定・大きな停止の 4 つだけ。横向きにも対応）。`#set` が従来の設定画面（目標指定・条件・記録・ジョイスティック速度上限・台車の状態）。ジョイスティックは `/joy?x=&y=&cap=&flip=`（アーケード式の左右ミックス・不感帯の上に持ち上げ・立ち上がり約 0.3 秒／停止約 0.1 秒の追従・方向反転は必ず 0 を経由）。**更新が 400ms 途切れたら自動で止まる**（電波切れ・画面ロック・ページを閉じた場合）。操作画面は開くたびに必ず「ゆっくり」（既定上限 25%）から始まり、設定画面を開く・タブが隠れると停止を送る。指を離すと 0 を 4 回送る。時間指定の走行中はジョイスティックを受け付けず、逆も同じ（`busy`）
- **ホーム画面のアイコン（2026-10-07）**: 開発用スマホのホーム左上に「Romi」ショートカットを置いた（Chrome のメニュー →「ホーム画面に追加」→「自動的に追加」）。アイコンはファームが `/icon.png` で配信（`tools/romi/make-icon.py` が `diag/icon.h` を生成）、`/manifest.json` も配信。**http なので Chrome の標準ショートカットとして開く（全画面アプリにはならない・アドレスバーが出る）**。他の端末にも置くときは同じ手順
- **開発用スマホ（motorola edge 20 fusion・adb `ZY22CWZHZM`・Android 11・PIN はユーザーに聞く）**: **静的 IP `192.168.10.61`**（`kougaku-lab-exp-a`・5GHz）。保存済みネットワークは exp-a だけ（kougaku-lab-A / -G は 2026-10-07 にユーザー指示で削除）。captive portal 検出を切ってある（`captive_portal_mode 0`）。Wi-Fi を切って入れ直すと 3 秒で同じ IP に戻る。Chrome の広告プライバシー 3 項目はオフにした。画面を点ける・撮る・要素を読む道具は `tools/romi/phone.ps1`（`wake` は環境変数 `PHONE_PIN`、`shot` `ui` `tap`）。⚠ 静的 IP は Settings の UI 操作で入れた（Android 11 の adb に静的 IP の命令は無い）。⚠ **日本語の Gboard だと IP が全角で入る**ので `ime set com.android.inputmethod.latin/.LatinIME` に一時的に替えて入れ、終わったら Gboard（`com.google.android.inputmethod.latin/com.android.inputmethod.latin.LatinIME`）へ戻す。⚠ 入力欄の削除は `input keyevent 67` を 1 つずつ送ると効かないことがあり、カーソル位置も不定なので、結果を `ui` で毎回読んで確かめる。⚠ スクリーンショットは PowerShell の `>` でリダイレクトするとバイナリが壊れる（`screencap` → `adb pull`）。⚠ 画面が消えていると撮れる画は真っ黒（`dumpsys power` の `mWakefulness`）
- **手動操作の WebUI（v4・2026-10-07）**: `http://romi.local/`（非常用 AP のときは AP `ROMI-DIAG`・パスワード `romi1234`・机上用に接続して `http://192.168.4.1/`）。**流れは「条件（電池の残量・載っているもの）を入れる → 目標（直進 N cm / 回転 N 度）と強さを決めて動かす → 止まった結果（実際の距離・角度・左右のずれ）を入れる → 『記録をコピー』で私へ渡す」**。時間は較正モデルから自動計算する（直進 `v[cm/s]=sv·(強さ%−sd)`、回転 `ω[度/s]=rv·(強さ%−rd)`、時間=目標/速さ+オフセット。既定値は公式仕様からの当て推量 `sv=0.75 sd=8 rv=4.5 rd=10` なので**最初の数回は外れる前提**）。実測が溜まったら私が当てはめて **`/cal?sv=..&sd=..&st=..&rv=..&rd=..&rt=..`（またはシリアル `cal set sv=..`）で再計算の係数を入れ直す**（NVS 保存・`ver` が増える。コピーにも `cal=` が付く）。コピーは CSV（`id,kind,dir,target,duty_pct,planned_ms,actual_ms,trim,flip,result,lateral_cm,battery,load,memo`）。結果を入れるとシリアルにも `EVT res ...` が出る。駆動は時間で自動停止・強さ上限 68%（700/1023）・時間上限 8 秒・目標上限 直進 150cm／回転 720 度・120ms の立ち上げランプ。**前進は dir=1（2026-10-07 にユーザーの実測で確定。最初は dir=0 と仮定して逆だった。ファームの既定を直し、画面の「前後を逆にする」は既定の反転）**。画面は `tools/romi/diag/webui.h`、API は `/run /stop /state /res /cal /info /health`。机上の画面確認は `tools/romi/webui-stub.py`（ESP32 を模す代役サーバ。画面を直したらリロードだけ）。**`hidden` 属性は CSS の `display:grid` に負ける**（`.go[hidden]{display:none}` が要った）。結果の受け取りの保険は `tools/romi/evtlog.py`（`output/romi/evt.log` に追記・**COM を占有する**ので rc.py や書き込みの前に止める）
- **走行の実測（較正の元データ・何も載せない床上）**: 強さ 40%・1.25 秒の直進で目標 30cm に対し **20.5cm**（≒16.4 cm/s。当て推量は 24 cm/s）、左右のずれ 0cm（補正 0 で直進）。これで `sv` を 0.75→**0.5125** に入れた（`sd=8` 固定の 1 点当てはめ・`cal ver=3`）。**まだ 1 点なので傾き（強さ依存）と立ち上がり損（`st`）は未確定**。次は強さを変えて（例 30/50/60%）同じ 30cm を数回測る。回転の係数 `rv/rd` は実測ゼロ（当て推量のまま）。電池の残量は未入力
- **走行の実測 2 回目（何も載せない・強さ 40% だけ・各 2 回で同値）**: 直進 30cm 指定（1.829 秒）→ **31cm**・ずれ +0.5cm。左回転 90 度指定（0.667 秒）→ **80 度**。2 回とも同じ値で再現性は高い。係数を `sv=0.5297` `rv=4.0` に更新（`cal ver=4`）。**強さ 40% の 1 点しか無い**ので傾き `sd`/`rd` と動き出しの損 `st`/`rt` は未確定。右回転は未測定
- USB シリアルの往復遅延は中央値 15.5ms（p99 16.6ms）、ファーム内の駆動窓は ±3ms
- Romi シャーシ自体の公式仕様: 直径 165mm・163×149×70mm・160g（電池なし）、Mini Plastic Gearmotor 120:1 HP、ホイール 70×8mm、エンコーダは別売りで軸 1 回転 12 カウント、単三 6 本。**積載量・モーター定格電圧は公式ページに数値が無く、人形の重さに耐えるかは未確認**

**Why:** 台車の制御を作りこむとき、まず「何が載っていて、どこまで分かっているか」を探し直さないため。
**How to apply:** 台車を触る話が出たら、まず `[System.IO.Ports.SerialPort]::GetPortNames()` と `Get-PnpDevice -PresentOnly` で CP2102N が COM に出ているかを見る。esptool は `~/.platformio/packages/tool-esptoolpy/esptool.py`（`--after no_reset` で読むだけ、終わりに `--after hard_reset`）。書き込みは元のスケッチを消すので、先に app0（0x10000 から 0x140000）を `read_flash` で退避する。関連: [[quest-fleet-two-devices]]
