2-C の追いつきから人形化の暗転まで、主画面に掛かる（LEDGER 0313）。`RoomWarpField` が場を、`RoomWarpLogic` が時間を持つ。書き手は `CameraFeelFx`、読むのは `CrtCompositeShared.hlsl`。試作と計測は `tools/space-warp-study/`。

**画像の波に見えない条件**（A/B/C で版を作り、参考動画と同じ計器で比べた結果）:

- 変形は部屋全体の低次の 3D 変形（伸縮・剪断・わずかな射影）が主。3D の直線は直線のまま写るので、手すりや柱が波打たない
- 中央を止めて外を動かす。参考動画の半径別の変位は 2.5 / 7.4 / 17.4 / 24.2 / 25.6px。画面座標の波は 26.6 / 23.3 / 30.2 / 28.4 / 27.3px で中央まで動く
- 波を足すなら部屋より長く（2.4〜4.5m）、支点の周りでは消す
- **奥行きは足しても変わらない。** 平面 1 枚・平滑化した深度・壁と床の深度で差が出なかった（A .846/.832 B .976/.964 がその平面で説明できる）。だからカメラごとに `1/z = a·x + b·y + c` の 3 値だけ持つ

**測り方の罠**:

- RANSAC の倍率計は参考動画で .0029 と読んだ。全点の最小二乗（`measure.py`）で .0203。既知の倍率で校正してから使う
- 動画中の線の本数は内容で変わる。シーンをまたいで絶対数を比べない
- `heave` と `bend` の比較は振幅が小さく、影の版は金属の縞に見えたので外した。「影は効かない」の証拠にはしていない

**実装の罠**:

- 頭打ちは引く座標ではなく**変位の大きさ**に掛ける（tanh・.15）。座標へ掛けると画の端で筋が出た
- 深度の段差は `z_far` で切り、逆深度の勾配を 1 マス .05 に抑えないと局所の折り返しが出た（試作の深度版の話。平面版には段差が無い）
- 強さはカメラごとの利得で揃える（`TARGET=.20`）。揃えないと B/C の半分が頭打ちに張り付く
- `ResetAll` では畳まない。カットの中止で消えるため。畳むのは `NotifyRoomWarpCovered` と `ResetRun`
- 低解像度のブロック・砂・時計・固定パターンは動かさない。固定パターンの座標は `roomWarpDelta` を引いて元へ戻している
- カメラの据え付けを変えたら `export_table.py` で表を書き出し直し、`RoomWarpField` と `RoomWarpTests` の値を差し替える

**通しの実測**（twin-verify 20261106_015137）: 歪みは砂嵐が晴れた 152s から暗転の 159s まで見えた。XP ログの `t=` は eye.mp4 より約 16 秒進んでいるので、照合するときは引く。暗転直前の 6 コマで画が左右に割れるのは歪みと無関係（20261105_211652_tv4 にも出ている）。

**確かめていないこと**: HMD での両眼視差と頭の動き・酔い・暗所で歩く安全。人が映るライブの本番配信。参考動画にある櫛状の揺れは入れていない。
