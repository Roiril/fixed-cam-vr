2026-11-06 ユーザー依頼（0317・逐語は LEDGER）を受けた試作。闇の目の代わりに、メインスクリーンと同じ画を映す面が頭の周りへ増える。参考は `mul.jpg`。

**切替**: `AnomalyEyes.ScreensReplaceEyes`。false にすれば目へ戻る。目のコードと版は消していない。

**時計と出番は目のまま**: `AnomalyEyesLogic`（兆し → 凝視 → 開眼 → 閉じ）と `EyesCueLogic`（0093）を流用。`eyes=` の開いた数は面の枚数になる。

**席**: `tools/make-screen-wall.py` が `ScreenMultiplySeats.cs` を焼く（seed 11・141 席。手前 95 ＋ 霧の奥 46）。霧の奥の段（6.8〜10.5m・幅 3.6〜6.4°）は別の乱数で足すので、手前の席の位置・傾き・色は動かない。奥の段だけ手前の面へ 1.6° まで隠れてよい。先に Python で実フレームを貼って形を決めた。面どうしは重ねない。86% が前方 ±112°。0 番はメインの右上に固定で、点く順は 0 番から近い順に ±12° のゆらぎ。3 段（幅 20〜27° / 13〜19° / 7.5〜12°）で大きいほど手前。全部メイン（2m）より奥なので、メインは常に前に残る。

**画**: `ScreenMultiply` が手動カメラでメインスクリーンを正射影で撮る（10Hz・640x516 → 320x258）。リング 16 枚の `Tex2DArray` に積み、席ごとに 0〜1.5 秒前の画を映す。人形も乱れも外形も付いて来るのはこのため。外形は取り込みの alpha で切る。
- ⚠ 本編のメインはテレビの枠つき（0321・`_CrtTvCase` = 1）。そのまま撮ると輪郭の外にも alpha 1 が書かれ、面の中にメインの筐体ごと入る（枠の中にもう 1 つ枠）。取り込みは `using (ScreenMultiply.HideTvCase(mat)) _captureCam.Render();` で、撮る間だけ 0 にして輪郭で切り抜かせ、`Dispose`（finally）で元の値へ戻す。面に写るのは 0319 のとおり管の形の映像だけで、枠は面の自前（`WALL_PICTURE`）
- 順序の根拠: 取り込みは `AnomalyEyes.LateUpdate` → `Drive` → `CaptureMainScreen` の中で、`Camera.Render()` は同期で描き切る。目のカメラが描くのは全 LateUpdate の後なので、同じフレームで目のカメラが 0 を描くことはない。リポジトリの検証道具も `SetFloat` → `camera.Render()` を続けて別の結果を得ている（`CrtReferenceValidation` の `_ScreenPower`）。Quest 実機（マルチスレッド描画）での確認はまだ。テストは `ScreenMultiplyCaptureTests`（戻し・投げても戻る・0 と null は触らない）

**描画**: メッシュは面と箱で 1 draw、暈で 1 draw。`Queue=Geometry+50` なのでメインに隠れた所は深度で捨てる。暈は `Geometry+60` の加算で alpha を変えない。シェーダは `Assets/Resources` に置いて `Resources.Load`（`ProjectSettings` を触らないため）。

**色**: `ScreenMultiplyLayout.Tints` の 3 色（寒色・淡い寒色・橙）で決まる。暖色は `make-screen-wall.py` がメインの左右へ 1 枚ずつ必ず置く。残りは席の 7% が乱数で橙になるが、ほとんど正面の画に入らない。正面の範囲は目線の絵で測った（メインが隠すのは方位 ±20 度・高さ -17〜12 度）。Tints を全部 1 にするとモノクロ版になる。暈も同じ色で白く見える。

**音**: 最初の 1 枚が `ScreenOn`、以降が新しい `SoundCue.ScreenAdd`（`sfx_switch_1..6` の流用）。間引きは目と同じ 0.09 秒で、`sndEye=` に出る。耳では確かめていない。

**計器**: `scrMul=<組めたか>/<点いた枚数>/<取り込みの累計>`。点いたのに取り込みが 0 なら FAIL。

**霧と奥行き（0318・2026-11-10）**: 式は `ScreenFogLogic`（濃さ .38/m・2.2m まで無し）と `Resources/ScreenFog.hlsl`。面は距離で暗くなり、`(1 - 届く光) × 3.6` 段の mip でぼける。暈は霧の中ほど裾が広く、面より暗くなりにくい。濃さには方角ごとのむら（0.55〜1.6 倍）を頂点で掛ける。
- 点いた面は席より `EmergeM` 3.4m（席ごとに 0.75〜1.25 倍）奥に現れ、`ArriveSec` 1.5 秒で寄る。時計は `ScreenMultiply` が席ごとに持つ点いた時刻（`_WallOpenAt`）。目の時計の Field で寄せると、さざめきの後の「間」で面が宙に止まる
- 取り込みのリングは mip 5 段。`_tileRt.GenerateMips()` の後、段ごとに `CopyTexture` する
- 暈の揺らぎは表示の 1 階調ぶんにする。linear の 1/255 を足すと黒の近くで 6 階調になり、織り目が見えた
- にじみを強めると闇が灰色に寄る（2.5 倍で駄目、1.2 倍にした）。前の版の「灰色の枠」と同じ向きの失敗
- 見るのは `.\tools\unity.ps1 menu screen-wall`。fog と flat（霧なし・その場で点く・奥の段なし）を同じ時刻で焼く。メインスクリーンは本番と同じ面で組み（`IntroPreview` のテレビ方式と同じ手順）、面は本番の取り込みを通す（`SetCaptureSource`）。Awake が走らないので `ScreenMultiply.Build()` を直接呼ぶ
- ⚠ 最初の 2 版は、16:9 の平らな板に写真を貼った代用品をメインにし、面にも写真を直接渡していた。メインの形・縦横比・加工と面の外形が本番と違う画をユーザーへ見せ、2 回指摘された（0319 / 0320）。本番のメインは幅 1.66m × 高さ 1.33m の曲面で、テレビの枠がつく（0321。0302 の枠なしは上書きされた）。新しいプレビューを作るときは、本番の面を組む。代用するなら画の中に書く
- 正面の画では手前の面が視界をほぼ埋め、奥の段は隙間にしか見えない。奥行きが読めるのは左右を向いた画
- 計器: `scrEmg=<寄っている途中の枚数>/<席より奥に居た最大 m>`
- 枠（0319）: 画は面の内側 88%（`WALL_PICTURE`）に収め、周りが筐体。内側の縁で管の光を拾い、外へ暗くなる。前は画が面いっぱいで、筐体は四隅にしか無く、ほぼ黒だった
- `report.tsv` の手前と奥の明るさは、flat に奥の段が無いので前後の比較に使えない

**確かめていないこと**: 霧と奥行きは実機と HMD で見ていない（2026-11-10 は実機がつながっていなかった）。実機の fps。別セッションの実測で、10-23 の実機は目が出ている 3-C で既に 40〜55fps（通常 88〜90）だった。専用カメラの Render は 10Hz の周期スパイクになりうる。
