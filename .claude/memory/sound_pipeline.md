## 計器の方が嘘をつく（1 日で 4 回踏み、2026-08-18 にもう 1 回）

**音は耳で確かめられないので、数値が唯一の証拠になる。だから計器の誤りは実害に直結する。**

| 何が起きたか | 真因 |
|---|---|
| 尖頭 -3dB の素材に **true peak +4.6dB** と出た | 0 を挟んで 4 倍にした信号を**元の 48kHz の係数**で濾していた。20kHz 4 次では 24kHz から始まる像を落とせない → **周波数領域で 0 詰めして戻す**（厳密な帯域制限補間）に変更 |
| `bed_device_worn` に **直流 0.31** | `tilt()` の `log2(f/hinge)` が f=0 で発散し、直流の桶が **1585 倍**になっていた → 周波数に 20Hz の床を敷き、`spec_shape` が最後に直流を落とす |
| 敷く音が設計より **+14.7dB** で書かれていた | `write_wav` が**無条件に尖頭を -3dB へ正規化**していて、LUFS で揃えた意味が書き出しで全部消えていた。**合成側の指標だけ見ていると気づけない** → 上限としてだけ効かせる。**書いたファイルを読み直して測る**（`sound-lint.py`）ことでしか捕まらない |
| `bed_seal` の継ぎ目が「不合格」に見えた | 段差を**信号全体**の隣接標本差と比べていた。低い音が主で時々粒が入る素材は、粒 1 つが欠陥に化ける → **継ぎ目の周りの**隣接標本差で割る |
| **まばらな笑いの輪**の継ぎ目が「密度が +55.8dB 変わる」と出た（2026-08-18） | 同じ間違いを**密度の側**でやっていた。継ぎ目の前後 10ms を比べるので、直前が余韻・直後が笑いの立ち上がりだと必ず落ちる。**同じ跳ね上がりは輪の中で 4 回起きている**（素材の中の最大 55.9dB）→ **素材の中でいちばん大きい変化と比べる**（`loop_seam` の `rms_d_max`）。連続した敷く音は素材の中の変化が 3〜15dB なので、本当の段差は依然として落ちる |

⚠⚠ **物差しを直したのは 2 回とも「同じ形の間違い」だった** — 絶対値で見て、**その素材にとっての普通**と
比べていない。⇒ **ループの検査を足すときは、まず「この素材の中では何が普通か」を出す。**

⚠ **あり得ない値（+4.6dB）だから気づけた。** `+0.5dB` のような「もっともらしい嘘」なら通っていた。
**計器を足したら、既知の答えが出る入力で 1 度は確かめる。**

## 「加工して毎回違う音」を作るときの罠（2026-08-23・0112）

### ⚠⚠ ラウドネスは**尺の関数**なので、長さの違う変種を 1 本ずつ揃えてはいけない

同じ素材から尾の長さだけ変えた 6 本を焼いて、それぞれ -23.0 LUFS へ揃えたら、
**短い変種ほど尖頭が下がった**（実測 tp -3.00 〜 -5.51 ＝ 2.5dB の差）。
LUFS は全長の平均なので、尾（低い床）を落とすほど平均が上がり、その分だけ絞られる。
**耳が聞くのは頭の一撃**なので、絞られたぶんそのまま小さく聞こえる。

⇒ **揃えるのは「頭 35ms の実効値」。そのあと 1 本目で決めた丸めと倍率を全部へ掛ける。**
`CUTS` の「1 発ずつ正規化しない」と同じ結論だが、**向きが逆**（あちらは素材の強弱を守る話、
こちらは自分で作った長さの違いが音量に化けるのを防ぐ話）。

⚠ 同じ罠が**割れる音**にもあった。統合 LUFS を目標にすると
「尻を静かにするほど頭を上げる」という逆向きの力が働く（尻を疎にすると平均が下がるので）。
⇒ **頭 0.5 秒の短期ラウドネスで揃える**（`SWARM_HEAD_LUFS`）。通しの値は結果であって目標ではない。

### ⚠⚠ 「滑らかな減衰の式」は、粒を重ねる音では逆に働く

割れる音の減り方は `(1-u)^1.9` で、**設計上は最初から減っている**。ところが 25ms 窓の山は
**150ms** にあった。粒の重なりが 1 → 6.5 と増えるあいだ、式が頭で平らなので**実際は膨らむ**。

⇒ **dB の折れ線で書く**（`SWARM_FALL_KNOTS`）。最初の 0.15 秒で 5.5dB 落として重なりを打ち消す。
⚠ **「減衰の式を書いた」ことは「減っている」の証拠にならない。** 25ms 窓の山の位置を測る。

### ⚠⚠ 計器（包絡の自己相関）は**減衰の傾きを取り除いてから**見る

「粒が等間隔で連射に聞こえるか」を包絡の自己相関で見ようとしたら、**よく減衰している音ほど
相関が高く出た**（山の有無を何も言っていない）。移動平均で傾きを引いてから見ると、
旧版は 20ms に山（+0.31 → 検出したかった周期性）、新版は山なし、と分かれた。

⚠⚠ **この形の間違いは音側で 4 回目**（true peak / 継ぎ目の段差 / 継ぎ目の密度差 に続く）。
どれも**絶対値で見て、その素材にとっての普通と比べていない**。
⇒ **計器を足したら、既知の答えが出る入力で 1 度は確かめる。**

⚠⚠ **同じ形は画でも起きる。一般則はグローバルへ昇格済み**（2026-08-23・
`~/.claude/rules/work-style.md` §2「効果を測る指標が、その効果自身の副作用で打ち消されていないか」）。
終幕（0111）で**潰れる演出の眩しさを平均輝度で測り、潰れると光る面積が 1/167 に減るので
輝度補償が何倍掛かっても平均は必ず下がる**、という同型が出た（実際は白飛びしていた）。
**ここに書いてある 4 例はその出典**なので、次に計器を足すときは先に向こうを読む。

### ⚠ 素材は「1 発」に見えて複数の一撃を持っている

割れる音の素材（PC-Mouse06-1 ＝ マウスのクリック）は **押し込み / 中間 / 戻りの手前 /
戻りの本体**の 4 つでできていて、**いちばん大きいのは戻りの本体**（押し込みではない）。
旧実装は頭から 130ms を丸ごと 1 粒にしていたので、**尻の 12ms フェードが毎粒でその一撃を潰していた**。

同じことが切替音にもある — 立ち上がりは 5.5ms に 1 つだけだが、
**尾に二次の粒が 4 つ**（56 / 71 / 77 / 96ms）。ここが変種の材料になった。

⇒ **素材を使う前に 1〜2ms 窓で包絡を出して、一撃がいくつあるか数える。**

### ⚠ 「重なり」と「密度」は別物。密度だけで弧を作ると頭の音量を失う

粒を短くすると粒立ちは出るが、**重なりの数が減るので頭の音量も落ちる**
（実測: 粒 130 → 35ms で頭 0.5 秒が -14.7 → -17.5 LUFS）。
⇒ **粒の長さを時間で縮める**（頭は長い粒が重なって轟き、尻は破片 1 つ）。

### ⚠ 尻の下限は「同時に鳴っている敷く音」で決まる

割れる音の尻は -37.6 LUFS で、段 4 の敷く音（room ＋ device で約 -30.5 LUFS）より 7dB 低かった
＝ 「小さくなった」ではなく「無くなった」。**静けさの縁が立たない。**
⇒ 敷く音と同じ高さ（-30.9）まで上げた。**素の無音で聴くと沈んでいても直っているように聞こえる**ので、
`preview_break.wav` は敷く音の上で鳴らしてある。

### ⚠ 変種を作ったら、その上に重ねる音も同じ本数焼く

切替音を 6 本にしたとき、警告音つき（`MIXES`）を 1 本のままにすると
**いちばん連続して鳴る 2 周目 C の 5 発だけが「毎回同じ」に戻る**。
⚠ **警告の高さは常に 1 本目を基準**にする — 土台ごとのラウドネスを基準にすると、
尾の短い変種で警告だけが 6dB 大きくなる（上の「尺の関数」がここでも効く）。

## 実機の物理で 4 素材が落ちた

- **内蔵スピーカーは 200Hz より下をほとんど返さない。** 封印の箱は正体を 58/87Hz に置いていて
  損失 **-18.3dB** ＝ 実機では存在しないのと同じだった。低い基音は「ヘッドホンなら効くボーナス」に
  降ろし、物としての正体は円板モード（160/313Hz）と熾のはぜ（420-2400Hz）へ移した
- **遅延で広げるとモノで消える。** `sfx_title_out` は **-11.2dB**。至近距離の 2 スピーカーは
  空中でほぼ合成されるので、櫛形の谷に当たった帯域は実機で消える →
  左右に**独立に位相を散らした複製**を混ぜる（`widen`）。無相関の和は -3dB で止まり、谷を作らない
- **spatializer はモノのクリップしか処理しない。** 3D の音は `mono=True` で焼く

## 実機ログが捕まえた実装の欠陥

**隔離が閉じても部屋の帯域が 22kHz → 9.9kHz までしか下がっていなかった。**
`Lerp(380, 22000, open^0.45)` は閉じ切った状態（open=0.16）でも 9.9kHz を返す。
部屋のトーンは中身の大半が 4kHz より下なので、**10kHz の低域通過は何もしないのと同じ**。
絵は閉じているのに音は開いたまま、という食い違いが実機で起きていた。
→ **周波数は対数で写す**（`ClosedCutoffHz * (Open/Closed)^open`）。人の音高の知覚は対数なので、
線形補間は必ず上へ偏る。

## テストが捕まえた実装の欠陥

**平滑化の状態へ分配結果を書き戻していて、周回が進むほど装置の合計が痩せていた**
（decay 0.2 で合成パワー 0.976）。絵の劣化は正しく進むのに音だけ小さくなるので、
**実機で聴いても「そういう演出」に見えて気づけない**。合計は別のフィールドで持つ。

## 触るときに引っかかるもの

- **`AudioImporter.normalize` に公開 API が無い**（`.meta` には書いてあるのに）。
  `SerializedObject` の `m_Normalize` 経由。しかも**効くのは `forceToMono` が立っているときだけ**
  — `HorrBGM.mp3` は `normalize: 1` だったが `forceToMono: 0` なので**実際には効いていなかった**。
  **設定ファイルの値だけを見て効いていると決めない**
- **`AudioImporter.preloadAudioData` は obsolete。** `defaultSampleSettings.preloadAudioData` へ移った
- **シーン YAML の `[Sound]` は `m_Name: '[Sound]'`**（YAML が `[` で始まる文字列を引用符で括る）。
  `grep "m_Name: \[Sound\]"` は 0 件になる
- **`quest-record.py` は APK を入れない。** 焼いたら `adb install -r --no-streaming` を自分で打つ
  （入れ忘れると `[XP] 0 lines` になり、Development ビルドかどうかを疑って時間を溶かす）
- **カメラが 1 台も繋がっていない走行では導入が段 Swap まで進まない**
  （`liveFresh` が false のあいだ段 5 へ行かない＝砂嵐を見せない設計）。
  `Swap` の音が鳴らないのは正常。**カメラ無しの走行で段 5 の音は検証できない**
- **`Temp/UnityLockfile` が死骸で残る。** batchmode が途中で落ちると消えない。
  `Unity.exe` が動いていないことを確かめてから消す（`mcp-for-unity.exe` は無関係）

## 判定の限界

数値と絵は**落とすため**の道具で、「怖いか」「間が持つか」は何も言わない
（[reference/why.md](../reference/why.md)「品質を採点しない」）。
音は録画にも映らないので、**最後は人に聴いてもらうしかない** →
`tools/sound-preview.py` の 2 本を `skills/direction-round` で出す。
