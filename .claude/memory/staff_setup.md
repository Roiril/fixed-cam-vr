# スタッフ起動・交代フロー（2026-10-10）

スタッフの主画面は博士タブレット。起動時から全画面で「準備 → 来場者 → 装着 → 体験 → 回収」を示す。Questに残す作業は位置合わせと目視確認。スタッフ画面の表示中はスクリーンをワールド位置に固定する。本編の既存追従は維持する。

2026-10-10の追加依頼「設定のあとのチュートリアル画面で体験者が見る必要のあるのは博士の説明とその字幕だけ。」に合わせ、来場者の通常説明は博士と字幕へ限定する。自動送りが既定。画面タップで一時停止して操作を出す。スタッフ入口も操作中だけにし、「スタッフ専用」の1.5秒長押しで開く。返却時は来場者へ返す案内だけを表示し、スタッフ画面を自動で開かない。受け取ったスタッフが同名の入口を開く。体験者自身の設定と混同しないよう、歯車は採用していない。設定の実反映と今回の説明完了と装着確定の照合条件は維持する。

位置合わせ中は既存の右手追従画面にも現在の指示と点数と測定値と入力を出す。Aの0.5秒採取も更新する。右手の接続と追跡が有効な間だけ表示する。退出時に従来の操作早見表へ戻す。新しい手元パネルと入力は増やさない。

位置合わせの途中でOS再センタリングを受けた場合は、確定前の変換と記録点を破棄して点1へ戻す。Aを一度離して新しい点を採り直す。途中のBでは確定しない。取消後も要再登録を維持する。可視化に生成したMaterialは退出と再構築で解放する。

スタッフ画面には機器6項目の確認件数を表示する。タブレット本体の音量は別に実数で出す。0または消音なら本体の音量ボタンを案内する。音量を自動変更しない。リセットの実完了と同じ接続先の復旧を知らせる。回収後は1.5秒長押しで次の準備へ進む。指がボタン外へ出た時と背景移行で長押しを取り消す。体験開始を観測できず終了だけを受けた場合も回収画面へ戻る。

引き渡し確認の実受理を照合した来場者だけ、開始阻害の6秒継続を短音で一度知らせる。通信断と更新停止と位置とカメラと素材と設定を対象にする。引き渡し後のタブレット応答だけの低下は開始を妨げないため鳴らさない。理由が変わっても同じ異常中は再通知しない。回復してからの新しい異常は通知する。本編開始を一度観測した来場者は遅延した状態でも再開しない。終幕と終了と接続先の変更でも閉じる。背景中の異常は無音で消費する。音声の解除失敗は表示し、解除後も古い音を再生しない。設営時に「困ったとき」の「通知音を確認する」で同じ音を確認する。

タブレットは今行うことと主操作を左に表示する。右に機器ごとの状態と直し方を表示する。主操作は1つ。「困ったとき」に接続先と予備操作と説明確認をまとめる。通常の引き渡し確認は「長押しで装着へ進む」。本体のB短押しは予備操作。確認だけのために被り直す手順は要求しない。Questの位置合わせは目視操作を先に表示し、数値と進捗も残す。引き渡し後の異常は日本語と英語とフランス語でスタッフを呼ぶよう案内する。

博士UIはタブレット専用の独立アプリ「廻リ視 博士」。スマホA・B・Cは「FixedCam Streamer」でカメラ映像を配信する。Questでは「廻リ視」のスタッフ用セットアップと既存体験画面を使う。機器確認画面もこの端末別のアプリ名と用途を案内する。Questから博士UIを開いたり表示したりする処理は追加していない。

1. **機器を確認**。タブレットとA/B/Cの実状態を並列に観測する。順番を強制せず、カメラの接続待ちでも位置合わせを始められる。機器が揃ったかは引き渡し時に一括して再検査する。
2. **位置を合わせる**。右トリガー2秒で既存位置合わせ。床の×印で右Aを0.5秒静止。既存Verifyで実物とガイド線を目視しB確定、Aやり直し。保存済み位置もReviewで目視してB明示再利用。ファイルがあるだけでは合格しない。`NeedsReRegistration`があるReviewはBで合格しない。
3. **体験者を迎える**。最初の人も毎回、スタッフが実リセットを行う。Questが実際に新しいWaitへ戻った応答を待ち、「来場者の画面にする」で新しい設定と博士の説明へ進む。右A2秒は予備操作。設定の受理・適用番号・実値と今回の説明終了を照合する。スタッフが「長押しで装着へ進む」を押し続ける。Questの応答後に博士の装着案内2文を自動で進める。受理時と開始時の実状態の再検査は維持する。確認は練習を許可する区切りであり、本編・録画は始めない。体験者の左X/Y練習と題字の短押しを残す。

## 非装着・休止の限界

タブレットのリセット・装着確定は非装着を禁止条件にしていない。実行はUnityメインスレッドなので、OS休止中は実行も状態更新も止まる。500msごとの`questTick`が4秒以上進まなければ、接続の緑と現在の実値表示を外し「Questの復帰・更新待ち」とする。電源ボタンで復帰させ、実更新を確認する。リセット完了前は来場者の設定へ進めない。リセットと設定が完了している場合、博士の説明は継続できる。装着確定がまだ未処理なら、来場者の装着後に現在の条件を再検査してから練習へ進む。OS設定は変更しない。

このPCの自動検証は『被らず操作できる設計』を検証する。2026-10-10の接続中のQuest βでは休止と復帰後の更新継続を確認した。実際の着脱と歩行を含む一巡は未確認。接続していないQuest αは対象外。

## 確認の証拠

描画の手順は[staff-preview-verification.md](../reference/staff-preview-verification.md)。実パネルの文字領域と実描画を同時に測る。タブレットのmockにも正常と異常の対照を通す。

- カメラは現在のエンドポイント・MJPEG接続世代の正常デコード、受信時点の新鮮さ、デコードから1.5秒以内、現在接続の`/info`から4.5秒以内のcameraIdとshow一致で確認。初回／復旧は0.5秒安定確認。ソケット接続・黒プレースホルダ・前の接続のテクスチャは合格にしない。
- `StreamWatchdogLogic.LastFrameRealtime`はresume-gapで現在時刻へ補正するので準備証拠に使わない。`DecodedFrameEvidence`は正常LoadImageでのみ更新し、pause/resume・エンドポイント変更で無効化。復帰前に受信キューへあったJPEG、接続世代が異なるJPEGも合格にしない。
- タブレットのlisten成功は口が開いた事実だけ。実通信は`/tablet/pulse`から12秒以内（送信は5秒間隔）。機器確認では要求が無くても通信を確認して進めるが、体験者の引き渡しは既定値だけでは通さず、毎回新しい設定の証拠が必須。
- 実リセット前に`portalSessionId`を更新し、pending・適用番号・消費番号と前回の受理情報を破棄する。HTTPのセッション検証・受付と世代更新は同じロック内。受理済みのキューが取り出されていても旧世代の設定／取消は実行しない。受理番号と累計受理・適用回数は単調に保持する。`visitorGeneration`でタブレットも博士の入口へ戻り、旧送信応答と説明復元を破棄する。
- 新設定は最新受理番号とAppliedSeq・言語・軽減の実値を照合。題字表示でpendingが消費された後も同じConsumedSeqだけを証拠として保持し、明示取消や別設定の未反映は開始を止める。引き渡し後のpulse途絶だけでは本編を中断しない。次の体験者の引き渡しでは改めて実通信と新設定が必要。前の本編中に受け付けた予約も、実リセットで破棄してから体験者が新たに設定する。
- `/tablet/pulse`に今回の`portalSessionId`・タブレットページID・設定`seq`・単調な`briefingRevision`と説明終了／スタッフ確定を載せる。同一版の再送は冪等。前セッション・別ページ・別設定・古い版・同一版で異なる完了値は採用しない。戻る／再説明で新しい版のfalseを直ちに送り、HTTPキュー未適用でも開始を閉じる。
- タブレットリセットは`resetRequestId`・現在セッション・最後に見た`settingsSeq`を照合し、メインスレッドで再検査。実リセット成功だけを`staffResetId`で返す。二重入力は一回、設定競合や前回要求は捨てる。位置合わせ中・本編中・終わりの演出中はタブレットリセットを拒否する。終わりの演出の完了後は許可する。
- 明示取消は対象`seq`を添え、遅れた取消で新設定を消さない。取消受付直後から開始を閉じ、適用後は受理情報と説明／スタッフ確認も破棄する。題字で消費された旧設定を古いpulseで再承認できない。
- 素材は既存`ShowControlClient.ContentVerified`。開始前の失敗を準備完了にしない。

通信喪失は対象行の緑と開始ゲートを取り消すが、確認済み位置を消さない。OSリセンターは別理由で位置再確認。サスペンド復帰は新しい正常デコードを待つ。世代が古い観測・確認を採用しない。

引き渡し後の短い映像揺らぎも開始ゲートは即閉じる。全面のスタッフ画面へ戻すのは継続1.5秒後とし、瞬間的な断で題字／案内が点滅しないようにする。位置基準変更・未反映設定は即時案内。旧シーンの起動時自動位置合わせはBridgeが順序に依らず保留し、機器確認から始める。
