# スタッフのステータス表示（右 B）を触る前に

2026-09-14 の設計変更。**トグルをやめ、押しているあいだだけ出す形にした。**
入力は右 B のままで、ボタンは増やしていない。

## なぜトグルをやめたか

前提が 2026-08-15 に変わっている。左は体験者が持ち、**右は本編中もスタッフの手にある**。
`StatusHud` のコメントは「コントローラを持つ人にしか起こせないので体験者には出ない」と
書いていたが、これはもう成り立たない。B を押せば体験者の視界 1.6m 先に日本語の業務表示が出る。

ラッチが残る限り、次の 5 つが構造的に消えない。

- 自然な手順（A 2 秒でリセット → B でカメラの○×を見る → 被せる）だと、消える縁であるラン開始が
  B より先に来る。**出たまま体験者へ渡る。**
- 開いたか閉じたかの返事が同じ 1 粒なので、被っていないスタッフは自分がどちらにしたか分からない。
- 机の上の HMD で押しても見えないまま状態が変わり、次に被った人に出る。
- 誤押し 1 回の害が永続する。`autoHideSec` は既定 0 で、自動で閉じる経路が無かった。
- 出ていたことが後から分からない。`IsVisible` はテレメトリにも heartbeat にも無かった。

押しているあいだだけにすると、**誤押しの害は押した長さに収まり、秒として数えられる量になる。**
閉じる縁を足す案（自動で N 秒・題字が立った・左入力が来た）も検討したが、縁に当たらない経路が
1 つでも残れば漏れるので採らなかった。

## 黒の上に描く

`sortingOrder` では越えられない。題字の黒（`TitleVeil.shader` queue 4950・ZTest Always・メッシュ）と
導入の覆い（`IntroVeil.shader` queue 4900・**乗算ブレンド**・段 4 は ZWrite 1）が相手で、
Canvas の sortingOrder は同じ Canvas 系の中の順でしかない。乗算の相手には、先に描いた文字が必ず潰れる。

手段は 3 点セットで、どれが欠けても出ない。

1. UGUI の Canvas をやめて **3D の TextMeshPro** にする
2. シェーダを `TextMeshPro/Distance Field Overlay`（ZTest Always）へ差し替える
3. `fontMaterial.renderQueue = 5000`（覆いの 4900〜4950 より後ろ）

`OutroReport.cs` と `TitleNotice.cs` が同じ形で黒の中に文字を出しているので、実績のある手順をなぞる。
⚠ 実行時の `Shader.Find` はビルドで剥がれることがある。この 2 つが既に同じシェーダを参照しているので
相乗りになっていて、追加の参照は要らない。

## 題字を譲らせない

`TitleScreen.IsYielding` から `StatusVisible` を外した。位置合わせの譲りは残す。

譲っていた頃は、B を押すと題字の黒が引っ込んで**体験者にパススルーの現実が見えた**。
さらに `ReadyForStart` が `!IsYielding` を要求するので、**体験者の開始押しが黙って無視されていた**。
スタッフには分からない。黒の上に描けるようになったので、譲る理由が無くなった。
B 中も体験者の X / Y 短押しで題字は閉じる。

## faceButtonHeld から B を外した

`ControllerModeLogic.Frame.faceButtonHeld = aHeld`（B を外す）。
2026-09-11 の事故は「親指で A を押す手の中指が握り込む」形で、A にしか起きない。
B は押しているあいだ表示するだけなので、握り込みと重ねても発火するものが無い。
外したことで、**B を押したままトリガー長押しで位置合わせへ入れる**。早見表を読みながら入れる。

## 電池は出さない

`OVRInput.GetControllerBatteryPercentRemaining` は OpenXR 側で廃止されている。
未接続のコントローラでも 0 を返すので、「電池切れ」と「繋がっていない」が同じ顔で出る。
出すのは接続と位置の 2 つだけにした（`VisitorControllerLost` / `VisitorControllerUntracked`）。

## 証拠の読み方

**画にも音にも出ない。** ステータスは HMD の中にしか出ないので、出ていたかは次の 3 つにしか残らない。

| 見るもの | どこに出るか | 読み方 |
|---|---|---|
| `ev=status st=on\|off src=held\|pin\|probe sec=…` | logcat の `[XP]` | 出た縁と消えた縁。`sec` は出ていた秒 |
| `ev=sum` の `hud=` `hudSec=` `hudN=` | logcat の `[XP]` | このランの累計。ラン開始で 0 へ戻る |
| heartbeat の `statusHud` | 卓（`#runMode` が `NORMAL／ステータス表示中`） | 本番中に唯一その場で分かる面 |

判定は `tools/analyze-xp-log.py` の「ステータス表示（右 B）」節。
`hud` が 1 度も出ていなければ古い APK、値が全部 `-` なら `StatusHud` がシーンに居ない。

⚠ **テレメトリが言えるのは「面を出した」までで、黒に潰されていても同じように出る。**
黒の上に文字が読めるかは画でしか分からない。人が被らずに撮るには
`py -3.11 tools/quest-record.py --sec 45 --walk --status-probe`
（`-e xpstatus 1` を渡す。題字と導入の黒で 2 秒ずつ自分で出す）。
切り出しは `tools/xp-evidence.py` が `ev=status st=on` の 0.25 秒後を 1 枚撮る。
