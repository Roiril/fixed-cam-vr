ここは**そこに数値が無かったこと**だけ。

## 1. 覆いの形は 2 系統。カットごとに片方だけが効く

| 場面 | show.json | 形 |
|---|---|---|
| 2 周目 C の末尾 | `L2C2#1` カット 5（`swapHold` / `swapMinX 0`） | **背景差分 100%**（ライブ C − `plate_C`） |
| 3 周目 A の入り 2 カット | `L3C0#0` カット 1・2（`swapHold` / `swapMinX 0.5`） | **背景差分 100%**・右半分だけ |
| 3 周目 A の入れ替わり | `L3C0#0` カット 3（`transition swap`） | **CG の人型 100%**（縮む） |
| 4 周目 A の入れ替わり | `L4C0#0` カット 2（`transition swap`） | **CG の人型 100%**（育つ） |

入れ替わりの段が CG だけになるのは `startCovered` の帰結。持続の覆いから引き継ぐと
`cover` が 1 のまま始まるので `hand = smoothstep(0.86, 1.0, cover)` が即 1 になる
＝ 差分は 1 フレームも読まれない。**差分と CG が混ざる区間は事実上無い。**

⚠ プレートの束縛は `CameraSwitchDirector` が `registry.ActiveIndex`（いま画面に出ているカメラ）で
決める。`TakeRunner` が渡す引数は**覆い切った後に切り替える先**であって、プレートのカメラではない。

## 2. 差分は linear 空間で引かれる（明るい面は敏感・暗い面は鈍い）

プロジェクトは Linear color space（`m_ActiveColorSpace: 1`）で、ライブもプレートも
`linear:false` の sRGB テクスチャ。**シェーダが読む時点で linear へ変換される**ので、
`MaskDiffLo/Hi = 0.060 / 0.20` は linear の差。

| 背景 (sRGB) | 拾われ始める明るさ | 完全に黒くなる明るさ |
|---|---|---|
| 20 | 73（×3.7） | 126（×6.3） |
| 60 | 91（×1.5） | 136（×2.3） |
| 120 | 136（×1.14） | 167（×1.39） |
| 200 | 209（×1.04） | 228（×1.14） |

⇒ **画全体の露出が振れても誤検出しない**（linear で ×1.05 なら 1 画素も届かない。
×1.10 で sRGB 203 より明るい所だけ）。⇒ 逆に**暗い所に立つ人は拾えない**。

## 3. 実測（`tools/web-compositor/captures/` の無人プレート同士・人は 1 人も写っていない）

差分を引く範囲の中で黒くなる割合:

| プレートのずれ | 被覆率 |
|---|---|
| 同じ設営・同じ日・18 分差 | **2.8%** |
| 2 日差（同じ設営・時刻違い） | 22.7% |
| 設営を組み替えた後 | 52.6% |
| 同じ 1 枚に明るさ +10%（露出 +0.3EV 相当） | 2.6% |

⇒ **効くのは光の揺れではなくプレートと現場の食い違い。** 当日その設営で撮り直せば 3% 以下。

⚠ 数値はすべて**実効 lod 1.68**（3 周目 A ＝ `ScreenDecayLogic` の 267 ブロック）で測ってある。
`CoarseLod() = log2(640 / (blocks × 0.75))` なので、1 周目の頭（800）は 0.09、2 周目 C 末尾（≒320）は 1.42。

## 3b. カメラがずれても全体は黒くならない — **輪郭だけ**

平らな面は何画素ずらしても同じ値が読める ＝ 差が出ない。差が出るのは値が急に変わる所だけなので、
**面積はずれの量に比例せず輪郭の総量で頭打ちになる**（カメラ A・3 周目 A の粗さで測定）:

| ずれ | 視野角 | 被覆率 | | 傾き | 被覆率 |
|---|---|---|---|---|---|
| 1 px | 0.14° | 0.8% | | 0.5° | 4.0% |
| 2 px | 0.29° | 3.6% | | 1.0° | 8.2% |
| 5 px | 0.72° | 9.5% | | 2.0° | 13.4% |
| 15 px | 2.15° | 16.2% | | | |
| 30 px | 4.30° | 18.6%（飽和） | | | |

- **後半ほどずれに強い**。同じ 5px でも 1 周目の頭の鮮明さなら 14.9%、3 周目 A なら 9.5%
  （細かい模様が先に潰れる）
- ⚠ 面積は小さくても**形が悪い**。散った輪郭それぞれから覆いの「棒」が横へ泳ぐので、
  人型として読めない黒い帯が人の居ない所に何本も出る
- ⚠⚠ **カメラが動いたなら狂うのは覆いだけではない。** 較正がずれるので、人形の立ち位置・影・
  差分を引く範囲の位置・3 周目 A と 4 周目 A の入れ替わりの人型が全部同じだけずれる。
  検知は端末の傾きと保存した較正の突き合わせ（[[camera_fleet]]）

## 4. 差分を引く範囲（早い棄却の箱）は思っているより広い

シェーダの箱は figure 空間で `|x| < 1.25` / `|y| < 1.35`。カメラ A で 3 周目 A の凍結点
（`line_freeze` 中点・1.36m）に立つと、**箱は映像の 83%**・そのうち**人は 17% だけ**。
残りは背景なので、プレートがずれた分はそのまま黒として出る。

⚠ **箱は CG の人型から作られる**（`ShowCgLayer.TrySwapRect` ＝ `visitor` 代役の投影）。
差分の区間でも、CG が立てられなければ `RectResolved=false` で**覆いは 1 画素も出ない**。

⚠ `swapMinX 0.5` は枠 UV 0.5 ＝ **映像の中央**（`_LiveScale.x=0.75` の contain-fit 後）。
体験者の投影中心は床の位置で 0.27〜0.76 まで動く。凍結点なら 0.685 で右に居る。

## 5. 拾えなかった画素の受け皿が無い

`sil = silDiff < 0.0 ? silCg : lerp(silDiff, silCg, hand)`。CG へ落ちるのは
**プレートを掴めなかったとき（−1）だけ**で、「プレートはあるが人を見つけられなかった（0）」は
0 のまま ＝ **素通し**。持続の覆いは `_SwapDiffHold` で `hand` も 0 に潰すので、穴は必ず残る。

現行 `plate_A` の右半分は暗い（sRGB 中央値 49）。仮定計算で、
**黒っぽい服（sRGB 30）は箱の中の 29% しか覆えない**（中間 52% / 明るい服 99%）。
⚠ ここは lod をどれだけ上げても変わらない（面の明るさの差なので、粗くしても埋まらない）。

⚠ **2 段の mip が実質 1 段になっている。** `MaskDiffLod = 0.6` に対して
`lodA = lod + 0.6` / `lodB = lod + max(0.6 - 2, 0) = lod`。差は 0.6 段しかなく、
コメントが意図する「粗い段が人の中の穴を埋める」は効いていない。

## 6. 観測されていないこと

- `ev=swap` の `mask=` は**プレートを掴めたか（0/1）だけ**。誤検出も穴も実機ログに出ない
- `Preview Swap Morph` は**プレートに人を焼き込んだ画**を「現在の画」にする ＝
  プレートと現場が 1 画素も違わない理想条件しか焼いていない
- プレートの撮影時刻はファイル名にあるが、実行時に古さを見る経路が無い
- **実写の人が写ったカメラフレームが手元に無い**ので、人がどれだけ拾われるかは未実測
  （§5 は「その画素にその明るさの服が来たら」の仮定）
