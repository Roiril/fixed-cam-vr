# 不正アクセスのエラー演出

2026-09-19。表示部品を用意した。登場場面と見た目の採否は未判定。
使い方は [docs/unauthorized-access-effect.md](../../docs/unauthorized-access-effect.md)。

- `Assets/Prefabs/Effects/UnauthorizedAccess.prefab`。本編と show.json には未接続。
- 第 3 版は文字と記号とノイズを独立させる。英字 DSEG14 Modern Bold。日本語 DotGothic16。
- 第 4 版は同じ素材を継続し「映像回線　接続元不明」と「遮断を試行 → 遮断失敗」を実フォントで加える。
- 文脈の意図は `canon/OPEN.md` の案。通信や犯人について確定した設定ではない。
- 字の付近で信号を薄くする処理はシェーダが各視点から投影して判定する。空間の位置は頭へ追従させない。
- 明るい背景の読字は文字の暗い縁と背景検査で確認する。白い映像面と赤い細模様も焼く。
- 文字は `tools/make-error-typography.py` で実フォントから描画する。字形を画像生成しない。
- 生成するのは単体の三角記号と信号の断裂。感嘆符と斜線はコードで描く。
- 11 帯の英字と 220 個の数字を使う。数字は専用シェーダで描く。TMP は使わない。
- スクリーン側は指定した面へ追従。数字列側は発火時の座標へ固定する。
- Editor でも停止と破棄を実行するため `ExecuteAlways` を付ける。自動再生と Update の時間進行は `Application.isPlaying` で制限する。

## 見た目への指摘

初版へのユーザーの指摘: 「フォントも出方も枠の形も演出全体がすべて整列されすぎている。チープである。」
初版の細い文字と整列した枠を採用基準にしない。
参考画像の巨大な警告文字に戻る。空間の数字も距離と密度をばらつかせる。
読める瞬間と裂ける瞬間を分ける。

第 2 版へのユーザーの指摘: 「良くなってきてはいるが、AI臭さが出てしまった。」
「警告の表示を全部一気に画像生成するのではなくパーツごとに生成、フォントもデジタルチックなものにしてAI臭さを無くしてほしい。」
全体を生成してから分割する方式には戻さない。文字と記号を最初から別素材として組む。
第 3 版の採否は未判定。

## 描画の確認で必要だったこと

警告は映像用の面より手前へ 6 cm 出す。専用シェーダの描画順は 3450。
プレビュー背景にも実際のスクリーンと同じく深度を書く不透明な面を使う。
透明の面を背景の代用品にすると描画順の問題を再現しにくい。

`tools/check-error-preview.py` は中央と左右の表示を別々に測る。
表示が欠けた最初の画像を失敗として検出できることも確認した。
時刻 0 と終了後と Stop 後の画像を比較する。停止後は差分 0 であることを確認する。
文字の頂点数だけで表示の成功を判断しない。

第 3 版は EditMode 6 件が成功。Unity の連番 211 枚を確認した。
第 4 版の最終調整後は EditMode 7 件が成功。連番 211 枚のうち 209 枚が異なる。
`Logs/unauthorized-access/v4-final/` に白と赤の背景と実写上の読字検査を残す。
読字保護の有無で 14,003 画素が変化した。終了と Stop 後は差分 0 画素。
動画は `output/unauthorized-access/unauthorized-access-v4.mp4`。Quest の読字と負荷は未確認。
プレビューではスクリーンを含む親を壊す前に演出コンポーネントを破棄する。
親を先に壊すと演出の終了処理とスクリーンの削除が重なって二重破棄の警告が出る。

コンテキストが一致しないパッチは一部だけ適用されたと考えない。
対象の現行行を読み直し、ファイル内の順番で必要な差分だけを再構成する。
