# ビューア体験の根本設計（追従の緩急・切替作法・フェイルソフト）

## 概要

Quest 装着者が見るものの UX を、確立した先行知見（2D ゲームカメラ理論・Meta 快適性ガイドライン・
映像編集の切替作法・LBE 運用・diegetic エラー演出）を輸入して底上げする。
調査で確定した欠落 11 件のうち、**芯（追従・切替・cue 調停）+ フェイルソフト（信号ロスト・ロスト凍結）** を今回実装。
登録の Spatial Anchor 自動化・床 rest frame・輝度規律は次回スコープ。

ユーザー決定（2026-07-19）: ①切替トランジション = **dip-to-black（CCTV 風）** ②スコープ = 芯 + フェイルソフト
③スクリーン **2.0m + 中心やや下げ（角径維持のためサイズ連動拡大）** ④音マスクは**仕組みのみ**（音源は空スロット）

## 現状の欠落（実装事実調査 2026-07-18 より・対象は今回分のみ）

- ScreenAnchor は yaw 純スナップ（補間・deadzone・角速度上限なし）。再ロック時に瞬間ジャンプ
- カメラ切替は無条件ハードカット。時間クールダウン・最小ショット長なし
- cue 再生中の切替が未調停（オーバーレイ残留・マスク付きは下地だけ透ける）
- 手動 A/B とゾーン自動切替の調停なし
- 配信断は「最終フレーム凍結 + 小さな○」のみ。トラッキングロストの体験層ハンドリングなし
- 診断 HUD が既定 ON で本番の視界に被る

## 設計契約（実装の正）

### A. 追従の緩急（ScreenAnchor 改修）

2D カメラの camera window + damped smoothing + 速度上限（Itay Keren 分類）を yaw に適用:

```csharp
float e = Mathf.DeltaAngle(screenYaw, headYaw);
float targetYaw = (Mathf.Abs(e) <= yawDeadzoneDeg) ? screenYaw
                : headYaw - Mathf.Sign(e) * yawDeadzoneDeg;   // 枠端トレール
screenYaw = Mathf.SmoothDampAngle(screenYaw, targetYaw, ref _yawVel,
            smoothTime, maxYawSpeedDegPerSec, Time.deltaTime);
```

| パラメータ | 初期値 | 意味 |
|---|---|---|
| yawDeadzoneDeg | 10 | この範囲の頭の動きではスクリーン不動（微小 jitter 吸収） |
| smoothTime | 0.30 | 臨界減衰の時定数（行き過ぎない） |
| maxYawSpeedDegPerSec | 110 | full-field スライドの上限（vection 抑制） |
| catchUpThresholdDeg / catchUpBoost | 45 / 2.0 | 逆走ガード: 大きく置いていかれたら上限を一時 2 倍 |
| distance | **2.0**（旧 1.5） | Meta 焦点快適域 |
| heightOffset | 中心を head から **-8°** 相当下げ（= -distance·tan8° ≈ -0.28m） | 歩行時の自然な視線 |
| スクリーン scale | **4/3 倍**（幅 2.370×高 1.333） | 距離 1.5→2.0 で角径維持（水平 ≈61° のまま） |

- ピッチ追従は入れない（垂直 vection 回避・現状踏襲）。高さは head.y + heightOffset に追従（上下の「位置」は従来同様 head 基準）
- **再ロック時のジャンプ排除**: lock ON にした瞬間は現在のスクリーン yaw を初期値として減衰追従で合流（スナップ禁止）
- 純ロジックは `YawFollowLogic`（plain class）に分離し EditMode テスト

### B. 切替作法（新規 CameraSwitchDirector）

registry.SetActive を直接叩いている経路（PlayerZoneTracker / OvrControllerBridge / CameraSwitchInput）を
**Director 経由に一本化**し、時間軸のガードと演出を持たせる:

| ルール | 値 | 由来 |
|---|---|---|
| switchCooldownSec | 2.0 | 切替直後の再切替ロック（Murch: 最小ショット長） |
| minDwellSec | 2.0 | ゾーン切替要求はペンディング→滞在が続いたら適用（一瞬の通過で切らない） |
| cue 再生中の自動切替 | **凍結**（要求はペンディング、cue 終了後に最新を適用） | scare を切替で中断させない |
| 手動切替（右 A/B） | クールダウンのみ尊重・dwell 無視（意図的操作）。**手動後 manualHoldSec=8s は自動切替を抑止** | 手動 vs 自動の明示調停 |
| Web cameraOverride | 従来どおり最優先（tracker 無効化・既存挙動不変） | — |

**dip-to-black トランジション**: 黒へ 70ms → ソース差替 → 100ms で立ち上げ。
実装はポスト FX（ScreenComposite の post 数式は Web と一致規約があるため**触らない**）ではなく、
**スクリーン Quad 直前の黒 quad（または材質の独立 `_SwitchDim` 加算）**で行う。CCTV の瞬断に読める。

**音マスクフック**: `SwitchAudioCue`（AudioSource + [SerializeField] AudioClip switchClip = 空）。
切替シーケンス開始と同時に再生（dip の黒 70ms が視覚差替に先行するので J カット相当が成立）。クリップ未設定なら無音スキップ。

**HUD 既定 OFF**: MainDemoSceneSetup の startVisible を false へ（本番の視界保護。左 Y でいつでも表示）。

### C. フェイルソフト（「信号」語彙への一本化）

**SignalLostFx（配信断 → 砂嵐）**:
- 発火: アクティブカメラの新フレーム無し > 600ms（CameraStream.LastFrameAt 由来）
- 演出: 150ms で手続き砂嵐（シェーダ内ノイズ・ScreenComposite に `_SignalLost` uniform 追加は**post 数式と別系統**として可・Web 一致規約の対象外と明記）へクロスフェード → 保持 → 復帰時 150ms グリッチイン
- 体験者には「カメラの信号が落ちた」に見える（バグと演出の区別がつかない = フェイルソフト）

**トラッキングロスト / OS pause 明け**:
- OVRManager の tracking 状態 or resume-gap（既存 Time.unscaledDeltaTime > 0.5s 検知）で
  **ScreenAnchor の追従を凍結**（最後の良ポーズ維持・暴れ禁止）+ SignalLostFx を弱く適用（減光+微ノイズ）
- 復帰したら減衰追従で無音で合流（スナップ禁止）
- ガーディアン表示には触らない（次回スコープ）

### 診断との分離

体験者向けは上記の diegetic 表現のみ。スタッフ向けの真実（断・ロスト・切替抑止状態）は HUD / Web 卓 heartbeat に出す。
