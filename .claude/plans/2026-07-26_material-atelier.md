# 素材工房（🧪 素材）— 試写室としての再設計

対象: `tools/web-compositor/`（卓 Web UI）。Unity 側の変更は無し。

## 1. なにを作る面なのか（設計の芯）

素材工房は **記録装置ではなく試写室** である。

固定カメラ映像に AI 生成の異変を重ねる、という作り方の判断基準は
「動画単体がよく出来ているか」ではなく **「その構図の live に載せた時に破綻しないか」** の 1 点しかない。
だから工房の中心は生成レコードの一覧ではなく、**合成の見え**でなければならない。記録
（レシピ・束縛値・全文プロンプト・採否）はその作業の副産物として自動で溜まればよい。

初版（2026-07-26 午前・コミット 3b08ebf）はここを取り違えていた。記録の構造は正しいが、

- カメラが**タブ**なので 3 つの構図を並べて比べられない
- 合成が**見えない**。確認するにはタイムラインのセグメントインスペクタへ面をまたぐ必要がある
- 種フレームを撮る 📷 が別セクション（監視列）にあり、撮っても**モードを往復しないと候補に出ない**
- 生成物カードは記録専用で、**合成の入力にならない**

## 2. 構造 — 列 = 1 カメラ、上から下へ 1 本の流れ

カメラを横に並べる（縦割り）。1 列の中で「種 → 指示 → 生成物 → 合成の見え」が閉じる。

```
[📐 レシピ（全カメラ共通・畳める）]

┌ カメラ A ────────┐ ┌ カメラ B ─┐ ┌ カメラ C ─┐
│ ① 試写（合成プレビュー）      │ │ …        │ │ …        │
│    背景: 種フレーム / ライブ   │ │          │ │          │
│    前景: 選択中の生成物        │ │          │ │          │
│    マスク: 全面 / 動くところだけ│ │          │ │          │
│    [💾 カットの素材にする]      │ │          │ │          │
│ ② 種フレーム [📷 いま撮る]     │ │          │ │          │
│    サムネのストリップ（最新が先頭）│ │        │ │          │
│ ③ 指示（レシピ + 束縛 + 全文）  │ │          │ │          │
│    [📋 コピーして記録する]      │ │          │ │          │
│ ④ 生成物の棚（クリック→①へ）   │ │          │ │          │
└────────────────┘ └─────────┘ └─────────┘
```

**上下の順序は作業順ではなく重要度順**。試写を一番上に置くのは、作業中いちばん長く見るものだから。
種・指示・棚はその材料であり、下へ行くほど「触る頻度が下がる」。

## 3. 決めたこと（設計判断とその理由）

| 判断 | 理由 |
|---|---|
| 背景の既定は**種フレーム**（ライブは切替） | 素材づくりは現場ではなく自宅で行う時間の方が長い。カメラ未接続でも工房が全機能で成立する必要がある |
| マスクは **全面 / 動くところだけ（自動差分）** の 2 つだけ | 固定カメラ i2v は背景が入力画像と同一なので、差分＝「足されたもの」そのもの。手描きマスクは cue エディタの仕事で、工房は「どこが変わったか」を機械に出させる方が速い |
| 差分は**累積の最大値**（瞬間差分ではない） | Quest 側は静的マスク PNG を使う。累積は実運用と同じ形になり、再生が進むほど安定する。瞬間差分だと live に戻る領域がチラつき判断を誤らせる |
| 工房から **cue を直接保存できる**（マスク PNG も焼く） | 「試写で良かったもの」が 1 クリックでタイムラインの選択肢になる。ここが切れていると工房は行き止まりの実験場になる |
| 棚に **captures/ の未記録ファイルも出す** | 生成は外部ツールなので「先に作ってから記録する」順序も普通に起きる。棚へのドロップで素材だけ先に入れられる |
| DOM は**列ごとに永続**（毎回 innerHTML を捨てない） | 各列が WebGL コンテキスト（試写）を持つ。全書き換えすると毎回作り直しになり、再生位置も選択も飛ぶ |

## 4. 実装

サーバ（`capture-server.py`）は**変更なし**。既存 API だけで足りる。

| やること | 使う既存 API |
|---|---|
| 種フレーム一覧 | `GET /atelier/frames`（recordings/ の `camX_*.jpg` をカメラ別に束ねる） |
| 📷 いま撮る | `POST /save?type=image&to=recordings&cam=<camId>` → `{name,url}` を即クライアント側配列へ差し込む |
| 生成レコード | `POST /atelier/gen` / `/atelier/gen/delete` / `/atelier/attach` |
| レシピ | `POST /atelier/recipe` / `/atelier/recipe/delete` |
| 未記録素材 | `GET /captures/list`（`common.js` の `refreshCaptures`） |
| マスク PNG | `POST /masks?name=<cueId>`（cue エディタと同じ） |
| cue 保存 | `common.js` の `saveCueObject`（`state.cues` へ upsert） |

`app.js` からの注入（cue-editor と同じ deps 流儀）:

```js
createAtelier({ root, getCameras, getLiveImg, getCamPost, getAllCues, saveCue, onCueSaved })
```

返り値に `notifyFrameSaved(camId, {name,url})` を生やし、**監視列の 📷 でもリロードなしで反映**する。

## 5. 実装中に見つけたこと（実画面で確かめた結果）

- **`composite-view.js` の「再生終了」判定がループ試写を殺していた**。素材が 1 周した瞬間に `ended=true` になり、
  以後 `overlayOn` が落ちるまで live に戻り続ける。オーサリング面は素材をループさせて見るので致命的。
  → `loopPreview` を provider に追加（既定 false ＝従来動作）。工房と cue エディタで true にした
- **試写の平均輝度では合否を判定できない**。カメラ post（露出 −1.36 / 彩度 0.44 / ヴィネット 0.5 / 走査線 0.67）が
  合成後に掛かるため、素材を載せても平均は 9.66 → 9.5 としか動かない（実際にこれで「描画されていない」と誤判定し、
  無い原因を追った）。判定は**画素ごとの差**で行う（meanAbsDiff 2.63 / max 36.7 で載っていることを確認）。
  UI としても「画質: 本番 / 素の色」トグルを足した — 暗いグレーディングのまま素材の良し悪しは判断できない
- **保存の結果表示は再描画されない場所に置く**。`.atl-pick` に出すと cue 保存 → show.json rev 更新 → 再描画で
  消えてしまい「押したのに何も起きない」に見える（`.atl-savemsg` へ分離）

## 6. 検証済み（卓を実際に動かして）

3 カメラの列描画 / 種の自動選択 / レシピ選択 → 束縛 → プロンプト合成 → 📋 でレコード生成 → 採用トグル →
レシピ採用率 `1/1` 反映 → 🗑 削除 / 生成物クリック → 試写に合成（画素差で確認）/ 全面・動くところだけ・画質トグル /
💾 で `cue_A_1` + `masks/cue_A_1.png`（640×480）作成 → タイムラインへ反映（**確認後に元へ戻した**）/
1600・1100・820 px で横はみ出しなし（列は auto-fit で 3→2→2 に折る）。

**実機カメラが繋がっていないため未検証**: 📷 いま撮る（`getLiveImg` 経由）・監視列 📷 からの `notifyFrameSaved`・
ファイルのドラッグ&ドロップ取り込み。

## 7. 未検証・現場で決めること

- **差分しきい値の既定 0.12**（0..1 の色差）。照明・ノイズで最適値が変わるので列ごとにスライダを出す
- 工房で焼いたマスクの解像度は 640×480 固定（差分計算は 192×144 で行い保存時に拡大 + ぼかし）。
  Quest 側はスクリーン枠空間で伸ばしてサンプルするので、素材と種のアスペクトが揃っていることが前提
- 実機（Quest）での見えは未確認。工房の試写は `composite-view.js`＝Unity ScreenComposite の再現なので
  式は一致するが、**マスクのフェザー量と強度の体感は現場調整**
