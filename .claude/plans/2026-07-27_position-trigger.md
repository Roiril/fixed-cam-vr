## ユーザー要求（原文）

> 固定カメラプロジェクトについて、演出のトリガーに、「体験者がこの位置X」みたいなのを、
> フロアマップで位置Xを置くみたいなことをして作れそうだよね。設計から実装までお願い

> この「エリア」に入ったらじゃなくて、このラインを通過したらにしてほしい。そして、基本的にラインは各区間に
> 紐づかせて、何かの手違いでほかの領域でラインを踏んでも何も起こらないように。
> ここら辺の設計はあなたの方がよく知っていると思うので既存システムと整合性をとりながらお願い

## 1. 何を足したか（1 行）

**演出（Take）の開始規則に 3 つ目「ライン通過」を足した。** 進入 +t 秒 / 離脱時 に並ぶ第一級の開始条件で、
発火点はフロアマップに引いた線分（course 空間）＝ **通過ライン**。

```
開始規則:  進入 +t 秒（時刻）  |  離脱時（事象）  |  このラインを通過したら（場所） ← 追加
```

**なぜ円ではなく線か**: エリアは「入って居続ける状態」、ラインは「一度きりの事象」。
演出の開始規則（＝ちょうど 1 回発火する）と型が合うのは後者で、
体験の言葉（「ここを通ったら」）もそのまま写る。滞在秒（`holdSec`）のような追加概念も要らなくなった。

## 2. 設計の核 — ラインは「区間に紐づく」二重の縛り

ユーザー要求「他の領域でラインを踏んでも何も起こらない」を **2 段**で保証する。

| 段 | 仕組み | 効くケース |
|---|---|---|
| ① **武装が区間限定**（既存機構） | 演出は区間 (lap, camera) に属し、その区間に居ると時計が確定しているあいだだけ武装される | 別の周・別のカメラの区間に居るあいだに踏んでも発火しない |
| ② **ラインの担当カメラ照合**（新規） | `layout.lines[].camera` と演出の区間カメラが一致しないと due にしない（`TakeRunnerLogic.IsDue`） | 著作ミス（別カメラ担当の線を選んだ）を構造的に無効化。卓も同じ理由で選択肢に出さない |

区間の外に独立したトリガー表を作らないので、`once` / `ifMissed` / 「同時 1 本」/ 離脱時の決着 /
ランリセット / リボン UI の置き場は**すべてそのまま効く**。

### 猶予（latch）— 「入口の線が永久に沈黙する」を防ぐ

演出の武装は**ゾーン確定**（dwell 既定 0.5s）で起きる。ゾーンの入口すぐに引いた線は
「入った瞬間に横切る → 0.5s 後に武装」となり、横断を 1 フレームで消すと**永久に発火しない**。
そこで横断時刻を覚え、**`CrossLatchSec = 0.6s`** の猶予内なら due と認める
（担当カメラの照合は猶予中も効くので ② の保証は保たれる）。
golden トレースがこの経路を固定している（`t_B_line` は「ゾーン確定と同フレーム」で発火する）。

## 3. スキーマ（追加分）

### 3.1 `layout.lines[]`（フロアマップで著作）

```jsonc
"layout": {
  "lines": [
    { "id": "line_1", "camera": 1, "x1": -0.2, "z1": 0.4, "x2": 0.2, "z2": 0.4,
      "dir": "both", "label": "人形の前" }
  ]
}
```

| フィールド | 意味 |
|---|---|
| `id` | 演出から参照するキー（卓が `line_1`… で採番。UI では `label` を表示） |
| `camera` | **担当カメラ index**（-1 = 未指定）。この区間の演出しか使えない＝紐づけの正 |
| `x1,z1 / x2,z2` | 線分の端点（course 空間・m）。`0.05m` 未満は無効 |
| `dir` | `both`（既定）/ `fwd`（卓の矢印の向きに横切った時だけ）/ `back`（逆だけ） |

- 判定に使うのは **HMD の course 空間 XZ**（`ShowControlClient.HeadCourseXZProvider`／登録済み座標）
- `layout` の一部なので **端末キャッシュ・APK 焼き込み・卓の shallow 置換保存**に自動で乗る
  （`regPoints` と同じ扱い。サーバ側の変更は不要）

### 3.2 演出（Take）の開始規則

```jsonc
{ "at": "line", "lineId": "line_1", "ifMissed": "skip", "offsetSec": 0 }
```

| フィールド | 意味 |
|---|---|
| `at: "line"` | 3 つ目の判別子（未知値は従来どおり `enter` へ倒す） |
| `lineId` | `layout.lines[].id`。空 / 未定義 id / **担当カメラ不一致**は発火しない（卓が警告・実機はログ 1 回） |
| `offsetSec` | **at=line では無視**（卓は 0 で書き出す） |
| `ifMissed` | そのまま効く（この区間に居るあいだに通らなかった時）。`skip`=出さない（**卓の既定**）/ `fireOnExit`=離脱の瞬間に出す |
| `once` / `policy` / `maxDurationSec` / `steps` / `bgm` | 変更なし |

**発火は 1 区間滞在につき最大 1 回**（武装は区間進入時のみ・発火で武装から外れる）。

### 3.3 判定の細部（純ロジック `LineCrossLogic`）

- **毎フレームの移動線分 × ライン線分の交差**で判定する（無限直線ではないので、
  **端の外を回り込んだら横切っていない**）
- 横切った直後は線から **`RearmMarginM = 0.06m`** 離れるまで再検出しない
  （線上での足踏み・トラッキング揺れで連発しない）
- dt が不連続（`> 0.5s`・HMD 着脱／復帰）／1 フレームの移動が **`MaxStepM = 1.0m`** 超（recenter・テレポート）なら
  その間の横断は数えない（幽霊の発火を作らない）
- **高さは見ない** / **短すぎる線（0.05m 未満）は無効**
- 走行中・ライブ卓の抑止中に横切った場合は時刻トリガーと同じ規則で決着（`skip`=破棄 / `fireOnExit`=離脱時へ）
- 位置が取れない（provider 未注入・未登録）間は発火しない（警告ログ 1 回）

### 卓が出す警告（黙って出ない状態を作らない）

1. `lineId` 未選択 / `layout.lines` に無い id → 「発火しません」
2. **担当カメラが区間のカメラと違う** → 「カメラ C 担当です（この演出はカメラ B の区間なので出ません）」
3. 担当カメラ未指定 → 「どの区間からでも使えてしまう」
4. **線が担当カメラ以外のゾーンに引かれている** → 「担当は B ですが線は C のゾーンにあります」
5. 線が短すぎる（0.05m 未満）
6. ライントリガーの演出は**リボン上で位置を持たない**（時間軸に乗らない）ので、区間ブロック内の
   専用レーンに 📏 付き・破線で描き、ヘッダに常時 `ライン「人形の前」→` と出す

## 6. 決めたこと（覆すなら理由と一緒に）

- **線分（有限）にした**。無限直線だと「線を延長した先」で誤爆する。端の外を回り込む歩き方は
  横断ではない、が現場の直感と合う
- **通過方向を持たせた**（`dir`）。既定は両方向。「奥へ入った時だけ / 戻った時だけ」は
  後から足せない意味なので最初から入れる（卓は矢印で見せる）
- **担当カメラをデータに持たせた**（`camera`）。武装の区間限定だけでも「他領域で踏んでも起きない」は
  成立するが、著作ミス（別ゾーンの線を選ぶ）は残る。データに持たせると卓が選択肢から外せて、
  実機も同じ理由で拒否できる（二重の縛り）
- **横断に 0.6s の猶予**（§2）。dwell の確定待ちで入口の線が沈黙するのを防ぐ。
  猶予中も担当カメラ照合は効く
- **高さは見ない**。しゃがみ・背の高さで発火が変わると現場で説明できない
- **1 本の線を複数の演出が参照してよい**（周ごとに別の演出を同じ線に置く＝主な使い方）

## 6.5 ついでに直した既存の flaky テスト（この作業中に発覚）

`TakeWiringTests` / `SwitchWiringTests` は **Editor の実フレーム間隔に依存して run ごとに落ちていた**。
原因は 2026-07-26 に遷移を「カットごとの引数」へ移した時から: カットの `transition` 既定が dip
（= 170ms・落とし 68ms）で、rig が `dipDownSec=0` にしても**カット側の値が上書きする**ため、
`PumpDirector` の 4 フレームで `Time.unscaledDeltaTime`（フォーカス中 7〜16ms / 非フォーカス数百 ms）が
68ms 貯まるかどうかで結果が変わっていた（1 件 → 7 件 → 1 件と run ごとに違う顔で落ちた）。

- [`CameraSwitchDirector.SetDeltaSource`](../../Assets/Scripts/Streaming/CameraSwitchDirector.cs) を追加
  （dip の dt を差し替える **EditMode 用 seam**。`TakeRunner.SetTimeSource` と同じ流儀・本番挙動は不変）
- 両 wiring テストの rig で `SetDeltaSource(() => 1f)`（1 フレーム = 1 秒）にし、
  遷移が検査対象でない fixture は `transition = cut` に落とした（dip の計時は `DipTransition_*` の担当）
