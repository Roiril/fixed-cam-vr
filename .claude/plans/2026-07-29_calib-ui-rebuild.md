# 姿勢を合わせる UI の立て直し（2026-07-29）

対象は卓の較正パネル（`tools/web-compositor/calib-ui.js` / `calib.js` / `floor-sketch.js`）。
数学（`calib.js`）は独立監査で問題が見つかっていない。壊れているのは**状態管理と、卓⇄実機の契約と、
「実測していない数字を実測のように扱う」設計**の 3 つ。

## いま何が起きているか（事実）

- show.json の 4 台とも `hasCalib=false`。**この道具は一度も現場で成功していない**
- `layout.wall` は卓の既定値（1m × 1m の L）のまま。`regPoints` / `calibPoints` / `room` は未設定
- したがって候補点 172 個のうち、**現場の床で同定できる点はほぼ無い**
  （タイルの角 165 個は 0.15m × 12×12 の定数から生成され、床に目印は無い）
- 品質欄が同じことを違う数字で 2 回言う（`6 点まであと 6` と `あと 4 点（最低 4 点）`）

較正が合わない原因は、点の打ち方より**手前の前提**にある。

## 段 0 — 状態遷移を純ロジックへ出す（他のすべての前提）

`calib-ui.js` は 1045 行で、状態遷移（開く / 取り直す / 打つ / 解く / 保存）が DOM ハンドラの中にある。
既存テストは純関数だけで、**状態遷移を 1 本も踏んでいない**。下の実バグ 5 件はすべてこの空白から出た。

→ `calib-session.js` を新設し、DOM 非依存の純関数（既存分 + 状態遷移の判断）を全部そこへ移す。
`calib-ui.js` は DOM シェルだけにする。テストは `calib-session.test.mjs`。

新しく純関数にする判断:

| 関数 | 何を決めるか |
|---|---|
| `openSession(cam, frame)` | 復元する点・固定できる画角・置き直しの疑い |
| `refreshSession(s, newFrame)` | 解像度が変わったとき何を捨てるか（点・固定画角） |
| `resolvePointLabels(pts, layout)` | 復元した点が「何の目印か」を座標から引き直す |
| `calibMatchesSource(calib, w, h, lensId)` | Unity の `MatchesSource` と**同じ判定**（lensId を含める） |

## 段 A — 実バグ（監査で全部コード確認済み）

| # | 症状 | 直し方 |
|---|---|---|
| A1 | 🔄 で解像度が変わっても固定画角を捨てない（`open()` は捨てるのに `\|\|` で旧値が残る） | `refreshSession` で判定を一本化。解像度が変わったら固定画角も**点の画素座標も**捨てる |
| A2 | 点の質判定が高さの点を床の点と混ぜ、必ず「3 点が一直線」と誤警告（高さ点は基準点と (x,z) が同一） | 床の点だけで一直線・広がりを見る。必要点数も床の点で数える |
| A3 | 映像が来る前に開くと `refs` が復元されず、🔄 でも戻らない | 復元経路を `refreshSession` にも通す |
| A4 | 「壁の高さ」を後から変えても既に打った点の `y` が変わらない（拘束 1.80 / 検証線 2.40 になる） | 高さは**点ごとに持つ**。一覧で直せる。壁と箱で高さが違う現場に対応 |
| A5 | 卓は lensId を照合しないが Unity は照合して較正を捨てる → 卓は「較正済み」で実機だけ概算姿勢 | 卓も同判定にする。バッジで言う |
| A6 | 解に失敗した直後、古い較正のワイヤーが残って「合っているように見える」 | 失敗中は線を引かない |
| A7 | 🔄 が品質を再計算しない（画面の広がり % が旧フレーム基準のまま） | 再計算する |
| A8 | `saveLayout` 未提供時、印は保存されないのに「置きました」と ok 表示 | 保存できたときだけ ok |
| A9 | `refs` にラベルが無く、復元した点が「何の目印か」分からない | 座標から候補を引き直して名前を戻す |
| A10 | 未保存の解を確認なしで捨てる（背景クリック・✕・Esc） | 未保存なら確認する |
| A11 | 品質欄が同じことを違う数字で 2 回言う | 1 回にする |
| A12 | 候補 172 個でセレクトとして機能しない | 段 B7 と一緒に解く（出典で畳む） |

## 段 B — 概念を足す

### B1 レンズ（内部パラメータ）を一級市民にする

画角を固定する値の供給源が「**このカメラの前回の解の `fxPx`**」しか無い。4 点でフリーに解いた
いい加減な f が、翌日「正確な内部パラメータ」として再利用される。しかも **f を固定すると rms は下がる**
ので、誤りが良い数字に化けて発見できない。

→ show.json トップレベルに `lenses[]` を新設し、カメラが参照する。

```jsonc
"lenses": [{ "id": "pixel7a-uw", "name": "Pixel 7a 超広角",
             "fxPx": 431.2, "srcW": 640, "srcH": 480, "k1": 0.18,
             "measuredAtIso": "2026-07-29T20:10:00",
             "pointCount": 11, "raisedCount": 3, "rmsPx": 0.8 }]
```

- カメラは `lensRef: "pixel7a-uw"` で参照する。**同型機（iPhone 13 Pro ×2）で共有できる**のが要点
- 較正パネルの既定を「レンズを選ぶ → 外部（置き場所）だけ解く」にする
- レンズの登録は「良い解が出たとき、その画角をレンズとして名前を付けて保存」。
  測定条件（点数・高さの点の本数・rms）を一緒に焼くので、**素性の分からない f が混ざらない**
- Unity は `lenses[]` を読まない（`cameras[].calib.fxPx` に解決済みの値が入る）。契約は広げない

### B2 精度を cm で言う（leave-one-out）

`rmsPx` は当てはまりであって精度ではない（設計文書自身が「4 点なら誤差 0 でも嘘」と書いている）。
作業者が知りたいのは「人形が何 cm ずれるか」。

→ 1 点を抜いて残りで解き、抜いた点の再投影誤差を測る（全点で回して中央値）。
当てはまりと精度が分離する。代表距離での cm 換算を結果の 1 行目に置く。

### B3 本番前チェックに較正の行

`preflightRows`（app.js）に卓サーバ・Quest・カメラ受信・位置合わせ・録画・BGM はあるのに較正だけ無い。
CG 人形を出すカットがあるのに未較正 / 解像度不一致 / 前回設営の古い解、を**押す前に見る場所で誰も言わない**。

### B4 置き直しフローと B5 保存の 1 世代 undo

較正は設営ごとに無効になるのに、鮮度は日時表示だけ。前回の refs 復元は小さいドリフト専用で、
置き直した後は無関係な画素に点が散らばる。しかも**全消しが無い**（右クリックで 1 個ずつ）。
`save()` は前の calib を上書きして復元手段が無い（`discard` は pose へ落ちるだけ）。

→ 開いた瞬間に「復元した点はいまの絵と合っていますか」を問い、［全部やり直す］を置く。
保存は直前の 1 世代を持って［元に戻す］。

### B6 / B7 実測していない幾何を使わない

`wireSegments` は `layout.floor` 不在時に **1.8m 四方を捏造**して外周を引く。
候補点も同じ病で、既定値の壁・定数のタイル格子が「打てる点」として並ぶ。
**唯一の反証可能な一次証拠（実映像へのワイヤー重畳）が、実在しない部屋の絵になりうる。**

→ 候補点と検証線に**出典**を持たせる。実測済み（作者が置いた印・実測した部屋）と
既定値由来（未測定の壁・床・定数格子）を区別し、後者は既定で出さない。
`layout.wall` には直接編集 UI が無い（🧱 部屋モードからの一方向取り込みのみ）ので、
較正パネルからその導線を出す。

### 実装中に分かったこと

- **`<img>` の `load` / `decode` は非表示ウィンドウで永久に解決しない**。プレート読み込みは
  `fetch` + `createImageBitmap` に寄せた（描画パイプラインに依存しない）
- **Quest 経由の記録は 480×360、配信は 640×480**。縦横比が同じなので `rescaleCalib` で内部行列を
  比例で移せる（k1 は正規化半径なので不変・姿勢も不変）。縦横比が違えば移さない
