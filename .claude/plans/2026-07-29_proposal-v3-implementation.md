## 2. やること（7 本）

独立に出せる単位へ割る。上から順に実装し、各段でコンパイルとテストを通す。

### A. 体験の骨格 — フェーズ・時計・終端

**新規**：`Assets/Scripts/Streaming/ShowRunLogic.cs`（純ロジック）/ `ShowRunDirector.cs`（実行体）。

3 相：`Intro`（導入）→ `Run`（本編 1..N 周）→ `Finished`（終了）。

show.json トップレベルに `run` を新設する。

```jsonc
"run": {
  "totalLaps": 3,          // 走り切る周数。lap > totalLaps で終了
  "introEnabled": true,
  "introMinSec": 20,       // 導入の最低尺
  "softLimitSec": 180,     // 3 分。超えたら卓に警告（体験は止めない）
  "hardLimitSec": 300,     // 動かない体験者への保険。強制終了
  "endFadeSec": 1.5
}
```

- **Intro → Run**：`introMinSec` 経過 かつ 体験者がスタート区間（`course.order[0]`）に居る、で自動。卓の「⏭ 導入を終える」でも即座に。
  遷移の瞬間に既存の `TriggerRunReset` 相当を打つ。**導入は「ラン開始前の自由歩行」と定義する**ので、本編は必ず lap=1 の区間 order[0] から始まる。
- **Intro 中**：演出を武装しない・周回を数えない。映像とゾーン切替は通常どおり動く（固定視点に慣れるのが目的なので画は出す）。
  実装は ShowControlClient が既に持つ抑止フラグへ `!runActive` を OR する。LapCounter には `SetCounting(bool)` を足す。
- **Run → Finished**：`lap > totalLaps` / `runElapsed >= hardLimitSec` / 卓の「■ 体験を終える」。
  **走行中の演出があれば終了を保留する**（3 周目最後の区間の離脱時演出と、同じ瞬間に立つ lap=4 が競合するため）。保留にも上限を置く。
- **Finished**：黒へフェード → 演出を畳む → BGM をフェードアウト → ゾーン自動切替を凍結。次のラン開始で解除。
  `StartupFader` は解除後に自分を Destroy するので再利用できない。終了用のフェーダは別に持つ。
- heartbeat に `phase` / `runSec` / `lapSec` / `totalLaps` を追加。

### B. 映像の乱れ（グリッチ）

**新規**：`GlitchEnvelopeLogic.cs`（純ロジック）/ `GlitchFx.cs`（`_Glitch` の唯一の writer）。

- `ScreenComposite.shader` に `_Glitch`(0..1) と `_GlitchSeed` を新設。**`_SignalLost`（障害表示）とは別 uniform**にして所有者を分ける。
- 乱れの中身：
  1. 帯ごとの水平シフト＋微小な垂直ローリングを**全層のサンプル前の uv** に掛ける（ライブ・オーバーレイ・マスク・CG が一緒にずれる＝差し替えの継ぎ目も一緒に乱れる）
  2. post の後に砂嵐混合と横方向の色ずれ
- 出し方を 4 つ用意する：
  - カットの遷移 `glitch`（4 つ目。既定 220ms）。dip 状態機械をそのまま使い、黒の代わりに乱れで差し替える
  - カット頭の単発パルス `ShowStepDef.glitch` / `glitchSec`
  - ゾーン切替への重畳 `control.switchGlitch`
  - 手動発火 `/command {type:'glitch'}` → `control.glitchEpoch`++（世代カウンタ方式。「空を空にする」問題を避ける）

### C. 進入カットの切替同期

`CameraSwitchDirector.InsertBegin` に「進行中の dip が Down 相なら相乗りする」判定を足す。
`TakeHoldBegin` と `InsertExitRedirect` には既にあり、`InsertBegin` だけ欠けている。

### D. 遅延の管理

端末間クロック差を解く材料が無いので、**絶対 E2E は測らないと決める**。代わりに Unity が測れるものを分けて出す。

- 到着の揺らぎ（`受信時刻 − captureNs` の窓 min からの超過）
- デコード所要（既存の EstimatedLatencyMs を活かす）
- 提示（表示レートから 1.5 フレーム）
- 配信側の鮮度（`/health.latestFrameAgeMs`。DTO にあって未使用）

合計に「撮影＋エンコード＋伝送の下限想定」を設定値として足し、**推定であることを明示**する。
新規 `LatencyEstimatorLogic.cs`（純ロジック）。StatusHud に 1 行、heartbeat に載せ、卓の本番前チェックで超過を警告する。

あわせて：

- `/health` DTO に `thermalStatus` / `throttleStage` / `thermalHeadroom` を足し、**熱スロットル中は lag 判定を抑止**する。
  いまは熱で fps が落ちると 5 秒ごとに MJPEG を張り直して事態を悪化させる。
- 表示レート 90Hz を実行時 API で要求する（共有 ProjectSettings を触らずスクリプト 1 本で完結する）。

### E. 色統計マッチングを実機へ届ける

卓が持っている Reinhard per-channel の統計を **RGB 3 対の gain/offset（6 float）** に落として cue へ焼き、
実機はオーバーレイのサンプル後に `ov*gain+offset` を掛けるだけにする。

多重帯域ブレンディングは Quest で重いので実装しない。フェザー焼き込み（既存）で妥協する
（企画書は「フェザリング**や**多重帯域ブレンディング」と選択で書いている）。

### F. post を 9 → 12 項目へ

色収差 / 低解像度化 / 走査線の本数を追加する。
「固定カメラ映像らしい質感」の語彙を揃えると同時に、**卓で見えて実機で出ない**という乖離を 2 つ潰す
（色収差は卓に uniform があって 0 固定、走査線の本数は実機 240 固定で卓は canvas 高さ）。

実機シェーダ・卓の FS_POST・共通の FX 定義表を**同時に**直す。

### G. CG 人形が出る条件を実機と卓で揃える

実機は `cameras[].pose` が無いと人形を出さない。卓は「較正 calib があれば出る」と判定して輪郭を描く。
実機のゲートを「pose あり **または** 使える calib あり」に緩める。

## 3. スコープ外（理由つき）

- **空間音響・効果音**：論文版に音の記述が 1 行も無い。旧企画書の要求だった。素材も無い。
- **しゃがみ・振り向き・着座の検知**：論文版の体験構成（3 周）から落ちた。
- **監視カメラ風 UI（カメラ番号・タイムスタンプ）**：論文版に無い。
- **多重帯域ブレンディング**：上記 E のとおり。
- **人形の歩行アニメ**：3 周目の人形は「操作対象」であって歩き回る必要が無い。定位置に立たせる著作で成立する。

## 3.5 実装した結果（2026-07-29）

7 本すべて実装済み。EditMode 849/849・node 219/219。**Quest 実機は未検証**。

設計批評（design-critic）を受けて、当初案から 3 点変えた。いずれも実害を避けるための変更:

1. **導入をランの第 1 相にした**（当初は「ラン開始前の自由歩行」で、Intro→Run に既存の `TriggerRunReset` を打つ案）。
   そのままだと `SegmentRecorder.ResetRun` の系統に乗り、ラン開始が複数系統に増えて
   「遅れて届いた runEpoch が 1 周目の録画を消す」経路ができた。`BeginMainRun()` を分けて録画を触らない。
2. **終了の判定を次フレームの Tick に置いた**（当初は周回の変化を受けたその場で確定）。
   周回の確定と離脱時演出の発火は同じ同期連鎖なので、その場で終わらせると
   3 周目最後の区間に置いた離脱時演出が始まる前に体験が終わる。
3. **終了で新しい凍結ラッチを作らない**（当初はゾーン自動切替を凍結する案）。黒 + ゲートだけにした。
   凍結が解けない事故をこの codebase は 4 回踏んでいる。

批評の指摘のうち、遅延の扱いも変えた。当初は「撮影＋エンコード＋伝送の下限」を設定値（55ms）として足し
合計を出す案だったが、**推定の定数を混ぜた数字を「100ms 以内でした」の根拠にしない**方針へ変更した。
測れる 3 つ（到着の揺らぎ / 展開 / 提示）と配信側の鮮度だけを出し、絶対値が要るなら配信アプリに
`/clock` を足す、と明記する。`softLimitSec` は表示専用であることを名前に出して `targetSec` へ改名した。

## 4. 守る不変条件（既存の設計判断・壊さないこと）

- **ショーの時計（`ZoneCommitted`）は画面の凍結にも dip にも左右されない**。演出で画面が止まっていても、歩けば周回は進む。
- **同時に走る演出は常に 1 本**。区間内では武装したまま待ち、区間を出た瞬間に決着する。捨てたら必ず報告する。
- **ラン開始は世代カウンタの「変化」でしか伝わらない**。停止・中止系を足すときは必ず同じ流儀にする。
- **present-flag は「宣言 bool ∧ 実体 != null」**。既定オブジェクトを常時出力すると全区間に幽霊が武装する。
- **長押し閾値・dwell・クールダウンは非シリアライズの const**。SerializeField へ戻すと既存シーン YAML の 0 が復活する。
- **卓と Unity の二重実装は片方だけ直すと沈黙して食い違う**。post の数式、射影、色温度、録画可否、演出セマンティクスが該当する。
  食い違ったら直すのは JS 側（C# が正）で、golden fixture を書き換えて通すのは禁止。
- **`show.json` は git 管理外の現地設定**。検証で書き換えたら復元できない。
