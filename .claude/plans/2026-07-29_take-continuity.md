# 演出の連続と、継ぎ目の遷移

ユーザーが挙げた 3 つの不整合（2026-07-29）。契約の正本は
[.claude/rules/streaming.md](../rules/streaming.md) の「演出の連続と、継ぎ目の遷移」節。

## 1. 何が起きていたか

調査（実行系 / 卓のミラー / 遷移の 3 視点）で確定した事実。

**離脱時の演出があると、次の区間の演出が消える**

実行側は待っている（区間内では Ready のまま保持する）。これ自体は正しく、ユーザーの
「離脱時の演出が終わるまで出さないでほしい」という要望どおり。壊れていたのはその先で、
**次の区間の滞在が前の演出より短いと、待っている間に区間を出て捨てられる**。
しかも離脱の瞬間は画面が塞がっているので、`ifMissed:"fireOnExit"` のフォールバックにも入れない
（`FindExitCandidate` の結果ごと捨てられる）。つまり**フォールバックにも入れずに消えている**。

記録に残っている実害「3 周目 B の離脱演出 8 秒が C の滞在を丸ごと覆い、C の進入演出 3 カットが
一度も出なかった」は 2026-07-27 に「待つ」ようにして半分だけ直り、残り半分がここだった。

**卓は一度も警告していなかった**。リボンの警告（`takeIssue` / `takeTimingRisk`）は
「その演出単体」しか見ておらず、前の区間との関係を見る箇所が 1 つも無い。
離脱時の演出は次の区間ブロックに重ならないので絵からも読めない。

**連続で置くと、2 本目の遷移が必ず死ぬ**

演出が終わると必ず復帰の暗転（`InsertReturn`・インスペクタ既定 70/100ms）が走り、
次の演出は最短で次フレームに始まってその暗転へ割り込む。割り込みは遷移指定を捨てるので、
**2 本目以降が作者の選んだ遷移で始まることが構造的にできない**。
加えて卓は演出を足すとき常に「進入 +0s」に置くので、描かれた位置と実際の発火時刻も食い違っていた。

**相乗りは Down 相の 70ms しか効かない**

相乗り 3 経路（`InsertExitRedirect` / `TakeHoldBegin` / `InsertBegin`）はどれもカット側の
遷移指定を捨てる。効くのは Down 相だけで、Up 相の 100ms に来た演出は今も二重暗転していた
（前回のコミットで塞いだのは Down 側だけ）。「瞬時」は走行タイミングで 3 通りの見え方になっていた。

黒の瞬間の予約は単一スロットで、**上書きされたカットは一度も画面に出ないまま報告もされない**。

## 2. 決めたこと

設計案を 3 つ並列で詰めさせ、2 案が独立に同じ結論へ収束した部分をそのまま採った。

### 待ちの寿命 `wait: "segment" | "chain"`

ユーザーの「前の演出が終わった後に発動する設定」に対応する。`chain` は
「自分を塞いでいた演出が終わるまで、区間を出ても待つ」。

持ち越しの条件を**因果**に絞ったのが芯：離脱の瞬間に実際に画面が塞がっていて、かつ
開始条件は既に満たしていた演出だけ。「歩くのが速くて時刻に届かなかった」ものは持ち越さない
（それは `ifMissed` の担当）。これで「著作者の知らないうちに遅れて誤爆する」v2 の失敗を繰り返さない。

上限 2 本 / 60 秒、いま居る区間の演出に劣後、捨てる出口はすべて報告。

### 連続の渡し `chainNext`

次に出せるものが控えていれば画面を返さない。安全網（次フレームで始まらなければ返す）つき。

### 継ぎ目の遷移は「いま画面を取る側」が所有する

相乗りを `HandoffDip` 1 本へ集約し、Down / Up の両相で「暗さを保ったまま割り込む側の指定へ
乗り換える」に統一した。詳細は rules 参照。

## 3. やらなかったこと

- **golden トレースの追加**。新機能は両側のユニットテストで固定した（既存の drop 系と同じ流儀）。
  既存 golden（`scenario_walk` / `scenario_line`）が**1 バイトも変わらない**ことが
  「既定 `segment` の挙動は変えていない」の機械的な証拠になる。
- **離脱時の演出そのものの救済**。`at:"exit"` に `wait` は出さない。
  離脱時の演出を別の区間で出すと文脈が最も壊れるため。
- **リボンで離脱時の演出を次の区間へはみ出して描く**。絵の変更より、著作の段階で言葉で言う方を採った。

## 4. 残っている弱点（正直に）

- 持ち越して出た演出は、体験者が居ない場所のカメラを映しうる。1 区間ぶんに絞り、劣後させ、
  必ず報告するようにしたが、**体験として許容できるかは実機で見るまで分からない**。
  許容できなければ `wait` を `segment` に戻せば元の挙動になる。
- 前区間の離脱時演出が食う危険の警告は、具体秒を出す部分が実測滞在に依存する。
  実測が 1 件も無い初回の現場では「短いと出ません」という一般論しか言えない。
- 相乗り（`HandoffDip`）は**既存テストのカバレッジがゼロだった領域**。
  配線テスト（`TakeWiringTests` / `SwitchWiringTests`）は dip を 0 にして駆動しているので、
  この分岐を通るテストがまだ無い。「暗転が 1 回に見える」「明るさが飛ばない」の一次証拠は実機でしか取れない。
- `dipDownSec` / `dipUpSec` は SerializeField のままなので、既存シーン YAML の焼き付き値が
  コード既定を上書きする（`minDwellSec` 等が非シリアライズ化された理由と同じ罠がここには残っている）。
