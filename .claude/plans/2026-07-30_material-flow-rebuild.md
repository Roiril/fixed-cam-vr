# 素材の作成フロー・マスクと合成・プロンプト管理の立て直し

## 概要

ユーザー依頼（2026-07-30）:「**素材の作成フロー、マスクや合成、プロンプト管理などについて、設計から細かく考えて**」。

対象は **廻リ視（fixedcam）の Web オペレータ卓 `tools/web-compositor/`**、および
マスクの座標系を確定させるための Unity 側の**検査テスト 1 本**だけ。実機シェーダは変えない。

独立した design-critic 2 体（来歴とプロンプト管理 / マスクと合成）+ code-auditor 1 体を並列で走らせ、
シュビー本体が実データと実コードで裏取りした。**3 体が独立に同じ 3 点へ収束**した。
マスクの座標系だけは 1 体しか挙げなかったので、シェーダと既存 PNG 8 件を自分で照合して確定させた。

## 現状の実測（2026-07-30）

### 台帳が現実と逆を言う

| 見ているもの | 値 |
|---|---|
| `captures/` の `gen_*`（生成物の実ファイル） | **5 枚** |
| `atelier.json` の生成レコード | **2 件**（うち 1 件は出力がまだ無い送信待ち） |
| 本番の演出に載っている生成物 | **2 枚**（`gen_handB_01.png`→`cue_hand_B` / `gen_monsterA_01.png`→`cue_ningyo_A`） |
| そのうち台帳に記録があるもの | **0 枚** |
| 台帳が持つ唯一の完成品 `gen_camC_doll_*.png` を参照する cue | **0 件** |
| 工房のカメラ A / B のバッジ | **「素材なし」**（実際は両方とも本番素材を持っている） |
| 工房のカメラ C のバッジ | **「素材 2（採用 0）」**（実際の採用は他カメラで 2） |
| レコードの `verdict` | 2 件とも `unrated`（採用ボタンは一度も押されていない） |

### 卓の絵と実機の絵が違う

| 層 | 実機（`ScreenComposite.shader`） | 卓（`composite-view.js` / `pipeline.js`） |
|---|---|---|
| live | `ContainUv(uv, _LiveScale)` — 4:3→16:9 で `(0.75, 1)` | 同じ |
| overlay | `ContainUv(uv, _OverlayScale)` | 同じ |
| CG 人形 | `ContainUv(uv, _CgScale)`（2026-07-27 に同型のバグを修正済み） | 描かない（意図的） |
| **マスク** | **生 uv**（`_MaskScale` はプロパティに存在しない）＝枠空間 16:9 | 工房は 640×480 枠でプレビュー＝**ずれが原理的に見えない** |
| 色統計 | `overlay * _OverlayGain + _OverlayOffset`（cue に焼かれた 6 float） | 毎フレーム解いて掛ける（既定 ON） |
| ラプラシアン | **無い** | 既定 ON（`common.js:45`） |

マスク生成器は 3 つあり、出力座標系が割れている:

| 生成器 | 出力 | 座標系 |
|---|---|---|
| 素材工房の自動差分（`atelier.js:25` `MASK_W=640, MASK_H=480`） | 640×480 | **ソース映像（4:3）** |
| cue エディタのスライダ分割（`cue-editor.js:18` `MW=640, MH=360`） | 640×360 | 枠空間（16:9）✓ |
| `make-diff-mask.py`（CLI・`:65-66`） | 種フレーム実寸 | **ソース映像（4:3）** |

現地 `masks/` の 8 件は、testassets 用の 6 件が 16:9、**実素材を指す 2 件が 4:3**。
つまり**いま本番で使う唯一の 2 つの素材が、実機で水平 1.33 倍に伸び、枠幅の最大 12.5% 外側へずれて合成されている**。

### 工房から外へ出る橋（`atelier.js:635-663`・26 行）で 3 つ落ちている

「工房が行き止まりにならないための唯一の橋」（計画 2026-07-26 §3）に、独立した欠落が 3 つ同居している。

1. 生成レコードへ書き戻さない（`st.pickGenId` を持っているのに送らない。サーバの受け入れキー一覧 `capture-server.py:1811-1813` にも `cueId` が無く**構造として持てない**）
2. 色統計を焼かない（`matchGain`/`matchOffset` が無い。焼くのは `cue-editor.js:250` だけ）
3. マスクを 4:3 で焼く（上記）

### プロンプト管理が 2 系統に割れている

- `prompts.json` に **7 件**（貞子系・700〜1031 字の作り込まれたもの）。**UI は 2026-07-28 に撤去済みで、作者からは見えない**。サーバ API だけ生きている（`capture-server.py:1001, 1313, 1339`）
- `atelier.json` のレシピ **3 件**（すべて `kind:"video"`・スロット付き）。唯一の実生成はレシピを使わず、本文は作者が書いた一行

レシピが担っていた不変部（locked-off / 部屋を変えるな / negative 列）は、
**2026-07-29 に `/generate` がサーバ側で自動付与するようになった**（`atelier.js:349` が UI に明記）。
骨格が自動化された時点で、テンプレに残るのは作者が書く一行だけになっている。

## 思想 — 3 つの原則

素材工房の芯 —「**素材の可否は live に載せた見えでしか決まらない**から、試写を出したまま作る」（計画 2026-07-26 §1）— は正しい。変えない。壊れているのはその外側の 3 点で、いずれも同じ形をしている。**道具が事実でないことを言っている**。

### 原則 1: 卓が出す絵は、実機と同じ式で作る。違うものを出すときは画面にそう書く

マスクの座標系・色統計の焼き漏れ・ラプラシアンは、すべて「卓で OK と判断したものが実機で違う」に帰着する。
この道具の唯一の存在理由が判断の代行である以上、ここが崩れると道具ごと無価値になる。

### 原則 2: 状態を二重に持たない。導出できるものは導出する

「採用したか」は show.json が既に持っている（`cues[].sourceUrl` がそのファイルを指しているか）。
台帳に別の札（`verdict` / `usedCount` / `keptCount`）を置いたから、押し忘れた瞬間に食い違った。
**押されないボタンは、無いのと同じではなく、嘘をつく分だけ有害**。

### 原則 3: 素材の身元はファイルパスで足りる。新しい id を作らない

生成レコードの `outputUrl` と cue の `sourceUrl` が同じファイルを指していれば、それは同じものである。
これで採用状態も、cue からプロンプトへの逆引きも、フィールドを 1 つも足さずに引ける。
`cueId` を持たせる案は、cue を消したときに孤児が出る（そして cue を消す面は現状どこにも無い）。

## 決めたこと

| 判断 | 理由 |
|---|---|
| **マスクの正は枠空間 16:9**。実機シェーダは変えず、生成器 2 つを寄せる | 合成 `lerp(live, overlay, mask)` は枠空間で評価される。マスクは live と overlay の**混合率**であって素材の一部ではない。素材が 16:9 になる日、素材座標系のマスクは live の隠したい場所を指せなくなる。加えて Quest 実機で検証する手段が今無い以上、差異が出た場所（生成器）を直すべきで、出ていない場所（シェーダ）を動かすのは修正範囲の膨張（アドバイザー諮問の結論） |
| **枠アスペクトは卓と実機の両方で機械的に固定**する | 卓は Quad の localScale を知らないので定数を持つしかない。片側だけ変わって沈黙するのを防ぐため、Unity 側に「スクリーン枠が 16:9 であること」を検査する EditMode テストを対で置く（このプロジェクトが色温度・投影・尺で繰り返し使っている流儀） |
| **採用状態は保存しない。show.json から導出する** | 原則 2。`verdict` / `usedCount` / `keptCount` を撤去 |
| **生成レコードと cue は `outputUrl` == `sourceUrl` で突合** | 原則 3 |
| **レシピはスロット機構を捨て「保存したプロンプト」へ降格**し、`prompts.json` の 7 件と同じ棚に統合 | 不変部は自動付与になった。数十枚を試す作業に穴埋めのコストは合わない。ただし 7 件の本文は**消す前に移す**（ここにしか無い craft） |
| **ラプラシアンは撤去せず、既定 OFF + 「実機には出ません」表示** | ユーザーが明示的に要望して復活させた機能（memory `web_compositor`）。設計の純度のために消さない。嘘だけ消す。**色統計は焼けるので既定 ON のまま** |
| **色統計は工房でも焼き、動画は尺全体から統計を取る** | 保存時の 1 フレームだけだと暗→明の素材で破綻する |
| **`atelier-index.md` の自動生成は残す** | 1 体は「JSON の冗長な複製」として撤去を推したが、これは git 追跡されていて次セッションの引き継ぎに実際に効いている。**間違った内容を固定していたのが問題**であって、台帳が正しくなれば index も正しくなる |

## 段 0 — 卓が嘘をつくのを止める（最優先）

「本番で嘘をつくもの」を先に潰す（2026-07-28 計画が採った実施順の判断基準を踏襲）。

### 0-1. マスクを枠空間 16:9 へ寄せる

- `atelier.js` の `MASK_W/MASK_H` を 640×360 にし、差分の累積（ソース座標 192×144）を
  **contain-fit と同じ配置**で描く（4:3 ソースなら幅 480px 中央・左右 80px はマスク 0）
- `make-diff-mask.py` に同じ変換を入れる（`--frame-aspect` 既定 16/9）
- **工房のプレビュー枠を 16:9 にする**。これをやらないと直しても検証できない（`atelier.js:303`）
- 枠アスペクトは `common.js` に `FRAME_ASPECT = 16 / 9` を 1 箇所だけ置く
- Unity 側に `MjpegScreenStage.prefab` の枠が 16:9 であることを検査する EditMode テストを追加
- **既存の 4:3 マスク 2 件（`cue_hand_B` / `cue_ningyo_A`）は再生成が要る**。
  これは挙動の温存ではなくバグ修正で、再生成後に 16:9 プレビューで位置を目視確認する

### 0-2. 工房の cue に色統計を焼く

`atelier.js:651-655` の cue オブジェクトへ `bakeColorMatch()` 相当を入れ、`cue-editor.js:241-250` と同じ形にする。
同じ `cues[]` に別の形の物が混ざっている状態（監査 12）を解消する。

### 0-3. ラプラシアンを既定 OFF にし、ON のとき明示する

`common.js:45` の `laplacian: true` → `false`。境界ブレンドバーの当該トグルに
「実機には出ません（卓プレビュー専用）」を出す。色統計トグルには出さない（焼かれるので実機に届く）。

## 段 1 — 台帳を現実に合わせる

### 1-1. 採用を導出値にする

- `verdict` の 3 択 UI（`atelier.js:825-828, 848-850`）と `usedCount`/`keptCount`（`capture-server.py:514-515, 535`）を撤去
- カメラ列のバッジを「素材 N（**本番で使用 M**）」に。M は `cues[].sourceUrl` との突合で毎回数え直す
- `status` の 3 値（draft/running/done）は `outputUrl` の有無に畳む

### 1-2. レコードの無い生成物を一級市民にする

過去分（`gen_handB_01` 等 4 枚）はレコードが無く、これからも「先に作ってから記録する」順序は起き続ける。
棚は既に `captures/` の未記録ファイルを出しているので、そこに

- **「この cue が使っています」バッジ**（`sourceUrl` 突合）
- **「プロンプトを書き足す」導線**（後からレコードを起こす）

を足す。カメラで絞る（現状は 4 列すべてに同じ 24 件が出ていて、「素材は構図に属する」原則が棚の下半分で破れている）。

### 1-3. cue からプロンプトへ戻る線

リボンのカット詳細と工房の試写に、`sourceUrl` 一致で引いたプロンプト全文を出す。
いま「あの絵の作り方」は失われていて、同じ系統の 2 枚目を作れない。

## 段 2 — プロンプト管理を 1 つにする

1. **`prompts.json` の 7 件を `atelier.json` の「保存したプロンプト」へ移す**（移行スクリプト・1 回限り）
2. `/prompts` `/prompts/delete` `prompts.json` を撤去（**移した後**）
3. レシピの `slots` / `bind` / `{{…}}` 展開を撤去し、「保存したプロンプト」へ降格。
   `kind`（画像/動画）は残す（どのツールを開くかが変わるため）
4. 送信待ちレコードの事前生成をやめる。📋 コピーは**コピーするだけ**にし、
   戻ってきたファイルを棚へ落とした時に初めてプロンプト付きで記録する（状態が 1 つ減る）
5. 動画の生成条件の横に **1 行だけ**知見を出す:「Veo / Flow は horror・ghost・blood 等で弾かれる。
   Kling とローカル Wan は寛容」。**作風のコツ（静止→異常な一拍 / 瞬間移動）は卓に出さない** —
   必ず古くなるものを UI に焼くと嘘になる。memory に置いたままにする

## 段 4 — 工房のレイアウト

カメラが 4 台（D 追加）になって設計の前提が崩れている。実測（1280×720）:

- `atl-cams` は `403px 403px 403px` の 3 列 grid。**カメラ D は 2 行目に単独で落ちる**（y=1801 = 2 画面半下）
- 列の高さが素材の数で変わる（C だけ 1505px、他は 1193px）。**構図を並べて比べるという芯が崩れる**
- 1 列 1193px のうち試写は 335px。いちばん長く見るものが 4 分の 1

対処:

- **演出専用カメラ（`role:"fx"`）は既定で畳む**。D はゾーンを持たず、種フレームも 0 件（配信していない）。
  他と同じ重さで出す理由が無い（ゾーン塗りパレットから外しているのと同じ論理）
- 列の高さを揃える（棚を固定高 + 内部スクロール）
- 試写を大きくし、種・指示・棚を畳める形に

**この段だけ 2026-07-28 の UX 立て直し計画（段 1b / 段 3）と領域が重なる。**
トークン（`tokens.css`）が入る前に工房だけ独自の値を足さない。先に UX 側の段 3 が入るならそれに従う。

## やらないと決めたこと

- **Quest でのラプラシアン実装** — 企画書は「フェザリング**や**多重帯域」と選択で書いている。
  負荷に加え、一致を検証する手段が無い（「卓で CG 人形を実描画しない」と同じ理由）
- **実機シェーダへの `_MaskScale` 追加** — アドバイザー諮問で退けた。上表の理由
- **ラプラシアンと境界ブレンドバーの撤去** — ユーザー要望で復活した機能。嘘だけ消す
- **生成レコードに `cueId` を持たせる** — 原則 3。cue 削除で孤児が出る
- **`atelier-index.md` の廃止** — 台帳が正しくなれば index も正しくなる
- **AI 生成の作風の知見を卓へ持ち込む** — 陳腐化して嘘になる。ツール選択に効く 1 行だけ出す
- **レシピのスロットを「もっと良い形」に作り直す** — 用済みになったものを設計し直さない
