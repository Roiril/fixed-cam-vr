## 対象のフロー

1. ライブ映像から種フレームを 1 枚切り抜く（卓の 📷）
2. 種フレームを Codex に渡して「同じ構図に異物を足した」静止画を作る（`POST /generate`）
3. その静止画を外部ツール（Kling / ローカル Wan）で動画にする（i2v）
4. できた素材を cue にして live へ合成する ← **どこを差し替えるか＝マスクが要る**

## 実測した現状（2026-07-31）

マスクを作る道具が 3 つあり、決定論性が割れています。

| 道具 | 同じ入力から同じ出力が出るか | 何を見ているか |
|---|---|---|
| 工房の差分（`atelier.js:601` `updateMotion`） | **出ない** | プレビュー再生中の各フレームと種フレームの差を累積 |
| `make-diff-mask.py` | 出る | 種 1 枚と生成 1 枚の差 |
| cue エディタのスライダ（`cue-editor.js:91` `drawMask`） | 出る | 作者が選んだ上下左右と % |

### 工房の差分が揺れる理由（3 つとも別の原因）

1. **累積 `acc` が単調増加**（`atelier.js:614` の `if (acc[i]) continue`）。一度立った画素は落ちない
   → **何秒試写を見てから 💾 を押したかでマスクの広さが変わる**
2. **走査がプレビューの再生に乗っている**。タブが裏に回る・フレームが落ちると穴が空く
3. **閾値 `st.thresh`（`atelier.js:294` 既定 0.12）が cue に保存されない** → 後から同じ値で焼き直せない

### `make-diff-mask.py` の限界

決定的だが **静止画 1 枚しか見ない**ので i2v の動画に使えない。焼いたときの
`--threshold` / `--feather` / `--dilate` / `--roi` はどこにも残らない。

### feather も残っていない

`cue-editor.js:191` は焼き出しの瞬間に `blendCfg.feather`（卓のグローバル設定・既定 0.3）を読むだけ。
**その cue をどのぼかし量で焼いたか**は cue にも台帳にも無い。

## 提案：マスクは測るものではなく決めるもの。cue に「作り方」を持たせる

`cues[]` が持つのは `maskUrl`（PNG の URL）だけです。ここへレシピを足し、**PNG は毎回そこから焼く**。
決定論はレシピが保存されていることから定義として従います。

```jsonc
"mask": {
  "shapes": [ { "kind": "poly", "pts": [[0.62,0.31],[0.71,0.30], ...] } ],  // 素材座標 0..1
  "diff":   { "seed": "captures/…jpg", "threshold": 30, "frames": 24,
              "dilate": 3, "minArea": 400, "op": "intersect" },             // 任意
  "feather": 6
}
```

### 図形は「素材座標」で持つ

**マスクの白は素材が存在する矩形の中でしか意味を持たない**（外に白を置くと `ContainUv` が
overlay を 0 にするので live が隠れて黒が出るだけ）。枠空間で持つと素材を差し替えたときに意味が壊れます。
焼き出しのときだけ `containRect` で枠空間 16:9 へ移す（変換は `common.js` に既にある）。

これで初期形の供給源が 3 本とも同じ座標系に乗ります。

| 供給源 | 何から出るか | 使いどころ |
|---|---|---|
| 作者が引く | 試写を見ながら多角形を置く | 常に最終権限 |
| 差分 | 種と素材の走査結果を輪郭ポリゴンへ落とす | 生成物が背景を保っているとき（実測: 差 2.5%・マスク 1.5% → [[codex_image_pipeline]]） |
| 幾何 | `cameras[].calib` で床座標を投影し `actor-proxy.js` の人型シルエットを引く | 「左奥に立つ」が演出として決まっているとき |

3 本目が効くのは較正・部屋プロキシ・人型投影が既にあるからです（→ [[cg_compositing]]）。
CG 人形の `placement` と同じ座標系なので「人形を置く」と「マスクを引く」が同じ操作になります。

### 差分を使うなら走査を保存時の 1 回に固定する

- 再生の進行ではなく、trim 区間を**等間隔で N フレーム（例 24）シークして走査**する。
  `video.currentTime = t` は決定的
- 種フレームを 1 枚でなく連続 K 枚撮り、画素ごとの中央値とばらつきから背景モデルを作る。
  閾値を「ばらつきの何倍」にすれば蛍光灯のちらつきと JPEG ノイズを自動で外せる（閾値スライダの恣意性が減る）
- 形態処理の順を固定する（閾値 → 穴埋め → 最大領域 → 膨張 → 枠空間へ → ぼかし）
- 結果は輪郭ポリゴンへ落として `shapes` に入れる。**ラスタのまま保存すると作者が直せない**
- 焼く式は今 Web の canvas（`atelier.js:583`）と Python（`make-diff-mask.py:114`）の 2 本ある。
  **1 本に寄せる** — このプロジェクトが繰り返し踏んでいる「片方だけ直して沈黙して食い違う」型

## 素材の動きの量で、マスクの種類が変わる

**ここが設計の分かれ目です。** 実機の `_MaskTex` は静止画 1 枚なので、動く素材のマスクは
「動いた範囲すべて」を覆う必要があります。人影が居ない時間もその範囲は素材の背景に置き換わります。

| 素材の動き | 選ぶもの |
|---|---|
| 立って揺れるだけ | 図形マスク。輪郭に沿わせず 1 割ほど広く取り、ぼかしで吸収する |
| 手が伸びる程度 | 図形マスク。動く先まで含めた形で引く |
| 横切る・近づく | 全面差し替え + 短い尺 + 継ぎ目に乱れ（`steps[].glitch`） |

工房の `STARTER_RECIPES`（`atelier.js:40`）が「静止している人影」を最初の 1 本に置いているのは、
この理由で正しい判断です。

## やらないと判断したこと

- **時間変化するマスク**（マスク動画）— 実機のシェーダと cue と卓が同時に増える。
  素材動画のアルファで代用する道はあるが、Android の H.264 にアルファが無く VP9 のアルファは不安定
- **実機シェーダの変更** — 2026-07-30 の計画がアドバイザー諮問で退けた判断を維持する
  （差異が出た場所＝生成器を直す。出ていない場所＝シェーダを動かさない）
- **マスクの輪郭精度への投資** — スクリーンは 2m 先の枠、映像は 640×480 q40、暗いグレーディングと
  グレインが乗る。継ぎ目は乱れ（企画書 2.3 の機構）で隠す方が安い

## 段階（1 だけで決定論は成立する）

1. cue に `mask` レシピを持たせ、差分走査を保存時の 1 回・固定 N フレームに変える（既存 `maskUrl` は残す）
2. 図形マスクを引く面を作る。差分の結果を輪郭ポリゴンとして初期投入する
3. 較正からの人型シルエットを初期形の 2 本目の供給源にする
4. 種フレームを K 枚にして背景モデルを作る

2 以降は「引き直せる」ための投資です。

## 未決の判断点（着手前に決める）

1. **段 1 だけで足りるか、2 まで要るか**。ユーザーは「決定論的に決めたい」と言っただけで、
   「引き直したい」とは言っていない。段 1 は既存 UI のまま中身を直すので安く、段 2 は新しい面が要る
2. **既存 cue（`cue_hand_B` / `cue_ningyo_A`）をレシピ化するか**。この 2 件は 2026-07-30 に
   4:3 → 16:9 の座標変換をした PNG で、元の閾値も種フレームも記録が無い。
   遡って作り直すか、PNG のまま「レシピ無し」として残すか
3. **動きの量の分かれ目を誰が判断するか**。上の表は作者の目視前提。卓が素材の動き量
   （走査した差分の面積比）を出して助言する手はあるが、判断を機械に寄せるほど嘘をつく余地が増える
4. **段 4 の背景モデルは種フレームの撮り方を変える**（1 枚 → K 枚）。現場の手順が増えるので、
   閾値の恣意性がどれだけ実害を出しているかを見てから
