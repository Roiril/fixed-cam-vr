# 実物の日本人形を CG 人形（ShowActor）にする

2026-08-03。買ってきた市松人形（高さ約 30cm・赤い着物・人毛風の髪・白い陶器質の顔と手）を
3D 化し、廻リ視の映像に合成して**腕を体験者のハンドトラッキングで動かす**までの計画。

> **2026-08-03 追記: 完了。ただし手段は変わった。**
> RealityScan は実際に試して精度が出ず、フォトグラメトリ路線は捨てた。
> 代わりに **正面写真のシルエットをそのまま前後へ押し出す**方式で作り、リグと動作確認まで終えた。
> 一式は [tools/doll-model/](../../tools/doll-model/README.md)、成果物は
> `Assets/Resources/ShowActors/Ichimatsu.prefab`。
> 以下の「結論」は当初の計画で、**撮影と再構成の節はもう実行しない**（記録として残す）。
> 実装側の制約（テクスチャ・ボーン規約・袖のウェイト）はそのまま生きている。

## 結論

**RealityScan で撮る → Blender で均して骨を 8 本手で置く → Generic FBX → Unity。**
加えて **`ShowActor.shader` にテクスチャを足す改修が要る**（これが無いと色が出ない）。

AI 画像生成（TRELLIS / Hunyuan3D / Meshy / Tripo）は使わない。理由は 2 つ。
実物が手元にあるのに学習分布から「市松人形らしいもの」を作ることになるのと、
**この PC の VRAM が 16GB** で TRELLIS.2（24GB 必須）が動かず、
Hunyuan3D 2.1 も形状 10GB は通るがテクスチャ生成 29GB が通らない（＝色が出ない）。

## この用途で効くもの / 効かないもの

合成先は **640×480 の MJPEG 映像**で、人形が占めるのは数百画素。
[cg_compositing](../memory/cg_compositing.md) が言うとおり、CG が映像より鮮明だと
「貼り付けた絵」に見えるので、RT はソース実寸まで落としてさらに鈍らせている。

したがって**メッシュの精度はほぼ効かない**。効くのは次の 3 つで、工数はここへ寄せる。

| 効く | なぜ |
|---|---|
| **色** | 数百画素では形より色が支配的。赤い着物が出るかどうかが同一性のほぼ全て |
| **シルエット** | 髪の輪郭・袖の広がり・全体の比率 |
| **腕の動き** | 体験者の手に追従する唯一の要素。ここが演出の主役 |

逆に、顔の造形・指の形・布の皺は**観測できない**。時間を掛けない。

## 実装側の確定事項（コードを読んで確認済み）

### 1. いまはテクスチャが出ない — 改修が要る

[`ShowActor.shader`](../../Assets/Art/Shaders/Cg/ShowActor.shader) は `_BaseColor` の単色に
wrap lighting と rim を乗せるだけで、**UV すら読んでいない**（`Attributes` に texcoord が無い）。
さらに [`ShowActorPrefabBuilder`](../../Assets/Scripts/Streaming/Editor/ShowActorPrefabBuilder.cs) の
`r.sharedMaterials = mats` が全メッシュのマテリアルを共有の 1 枚へ潰す。

→ **スキャンして色を取っても、現状のまま入れると灰色のマネキンとして映る。**

改修は小さく、設計思想（シーンのライトを一切参照しない）を崩さない:

- シェーダに `_BaseMap` と UV を足し、`_BaseColor` を乗算に変える（既定 白 なら既存の人形は不変）
- ビルダーは**人形ごとにマテリアルを作る**（いまは共有 1 枚なので、テクスチャを持たせると
  他の人形にも同じ絵が乗る）。元モデルの `_BaseMap` / `_MainTex` を引き継ぐ

⚠ この改修を先にやらないと、撮影・スキャンの成果が画に出ない。**順序として先。**

### 2. 骨は 8 本でよい。ただし置き方が決まっている

[`ShowActorRig.Prepare`](../../Assets/Scripts/Streaming/Cg/ShowActorRig.cs) は Humanoid を要求しない。
Generic なら**名前で手を見つけて親を 2 つ遡る**。したがって置くのは:

| ボーン | 名前 | 役割 |
|---|---|---|
| ルート | 何でもよい | 胴。ここに**着物の身頃と袖**を固定する（後述） |
| 頭 | `Head` | `HeadWorldPosition` の基準 + 身長計測の最高点 |
| 左肩・左肘・左手首 | 末端が `LeftHand` | 親 2 つが自動で肘・肩になる |
| 右肩・右肘・右手首 | 末端が `RightHand` | 同上 |

名前の規約（`FindHand` / `FindBone` の実装）:

- 手 = `hand` を含み、`left`/`right` のどちらかを含み、
  `index` `thumb` `middle` `ring` `pinky` `end` を**含まない**
- 頭 = `head` を含み `top` `end` を含まない
- 肩・肘の名前は見ない（親を辿るだけ）

⚠ **捻りボーンを入れてはいけない。** 手首の親の親を肘とみなすので、
`Hand → ForeArmTwist → ForeArm` のような階層だと肩の位置を取り違える。
オートリグ（AccuRig の 19 関節など）を使うならこの点を書き出し後に必ず確認する。
手で置けば起きない。

⚠ **頭ボーンを置かないと身長が壊れる。** `MeasureHeight` はボーンの最高点を使うので、
頭が無いと腕の高さが身長になる。実寸そのものは気にしなくてよい
（show.json の `heightM` との比で自動縮尺される）。

### 3. 袖は「胴」に固定する — 肩ではない

> **⚠ 2026-08-03 に改訂。この節の結論（袖を Root に 1.0）は採用していない。**
> 実装して動かしたところ、袖が完全に不動なのは実物と違って見えた（ユーザー指摘）。
> 正しくは **付け根は腕に持ち上げられ、下端は垂れたまま**。いまは
> 「腕の高さからの落差」で腕→Root へ滑らかに配分している（`SLEEVE_FALL = 0.105m`）。
> 下の「肩に固定すると袖が丸ごと回る」という指摘自体は正しく、**剛体で付けてはいけない**。


調査は「袖を肩ボーンに 1.0 で固定」と勧めたが、**この実装では誤り**。
[`DriveArm`](../../Assets/Scripts/Streaming/Cg/ShowActorRig.cs) は
`AlignBone(upper, ...)` で**上腕（肩）ボーンそのものを回す**ので、
袖を肩に付けると腕を動かすたび袖が丸ごと回る。

着物の袖は肩から吊り下がっていて、上腕の回転には追従せず垂れたままなのが実物の挙動。

→ **袖と身頃はルート（胴）に 1.0。腕ボーンに乗せるのは、袖口から出る手首と手だけ。**
これで腕を上げると袖から手が出て、袖自体は垂れたまま。実物と同じになる。

## 手順

### 段 0 — シェーダ改修（先にやる・1 時間）

上記 1。撮影の前に済ませる。既存の人形（Remy）が変わらないことをプレビューで確認する
（`Tools/FixedCamVr/Diagnostics/Preview Show Actor`）。

### 段 1 — 撮り直し（30〜45 分）

**いまある 3 枚は使えない。** 1 枚目と 2 枚目で腕の広げ方が違う（＝同一形状として解けない）、
3 枚目は髪しか写っていない、背景が白机で特徴点が立たない。

- **人形に触れない。** 撮影開始から終了まで腕を動かさない。カメラだけが動く
- **背景に模様のあるものを敷く。** 新聞紙・チラシ・木目。白い机は最悪
- **テカリを消す。** 顔と手の白い陶器面はフォトグラメトリが最も苦手とする対象
  （対応点が立たず、鏡面ハイライトは視点ごとに動く）。
  レンズと光源の両方に偏光板を付けて直交させると、スプレー無しでハイライトだけ消える。
  ⚠ 昇華スプレー（AESUB 等）は着物に掛かる危険があるので使わない
- **影を消す。** 曇りの日の窓際か、部屋の照明を複数。強い 1 灯と直射日光は避ける
- **3 段 × 各 24〜36 枚 = 70〜110 枚。** 腰・目線・見下ろしの高さでそれぞれ 1 周。
  隣の写真と 7 割以上重なるよう 10〜15 度ずつ
- **ピントと露出を固定。** Pixel は画面長押しで AE/AF ロック
- 立たせるなら支えが穴になる。支えの位置を変えて 2 周撮ると埋まる

### 段 2 — 再構成（30 分・待ち時間含む）

**RealityScan 2.x デスクトップ版**（無料。過去 12 か月の売上 100 万 USD 未満の個人が対象）。
GPU は RTX 4090 Laptop なので余裕。代替は Meshroom 2025.1.0（MPL2・CUDA 12）。

**髪は取れない。** 人毛風の細い房は画素以下の太さと半透明を同時に持つ。
フォトグラメトリは対応点が立たず、3D Gaussian Splatting でも破片が散る（HairGS 論文）。
頭は「髪を含まない地肌の形」として出るか、溶けた塊になる。どちらでもよい。**髪は段 3 で作る。**

### 段 3 — Blender（1〜2 時間）

1. **Voxel Remesh**（ボクセル 2〜4mm）。四角リトポは**やらない**。
   要るのは四角化ではなく多様体化で、Blender の自動ウェイト（bone heat）は
   穴・重複頂点・自己交差があると行列が解けずに失敗する（開発トラッカー #51250 / #127345）。
   Voxel Remesh はこれを原因ごと消す。曲げ角が小さく数百画素なので、
   エッジループが無いことによる肘の潰れは観測できない
2. **Decimate**（Collapse・3,000〜8,000 三角）
3. **髪を作る**。頭の上に塊としてモデリングするか、ヘアカードを数枚。
   シルエットだけ合っていればよい
4. **ボーン 8 本**を上記の名前で置く
5. **自動ウェイト** → 袖と身頃をルートへ 1.0 で塗り直す（上記 3）
6. **FBX 書き出し**（実寸 0.3m。cm で書くと Unity で 100 倍になる）

### 段 4 — Unity（30 分）

- Rig = **Generic**（Humanoid は必須ボーン 15 本と T ポーズを要求するので使わない）
- `Tools/FixedCamVr/Setup/Build Show Actor Prefab` でプレハブ化
- `Tools/FixedCamVr/Diagnostics/Preview Show Actor` で 4 ポーズ × 2 角度を確認
- `Tools/FixedCamVr/Diagnostics/Preview Show Composite` で実写プレートへの合成を確認
- show.json の `actors[]` に登録（`heightM` は演出上の見せたい身長でよい）

## 未確定・要確認

- **RealityScan Mobile の書き出し形式と上限**は一次ソースで取れなかった（公式 FAQ が取得不能）。
  デスクトップ版を使う前提なら影響なし
- **偏光でどこまでテカリが消えるか**は実測していない。効かなければ、撮影段数を増やして
  白い面を多方向から押さえる
- **袖のウェイトを胴へ固定した見た目**は実機で見るまで分からない。
  腕を大きく上げたとき、袖口から腕が抜けて見える可能性がある
