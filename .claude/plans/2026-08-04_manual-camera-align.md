# カメラ位置合わせを「解く」から「合わせる」へ

2026-08-04。ユーザー依頼:

> カメラの位置合わせUIを根本から作り直してほしい。具体的には、カメラの位置合わせがある理由が
> 人形をうまく合成するためだけなので、人形を合成しながら、コンピューターはむりに解かなくていい。
> カメラ画像にワイヤーフレームの壁と床を重ねて表示しておいて、人間が手動で壁と床を、全体を
> 動かしたり頂点を調整したりして位置合わせする感じにしてほしい。CG人形とライトと影も用意して
> おいて、常に合成結果を見ながら、人形とかも動かしながら位置合わせ出来るようにして。

## なぜ作り直すのが正しいか（実測）

- **show.json の 4 台すべて `calib` 無し・`pose` 有り。** 2026-07-29 に較正 UI を全面立て直した
  あと 6 日間、**1 台も解かれていない**。現場で生きているのは人が置いた概算の方
- 4 台とも `hfovDeg: 77.4` ＝ **人がレンズ諸元を打った値**。内部パラメータは既に手で決まっている
- 失敗は数値ではなく**入力**にあった。候補点が「既定値の壁（1m×1m の L）」「定数のタイル格子」
  から作られていて、**現場の床にその目印が実在しない**。実在しない点をどれだけ丁寧に打っても解は歪む

## 決めたこと

### 1. 動かすのはカメラ。部屋は共有資産

`layout.room` は **4 台のカメラ × 3 用途**（CG のオクルーダ／影の落ち先／較正参照）が共有する。
A に合うよう頂点をずらすと **B・C・D の合成が黙って狂い**、人形の course 座標がカメラごとに
食い違う。だから:

- 掴めるのは**カメラの外部 6 自由度**（x / y / z / yaw / pitch / roll）
- 部屋の頂点も編集できるが、それは「**共有の実測値を直している**」のであって
  「このカメラに合わせている」のではない。UI が常にどちらを触っているか出す
- 部屋を直したら**別のカメラでも見直す**導線を置く（1 台に合わせて他が壊れたことに気づけるように）

### 2. 画角と歪みはドラッグさせない

「画角を広げて近づける」≈「狭めて狭めて遠ざける」は画の上でほぼ同じ。
`calib.test.mjs` の実測で、画角を未知にすると位置が **27cm** ずれ、固定すれば **2cm**。
手ドラッグは曖昧さを消さず**残差の表示だけ**を消すので、掴めるようにすると solver より悪くなる。

→ `fxPx` / `k1` は**レンズ単位で一度だけ**決めて `lenses[]` に固定。現場で動かすのは外部 6 DOF だけ。
k1 は「実物の直線が画像で直線に見えるか」で目視一意に決まる（手動法がいちばん強いところ）。

### 3. 書き先は `cameras[].calib`

`pose` ではない。レンズ歪みは `ScreenComposite.shader` の `_CgLens` が **`calib` があるときだけ**
効く（`pose` だけでは k1=0）。**Unity 側は 1 行も変えない。**
手で合わせた印として `method: "manual"` を立て、`rmsPx` / `accuracyM` / `refs` は書かない
（自動で解いた時の指標を、手で置いた値に付けると嘘になる）。卓のバッジと本番前チェックは
「手で合わせた（誤差の数値は無し）」を別表示にする。

### 4. 卓に人形を出す。ただし陰影は作らない

⚠ `.claude/rules/streaming.md` の「卓は CG 人形を描かない」を**部分的に覆す**。
覆す範囲を厳密に決める:

| 卓が描くもの | 根拠 |
|---|---|
| 実メッシュ（GLB）＋**実アルベド**（焼いたテクスチャそのもの） | 同じ PNG を貼るだけ。二重実装ではない |
| 平面投影の影 + 接地楕円 | `ShadowProjectionLogic`（実質 5 行）を JS へ写し、golden で突き合わせる |
| 投影（3D→画素）・レンズ歪み | 既に `calib.js` にあり `CgProjectionTests` と数値一致済み |

**卓が描かないもの**: 法線マップ・鏡面・リム・色温度・環境光。ここを移植すると
「卓では正しく見えて実機が違う」を再生産する（この repo が 3 回踏んでいる形）。
スライダは残すが、それは **Unity のプレビューへの入力**であって卓の絵には効かない。

**合成の見た目の正は Unity**（`Preview Show Composite`）。卓の画面に常時その旨を出す。

### 5. 幾何は機械で固定する

卓に人形の幾何を持たせる以上、ズレを検知する口が要る:

- 固定 fixture のカメラ姿勢で、**期待画素座標を JS と C# の両テストにハードコード**
  （`calib.test.mjs` / `CgProjectionTests` の既存の型をそのまま使う）
- `ShowCompositePreview` に **CG レイヤ単体を alpha つきで吐くモード**を足し、
  node 側が同 fixture のブラウザ描画と**シルエットの IoU** を assert する
- **このオラクルが無いまま人形をブラウザへ入れない**

## 段階

- **Phase 1**: solver を外し、既存のワイヤー重畳の上で**カメラ 6 DOF の手動ドラッグ**を成立させる。
  人形は既存プロキシのまま。画角は `lenses[]` から固定。フレームは必ず静止させる
  （動いているライブの上で合わせると「合った気」になる）。
  → これだけで「現場で 1 台も較正できない」が解ける
- **Phase 2**: シルエット IoU オラクルを組む → GLB の実メッシュ + 実アルベド + 平面投影影を卓へ。
  人形を床にドラッグして置ける
- **Phase 3**: 卓から `Preview Show Composite` を 1 発で焼く導線。合成品質の判定を Unity に戻す

## 捨てるもの

`refineCalib`(LM) / `leaveOneOutError` / `pointQuality` / `lensTrustIssues` /
`floor-sketch.js` の候補点地図 / `calib-session.js` の点管理の大半 ≈ **1,800 行**。
**求解経路は残さない** — 「解いた値」と「置いた値」が混ざると必ず食い違う。

残すのは `projectPoint` / `unprojectToFloor` / 歪みの順逆 / `rescaleCalib` /
解像度・レンズ照合（表示と操作に必須・約 150 行）。

## 現場で要るもの（人にしか用意できない）

- **部屋を巻尺で実測する。** しないと Phase 1 の精度は原理的に頭打ち
  （いまの `layout.floor` は既定値の 1.8×1.8、`layout.wall` は既定の 1m L のまま）
- **既知の高さの実物**（1m の棒か、実測した壁の高さ）。距離と画角の縮退を切れる唯一の観測。
  Ichimatsu は全高 0.40m なので 2〜4m 先の基準にはならない

## 破綻条件

- 作業者が**卓の絵で「馴染んでいるか」を判定した**時点で終わり（過去 3 件と同型）。
  だから卓の人形は写実へ寄せず、判定は Unity に戻す導線を常に出す
- 部屋の頂点編集を「このカメラに合わせる」道具として使った時点で他カメラが壊れる
