# 人形の追従と腕 — まず測る、それから直す

2026-08-05。ユーザー依頼:

> 人形の、体験者の位置に追従するという機能と、人形が、体験者のハンドトラッキングに合わせて
> 腕の位置が違和感なく変わるのか、コードベースから調査したのち、設計から実装まで進めて。
> なるべく画像での動作検証もしてほしい

## 調査で分かったこと

両機能とも**実装はある**。`follow` は [`ShowCgLayer.PlaceActor`](../../Assets/Scripts/Streaming/Cg/ShowCgLayer.cs) が
毎フレーム体験者の course XZ へ人形を置き、腕は `OvrHandTrackingBridge` → `ShowBodyInput` →
[`ShowActorRig.Drive`](../../Assets/Scripts/Streaming/Cg/ShowActorRig.cs) →
[`ActorArmLogic`](../../Assets/Scripts/Streaming/Cg/ActorArmLogic.cs) + `TwoBoneIk` で動く。
show.json では **3 周目のカメラ 1・2 と帰りの A の 3 カット**が `cgMode:"follow"`。

疑わしい点が 4 つ見つかった。**どれも実機でしか出ない類ではなく、Editor で測れる。**

### 1. 時刻がちぐはぐ（位置は「いま」・向きと腕は 0.15 秒前）

`CurrentBody()` は映像遅延ぶん過去（`VideoLatencySec = 0.15`）を読む。これは正しい —
スクリーンに映っているのは 0.15 秒前の絵なので、「いま」の体験者を描くと歩行中ずっと先行する。

ところが `PlaceActor` の**立ち位置だけ `HeadCourseXZProvider()`＝「いま」**を読んでいる。
向き（`body.HeadYawDeg`）と腕（`Drive(CurrentBody(), …)`）は 0.15 秒前。
1m/s で歩けば 15cm、90°/s で振り向けば 13.5° ぶん、体と腕の時刻が食い違う。

### 2. 腕の写像が頭基準で、頭身比に依存する

`MapHandToActor` は「頭 → 手」ベクトルを**全高比**でスケールして人形の頭へ乗せる。
これは人形と体験者の体の比率が同じことを仮定している。プレハブの実測（回転込みで解いた値）:

| | 頭−肩 / 身長 | 腕長 / 身長 | 肩の半幅 / 身長 |
|---|---|---|---|
| Remy（人体比率） | **9.0%** | 29.0% | 10.4% |
| Ichimatsu（市松人形） | **2.8%** | 34.0% | 7.9% |

頭から肩までが **3.2 倍**違う。頭基準の写像は人形が変わると肩の位置がずれ、
「肩から手までの必要距離」が腕長を超えると `TwoBoneIk` がクランプして**腕が伸び切る**。

⚠ **いまの show.json は Remy（人体比率）を使っている**ので破綻は小さいはず。
市松人形へ差し替えた瞬間に出る。ただし「腕を下ろす」姿勢では Remy でも届かない疑いがある
（机上計算で 3〜19% 超過。幅が広すぎて**推測では決められない**）。

### 3. 体の向きが頭 yaw そのまま

`follow` の人形は `yaw = body.HeadYawDeg`。**首だけ振ると体ごと回る**。
人間は体が遅れて追従するので、そのままだと不自然に見えるはず。

### 4. 到達限界の扱い

`TwoBoneIk` は届かない目標を**まっすぐ伸ばしてクランプ**する（発散しない・NaN も出ない）。
安全側で正しいが、頻繁に起きていれば「腕が伸び切ったまま」＝違和感の正体になる。

## 方針: 直す前に測る

上の 2 と 4 は**机上計算では幅が広すぎて結論が出せない**（3% なら無視でよく、20% なら作り直し）。
[visual-verification.md](../rules/visual-verification.md) §1 の「大改修の前に必ず現状を疑う」に従い、
**現状のまま測る道具を先に作る**。

### 道具 A: 腕の動きを絵と数値で見る（Editor・Play 不要）

`Tools/FixedCamVr/Diagnostics/Preview Actor Motion`。既存の
[`ShowActorVizPreview`](../../Assets/Scripts/Streaming/Editor/ShowActorVizPreview.cs)（静止 4 ポーズ ×
2 角度）と**別の道具**にする — あちらは「人形が出るか」、こちらは「動きが自然か」で、見たいものが違う。

- 体験者の動き（腕を下ろす → 上げる → 横へ広げる → 前へ出す → 歩きながら振り向く）を
  時系列で合成し、毎フレーム `ShowActorRig.Drive` を回す
- **数値**（これが本体）: フレームごとに
  - 手首の目標に**届かなかった距離**（m と腕長比）
  - 腕の伸び率（肩〜手首 / 腕長。1.0 が伸び切り）
  - 肩から手首への方向が体の前後どちらか（肘が前に突き出ていないか）
- **絵**: 連番 PNG ＋ 1 枚のコンタクトシート（フル解像度も残す — 縮小した一覧で判定しない）

⚠ Edit Mode ではスキニングがキャッシュされて**全フレームが同じ絵になる**ので
`forceMatrixRecalculationPerRender = true` が要る（[[cg_actor_and_layer_traps]] §2）。

### 道具 B: 追従の時刻整合は純ロジックで測る

立ち位置・向き・腕が**同じ時刻の体験者**を指しているかは数値の話で、絵にする必要がない。
`ShowCgLayer` から純ロジックを切り出して EditMode テストで固定する。

## 測った結果（`Preview Actor Motion` の実測）

**旧実装（頭基準 + 全高比）は、腕を下ろした姿勢で目標が腕の届く範囲を 26% 超えていた。**
体験中いちばん長い姿勢がこれなので、ほぼ常時 IK がクランプして腕が棒のように伸び切っていた。
首を振ると 41% まで悪化した。

| 場面 | 旧（頭基準・全高比） | 新（肩基準・腕長比） |
|---|---|---|
| 腕を下ろす（意識的に伸ばし切り） | 到達率 **1.26** / 届かない 0.123 m | **1.05** / 0.025 m |
| 首を 90° 振る | **1.41** / 0.190 m | **1.05** / 0.026 m |
| 胸の前・横に広げる・両手を上げる | 0.86 / 0.95 / 0.75（届く） | 0.66 / 0.89 / 0.86（届く） |

⚠ 最初のシナリオでは「腕を下ろす」に**意識的に真下へ伸ばし切った値**（頭から 0.78m 下）を
与えていた。人は立っているとき肘を伸ばし切らないので、自然な立位（0.70m 下）を別に足した。
**新実装ではそこが 0.89 になり、肘が曲がる**（旧実装なら 1.09 でやはり伸び切っていた）。

## 直したもの

### 1. 肩を基準に、腕の長さの比で写す

- 体験者の肩を頭から推定する。比率は Remy の実測から取った
  （頭から肩まで 0.15 × 身長 ＝ 目の高さ基準 / 肩の半幅 0.104 × 身長 / 腕長 0.29 × 身長）
- 「**肩 → 手**」ベクトルを**腕長比**でスケールし、人形の**実ボーンの肩**へ乗せる
- 頭身比・肩幅・腕長のどれが違っても破綻しない。**市松人形（頭−肩 2.8% / 腕長 34%）でも
  Remy（9.0% / 29%）と同じ到達率**になることを実測で確認した

### 2. 体の向きは頭の向きを鈍らせ、首の可動域で引く

半減期 0.35 秒 ＋ **ねじれ上限 50°**。遅れだけだと「首を振った」と「体ごと回った」を区別できず、
90° 振り向いた場面で体が置いていかれて**手が背中側へ回った**（実測で確認）。

### 3. 立ち位置も腕・向きと同じ時刻を読む

[`CourseTrack`](../../Assets/Scripts/Streaming/Cg/CourseTrack.cs) を新設。
実測で**歩行中（0.8 m/s）12cm 遅れ・止まれば 0cm**（理論値 0.15 × 0.8 = 12cm と一致）。

### 4. 人形の可動域を絞る（袖が伸びないように）

ユーザー指摘「ハンドトラッキングに滑らかに 100% 追従させちゃうと、袖が変な感じに伸びたりする」。

角度を 0〜90° まで振って撮り（`sweep` シナリオ）、**30° まで自然 / 45° で袖の先から手が突き出る**
ことを確認した。ただし**距離も 0.85 に制限すると 45° でも袖の形が保たれる**（角度だけ・距離だけでは足りない）。

- 腕を下ろした向きからの振れ **45°**（上限の 60% までは 1:1、そこから指数で飽和）
- 肩から手首は腕長の **0.85**（常に肘を少し曲げる）
- 単純に角度で切ると、体験者が動かしているのに人形が途中で止まってカクつく → 飽和にした
- **判定は本番で見える大きさ（`*_far.png`）でする**。遠景では袖から覗く手は数 px にしかならない。
  寄りだけで見ると本番より大きく見えて判断を誤る

⚠ トレードオフ: 可動域を絞るほど「体験者が動かした」ことが伝わりにくくなる。
35° は破綻ゼロだが動きがほとんど読めなかった。45° が「袖の形が保たれ、かつ動きが分かる」境界。

### 5. 身長の測り方（市松人形が 2.27m の巨人になっていた）

実寸は「ボーンの最高点」で測っていたが、**市松人形は Head が頭の中ほどまでしか無い**ので
実寸を 3 割小さく見積もり、show.json の `heightM: 1.6` に合わせる縮尺が 1.42 倍過大だった。
メッシュ上端がボーンより 25% 以上高ければメッシュ側を採る。実測で **1.60m ちょうど**に。
Remy は 11%（髪と服の膨らみ）なので従来どおりボーンで測る — 閾値 10% だと境界に乗って揺れた。
