# 端末の傾きを配信アプリから受け取って、位置合わせを 4 自由度にする

2026-08-05。ユーザー依頼:

> カメラの位置合わせが難しいので、せめてスマホの現在の姿勢（回転角）をストリーミングアプリで
> 取るようにして、それを UI からその値へ設定できるようにしたい。あとは平行移動だけで行けるから楽。

## 何が取れて、何が取れないか（ここが設計の全部）

**取れる**: 上下の向き（pitch）と傾き（roll）。重力ベクトルから決まる。三脚に固定した静止カメラでは
加速度計の読みがそのまま重力なので、実測誤差は 0.1〜0.5° 程度。

**取れない**: 左右の向き（yaw）。方位を出すには磁気コンパスが要るが、

- 室内・三脚・電子機器の近くで **±10〜30° ずれる**（鉄骨・スピーカー・端末自身の磁石）
- ずれ方が場所ごとに違うので、**1 台を基準にした相対 yaw も信用できない**
- そもそも course 座標の X/Z 軸は部屋の都合で決めてあり、**磁北との対応が未知**

→ **磁気は使わない。** 依頼の「あとは平行移動だけ」は正確には「平行移動 ＋ 左右の向き」になる。
6 自由度 → **4 自由度**。減るのは、目で合わせるのが最も難しい 2 つ（上下と傾きは、位置・高さと
見た目が縮退するので「どれがずれているのか」が判別できない）。左右の向きは横ドラッグ 1 つで合う。

当初は「参考値として磁気方位も送り、画面に出すだけにする」と書いていたが、**送らないことにした**。
使わないと決めた値を配ると必ず誰かが使う（この repo は「卓では正しく見えて実機が違う」を 3 回踏んでいる）。
磁気センサの購読とキャリブレーション状態の管理も乗る。`/info` は末尾追加で拡張できる契約なので、
必要になった時点で足せる。

## 上下と傾きが、左右の向きと独立に決まる理由

`calib` の姿勢は Unity の Euler（ZXY 順）で、`R = Ry(yaw)·Rx(-pitch)·Rz(roll)`。
yaw は**ワールド Y 軸まわりの最も外側の回転**なので、どのベクトルの **Y 成分も変えない**。

R の列がカメラ軸（0=右 / 1=上 / 2=前）なので、ワールド上向きを `U` として:

```
pitch = asin(fwd · U)
roll  = atan2(right · U, up · U)
```

どちらも「重力に対する量」だけで書けていて、yaw が出てこない。だから
**yaw を知らないまま pitch と roll だけを確定できる**。これが成立するから、この機能が成り立つ。

⚠ 前提: **course 空間の Y 軸は重力の上向き**。位置合わせリチュアルが決めるのは XZ 平行移動 + yaw +
床の高さ（`FloorHeightSolver`）だけで、Y 軸は Quest のトラッキング原点（床レベル基準）＝重力上向きのまま。
ここが崩れたらこの機能ごと嘘になる。

## 端末の姿勢 → 配信画像の姿勢

**計算は配信アプリ側でやり切る。** 受信側に端末座標系を解釈させない — センサの取り付け向き
（`SENSOR_ORIENTATION`）と `targetRotation` と正立化が絡むので、二重実装すると必ず食い違う。
配る値は「**配信されている画像**の光軸が、重力に対してどう向いているか」だけにする。

Android のデバイス座標（自然な向き基準・X 右 / Y 上 / Z 画面手前）で:

```
imgRight_dev = ( cos θ, -sin θ, 0)      θ = targetRotation の度数（0/90/180/270）
imgUp_dev    = ( sin θ,  cos θ, 0)
imgFwd_dev   = ( 0, 0, -1)              背面カメラの光軸
U_dev        = g / |g|                  重力センサの読み（水平に置くと (0,0,+9.81) なので符号反転は不要）
```

streamer は `targetRotation` を端末の物理向きへ追従させて**常に正立フレームを送る**ので、
θ は `CameraController.deviceSurfaceRotation` がそのまま使える（`deviceRotationDeg` として `/info` にも出ている）。

検算（`TiltMathTest` が固定する）:

| 置き方 | 期待 |
|---|---|
| 机に画面上向きで平置き（θ=0） | pitch −90°（真下）・roll 0 |
| 縦持ちで水平を向く（θ=0） | pitch 0・roll 0 |
| 横持ち（θ=90）で水平を向く | pitch 0・**roll 0**（正立化されているので傾かない） |
| 横持ち（θ=90）＋前傾 20° | pitch −20°・roll 0 |

⚠ **|pitch| が 85° を超えると roll が定義できない**（真下を向くと roll と yaw が縮退する）。
その領域は `valid=false` を返す。実運用の設置は pitch −30〜0° なので通常は踏まない。

## 精度を守るための 3 つ

1. **静止判定**: `|g|` が 9.81 から 0.35 m/s² 以上外れていたら動いている → `valid=false`。
   手に持って向けている最中の値を焼かせない
2. **平滑化**: 指数移動平均（時定数 0.4s）。センサノイズで最後の 0.3° が揺れるのを止める
3. **鮮度**: `tiltAgeMs`。センサが止まっている端末で古い値を「いまの姿勢」として出さない

## 卓（Web オペレータ卓）でどう使うか

`🎯 カメラを合わせる` の中に **📱 端末の傾き**パネルを足す。

- 現在値（上下 / 傾き）と、いまの `calib` とのずれを常時表示
- **［取り込む］** で pitch / roll だけを `calib` へ入れる（位置と左右の向きは触らない）
- **☑ センサの傾きを保つ** で X / Z 軸まわりの回転操作を止める。
  自由回転は元から Y 軸だけ（＝ pitch/roll を変えない）なので、止めるのは軸拘束の X / Z と
  数値欄の上下・傾きだけ。**平行移動と左右の向きは自由に動かせる**
- ライブ値に**自動追従はしない**。取り込みは明示操作にして、ずれたら「センサと 3.2° 違います」と言う
  （勝手に動くと、作業者が「自分が何をして絵が変わったのか」を追えなくなる）

作業順序を UI に書く: **① 傾きを取り込む → ② 位置を合わせる → ③ 左右の向きを合わせる**。
傾きを後から取り込むと、せっかく合わせた絵が動く。

`/info` はブラウザから直接引くと端末ごとの到達性・混合コンテンツに左右されるので、
**卓サーバ経由**（`GET /caminfo?host=&port=`）にする。`/diag` が既に PC → カメラ `/info` を
引いているので経路の実績がある。

## 傾きを送らない端末

iPhone の IP Camera Lite は姿勢を出さない（`/info` 自体が無い）。パネルは
「この端末は傾きを送っていません」と出して、従来どおり手で合わせる。
**現行フリートは Pixel 7a ×3（全台 streamer）なので実運用では全台に効く。**

## 変更範囲

### fixed-cam-streamer（v0.9.0）
| ファイル | 何を |
|---|---|
| `TiltMath.kt`（新） | 重力 + θ → pitch / roll の純関数。JVM テストで検算表を固定 |
| `TiltFilter.kt`（新） | 平滑化と整定待ち（時刻注入・純ロジック）。⚠ **平滑値は方向だけ使い、大きさを標準重力へ正規化してから `compute` へ渡す** — 正規化しないと、揺すった直後の減衰途中の大きさを「動いている」と誤判定して数百 ms 居座る |
| `TiltTracker.kt`（新） | センサ購読の殻。`TYPE_GRAVITY` → 無ければ `TYPE_ACCELEROMETER`・`SENSOR_DELAY_NORMAL` |
| `CameraController.kt` | tracker の起動/停止。`deviceSurfaceRotation` を tracker へ流す |
| `FrameDistributor.kt`（`StreamInfo`） | `tilt*` フィールドと `toJson` 追記（**既存フィールドの順序と形式は不変**） |
| `StreamInfoHolder.kt` | `onTilt()`。bind をまたいで保持（`deviceRotationDeg` と同じ扱い） |
| `MainActivity.kt` | 画面に傾きを表示（現場で「置いた → 値が出た」を目視できる） |

### fixed-cam-vr（卓）
| ファイル | 何を |

| `align-model.js` | `applyTilt` / `tiltMismatchDeg` / ロック時の操作制限。node テスト |

**Unity は 1 行も変えない。** `/info` の未知フィールドは JsonUtility が無視し、姿勢は従来どおり
`cameras[].calib` から読む。

## 破綻条件

- **磁気方位を「参考」から「既定で使う」へ格上げした時点で終わり。** 室内では合わない
- センサ値へ自動追従させると、カメラを触っていないのに保存値が変わる。取り込みは明示操作のまま
- 静止判定を外すと、設置中の手ぶれた値が焼かれる
