# 目は開かない、復号される。目は閉じない、脱落する

依頼（`canon/LEDGER.md` 0240・逐語）:
「目の出現と消失について、新しい目のデザインに合うようにしてほしい。」

## 1. 何が合っていないか（シュビーの読み）

R057 の出現と消失は**縦の潰し率 `squash`** で作ってある。版の行を中心線へ連続に潰す／線から連続に膨らませる。
これは**生き物の瞼**の語彙で、中身が壊れた画像データ（JPEG のブロック・行のずれ・落ちた矩形）になった今、
外形だけが滑らかに伸縮する。参考画像（`tools/eyes-ref/dejime.jpg`）に連続な変形は 1 つも無い。
あるのは**届いた行と届いていない行**、**ずれたまま止まった行**、**欠けたブロック**だけ。

## 2. 原則（これだけ守れば実装の細部は変えてよい）

1. **動く単位は画像データの単位**: 行（ブロック行）・ブロック・行の横ずれ。**連続の補間をしない**。
   値は 2 状態（届いた／届いていない、ずれている／ずれていない）で、遷移は 1 コマで跳ぶ
2. **縦に伸縮させない。** 版の 1 画素は常に同じ場所に描く。見えるのは「どの行が届いているか」だけ
3. **出現 ＝ 中心線から外へ行が届く**（虹彩の帯が先に見え、瞼の縁の行が最後に届く）。
   **消失 ＝ 外から内へブロックが落ちる**（最後に中心の 1 行が残って消える）
4. **時計は 1 ビットも触らない。** `AnomalyEyesLogic` の尺（0076 / 0094 / 0138）・`EyeOpen`・`HintOpenKnots`・
   瞬き・閉じの順の幅はそのまま。シェーダは `open`（0..1）を**どの行が届いているか**に写すだけ
5. 0085（閉じるアニメーションは見えること）は**外から内へ落ちる 0.11 秒**で満たす。落ちる縁がぎざぎざなので
   「瞼が下りる」ではなく「データが欠けていく」に読める。それがこの版の閉じ方

## 3. 触らないもの

- `AnomalyEyesLogic` 全部（尺・曲線・`EyeOpen` の式・瞬き・視線の時計）
- `AnomalyEyesMesh`（座席表・大きさ・縦横比・虹彩）
- 視線（眼球が瞼の下で回る・5 段の量子化）／中心線 `mid`（目尻の傾き・笑いの三日月）／版・色・`gain`
- 柱（`SMEAR_*`）の存在。動く条件だけ §6 で変える
- `ShowTelemetryHost` / `analyze-xp-log.py`（`eyes=` の 8 項目は足りている。画に出たかは fps と絵で見る）
- fps（塗る面積・版を引く回数は増やさない。足すのはハッシュと分岐だけ）

## 4. 出現の規則（`_EyeClosing` = 0）

版の目の箱（タイルの中の `TEX_EYE_W × TEX_EYE_W·TEX_RATIO`）を、**中心線から外へ片側 `rowsN` 行**に割る。
`rowsN = lerp(ROWS_MIN, ROWS_MAX, sizeN)`（小さい目 6 / 視界を埋める目 16）。行は横に `BLOCK_COLS`（10）のブロックへ割る。

| 記号 | 意味 |
|---|---|
| `r` | 中心線から数えた行番号（0 = 中心の行）。`floor(abs(t.y − 0.5) / (0.5·H) · rowsN)`、`H = TEX_EYE_W·TEX_RATIO` |
| `c` | ブロックの列番号 |
| `side` | 上（`t.y > 0.5`）／下 |
| `hSide` | 笑いの片側の高さ: 上 `1 − smile·SMILE_TOP`、下 `1 − smile·SMILE_LIFT`（いまの `hNow` の片側ぶん） |
| `openSide` | `open · hSide` |
| `hbk` | ブロックのハッシュ `h21(float2(r·31 + c, seed·7.9 + side))`。派生 `hbk2..4` は `frac(hbk·k + b)` |

- **A1 届く順**: ブロックの閾値 `thr = (r + hbk · ARRIVE_JITTER) / rowsN`。`openSide ≥ thr` なら描く。それ以外は描かない（alpha 0）。
  同じ行のブロックでも閾値が最大 `ARRIVE_JITTER`（0.6 行）ぶん違うので、届く縁はぎざぎざになる（穴が 1〜2 コマ残って埋まる）
- **A2 届いた瞬間はずれている**: `age = openSide − thr` が `TEAR_WIN / rowsN` 未満のあいだ、`t.x += sgn(hbk2 − 0.5) · TEAR_MAX · hbk3`。
  `TEAR_WIN` 1.5 行・`TEAR_MAX` 0.12 タイル。**補間しない**（ずれている／いない の 2 状態。過ぎた瞬間に正しい場所へ跳ぶ）。
  R057 の `SHEAR_EARLY`（0.55・`pow` の尾）と `DROP_EARLY`（0.70・帯の脱落）は**これで置き換える**。`SHEAR_HOLD`（0.03）は残す
- **A3 複製（任意・弱く）**: `hbk4 < DUP_P`（0.25）のブロックは、ずれている窓のあいだ**1 つ内側の行の画素**を写す
  （`t.y` を 1 行ぶん中心線へ寄せて引く）。壊れたストリームが前の行を使い回す形。fps に効かない（版を引く回数は同じ）
- **A4 箱の外（柱の行・`r ≥ rowsN`）**: 行の順に入れない。`open > 0` で最初のコマから出す（§6）
- **A5 縦の伸縮は無し**: `squash` を廃し `t.y = 0.5 + (p.y − mid) · Kv` に固定。`hFull` / `hNow` は `hSide` にだけ使う

## 5. 消失の規則（`_EyeClosing` = 1・`open` は 1 → 0）

- **B1 落ちる順**: A1 と同じ式を `open` の減る向きで読む（外の行から落ちる・縁はぎざぎざ）。ずれ（A2）と複製（A3）は掛けない
- **B2 居残るブロック**: `hbk2 < STUCK_P`（0.12）のブロックは閾値を `STUCK_EXTRA`（0.25・`open` の単位）ぶん下げる ＝
  周りが落ちた後も**同じ場所に**残って、遅れて消える（凍ったマクロブロック）。動かさない・薄めない
- **B3 最後**: `open < 1 / rowsN` で中心の行だけになり、次のコマで無い。線を「潰して」作るのではなく、行が 1 つ残っただけ
- **B4 中止（`Abort`）**は従来どおり 1 コマで消す（`_EyeFade` 0）

## 6. 柱・兆し・瞬き

- **柱は行より先に出て、行より後に消える**: 柱の重み `smearW` の `open` を `saturate(open · PILLAR_LEAD)`（`PILLAR_LEAD` 3.0）にする。
  最初のコマは「中心の 1 行 ＋ 上下の柱」＝ 引き伸ばされた画素の先に目が復号されていく形。消えるときも柱が最後まで残る
- **兆しの大きい目**（`HintOpenKnots`: 闇 0.70 → 0.04 秒で 0.45 → 0.27 秒で 1）: 音の頭で片側 16 行のうち 7 行が 2〜4 コマで届き、
  それぞれずれて跳ぶ。膨らみに合わせて残りが埋まる。**曲線は触らない**（届く行の数が曲線を読むだけ）
- **瞬き**（`_EyeBlink` が `open` に掛かる）: そのまま。行が 1〜2 コマ落ちて戻る ＝ コマ落ちに読める（瞼より合っている）
- **凝視の大きい目の瞬き**（`StareBlinkAt`）: 同上

## 7. 定数（シェーダの `#define`・全部この 1 か所）

| 名 | 値 | 何 |
|---|---|---|
| `ROWS_MIN` / `ROWS_MAX` | 6 / 16 | 片側の行数（小さい目 / 視界を埋める目・`sizeN` で補間） |
| `BLOCK_COLS` | 10 | 目の横幅あたりのブロック数 |
| `ARRIVE_JITTER` | 0.6 | 同じ行の中で届く時刻がずれる幅（行の単位） |
| `TEAR_WIN` | 1.5 | 届いてからずれている長さ（行の単位） |
| `TEAR_MAX` | 0.12 | 横ずれの最大（タイルの単位・R057 の `GAZE_MAX_T` と同じ桁） |
| `DUP_P` | 0.25 | 内側の行を写すブロックの割合 |
| `STUCK_P` | 0.12 | 居残るブロックの割合（閉じるときだけ） |
| `STUCK_EXTRA` | 0.25 | 居残る長さ（`open` の単位） |
| `PILLAR_LEAD` | 3.0 | 柱が行より先に立つ倍率 |

消すもの: `SHEAR_EARLY` / `DROP_EARLY` / `SHEAR_TAIL` と `squash`。`SHEAR_HOLD`・`BANDS_*`（視線の縁の刻み直し）は残す。

## 8. 安い門（焼く前に落とす）

`.\tools\unity.ps1 menu eyes -Set scale=2` → `Assets/Screenshots/eyes/`。測るのは R056 / R057 と同じ道具（`logs/eyes-look/`）。

1. **縦に伸縮していない**: 大きい目の瞳（暗い芯）の縦の画素数が、点灯している全コマで同じ（±1 行）。R057 は `squash` に比例して伸びる
2. **最初のコマは帯**: 大きい目が最初に点灯したコマで、点灯した箱の縦 ÷ 全開の縦 ≤ 0.2、かつ暗い芯の縦 ÷ 点灯した縦 ≥ 0.6
   （潰した全体なら 0.35 前後）
3. **縁はぎざぎざ**: 閉じの 3 段（`close_1_field` 〜 `close_3_last`）の大きい目で、点灯幅が目の幅の 70% 未満の行が 3 行以上あり、
   本体から 1 行以上離れて点いているブロックが少なくとも 1 コマにある（居残り）
4. `frames.tsv` の stage / big / field / open は旧版と全 349 行一致（時計を触っていない証拠）
5. `unity.ps1 test` 緑

実機は `py -3.11 tools/quest-record.py --sec 175 --walk --serial 2G0YC1ZF890864`。89 個が開いた 2 秒の fps が **49 以上**（R057 と同じ・版を引く回数は増えていない）、
`eyes=…/1`。生録画（`_raw.mp4` の左眼）で、開く瞬間と閉じる瞬間を各 1 枚開く（OSD の時計で探す・`memory/dark_eyes_slices.md` §5）。
