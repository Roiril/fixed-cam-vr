# 当日の設営と点検 UI

ユーザー要求: 当日のコーディングエージェントへの依存を減らす。何が動かず何が不足しているかを示す。既存の演出編集中心の画面を踏襲しない。スマホの A/B/C は固定 IP と対応して通常操作で入れ替えない。

## 決定

- `index.html` を当日の設営と点検にする。旧編集画面は `authoring.html` に保存。旧 `onsite.html` は新画面へ転送する。
- カメラ A/B/C と Quest α/β の期待する 5 台を常に表示する。未検出を一覧から消さない。
- `operations-fleet.json` を卓の固定登録とする。スマホは `CameraIdentity` が同じ既知 UUID の対応を持つ。交換端末の保守登録時は両方を更新する。
- 卓は A/B/C の host/port/pinned と並び順を守る。PC の自動追従と Quest の探索による切り替えを無効にする。アプリのキャッシュへは `/state` から渡る。Unity の共有設定は変更しない。
- 映像の正常は完成 JPEG 2 枚以上の連番進行で判定する。HTTP の応答と映像の到着を分ける。受信待ちの古い health 値で進行中の映像を異常扱いしない。
- Quest の応答を機ごとに見る。応答しただけで描画済みとは言わない。A/B/C の合成表示と音は装着時の確認を要求する。
- 復旧は識別情報を再照合した 1 台だけに行う。90 秒間の再実行制限を設ける。操作の受理と映像復旧を分ける。
- 手動確認は 1 時間で失効する。詳細点検は 30 分で失効する。設定変更と切断でも確認を無効にする。使用しない機能は対象外とする。
- 配信アプリは固定担当と指定 IP/実 IP を表示する。撮影/設営の操作は詳細へ移す。受信待ちと映像停止を分ける。
- 詳細点検は固定登録を適用した設定内容を比較する。使用する人形視点の映像ファイルを確認する。旧撮影画面の採用記録とインターネット接続は必須にしない。

## 根拠と助言

独立した設計検討と接続監査で、HTTP のみの正常表示と単一 Quest heartbeat の見逃しが一致した。advisor は UUID を照合してから復旧操作を行うよう助言した。端末は未接続なので、8 月の登録値を現在の実機照合済みとは扱わない。

## 検証と残る実機作業

Python は模擬 HTTP/MJPEG により正常/停止/ID 不一致/重複/固定値保護を検証する。JavaScript は欠落/古い観測/手動確認/詳細点検を検証する。Android は JVM テストと APK コンパイルを行う。

スマホ 3 台は未接続。更新インストールと縦横画面の実機表示は未検証。Android lint には既存の VIBRATE 権限不足と API レベル問題がある。APK はビルド済みでも現場投入済みとは扱わない。
