## 0. 方針（2 本の独立監査が収束した結論）

- **スタッフの主画面はタブレット 1 つ。** Quest の画面に残すのは「被らないとできない作業」= 位置合わせと、被った人への状態表示だけ
- **1 画面に主操作は 1 つ。** 一巡（準備 → 来場者 → 装着 → 体験 → 回収）のどこにいるかを常に見せる
- **関門は引き渡し時の一括検査 1 か所。** 機器確認と位置合わせは並行してよい（機器が揃うまで位置合わせに入れない直列を外す）
- **異常は名指しで、スタッフの手元（タブレット）に出す。** 「スマホ B：映像が届いていません」
- 予備操作（右 A 2 秒・B 1 秒）は「困ったとき」の 1 か所にだけ書く
- 体験中（題字を閉じて本編が始まってから終幕まで）の画・音・入力の意味は 1 ビットも変えない

既存の安全装置（`memory/staff_setup.md` の「確認の証拠」節）はすべて残す。リセット完了は要求 ID とセッション ID の変化で判定・反映は実値照合・questTick の鮮度 4 秒・引き渡し時の再検査。

## 1. 通信の追加（Quest → タブレット `GET /status` の `staffSetup`）

後方互換（タブレットは欠けた項目を「未確認」として扱う）。

```jsonc
"staffSetup": {
  "stage": "setup|alignment|reset|settings|explanation|ready|handedOff|playing|ended",
  "reason": "content|camera|tablet|position|settings|explanation|",
  "positionConfirmed": true,
  "resetProgress": 0,
  // ここから追加
  "position": "confirmed|needed|recenter|aligning",
  "cameras": [ {"id":"A","state":"ok|checking|trouble","problem":"|nostream|stale|identity|wrongcam|wrongshow"}, …3 件 ],
  "tablet": "ok|checking|trouble",
  "content": true,
  "run": { "phase": "INTRO|RUN|END|", "lap": 2, "laps": 3, "sec": 84, "outro": "off|playing|done", "ending": "released|trapped|" }
}
```

- `stage`: `devices` → **`setup`** に改名（初回の位置合わせ前）。`alignment` は確定後に位置が失われたときだけ。
  **`ended` を新設**（`Started` かつ本編の相が `Finished`）。旧 `playing` のまま終幕後も「体験中」と出ていた不具合の根
- タブレットは旧 Quest の `devices` も `setup` と同じに扱う
- `run.outro`: `OutroDirector.Stage` が Off なら off、Collapse/Dark/Report なら playing、Done なら done
- `run.ending`: `ShowRunDirector.EndingOutcome` が Released → released / Trapped → trapped / それ以外 ""

## 2. 体験の途中中止はタブレットに経路を足さない（advisor 諮問の結論）

本編中に Quest が受け付ける入力を 1 本増やすと、誤タップや古い応答による誤発火で来場者 1 人の体験を
失う（復元できない）。これは「体験中のものは変更しない」の最も厳しい読みに触れる唯一の項目。
右コントローラーは体験中もスタッフの手にあるので、既存の **右 A 2 秒長押し** をタブレットの
「体験中」画面に明記するだけにする。本編中のタブレットのリセット拒否（`OvrControllerBridge.TryResetVisitorFromTablet`）は残す。

## 2.1 Quest の休止（2026-10-10 調査）

公式: 外した直後は止まらない。**自動スリープ（既定 15 秒）が過ぎるとアプリが一時停止**する
（https://developers.meta.com/horizon/documentation/unity/unity-lifecycle/）。
一時停止中は `/status` は返るが `questTick` が止まり、リセット・設定の反映は進まない。
- アプリ側: タブレットが「ヘッドセットが休止しています → 電源ボタンを 1 回押す」と名指しする。要求は保持して、起きたら続ける
- 運用: Quest の「設定 > 電源 > 自動スリープ」を長く（最長 4 時間）すると台に置いても止まらない。
  OS 設定の変更なのでシュビーは触らない。人が設定する手順として書く

## 3. Quest のスタッフ用準備画面

初回設営は**チェックリスト**。順序を強制しない。

```
スタッフ用準備                                  クエスト α
位置合わせ      まだです        右トリガーを 2 秒押し続けると始まります
カメラ A        映っています
カメラ B        映像が届いていません    スマホ B の FixedCam Streamer を開く
カメラ C        映っています
タブレット      つながっています
全部そろったら、ヘッドセットを外して台に置きます
                                   画面が見えないとき：B を 1 秒押す
```

- 機器確認 → B 短押し → 位置合わせ の直列を廃止（右トリガー 2 秒はいつでも入れる）
- 本体が α か β かを表示する（IP の末尾 31 → α / 32 → β）
- 状態は記号（● / … / ✕）＋色＋語の 3 つで示す
- 体験者を迎える段（Welcome）は「次の体験者の準備はタブレットで行います」と状態だけ
- 引き渡し後に開始条件が崩れて来場者の視界に戻る画面は、最上段に 3 言語で「スタッフをお呼びください」を出す（題字より前。体験の中身ではない）

## 4. タブレットのスタッフ画面

モーダルの折りたたみ群をやめ、**全画面のスタッフ画面**にする。スタッフ画面がタブレットの「ホーム」で、来場者が使う間だけ来場者の画面へ切り替える。

上段：一巡の段 `1 準備 → 2 来場者 → 3 装着 → 4 体験 → 5 回収`（いまの段を強調）
左：いまやること（見出し・1〜2 文・主ボタン 1 つ）
右：機器の状態（クエスト／位置合わせ／カメラ A・B・C）。異常は直し方まで
下：困ったとき（折りたたみ 1 つ。予備操作・接続先の変更・音声と説明の確認・未開始の設定の取り消し）

| 状態 | 見出し | 主操作 |
|---|---|---|
| 接続先未選択 | このタブレットで使うクエストを選ぶ | α／β → 接続する |
| 接続できない | クエストに接続できません | もう一度確認する |
| スリープ | ヘッドセットがスリープしています | （電源ボタンを 1 回押す案内） |
| 初回設営 | ヘッドセットで最初の準備 | — |
| 位置の再確認 | 位置合わせをやり直してください | — |
| 準備 | 次の体験者の準備 | 準備を始める |
| 渡す | タブレットを来場者に渡す | 来場者の画面にする |
| 来場者が使用中 | 来場者が設定と説明を見ています | 来場者の画面に戻る |
| 確認 | 装着の前に確認 | 長押しで装着へ進む |
| 装着 | 装着を手伝う | — |
| 体験中 | 体験中 · 2 周目 · 1:24 | —（中止は右 A 2 秒と明記） |
| 終わりの演出 | 終わりの演出中です | — |
| 終了 | 体験が終わりました | 次の体験者の準備を始める |

自動で開く／閉じる:
- 起動時はスタッフ画面から始める
- 来場者が説明の最後で「スタッフへ返す」→ スタッフ画面の「確認」（上に 3 言語で「タブレットをスタッフにお渡しください」）
- 「装着へ進む」が Quest に受理されたら来場者の画面へ戻し、装着案内の 2 文を自動で再生する（旧：スタッフが閉じて「この文を再生」を押していた）
- 体験が始まったら（`playing`）スタッフ画面へ
- リセット完了は「渡す」で止まる（来場者の画面へは自動で切り替えない）
