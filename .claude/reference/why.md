# なぜこの形にしたか

実装は終わっている。ここから先は**作品にする**段で、問いは 1 つ。
**誰が世界観を決めたのかを、後から追えるようにするにはどうするか。**

---

## 潰そうとしている 3 つ

### 1. シュビーが書いた世界観が、いつのまにか正典になる

**これが本体。** 残り 2 つはこれの派生と言ってもいい。

ユーザーは「企画書を超えた世界観・物語性・企画書に無い演出を入れて作りこむ必要がある」と言った。
つまり**発明しろと明示的に命じられている**。だから「シュビーは世界観を書くな」は誤り。案は出す。

事故が起きるのは書いた瞬間ではなく、**次のセッションが読んだ瞬間**。
`rules/` や `plans/` にシュビーの案が事実の文体で残っていると、次のシュビーはそれを
ユーザーの意図として実行する。誰も言っていないものが拘束力を持つ。
このリポジトリは既にその器を持っている（`rules/streaming.md` は 1641 行あり、次のセッションは
これを契約として読む）。同じ器に世界観を書けば同じことが起きる。

だから禁じるのは**発案ではなく昇格**。

- シュビーの案は `canon/OPEN.md` に「案」として置く。**日付と、誰が言ったかを必ず書く**
- `canon/LEDGER.md` に入れてよいのは**ユーザーが口にした言葉だけ**
- 昇格の経路は 1 つ。ユーザーが判定を言う。それ以外に `LEDGER.md` へ入る道は無い

⚠ **要約は昇格ではなく破壊。** 「なんか怖くない」を「恐怖演出の強度不足」と書き直した時点で、
次のシュビーが読むのは別の指示になる。逐語で引く。

### 2. 往復が高いので、回らなくなる

unity-lab は WebGL を焼いて URL を渡せば済む。ここは APK を焼いて（数分）、install して、
起動して、録画して、pull する。**作りこみは往復回数が命なのに、その往復が高い。**

対処は 2 つ。

**安い門を先に通す。** 尺と滞在は卓のシミュレータが秒で出す。絵と数値は `ShowCompositePreview`、
文字は `HudPreviewScreenshot` が batchmode で出す。ここで落ちるものを実機まで持っていかない。

**ただし代理を厚くしない。** 卓と実機は既に 5 件食い違っている（`memory/sim_device_divergence.md`）。
代理を足すほど嘘が増える。**合否は配る乗り物＝実機で出す**。安い門は「落とす」ためだけに使い、
「通す」ためには使わない。

### 3. 初見を浪費する

ホラーは**同じ人が 2 回驚けない**。初めて被る人は消耗品で、しかも数に限りがある。

安い検証の代わりに人を呼ぶと、「まだ壊れている」を見つけて 1 人使って終わる。
逆に惜しんで一度も呼ばないと、本番で初めて怖くないと分かる。

だから初見は台帳で数える（`canon/ROUNDS.md`）。**使う前に「どこで何が起きるはずか」を 3 行書く。**
書けないなら、まだ人を呼ぶ段ではない。

## 決めたこと

### 企画書は読まない。骨格は実装が正

ユーザー宣言（2026-08-08）。企画書は企画段階のもので、いま読むとコンテキスト汚染になる。
`docs/proposal/` と `docs/archive/` はどちらも開かない。

ただし**骨格の制約まで捨てるわけではない**。導入 → 3 区間を 3 周 → 終幕、3 分以内、
1 周目の録画を 3 周目の背景に、100ms の管理 — これらは**既に実装され、機械が守っている**
（`analyze-xp-log.py` の期待値と `show.json`）。だから文書を読み直す必要が無い。

**骨格は機械が守る。人は絵と物語を作る。** この順序を先に立ててから、読まないと決めている。

### 品質を採点しない

明度・彩度・浮き（luma / sat / grain の比）は測る。**合否には使わない。**

数値で合否が出た瞬間に人の判断が降りる。「82 点なので通します」が成立すると、
このハーネスは目的の逆を回し始める。

**機械は「無い」を言えるが「良い」を言えない。** 出るはずの演出が出たか、尺が超えていないか、
幾何がずれていないかは機械の仕事。怖いか、気づくか、間が持つかは人の仕事。
数値は判定ではなく、**絵と並べる材料**として出す。

### 訊く。ただし止めない

グローバル規約（`~/.claude/rules/fable-advisor.md`）はユーザーへの許可要求と選択肢の問い合わせを
全廃している。**世界観と UX の判定はこれに当たらない。** 同規約の例外「ユーザーしか持たない事実の取得」と
「対話自体が目的の場面」の両方に該当する。ディレクションは許可ではない。

ただし訊き方を縛る。**既定を添えて 1 点だけ訊き、返事が無ければ既定で進む。**
返事待ちで止まる形にすると、結局は許可要求と同じものになる。

### 作風の原則（STYLE 相当）を作らない

unity-lab は「別々の作品で 2 回出たものだけを原則に上げる」。
**この作品は 1 本しかないので、その交差が原理的に起きない。**

だから原則の層は作らない。`LEDGER.md` に判定が並ぶだけでよい。
作品をまたぐ原則が要るようになったら、それはグローバルの `/encode` の仕事。

## 層

| 層 | 何 | どこ |
|---|---|---|
| L0 作品 | 廻リ視（実装済み） | `Assets/Scripts/` / `show.json` |
| L1 ハーネス | 焼く・撮る・測る道具 | `tools/` / `CLAUDE.md` / `rules/` |
| L2 メタハーネス | 判定を溜める仕組み | `.claude/canon/` / `.claude/skills/` |

既存の L1 は**十分に強い**（テレメトリ・自動走行・証拠切り出し・効果の実在の観測）。
unity-lab から道具を移植する必要は無い。あちらの道具はまだ一度も焼いていない未検証物で、
向きが逆になる。

**欠けているのは道具ではなく、判定の主語だった。** ここだけを足す。
