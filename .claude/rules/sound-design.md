# 廻リ視の音

**音を触る前にこれを読む。** 世界観の判定は `canon/LEDGER.md`、体験の骨格は `rules/show-design.md`、
配信と show.json の契約は `rules/streaming.md` が正本。ここは**音だけ**の正本。

制定 2026-08-12。それまで音は `HorrBGM.mp3` の全長ループ **1 本だけ**で、
タイトル・導入・封印の箱・隔離・破砕・すり替え・終幕・乱れ・信号断・周回の劣化は
**全部無音**だった。切替音は実装だけあってクリップが空だった。

## 0. 三行で

**敷く音は 2 つ — 現実の音と装置の音。⚠ その上に劇伴が 1 本乗る**（0115・ユーザーの判定）。
**音は絵より先に来る。** 段 1 で装置の声が入り、画が変わるのは段 3〜4。
**判定は数値と絵でする。** 耳で確かめられない前提で道具が組んである。

## 1. 劇伴はどこに居るか

この体験の恐怖は「**装置は正直に映している**」という信頼の上に乗っている。3 周目に
「映像の中の自分が手を上げない」で反転が成立するのは、それまで装置が嘘をつかなかったからで、
`rules/streaming.md` の「やってはいけないこと」も同じ理屈で**選択的彩度**や
**1 フレームの顔**を禁じている。

**敷く音**（`SoundBedLogic` が出し入れするもの）は 2 種類だけ:

| 層 | 何 | 例 |
|---|---|---|
| **現実の音** | 体験者が実際に居る場所が出す音 | 部屋のトーン、封印の箱の唸り |
| **装置の音** | カメラ・伝送・スクリーンが出す音 | 搬送のトーン、電源の唸り、リレー、砂嵐、乱れ、**連絡の面の打鍵** |

⚠⚠ **パススルー → 2D は 3 発で組む**（2026-08-16・`canon/LEDGER.md` 0057）。
**割れる → （静けさ）→ スクリーンが出る → 完全にスクリーンになる**。頭の表が正本。
2026-08-13 の「管が点く ＋ その後ノイズ」（0030）の 2 発構成は、
**管が点く段が無くなった**（0044）ので既に別物になっていた。

⚠ **もらった音は検査の一部を外してある** — 突出と純度は素材が実物である以上そうなるもので、
通すために作り変える方が §4.5 違反になる。`sound-lint.py` の `RECORDED` に入っている。
⚠ **`sfx_screen_on` は鋭さ 3.51 で一撃の上限（3.5）をわずかに超える。** ユーザーが選んだ音源なので
**イコライザは掛けない**（§4.5）。刺さると言われたら音量を下げるか、音源を替える。

⚠⚠ **劇伴は、リセット後の黒から 3 周目の終わりまで切れずに鳴る**
（2026-08-23・`canon/LEDGER.md` 0115・ユーザー逐語「1~3周目に設定した環境音が怖くなくて、
全部HorrorBGMにしてほしい」）。

⚠⚠ **曲は途中で 1 度だけ入れ替わる**（2026-08-23・`canon/LEDGER.md` **0119**）。
**人形の呼びかけ（「あーそぼー」）の次のカット**で `HorrBGM` → `LostPlace2` へ
3 秒のクロスフェード。**穴は開かない**（等パワーの対）。詳細は §4「追いつきから終幕までの劇伴」。

| いつ | 劇伴 | 部屋のトーン |
|---|---|---|
| リセット後の黒（A 待ち） | **鳴る**（2.5 秒かけて戻る） | 0 |
| 題字 → 導入 → 1〜3 周目 | **鳴りっぱなし**（切れ目を作らない） | **0**（導入だけ 0.85） |
| **終幕の頭** | **2.0 秒で退く** | 0 → 0.85（**現実の音だけが残る**） |
| 位置合わせ中・`Done` | 0 | 0 |

- 判断は [`SoundBedLogic.Target`](../../Assets/Scripts/Streaming/Sound/SoundBedLogic.cs) の
  `g.score`。いまの式は `s.outroActive ? 0 : 1` の 1 行
- ⚠⚠ **途中で 0 を挟まない。** ユーザーが言っているのは「**背景で流れ続ける**」なので、
  穴を作らないことが仕様。段でも周でも切らない
- 形は**聴感直線**（`SoundFade.Curve.Perceptual`）。半減期で寄せると振幅が指数で落ちる ＝ dB 直線で、
  「すぐ消えてから長く尾を引く」に聞こえる
- 退き（2.0 秒）を**装置の引き（1.5 秒）より長く**取ってある。逆にすると装置が死んだ後に
  音楽だけが残り、「まだ続く」と告げてしまう
- `BgmDirector` には**口が 2 つある**。`SetDuck`（一撃のたびの一時的な退き）と
  `SetScoreGain`（居てよいか）。掛け算で両方効く
- ⚠⚠ **人形の笑いは劇伴を深く退かせる**（群れ 0.85 / 一人 0.45）。0088 のあいだは引く相手が
  居なくて眠っていた値で、**0115 で生き返った**
- ⚠ **卓のタイムラインが著作した区間 BGM は、本編でも鳴るようになった**（`show.json` の
  `timeline.segments[].bgm` / `bgmTracks`）。いまの `show.json` は区間 BGM を持っていないので
  トップレベルの `bgm_HorrBGM` が鳴り続ける。区間ごとに曲を変える著作をすると、
  **それがそのまま「周ごとに背景が変わる」に戻る**（0115 が退けたもの）ので判定が要る

**なぜ 0088 まで劇伴を避けていたか**（判断の背景・いまは覆っている）: この体験の恐怖は
「装置は正直に映している」という信頼の上に乗っていて、劇伴は「作者がいま怖いと言っている」という
外部の声なので、同じものを音で壊す — という理屈だった。
**ユーザーは 3 本の環境音を聴いた上で「怖くない」と退けた**ので、この理屈より
実際の怖さを取った、という順序で読むこと。

## 2. 実機の物理（これは意見ではなく制約）

| 制約 | 数値 | 効き目 |
|---|---|---|
| **内蔵スピーカーは 200Hz より下をほとんど返さない** | 耳の脇に開いた小さな開放型 | **正体を低い方に置いた音は実機で存在しないのと同じ。** 2026-08-12 の実測で 4 素材が該当し、封印の箱は損失 **-18.3dB**（ヘッドホンでは立派に鳴る） |
| **左右のスピーカーは頭のすぐ両脇** | 空中でほぼ合成される | **逆相成分は消える。** 遅延で広げる疑似ステレオは櫛形の谷を作り、`sfx_title_out` は **モノ互換 -11.2dB** ＝ ほぼ消滅していた |
| **音声機構は 48kHz** | — | 44.1kHz の素材は実行時にリサンプルされる（CPU と品質を捨てる） |
| **DSP バッファ 1024 標本** | **21.3ms の粒** | `Play()` は次のバッファの頭で鳴る。暗転の下り 70ms に音を置く約束は、粒のままだと**回ごとにずれる** |
| **spatializer はモノしか処理しない** | Meta XR Audio | ステレオのクリップは `spatialBlend=1` にしても定位しない |

**帰結（守ること）**

- 伝えたいことは **150Hz 〜 6kHz** に置く。低い方は「ヘッドホンなら効くボーナス」
- 広がりは**遅延で作らない**。左右に独立に位相を散らした複製を混ぜる（`soundkit.widen`）
- 素材は **48kHz** で焼き、取り込みは `PreserveSampleRate`
- 時刻の約束がある音は **`PlayScheduled(AudioSettings.dspTime + 0.035)`**
- 3D の音は**モノで焼く**（`write_wav(mono=True)`）

⚠ **`ProjectSettings/AudioManager.asset` は 3 アプリの共有資源**（`rules/parallel-projects.md`）。
DSP バッファを 512 にすれば粒が半分になるが、CPU が増えて他の 2 アプリにも効く。
**触っていない。** 触るなら 3 アプリ分の影響を測ってから。

## 2.5 音はどこから鳴るか（定位）

⚠⚠ **2026-09-03 に音を 3D にした**（`canon/LEDGER.md` **0130**・ユーザー逐語
「音を3Dにしてほしい」「カメラの切り替え音や文字が出るときのカチカチ音などの
各種スクリーン関係の音はスクリーンから」「笑い声は周囲の体験者周囲のランダムな位置から」
「あーそーぼーは体験者の後ろから」）。それまでは `bed_seal` 1 本を除いて全部 2D だった。

| どこから | 何 | 置き先 |
|---|---|---|
| **スクリーン** | 切替（素・警告つき）／乱れ／装置の唸り 2 本／砂嵐／スクリーンが出る音／終幕の電源断 | `ScreenOverlayController` の Transform（`ScreenAnchor` が頭の正面へ運んでいる） |
| **連絡の面** | 打鍵 | `CommsPanel` の `CommsRoot`（頭から 1.5m・視線から 8° 左 / 17° 下） |
| **体験者の周囲** | 人形の笑い 4 声 | 頭を中心とした半径 2.5m の輪。**90° の区画へ 1 つずつ**入れて ±35° 振る |
| **体験者の後ろ** | 呼びかけ（あーそーぼー） | 鳴らした瞬間の後ろ 2.0m。真後ろから左右へ 15〜35° 振る |
| **2D のまま** | 部屋のトーン／割れる音／鈴／題字の音／劇伴／封印の箱（鳴らない） | — |

**2D に残す理由**は 2 つしかない。

- **現実の音は全周にある**（部屋のトーン）。1 点から鳴らすと「部屋」ではなく「部屋の音が出る何か」になる
- **誰も鳴らしていない音**（鈴・題字・割れる現実）。出どころを作ると、装置か人形が鳴らしたことになる

**守ること**

- ⚠⚠ **3D にするのは向きだけ。大きさは 1 ミリも変えない。** §3 の高さの設計（LUFS）は
  置いた場所に依らないので、減衰が始まる距離（`SpatialAudio.MinDistanceM`）を **50m** まで
  押し上げて減衰の区間へ入らないようにしてある（対数減衰は `minDistance` の内側で必ず 1.0）
- ⚠⚠ **spatializer はモノのクリップしか処理しない。** ステレオのまま `spatialBlend=1` にしても
  **定位せず頭の中で鳴る** — しかも**音は鳴る**ので気づけない。名簿は 2 か所:
  `tools/soundkit.py` の **`MONO3D`**（焼く側）と
  `Assets/Scripts/Streaming/Sound/SpatialAudio.cs` の **`MonoRequired`**（鳴らす側）。
  **`sound-lint.py` が両者を突き合わせて落とす**
- ⚠⚠ **モノへ落としたら高さを戻す**（`soundkit.to_mono_keep_lufs`）。素のまま平均すると
  切替音で **-2.6dB**・乱れの音で **-2.1dB** 下がり、**「3D にした」という別の変更に紛れて**
  §3 の設計が崩れる。実測で 34 本すべて元の LUFS を保って焼き直してある
- **笑いは頭の位置に付いていく（向きには付いていかない）。** 体験者は区間ごとに歩くので、
  ワールドへ釘で留めると「周囲に居る」が保てない。方角はワールドで固定なので**振り向ける**
- **呼びかけは鳴らした瞬間の後ろへ置いて、そこから動かさない。** 頭に貼り付けると、
  振り向いても声が後ろへ回り込み続ける ＝ 装置の音になる
- ⚠ **真後ろちょうど（180°）と真正面（0°）には置かない。** 正中面では左右差が消えるので、
  HRTF の手掛かりがいちばん少ない ＝ 前後が入れ替わって聞こえる
- **置き先を掴めなければ 2D へ落とす。** 黙って別の場所から鳴らすより、定位を捨てる方が事故が小さい
  （`bed_seal` が箱を掴めないときの既存の作法と同じ）
- ⚠ **鳴らなくなった音は名簿に入れない**（`sfx_swap` / `sfx_seal_close` / `sfx_screen_noise` /
  `sfx_shell_open`）。鳴らないものを 3D にしても確かめる手が無い

**観測**（§7 と対）: `ev=sum` の `snd3d` / `sndAz` / `sndCall`。
⚠⚠ **定位していないことは画にも録画にも一撃のログにも出ない。** ここが唯一の証拠。

## 2.6 劇伴を置き換える 3 つ（2026-09-03・`canon/LEDGER.md` **0131**）

**背景は `HorrBGM` / `LostPlace2` の 1 レーンだけではなくなった。** 3 か所で入れ替わる。

| いつ | 何が鳴るか | 劇伴 | 尺 |
|---|---|---|---|
| **別の場所（バックルームズ）が映っているあいだ** | `bed_wind`（風） | **切る** | 0.6 秒で入れ替え・戻りも同じ |
| **3 周目 B 〜 呪いが排除されるまで** | `bed_beat` ＋ `bed_horror2`（**2 本一緒**） | **切る** | 2.0 秒でクロスフェード |
| **呪いが排除された後** | `bed_white`（ホワイトノイズ） | 切ったまま | 同上 |

- ⚠⚠ **「環境音」＝ 劇伴**（ユーザーの語）。0115 で周ごとの環境音は退役している。
  **装置の唸り（`bed_device` / `bed_static`）は切らない** — 装置は動き続けていて、
  映しているものが変わっただけ
- ⚠⚠ **高さは「置き換える相手」から決めた。** 卓の `volume` 込みの実効値は
  `HorrBGM` = -21.7 × 0.50 ＝ **-27.7** ／ `LostPlace2` = -17.2 × 0.57 ＝ **-22.1 LUFS**。
  ⇒ 風 **-26.0**（1.7dB だけ上）／呪いの 2 本は**1 本ずつ -25.0**（**和が -22** ＝ 釣り合う）／
  ホワイトノイズ **-28.0**。**入れ替わったときに大きさが跳ねないこと**が条件
- **異世界の出入りだけ速い**（`OtherworldFadeSec` = 0.6 秒）。演出が **4.0 秒**しかないので、
  劇伴の既定の退き（2.0 秒）では窓の半分を食う。⚠ **戻りも同じ尺**（片道だけ速いと谷ができる）
- ⚠⚠ **入れ替えは等パワーの対**（2026-09-04）。置き換える 3 つは `sin` で立ち、劇伴は
  **その合成パワーの補（`sqrt(1 - Σ相手²)`）**で退くので、途中で背景の総量が 1 から動かない。
  2026-09-03 の初版は劇伴の退き（聴感直線）と相手の入り（聴感直線）を同じ尺で別々に走らせていて、
  **中央で合成パワーが 0.20（-7dB）へ凹んでいた**（走行 20260903_210843 の t=107.4 に
  劇伴 0.21 / 呪い 0.44 の標本）。0131「クロスフェードで入れ替える」に反する。
  ⚠ 相手は `max` ではなく**パワーの和**で見る — 呪い → ホワイトノイズの受け渡しの中央で
  `max` だと劇伴が 0.7 まで戻る。`SoundLayerSwapTests` が途中の tick まで固定する。
  `analyze-xp-log.py` は劇伴 1 本ではなく **4 つの合成パワー**が 0.5 を割ったら FAIL
- ⚠⚠ **呪いの 2 本は一度入ったら消えない**（`SoundShowState.curseArmed` のラッチ）。
  区間の条件を毎フレーム見ると、体験者が 3 周目 C から A へ**引き返した瞬間に曲が止まる**
- ⚠⚠ **異世界かどうかは、いま画面を取っているカットの素材 id で判じている**
  （`ShowSoundDirector.OtherworldCuePrefix` ＝ `backrooms`）。**卓で cue の名前を変えると
  音が黙って止まる**（画は 1 画素も変わらない）ので、`analyze-xp-log.py` が
  「異世界のカットが出たのに風が鳴っていない」を FAIL にする
- ⚠⚠ **`bed_beat` は実機の内蔵スピーカーではほとんど鳴らない**（内蔵SP **-21.0dB** ＝
  エネルギーのほぼ全部が 150Hz 以下）。§2 の制約そのもの。**もらった音なので直さない**（§4.5）。

| 何 | 音源 | いつ |

## 3. 音の高さの揃え方

⚠⚠ **ピークで揃えない。** 一撃の音と持続音は同じピークでも聴感が 20dB 違う。
実測（2026-08-12）: 尖頭を -3dBTP に揃えたら、隔離が閉じる音が **-28.7 LUFS** ＝
狙いより 11.7dB 小さかった。

**種類で揃え方を変える。境目は波高率（peak / RMS）。**

| 種類 | 揃え方 | 目標 | なぜ |
|---|---|---|---|
| **敷く音**（ループ・波高 6〜12dB） | ラウドネス | **-32 LUFS** | 会話の下に居る高さ |
| **繰り返す一撃**（切替・乱れ・波高 14〜20dB） | ラウドネス | **-23 LUFS** | 1 回の体験で 9 回以上並ぶ。揃っていないと機械に聞こえる |

⚠⚠ **乱れの音だけは、起きた回数で 1.94 dB ぶん上がる**（2026-08-16・`canon/LEDGER.md` 0055）。
**-23 LUFS は終盤の高さ**で、1 回目はそこから 1.94 dB 低い（倍率 0.80 → 1.00）。
上げ幅が小さいのはユーザー指定（「音の上昇は深いじゃない程度に」）。
⚠ **曲線は画と同じ 3 乗**なので、上がるのは終盤だけ（9 回目でまだ 0.88）。
⚠ **上へは伸ばせない** — `SfxPlayer.Play` が `Clamp01(gain × masterGain)` で `masterGain` は 1.0。
1 を超える倍率を返すと**潰れて何も変わらない**のに、コードは「大きくした」つもりになる。
数えているのは `GlitchFx` 1 か所で、画と同じ進みを読む（`rules/streaming.md` の乱れの節）。
| **一度きりの山**（隔離・破砕・すり替え） | **尖頭** | **-3 dBTP** | 400ms 平均のラウドネスでは実力より小さく出る。無理に上げると手応えだけ消える |
| **持続する節目**（りん・終幕） | ラウドネス | -24 〜 -26 LUFS | 波高が小さいので尖頭で揃えると突出する |

上限は全素材 **-3 dBTP**。届かないときは `soft_clip` で尖頭を丸めてから正規化する
（`make-sounds.py` の `norm_lufs` が自動で必要なぶんだけ探す）。

## 3.5 不快にしない（測れる）

ユーザー指示（`canon/LEDGER.md` 0015）「**不気味で怖くていいけど、不快にはならないように**」。

**「不気味」と「不快」は別の軸で、後者は測れる。** 心理音響では 3 つに分かれる。

| 何 | 測るもの | 敷く音 | 一撃 |
|---|---|---|---|
| **鋭さ**（acum） | 高い臨界帯域への偏り ＝ 耳に刺さる | **≤ 2.5** | ≤ 3.5 |
| **粗さ**（asper） | 20〜300Hz（山は 70Hz）の**はっきりした**振幅変調 ＝ ざらついて苛立つ | **≤ 0.4** | ≤ 1.0 |
| **突出したトーン**（dB） | 周囲より突き出た純音 ＝ 数分浴びると疲れる | **≤ 25**（§3.6） | ≤ 25 |

敷く音の線が厳しいのは、**3 分間かけ続ける**から。一撃は一瞬なので緩い。
⚠ **突出したトーンは 2026-08-12 に合否へ入れた**（§3.6）。それまで「蛍光灯の線と搬送トーンは
意図して置いている」として情報扱いにしていたが、その 2 つがまさに
「チープな電子音」として指摘された。**意図して置いたことは、発振器に聞こえてよい理由にならない。**

⚠ **これは DIN 45692 / Zwicker の近似**であって規格実装ではない。ピンクノイズと
「1kHz を 70Hz で 100% 振幅変調した音」で較正してあるので、**この作品の中での比較にだけ使う**。

⚠ **粗さは「揺らいでいる量」ではなく「特定の速さで揺れている度合い」。** 最初これを
帯域ごとの変調スペクトルの**総和**で書いたら、ピンクノイズが 8.09 asper になった
（正しくは 0.1〜0.3）。ノイズの包絡は元々でたらめに揺れているので、総和で測ると
ノイズがいちばん粗いことになる。ざらついた広帯域ノイズの不快さは**鋭さ**が拾う。

⚠ **音量の順序も「不快」の一部。** 2026-08-12 に、体験で最初に聞く音（タイトル）が
いちばん大きく、隔離の音が導入の山（破砕）を超えていた。どちらも尖頭で揃えた結果で、
**数値上はどれも上限の内側**だった。順序は自分で決めること。

## 3.6 安っぽい電子音にしない（測れる）

ユーザー指示（`canon/LEDGER.md` 0016）「**チープな電子音はチープすぎるからやめてほしい**」。

**正弦波を 1 本置いた瞬間に発振器の音になる。** 自然界に純音は無いので、聞き手はそれを
「機械が鳴っている」ではなく「オシレータが鳴っている」と聞く。

指標は `tonality_db`（**細かい分解能で、対数周波数上の滑らかな地面からの隆起**）。

| 突出 | 何に聞こえるか |
|---|---|
| **40dB 超** | 発振器そのもの（正弦波 1 本 = 106dB） |
| 25〜35dB | はっきりした唸り。数分続けると機械に聞こえる |
| **15dB 前後** | 実物の機械・楽器。共振の帯 |
| 10dB 未満 | 音程の印象が無い |

**合成した音は 25dB 以下**（`sound-lint.py` が落とす）。**実録は判定から外す** —
鈴 44dB / 金属 32dB で、実物が突出しているのは正しい姿。

### ⚠⚠ 滑る純音（掃引）は突出では捕まらない

`tonality_db` は**スペクトルの形**を見るので、**チャープを原理的に検出できない**。
どのフレームで見ても山が広がるため、ピンクノイズより低く出る
（実測: 掃引の純音 **1.7dB** / ピンクノイズ 9.2dB）。フレーム長も地面の窓も変えたが分離しなかった。

だから**もう 1 本の物差し**が要る — `tone_purity`（**包絡の滑らかさ**）。
純音は振幅が一定なので包絡のばらつきがゼロ、ノイズはレイリー分布で変動係数 0.5227。
**掃引しても純音は純音**なので、帯域を狭く切って 30ms の窓で見ればどちらも捕まる。

| 純度 | 何 |
|---|---|
| **0.93〜1.00** | 正弦波（定常でも掃引でも） |
| 0.30〜0.45 | 帯域ノイズの掃引・強い共振 |
| **0.60 が線**（合成音） | これを超えたら発振器が居る |
| 0.08〜0.21 | ノイズ |

⚠ **`sk.sweep()`（正弦波の掃引）を出荷する音に使わない。** 滑る純音は SF の効果音の語彙で、
実物の「落ちる」「抜ける」は必ず幅を持つ。代わりに `sweep_band`（帯域ノイズの粒を重ねて
中心周波数を動かす）を使う。2026-08-12 にユーザーが**時刻を指して**指摘した 2 か所
（48-49s「ポウン」＝ 段 4 の飲み込み / 57-58s「ジューン⤴」＝ 終幕の解放）がどちらもこれだった。

### 直し方は 1 つだけ

**トーンそのものを狭帯域ノイズにする**（`soundkit.tone_band`）。音程は聞こえたまま
線スペクトルが消える。実物の唸りは周波数が絶えず揺れていて、平均すると狭い帯になる。

⚠⚠ **近接した部分音の束（`cluster`）では直らない。** 2026-08-12 にそう考えて実装したが、
測ったら **126dB**（純音 105dB より悪い）。束にしても線が増えるだけで、
効くのは**トーンの周りにノイズの地面があること**（束 ＋ 同帯域ノイズ半々 = 18.5dB）。
`cluster` は残してあるが、単独で使わないこと。

⚠ **整数倍の高調波を積まない。** 1900 → 3800 → 5700 は「発振器」を強める。
実物の共振は非調和なので **1.97 倍 / 3.06 倍**のように外す。

⚠ **`q` を上げるほど音程がはっきりし、同時に発振器へ近づく。** 40 を超えたら測り直す。

実測（2026-08-12・この指示で直した値）: `bed_device` **73.3 → 22.2dB** ／
`bed_seal` 54.5 → 16.9 ／ `sfx_title_out` 37.2 → 12.3 ／ `sfx_switch_1` 29.8 → 15.1。

### ⚠⚠ 現実が割れる音（2026-08-23 に作り直した・`canon/LEDGER.md` 0112）

ユーザー指示「**パススルーが割れるときの音を、もっとクオリティを上げて気持ち良くしたい**」
「**使う音声素材を増やすのではなくうまく加工して**」。0057 の音源（PC-Mouse06-1）は変えていない。

**旧版を測って分かった 3 つ。どれも「物理的にありえない」だった。**

| 何が | 実測 | 真因 |
|---|---|---|
| **一撃が無い** | 25ms 窓の山が **150ms** にあり、頭は -3.2dB から膨らむ | 減り方を `(1-u)^1.9` という**頭が平らな式**で書いていた。そのあいだに粒の重なりが 1 → 6.5 と増えるので、**設計上は減っていても実際は膨らむ** |
| **粒立ちが無い** | 粒 130ms を 21ms 刻み ＝ 常に 6.5 個重なる | 1 粒 1 粒が聞こえない。しかも尻の 12ms フェードが**素材でいちばん大きい一撃の本体を毎粒で潰していた** |
| **尻が消えている** | 1.2〜1.7 秒が **-37.6 LUFS** | 段 4 の敷く音（room ＋ device で約 **-30.5 LUFS**）より 7dB 低い ＝「小さくなった」ではなく「無くなった」。0057 の「静かにしてから」の**縁が立たない** |

**直したのは 4 つ。**

1. **t=0 に一撃を置く**（素材の戻りの本体を音程 0.38 で ＋ その 9ms 後に押し込みを 0.60 で）。
   ⚠ **音程を下げると「大きい破片」になる** — 実測で 0.30 まで下げても内蔵スピーカーの損失は
   -0.5dB（重心 2428Hz）＝ この素材の「重み」は下の 1 オクターブにしかない
2. **減り方を dB の折れ線で書く**（`SWARM_FALL_KNOTS`）。最初の 0.15 秒で 5.5dB 落として
   重なりを打ち消し、以後は**画の縁に合わせて折る**（`IntroShatterCurve` の PullAt 0.45 秒 /
   CloseAt 1.50 秒）。⚠ **音だけ別の弧を描かせない**
3. **粒の長さを時間で縮める**（頭 70ms → 尻 22ms）。頭は重なって轟き、尻は破片 1 つが単独で鳴る。
   ⚠⚠ **密度だけで弧を作らない** — 頭の音量は重なりの数で出ているので、密度と一緒に失う
4. **尻の下限を敷く音に合わせる**（最後の粒を -14.0dB）。実測 -14.0 で 1.2〜1.7 秒が
   **-30.9 LUFS** ＝ 敷く音と同じ高さ（かろうじて聞こえる）。-15.5 で -33.6、-19.0 で -34.7 は
   どちらも旧版と同じ「消えた」に戻る

⚠⚠ **揃えるのは「頭 0.5 秒の短期ラウドネス」**（-14.7 LUFS ＝ 旧版と同じ）。
統合 LUFS は**尺と尻の疎さの関数**なので、そこを狙うと「尻を静かにするほど頭を上げる」という
逆向きの力が働く。⚠ 通しの値（-22.1 LUFS）は結果であって目標ではない。

⚠ **素材の一撃は 4 つある**（押し込み / 中間 / 戻りの手前 / **戻りの本体 ＝ いちばん大きい**）。
粒が短くなってからはそこから引く ＝ 重なっても同じ波形でないので色が付かない。
⚠ 尺 **1.70 秒**は 0057 の逆算のまま（次の音が 2.125 秒に鳴り、0.37 秒の静けさを残す）。

- 聴く: `preview_break.wav`（**旧 → 新** を敷く音の上で並べ、そのあと段 4 の通し）。
  ⚠ **敷く音の上で聴く** — 素の無音で聴くと、尻が沈んでいても直っているように聞こえる
- ⚠ **実機未検証**（2026-08-23）。**耳の判定は未確定**

| 一人 / 群れの高さ | -26.0 / -20.0 LUFS | **-36.5 / -30.5 LUFS** |

0117 は「あーそぼーくらいの高さ前後に」で 0.45 まで下げたが、聴いて
「**ちょっと低すぎるかも**」と退けられた。⭐ **抑え方が「低くする」から「遠ざける」へ変わった** —
高さは素材寄りへ戻し、代わりに**ゆっくり笑い、10.5dB 小さく**なった。焼けた基音は 289〜416Hz。

⚠⚠ **一人（3 周 A・B）は背景 2 本のどちらよりも小さい** — 劇伴（-27.7 LUFS）より 8.5dB、
装置の声（-32.0）より 4.2dB 下。声の帯域が違うので消えるとは限らないが、**被って聴くまで分からない**。
埋もれていたら上げるのは `SWELL_SOLO_LUFS` と `CHORUS` の 2 数字。

⚠ 高さの倍率は `ingest-sounds.py` の `LAUGH_PITCH`、速さは `LAUGH_SPEED`（**どちらも 1 数字**）。
下の表の音程（`CHORUS_VOICES` / `SWELL_*`）は「どの人形がどれだけ高いか」の**相対**なので、
ここを動かせば 4 本とも一緒に動く。

⚠⚠ **テープ（`glide`）で高さを変えてはいけない。** テープは速さごと変わるので、
0.45 倍にすると笑いが **2.2 倍長くなり**、31 秒の輪に 9 回置いた 0110 の並べ方
（塊と間・在音率）が「笑いっぱなし」に潰れる。
⇒ **高さと速さは別々に動かす**（`pitch_down` と `time_squeeze`）。表の刻みは 1 つも動かしていない。
⚠ **速さを下げると在音率は上がる**（0118 の 0.79 で 1 回の笑いが 1.27 倍長い）。
どこまで許せるかは調整台の「在音率」を見る — 100% は笑いっぱなし。

⚠⚠ **声色（フォルマント）は元のまま残す**（`keep_formant`・0118 でも 1.00 が選ばれた）。
高さを動かしても**同じ女の子のまま**になる。声色も一緒に動かすと体格の違う別人になり、
**同じ人の声である呼びかけと繋がらない**。

**作りの中で踏んだ罠 3 つ**（どれも耳では気づけず、`sound-lint.py` と実測が出した）:

| 何が起きた | 真因 | 直し方 |
|---|---|---|
| 素材の**頭 5ms に打撃音**が付いた（尖頭 0.00085 → **0.092** ＝ 100 倍） | 重ね合わせの**端で、重みがほぼ 0 の所をその重みで割っていた** | 頭と尻に窓 1 枚ぶんの無音を足してから回す |
| **余韻だけが 2.5dB 痩せた**（本体 -6.5dB に対し余韻 -9dB） | 波形を重ねて繋ぐ方式は、息のようなでたらめな成分を**打ち消して 3dB 失う** | 元の大きさの移り変わりへ戻す（`keep_shape`） |
| 輪の**継ぎ目の密度差が 10dB 悪化**して検査が落ちた | **無音の枠にも包絡の比が掛かり、床の雑音だけが動いていた** | 無音の所は素通し（`floor_db`） |

- ⚠ **波高が 18.5 → 24dB に増える**（声色を戻す ＝ 帯域ごとに濃さを変える処理なので、
  倍音の位相が揃う瞬間が出る）。天井 -3dBTP には当たっていないが、
  `LAUGH_PITCH` をさらに下げるならここを見る
- **物証は `py -3.11 tools/sound-pitch.py`**（基音 Hz と呼びかけとの比）。
  `--gate` が計器そのものを答えの分かる音で通す
- 聴く: `logs/sound/preview_pitch.wav`（呼びかけ → 一人 → 呼びかけ → 群れ → 重ねる）
- **つまみで探すなら [`tools/laugh-lab/`](../../tools/laugh-lab/README.md)**（`serve.ps1` → 8130）。
  鳴らしっぱなしのまま高さ・**声色**・速さ・音量を動かせる。⚠ **卓サーバ（8099）とは別物**で、
  `show.json` も実機も触らない。組み方は `ingest-sounds.py` の関数そのものを呼ぶので、
  **台で聴いた音がそのまま焼ける**（実測: 台と焼いた wav が同じ LUFS・同じ基音）
- ⚠⚠ **音量は「背景を敷く」を押した状態で決める**（既定 ON・0118 で足した）。
  無音の上で決めた -10.5dB は、実機では劇伴（-27.7 LUFS）と装置の声（-32.0）の下に沈む。
  割れる音の「⚠ 敷く音の上で聴く」と**同じ罠を、この台が作っていた**
- ⚠ **実機未検証**（2026-08-23）。**耳の判定は未確定** — 「まだ高い」「下げすぎ」は
  どちらも `LAUGH_PITCH` の 1 数字で動く（下げるほど小さい値）

### 人形がたくさん出てくる所（2026-08-16・`canon/LEDGER.md` 0062 / 0064 / 0066）

**最後の演出で人形が並ぶあいだ、いろんな人形が笑い続ける。** もらった笑い声 1 本から、
**8 体の人形が 40 回**笑う 12 秒の輪を組んである（`tools/ingest-sounds.py` の `CHORUS_VOICES`）。

| 何 | 値 |
|---|---|
| 人形 | **8 体**。音程（0.68〜1.48 倍）と左右の位置が体ごとに固定 ＝ そこに立っている。⚠ この倍率は**表の値**で、実際はさらに `LAUGH_PITCH`（0.45）が掛かる（0117） |
| 笑う回数 | 12 秒に **40 回**（刻み約 0.30 秒） |
| 同時に笑っている数 | **本体で約 4 体**（余韻こみで約 10）。⚠ ここがユーザーの言う「体数」 |
| 音程のカーブ | 体ごとに上がる / 下がる（0.68 → 0.74 など）。速さごと変える |
| 全体 | 12.0 秒の輪 / **-20 LUFS** |

⚠⚠ **これは一撃ではなく敷く音の器に載っている**（`SoundBedLogic.dolls` / `bed_dolls_laugh`）。
**報告を押すまでループ**するので、`ev=sfx` には出ない。観測は `ev=sum` の **`sndDolls`**。

⚠⚠ **輪は「折り返し」ではなく「円環」で作る。** はみ出した声を頭へ回り込ませているので、
どの瞬間も同じ密度で、継ぎ目は数学的に消える。
**尻を頭へ混ぜる方式（`fold_loop`）では駄目だった** — 頭と尻が薄いぶんそこだけ密度が落ち、
1 周したことが分かる（実測: 端 -36dB / 中 -22dB。円環にしたら振れ 3.8dB）。

⚠ **山も谷も作らない。** 盛り上げたり減らしたりすると、巻き戻るたびに同じ波が来て
「繰り返している」と分かる。

⚠ **8 体の並びは 5 通りを持ち回り、刻みの揺らぎは 11 個・音量の揺らぎは 7 個**で回す。
長さが互いに素なので 40 回のあいだ同じ組み合わせが戻らない
（8 体を同じ順で回したら 2.4 秒周期の拍が聞こえた）。

⚠ **鳴る場所を「4 周目 A」と名指ししない。** 読むのは
**`TimelineDirector.IsWaitingForVisitorMark`**（締めのカットが報告を待っているあいだ）で、
`CommsCueLogic` の③と**同じ signal**。著作が変わっても追随する。

⚠ **劇伴は鳴っているあいだずっと退く**（`SoundBedLogic.DollsDuck` = 0.85）。
一撃の退き（`PushSpotDuck`・0.55 秒で戻る）とは別の経路。

⚠ **鳴り始めは輪の同じ所から**（`CueAmbientStart(fraction: 0)`）。頭出ししないと
体験者ごとに違う所から笑い出して、走行の再現性が消える。

⚠⚠ **体数を増やすときは 2 つ見る** — 「同時（本体）」と「聞き分けられそうな山」。
いまは本体 4 体 / 65 山（40 回 × 約 1.6 音節）。**山が回数を大きく下回ったら混ざっている。**

### 入れ替わった人形（3 周目・2026-08-18・`canon/LEDGER.md` 0087）

**映像の中で体験者が人形に入れ替わった瞬間から、その人形が笑い出す。**
音源は 4 周目 A の群れと同じ 1 本で、作り方も同じ（1 声ずつ表に書く・輪にして書く）。

| 区間 | 何が鳴るか |
|---|---|
| **3 周目 A**（入れ替わりのカット） | **一人**（`bed_doll_one`・**31 秒の輪に 9 回**・1 体ぶん -26 LUFS） |
| **3 周目 B** | 同じ一人（まだ増えない） |
| **3 周目 C** | 9 秒かけて `grow_a`（2 体）→ `grow_b`（4 体）が重なりながら入る。**全部で -23.2 LUFS** |
| **4 周目 A** | **群れだけ**（`bed_dolls_laugh` -20 LUFS）。一人ぶんは黙る。⚠ **報告を押したら劇伴と装置の声だけになる**（0115） |

⚠ **増え切るまでの 9 秒は実測の滞在（8 秒）に合わせた値。** 14 秒では増え具合が 0.47 までしか行かず、
**3 枚目が 1 度も入らなかった**（`SoundBedLogic.SwellRiseSec`）。

⚠⚠ **「増える」は層を足して作る。1 枚を大きくしない。** 音量を上げると
「人形が**近づいてくる**」に聞こえて、**数が増えたことにならない**。
2 枚目は増え具合 0〜0.55、3 枚目は 0.45〜1.0 に割り当ててあり、重なるので段が付かない。

⚠⚠ **1 枚ずつ狙いの LUFS へ揃えない**（`swell_build` が 1 枚目の倍率を 3 枚へ掛ける）。
1 枚ずつ合わせると**枚数が増えるほど 1 体が小さくなり、足したのに増えて聞こえない**
（実測: それをやったら 3 枚重ねても高さが 0.2dB しか動かなかった）。

#### ⚠⚠ 一人ぶんは「毎回すこしずつ違う」（2026-08-23・`canon/LEDGER.md` 0110）

ユーザー赤入れ「3-A,B では笑い声を一人分ループさせているが、**あまりに同じ音、同じ周期過ぎて、
一人というよりもただのループ音にしか聞こえない**。毎回、すこしずつ違うようにして、
一人分の笑い声だけど自然な感じにしてほしい」。

**原因は 4 つ、どれも「同じ声が同じ形で戻ってくる」ことだった。**

| | 旧 | 新 |
|---|---|---|
| 輪の長さ | 19 秒 ＝ **A と B の 30 秒で 1.5 周する** | **31 秒**（素数）＝ **1 周もしない** |
| 笑いの長さ | 毎回同じ（ばらつき **2.5%**） | **ばらつき 28.8%** |
| 間隔 | ほぼ等間隔（ばらつき **8.9%**） | **ばらつき 29.7%**（塊と間） |
| 音程 | 1.06〜1.16（±5%） | 0.98〜1.26（中心 1.12 は不変） |
| 左右 | **9 回とも +0.16 で固定** | +0.10〜+0.24（中心 +0.17 は不変） |

⚠⚠ **主因は「毎回まるごと同じ音節を鳴らしていた」こと。** 素材は「うふふふふ」＝
**本体 0.05〜0.80 秒に 5 音節、そのあと余韻 1.2 秒**。旧版は 5 回とも素材を丸ごと使っていたので、
**音程と音量を振っても「同じ長さの同じ笑い」**だった。人は同じ長さで笑わない。

⇒ **頭を落として音節の数を変える**（`ingest-sounds.py` の `syllable_skip`）。
落とす所は音節の谷（実測 0.15 / 0.30 / 0.50 / 0.66 秒）:

```
skip 0.00 → うふふふふ（5）   0.15 → ふふふふ（4）   0.30 → ふふふ（3）
skip 0.50 → ふふ（2）         0.66 → ふ（1）
```

- ⚠⚠ **尻を切って短くしてはいけない。** 余韻が消えて**ぶつ切りの乾いた音**になる。
  頭から落とせば**余韻は必ず付いてくる**（最後まで使うので）
- ⚠ **中心を動かさない。** 音程・左右の幅は広げてよいが、中心をずらすと**別人**になる。
  左右は頭を振る程度に留める — 大きく振ると「歩き回っている」になり、
  映像の中で立っている人形と食い違う
  ⚠⚠ **2026-08-23 に、ユーザーがその中心を動かした**（0117・「あーそぼーくらいの高さ前後に」）。
  動いたのは **4 本まとめて**（`LAUGH_PITCH`）なので、**人形どうしの関係は 1 つも変わっていない** —
  「中心を動かすと別人になる」は**この表の中で 1 体だけずらすな**という話で、
  全部を同じだけ下げるのはその外側。⚠ 表の数字（0.98〜1.26 / 中心 1.12）はそのまま残してある
- ⚠ **間隔を均さない。** 人は「ひとしきり笑って、間が空いて、また笑う」。
  塊（1.5〜2.8 秒）と間（4.5〜5.6 秒）を交互に置き、**同じ間隔を 2 度使わない**
- ⚠ **乱数を使わない**（`CHORUS` と同じ流儀）。9 回を 1 行ずつ表に書く ＝ 同じ版なら同じ波形

⚠ **3 枚のループ長は 31 / 13 / 17 秒**（どれも素数）。同じ所で巻き戻るとそこだけ「1 周した」と分かる。
この 3 つなら 6851 秒（114 分）戻ってこない。1 枚目だけ長いのは、A と B を合わせて
**30 秒ほど同じ 1 体だけが鳴り続ける**から。

⚠ **間を詰めない。** 笑いは余韻が 2 秒あるので 2.7 秒刻みで置くと**笑いっぱなし**になる
（実測: 11 秒に 4 回で在音率 76%）。31 秒に 9 回 ＝ 3.4 秒に 1 回で、旧（3.8 秒に 1 回）より
**頻度は上がっているのに在音率は下がる** — 短い笑い（1〜2 音節）が混ざるため。

⚠ **聴いて判定するのは `preview_swap.wav`**（A + B の **24 秒**を通しで鳴らす）。
`preview_materials.wav` の 11 秒では輪の 1/3 しか聴けず、**ループに聞こえるかを判定できない**。

⚠ **鳴る場所を「3 周目」と名指ししない。** 読むのは **`ShowCgLayer.DollVisible`**
（映像の中に**人形**が立っているか）で、群れが `IsWaitingForVisitorMark` を読むのと同じ構え。
⚠⚠ **`IsVisible` では駄目**（2026-08-22 に実機で踏んだ）。持続の覆い（`swapHold`）と
ほどける段は**人の代役**を立てるので、IsVisible だと黒に包まれた「まだ人形でないもの」に
人形の笑いが付く（実測: 2 周目 C の保持で sndSwap 0 → 2.29 / swell 0 → 0.71）。
笑い出してよいのは晴れて実体が出た縁（swap の settle）だけ。
⚠ ただし**増えるのは C だけ**なので、そこは区間のカメラ（`TimelineDirector.CurrentCamera` == 2）を読む。

⚠ **区間の継ぎ目で 1.5 秒は笑いを保つ**（`SoundBedLogic.DollHoldSec`）。3 周目は区間ごとに
別の演出が走るので、カットの入れ替わりで人形が数フレーム消える。保持が無いと A → B → C の
継ぎ目で 3 回途切れて、**人形が消えて戻ったように聞こえる**。

⚠ **劇伴の退きは 0.45**（群れの 0.85 より浅い）。3 周目はまだ山ではない。
⚠⚠ **2026-08-23（0115）で劇伴が本編へ戻ったので、この退きは実際に効いている。**
0088 のあいだは引く相手が居なくて眠っていた値で、**聴いて決め直すならここ**。

⚠ **一撃の退き（`SpotBedDuck`）を掛けない。** 3 周目は切替の一撃が 9 回以上入るので、
掛けると**笑いが切替のたびに凹む**。

⚠⚠ **2026-08-22 から、カメラを動かさない素材カットでも切替音が鳴る**（`canon/LEDGER.md` 0102）。
2 周目 C の接近は 0.5〜1.2 秒刻みで **7 発**並ぶので、**1 回の体験の切替音は 9 発から 16 発へ増えた**。
鳴らすかはカットの `switchSfx` が持ち、**画を差し替えるのと同じ行から**撃つ
（毎フレーム状態を見る `SoundCueLogic` では取りこぼす — 連絡の面の打鍵と同じ構え）。

#### ⚠⚠ 切替音は「毎回すこしずつ違う」（2026-08-23・`canon/LEDGER.md` 0112）

ユーザー指示「**カメラが切り替わるときの音を毎回同じではなく、加工して毎回違うようにしたい**」
「**使う音声素材を増やすのではなくうまく加工して**」。

**音源は 0057 でもらった 1 本のまま。そこから変種 6 本を焼く**（`ingest-sounds.py` の `SWITCH_VARIANTS`）。

**素材の中身**（実測・238ms）:

- 立ち上がりは **5.5ms に 1 つだけ**。-10dB へ 15ms、-20dB へ 75ms
- **尾に二次の粒が 4 つ**（56 / 71 / 77 / 96ms ＝ -19 / -20 / -22 / -28dB）。
  110ms より後はほぼ床（-33dB 前後）で、**そこを切っても聴感では変わらない**
- 重心は 8522 → 2668Hz と落ちる

⇒ **頭（0〜50ms）は毎回そのまま置く。**そこがこの音の身元で、変えると別の装置になる。
変えるのは**尾の来る時刻・長さ・高さ・音程** ＝ がらがら鳴る粒がいくつ・いつ来るか。
0110 で笑いの「音節の数」を変えたのと同じ手で、**素材の中にある構造を使う**。

| 変種 | 尾の粒 | 覚え書き |
|---|---|---|
| 1 | 4 | 素のまま（基準・旧ファイルと同じ姿） |
| 2 | 1 | すぐ止む |
| 3 | 3 | 低くて、尾が遅れて来る |
| 4 | 2 | 尾が早く、高い |
| 5 | 4 | 低くて、尾が長い |
| 6 | 0 | 乾いた 1 発（尾なし） |

- ⚠⚠ **1 本ずつ高さを揃えない。** ラウドネスは**尺の関数**なので、尾を短くしただけの変種が
  「短いぶん平均が高い」と判定されて小さく絞られる（`CUTS` の教訓と同型で向きが逆）。
  揃えるのは**頭 35ms の実効値**で、そのあと **1 本目で決めた丸めと倍率を 6 本すべてへ掛ける**
- ⚠ **左右は振らない。** この音は `spatialBlend=0`（装置の音）で、耳の脇の内蔵スピーカーでは
  可聴差にならず、素材の `mono_db -2.52`（下限 -3.5）を削るだけになる
- ⚠⚠ **警告つき（0106）も同じ 6 本に対応して焼く。** 素だけ変種にすると、
  **いちばん連続して鳴る 2 周目 C の 5 発が「毎回同じ」に戻る**。
  警告音の高さは**常に 1 本目を基準**にする（土台ごとのラウドネスを基準にすると、
  尾の短い変種で警告だけが 6dB 大きくなり、0106 の「あくまで通常の切り替え音がメイン」が崩れる）
- ⚠ **選ぶのは「直前と同じものは引かない」**（`TypeAudioCue.Pick` と同じ流儀・素と警告つきで番号を共有）。
  **袋（1 巡で全部使う）にはしない** — ラン跨ぎの状態を持つと、2026-08-15 に踏んだ
  「落とす経路の呼び出し元がどこにも無く、2 人目以降だけ挙動が変わる」型に当たる
- ⚠ **実行時の散らし（音程 ±3.5% / 音量 ±1.5dB）はそのまま残す。** 変種は粗い違い、
  実行時の散らしは連続の違いで、役割が別
- ⚠⚠ **合成で変種を作らない。** 6 本とももらった音源 1 本から出ている

### 印字の打鍵（2026-08-16・`canon/LEDGER.md` 0056 / 0063）

**1 文字が出るたびに 1 発鳴る。** **装置が印字している音**なので §1 の 2 層に収まる。

**鳴る面は 2 つ**（どちらも同じ装置なので、**同じ音源・同じ速さ**を使う）:

| 面 | いつ | 字数 |
|---|---|---|
| **AIエージェントからの連絡**（`CommsPanel`） | 本編。1 通ごと | 10〜13（打つ尺 0.83〜1.75 秒） |
| **終幕の報告**（`OutroReport`・0063） | 段 `Report` の頭から | **41**（打つ尺 **3.4 秒**） |

⚠ **速さを面ごとに変えない。** 同じ装置が違う速さで打つと、装置が 2 台あるように聞こえる。
どちらも `CommsPanelLogic.CharsPerSec` を読む（終幕側も**その定数をそのまま参照する** —
複製すると片方だけ直したときに黙って食い違う）。

| 何 | 値 | なぜ |
|---|---|---|
| 1 文字あたり | **1 発**。改行では鳴らさない | `maxVisibleCharacters` は改行も 1 文字として数える。鳴らすと字が出ないのに音だけ鳴る |
| 間隔 | **83ms（12 文字/秒）**・規則的 | ⚠ **これは `CommsPanelLogic.CharsPerSec` そのもの。** 22 だった頃の 45ms 間隔では 1 発ずつが分かれて聞こえず、カタカタではなく連続音になる（分けて聞けるのは 15〜20 発/秒あたりまで） |
| 音 | 8 種を**直前と同じものを引かずに**選び、音程 ±4% / 音量 ±2dB を散らす | 1 通で 10〜20 発並ぶ。同じ波形が続くと装置ではなく「効果音」に聞こえる |
| 音量 | **連ねて -32 LUFS**（1 発ずつは -29〜-33） | ⚠⚠ **2026-08-23 に -28 → -32 へ下げた**（0115・「エージェントがカタカタする音が大きい。小さくして」）。**敷く音と同じ高さ** ＝ 装置の音の中で打鍵だけが上に立つのをやめた。背景の劇伴（-27.7 LUFS）より 4.3dB 下。⚠ **決め所は `ingest-sounds.py` の `CUTS` 1 か所**（`TypeAudioCue` では倍率を掛けない）。まだ大きいと言われたら次は -36 |
| 劇伴のダッキング | **しない** | 節目の一撃は鳴るたび劇伴を引かせるが、12 回/秒でやると劇伴が波打つ |

⚠⚠ **鳴らすのは `CommsPanel.Apply` と `OutroReport.LateUpdate`** — **字を画へ書いているのと
同じ行**から [`TypeAudioCue`](../../Assets/Scripts/Streaming/Sound/TypeAudioCue.cs) を叩く。
`SoundCueLogic` には入れない（毎フレーム外から状態を見る層なので、1 秒に 12 回・字の刻みには
間に合わない）。カメラ切替が `SwitchAudioCue` を直接叩いているのと同じ理由。
**絵と音が同じ数えから出る**のでずれようがない。
⚠ **`TypeAudioCue` は面ごとに 1 つ**（それぞれの GameObject が持つ）。累計を別々に数えるので、
どちらが鳴っていないかがログで分かれる（`typeN` / `repTypeN`）。

⚠ **1 フレームで 2 字進んでも 1 発しか鳴らさない。** 同じ DSP 時刻に 2 発重なると
1 つの大きな音に潰れる（コマ落ちのときだけ音が変わる、という追いにくい壊れ方になる）。

⚠ **素材は「押し込み」だけ**（§4.5 の `CUTS`）。もらった録音は 1 打が
「押し込み → 76.9ms 後に戻り」の二山だが、**戻りが居るべき所には次の字の押し込みが来る**ので
捨ててある。両方入れると 24 発/秒 ＝ 連続音に戻る。

⚠ **速さを変えるなら素材を切り直す。** 切り出しは 60ms（`ingest-sounds.py` の `CUT_BODY`）なので、
間隔をそれより詰めると前の打鍵が鳴り終わる前に次が重なる。
`CommsPanelLogicTests.TypingSpeed_KeepsKeystrokesApart` が下限を固定している。

  **線が 1 本まっすぐ落ちる音そのもの**なので純度 0.86 / 突出 28.9dB が出る。
  これは「発振器に聞こえる」のではなく実物がそうなので、通すために作り変えたら §4.5 違反
- ⚠ **決めごと 4「終わりに音を残さない」は生きている。** 鳴るのは頭の 1.29 秒だけで、
  `Dark` の途中には消えている。最後に鳴っているのは無音のまま

⚠ **打鍵は従来どおり**（2026-08-16・0063）。報告の 41 字を打つあいだは装置が印字している音が鳴り、
打ち切ったら無音へ戻る。**新しい音源を持ち込んでいない**（連絡の面と同じ 8 種）ので、
「終幕に音を足す」ではなく「装置がまだ 1 つだけ仕事をしている」の側。

#### ⚠⚠ 終幕の音は「段」を読まない（2026-08-23・`canon/LEDGER.md` 0111）

ちかちか（`OutroStage.Flicker`・6 秒）が**電源断**（`Collapse`・0.9 秒）へ置き換わった。
音側で守ることが 2 つある。

- ⚠⚠ **段名で分岐しない。** 旧実装は `st != OutroStage.Flicker` で切っていたので、
  **段名を変えた瞬間に終幕が丸ごと無音**になる形だった。画は正しく落ちるので**実機で聴くまで
  気づけない**。いまは `SoundBedLogic.OutroDevice` / `OutroRoom` が
  **終幕の頭からの経過**（`SoundShowState.outroElapsedSec`）だけを読む。
  `SoundBedLogicTests.Outro_SoundDoesNotDependOnTheStageName` が固定する
- ⚠⚠ **段の進み（`StageProgress01`）を音のランプに使わない。** 段相対なので、段の尺を
  6.0 → 0.9 秒に詰めた時に**音だけが黙って 6.7 倍速くなる**（部屋の音が「せり上がる音」として
  聞こえる ＝ 誰も決めていない変更）。尺は音が自分で持つ —
  `OutroDeviceFadeSec` 1.5 秒 / `OutroRoomRiseSec` 2.0 秒
- ⭐ **音は画より少し遅れて終わる。** 画（潰れ）は 0.9 秒で落ちるが装置の声は 1.5 秒かけて引く。
  同時に切ると「ぶつっと切れた」になる。3 分鳴り続けた唸りが消えること自体が終幕の音で、
  **新しい音源は 1 本も足していない**

⚠ **消え方そのものを音へ写さない。** 旧ちかちかで踏んだ型と同じ — 画の細かい動きを音量に掛けると
「そう見えている物の音」ではなく歪みとして乗る（しかも 90Hz のフレームで階段状に切り替わると
クリックが出る）。写すのは**痩せていく方だけ**で、消え方は画が担う。

### 4 つの決めごと

1. **音は絵より先に来る。** 装置の声は段 2（色が抜ける）で入り始め、画が映像になるのは段 5。
   これが 13 秒を「1 つの出来事」として繋ぐ（切替の J カットと同じ考え）
2. **隔離は音量ではなく帯域で表す。** 段 5 で会場が黒へ落ちるとき、部屋の音は
   **小さくならず狭くなる**（`AudioLowPassFilter` を 22kHz → **420Hz**）。
   ⚠⚠ **閉じる縁は「パススルーが消える」こと**（`introWeights.passthrough` 1 → 0・2026-09-04）。
   0044 で隔離が閉じる段が無くなってから `shell` は導入の全段で 0 のままで、
   **2026-08-15 から 09-03 まで帯域は 1 度も閉じていなかった**（`sndLpf=22.0` が全標本。
   `analyze-xp-log.py` が毎回「部屋の帯域が動いていない」と警告し、誰も読んでいなかった）。
   いまの導入で会場が消えるのは段 5（映像だけになる）なので、そこで閉じる。
   終幕は現実へ返す段なので読まない（`SoundBedLogicTests` が固定）。
   ⚠ **周波数は対数で写す。** 線形補間だと閉じ切っても 9.9kHz までしか下がらず、
   部屋のトーンは 4kHz より下が主なので**何も起きていないのと同じ**になる（実機で踏んだ）。
   音量を下げると「遠ざかった」、帯域を閉じると「閉じ込められた」に聞こえる
3. **タイトルの音は導入の尾を切らない** — 題字が消えた後も鳴り続けて、
   パススルーへの継ぎ目を音が跨ぐ。⚠ 2026-08-15 まではここに**封印の箱の唸りを黒の下で
   先に鳴らす**（J カット）があった。箱を退避したので消え、
   **2026-08-23 からは劇伴が黒の下から本編まで続く**（0115）ので、
   一撃も劇伴も**黒から導入へ跨ぐ**。渡さないものは無い。
4. **終わりに音を残さない。** 最後に鳴っているのは無音が正しい
   （`~/.claude/rules/work-style.md` §4「決め台詞で締めない」の音版）

⚠⚠ **2026-08-23 にユーザーが「うまく加工して」と明示した**（`canon/LEDGER.md` 0112・
切替音の変種と割れる音の作り直し）。**開いたのは「加工」であって「別の音にすること」ではない** —
掛けてよいのは**切り出し・並べ方・音程・音量・左右・端の処理**までで、
**イコライザ・圧縮・残響は 1 つも足していない**。上の表の 6 系統がその語彙そのもので、
ここを越えるものは従来どおり `TAME` / `VOICES` の**明示的な例外**（ユーザーが耳で聴いて指示したとき）だけ。

⚠⚠ **例外はユーザーが耳で聴いて指示したときだけ**（`ingest-sounds.py` の `TAME`）。
2026-08-16 に鈴（`amb_bell`）の 4.2kHz より上を 10dB 落とした — ユーザー指示
「高すぎるところをカットして聞きやすいように」（`canon/LEDGER.md` 0057）。
**シュビーの判断で足さない。** 足したら 1 か所（`TAME`）に集めて、誰の指示かを書く。

⚠⚠ **切り出しは 1 発ずつ正規化しない。全部に同じ倍率を掛ける。** 1 発ずつ揃えると、
素材が持っている打鍵の強弱（実測で 3.3dB の幅）が消えて、等間隔・等音量で鳴る機械の音になる。
高さは**連ねた状態で測る**（`cut_strokes` が 12 発/秒で並べて -28 LUFS へ合わせる）—
1 発の LUFS で揃えると、実際に耳へ届く「打っているあいだの高さ」から外れる。

⚠ **減衰の終わりを自動で探さない**（2 回外した）。「無音が続く所」は押し込みと戻りのあいだに
**無い**（床が -35〜-42dB ある）ので戻りを飛び越し、「いちばん静かな所」は減衰の途中の
**孤立した 0 標本**を掴んで 24ms でぶつ切りにした。いまは長さを決め打ちにして、
**戻りの山まで余裕があるかを機械で確かめる**（足りなければ言う）。

⚠⚠ **もらった音が実機のスピーカーで消えることがある**（2026-08-15・`canon/LEDGER.md` 0047）。
タイトルの `sfx_title_in` を Bass Downer へ差し替えたら **内蔵SP -12.3dB**（下限 -10.0）で
`sound-lint.py` が NG を出した。正体が 200Hz より下にある音は、ヘッドホンでは立派に鳴るのに
**Quest の内蔵スピーカーでは存在しないのと同じ**になる（§2）。
**イコライザで直さない** — それはユーザーが選んだ音を別の音にすること。
できるのは音量を上げることだけで、それも聴いてもらってから決める。

⚠ **合成が苦手なもの**（細かい不規則さが本質になっている音 — 家鳴り・息・衣擦れ・実物の鈴）は
**頼む**。依頼の形は `docs/sound-wishlist.md`。

### 合成の原則（`tools/soundkit.py`）

- **ループは周波数領域で作る。** `loop_noise` は円環なので巻き戻りが**数学的に**継ぎ目ゼロ。
  時間領域で作って端をクロスフェードする方法より厳密で、中身も削らない
- **周期成分の周波数はループ長の整数倍へ丸める**（`loop_freqs`）。丸めないと位相が飛ぶ
- **変調は「秒」ではなく「ループあたり何回転」で指定する**（`loop_lfo`）
- **乱数種は固定。** 同じ版のスクリプトは同じ波形を出す（音を変えていないのに差分が出ると、
  何が効いたのか分からなくなる）

### 検査の合否（`tools/sound-lint.py`）

| 指標 | 線 | 何を見ている |
|---|---|---|
| `true_peak_db` | ≤ **-3.0** | 標本間のピーク。ここを見ないと数値上 -1dB でも実機の変換で歪む |
| `mono_db` | ≥ **-3.5** | モノにしたときの損失。-3dB は無相関の理論値なので、それより悪ければ**打ち消し** |
| `speaker_db` | 敷く音 ≥ **-6** / 一撃 ≥ **-10** | 内蔵スピーカーで残るか（200Hz 2 次×2 ＋ 12kHz の近似）。敷く音は 3 分間ずっと聞こえていなければならないので厳しい |
| `sharp` / `rough` | §3.5 の表 | 不快にならないか |
| `tonal_db` | 合成音 ≤ **25**（実録は判定外） | 定常の純音が立っていないか（§3.6） |
| `purity` | 合成音 ≤ **0.60**（実録は判定外） | **掃引する純音**が居ないか（§3.6） |
| `dc` | ≤ 0.002 | 直流。音にならず可動域だけ食う |
| ループの継ぎ目 `jump` | ≤ **3.0** | 巻き戻りの飛び ÷ **継ぎ目の周りの**隣接標本差 |
| 継ぎ目の密度差 `rms_d` | 6dB 超**かつ**素材の中の最大を超えたら NG | まばらな素材（数秒に 1 度笑う輪）は継ぎ目で +55dB 出るが、同じ跳ね上がりが輪の中で何度も起きている。**生の値では見ない**（2026-08-18） |

⚠ **これは耳の代わりであって耳ではない。** 全部緑でも「怖いか」「間が持つか」は
何も言っていない（`reference/why.md`「品質を採点しない」）。**落とすためだけに使う。**

⚠ **数値が緑でも絵を必ず開く。** 2026-08-12、`bed_seal` は全指標が緑のまま
「波形がほぼ平坦＋棘だけ」＝ 唸りではなく時々鳴る音になっていた（波高率 21.4dB）。
`Assets/Screenshots/sound/<名前>.png` を開けば一目で分かった。

**体験が終わった時点では 0 が正しい**。走行の最後の行だけを読むと
「3 周目に人形が笑わなかった」に見える（実際は 3 周目 C で `sndSwap` が 2.19 まで立っていた）。

- **一撃（`ev=sfx` / `sfxN` / `swN` / `typeN`）は累計なので最後の行でよい。** 両者を混ぜない
- ⚠ **ループする音は `ev=sfx` に 1 行も出ない**（鳴らす縁が無く、音量を出し入れするだけ）。
  だから「最大値を取る」以外に鳴ったかを知る方法が無い
- `analyze-xp-log.py` は最大値で判定している（「入れ替わった人形が笑った（sndSwap 最大 2.19）」）。
  **手でログを見るときだけこの罠に落ちる**

⚠⚠ **音が 0 でも、まず素材の側を疑う**（2026-08-23・0109 の実例）。
`ev=sfx id=DollCall` と `swAlert` が**揃って 0** だったので配線を疑ったが、真因は
**そのカットの素材（当日撮る人形視点）がまだ無く、カットごと飛ばされていた**こと。
実機ログの `[TakeRunner] clip だが素材が解決できない → このカットを飛ばす` が唯一の手掛かりだった。

- **切り分け**: その音と**同じカットに乗っている別の音**を見る。
  **両方 0 なら素材の側 / 片方だけ 0 なら配線か音源**（`pov_4` には呼びかけと切替音が同居している）
- **`sndBuilt` の右が 0 なら音源は全部掴めている** ＝ 音源の問題ではない
- ⚠ **当日まではその 0 が正常**。実装の証拠にも反証にもならない

⚠⚠ **「1 度だけ鳴る」は導入の段 0 へ入った縁で落ちる**（2026-08-15 に直した）。
それまで落とす経路は `SoundCueLogic.ResetRun()` だけで、**その呼び出し元がどこにも無かった** ＝
**アプリを起動してから 1 人目だけ導入の音が鳴り、2 人目以降は隔離も管の点灯も鈴も終幕も無音**だった。
展示は 1 日に数十人が続けて体験するので、**ほぼ全員が無音の側に当たる**。

- **画は正常なので気づけない。** 音は録画に映らないので、走行の証拠（PNG・動画）からは永久に出ない
- **既存のテストも捕まえられなかった** — `ResetRun_ClearsEveryLatch_...` は
  「`ResetRun` を呼べば鳴る」を確かめており、**呼ぶ前提を自分で作っていた**
- ⇒ いまは段 0（`IntroStage.Black`）へ入った縁で自分で落とす。段 0 はランリセットでも
  中止からの復帰でも必ず通るので、**号令を配る側の実装に依存しない**。
  `SoundCueLogicTests.SecondVisitor_HearsEverything_WithoutAnyoneCallingResetRun` が固定する

## 8. 触るときの手順

1. `canon/LEDGER.md` を読む（世界観の判定はそこにしか無い）
2. 音を変える → `make-sounds.py` → `sound-lint.py` が緑 → **PNG を開いて絵を見る**
3. 混ざり方を変える → `SoundBedLogic` と**この文書の §4 の表**を対で直す → `unity.ps1 test`
4. 節目を足す → `SoundCueLogic` の enum ＋ `ResourceName` ＋ 音源 ＋ テスト（**音源が無い節目を作らない**）。
   ⚠ **1 秒に何度も鳴るものはここに入れない** → §4「連絡の面の打鍵」の構え（叩く側が直接鳴らす）
5. 観測を足す → `ShowTelemetryHost` と `analyze-xp-log.py` を対で
6. `menu sound-import` → `menu scene` → ビルド
7. `sound-preview.py` を回して **ユーザーに聴いてもらう**（`skills/direction-round`）

⚠ **切替音の変種を増やす / 減らすときは 4 か所を対で直す**（0112）:
`ingest-sounds.py` の `SWITCH_VARIANTS` / `SwitchAudioCue.DefaultVariantCount` /
`analyze-xp-log.py` の `SWITCH_VARIANTS_WANT` / `sound-preview.py` の `SWITCH_VARIANTS_N`。
**焼き直しは素と警告つきの両方**（`--only sfx_switch_1` で両方付いてくる）。

## やってはいけないこと

- ❌ **劇伴を「増やす」。** 本編で同時に鳴っていてよいのは **1 本だけ**（0115）。
  ⚠ **曲が 2 本あるのは矛盾ではない** — `HorrBGM` と `LostPlace2` は
  **追いつきの 1 点で入れ替わる**（0119）のであって、区間ごとに変わるのではない。
  区間ごとに曲を変えると、0115 が退けた「周ごとに背景が変わる」に戻る
- ❌ **劇伴に穴を開ける。** ユーザーが言ったのは「流れ続ける背景」。段でも周でも切らない
- ❌ **驚かせるための突発音（ジャンプスケア）を置く。** この作品の恐怖は信頼の上に乗っている
- ❌ **正体を 200Hz より下に置く。** 実機で存在しないのと同じになる
- ❌ **遅延で広がりを作る。** モノにすると消える
- ❌ **周回で音まで単調に汚す。** 落とすのは解像度だけ（LEDGER 0012「落とすのは解像度だけ」）
- ❌ **一段ずつ落とす音を作る。** 劣化を名指ししてしまう
- ❌ **もらった音にイコライザ・圧縮・残響を掛ける。** 0112 で開いたのは切り出し・並べ方・音程・音量まで
- ❌ **合成音を変種として混ぜる。** 切替音の 6 本はすべてもらった音源 1 本から出ている
- ❌ **数値が緑だから完了と報告する。** 絵を開き、人に聴かせるまでが 1 周
  （`rules/visual-verification.md` §10 の音版）
