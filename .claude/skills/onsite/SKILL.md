## 開場前（設営が終わったら 1 回）

```bash
py -3.11 tools/onsite.py check --deep
```

`--deep` は heartbeat を 20 秒サンプリングする。**Quest を本番と同じ台数だけ起動してから**回す
（起動していないと音・コントローラ・目の写真の行が出ない。出ないのが正しい —
⚠ 卓は最後に受け取った heartbeat を何時間でも返すので、**古い値で判定させない**ためにこちらで捨てている）。

### この 4 つは check にしか出ない

1. **無線 adb が開いているか**（`<ip>:5555`）。閉じていると**当日その端末を 1 手も直せない**。
   開けるのは USB を挿して `py -3.11 tools/onsite.py adb-open`。⚠ **端末を再起動すると閉じる**

   ⭐ **PC を再起動しただけなら USB は要らない。** 端末側の `:5555` は開いたままで、
   切れているのは PC の adb サーバの接続だけ。繋ぎ直すのは 1 行（2026-09-05 実測・3 台とも即復帰）:

   ```bash
   for ip in 192.168.10.21 192.168.10.22 192.168.10.23; do adb connect $ip:5555; done
   ```

   ⚠ `adb devices` に `offline` で残っていることがある。その時は `adb disconnect <ip>:5555` してから繋ぎ直す
2. **傾きと較正の差**。40° ずれていた実績がある（そのとき CG 人形が盛大にずれた）。
   ⚠ 傾きが合っていても位置と左右の向きは分からない（[[camera_fleet]]）
3. **端末に入っている APK が焼いたものと同じか**。古い機に当たると「実装が効いていない」の顔で出る
4. **露出ロック**。素材を撮った時と本番で色が変わる。設営と照明が決まってから端末の 🔓 を押す

### ⚠⚠ 配信スマホは 3 台とも充電ケーブルを挿す（2026-09-05 リハで 2 回落ちた）

**画面が消えると配信が止まる。** そして「画面が消えない設定」（`stay_on_while_plugged_in`）は
**充電中しか効かない**。挿さっていない端末は `screen_off_timeout` の 30 分で画面が落ち、
**アプリは生きたまま配信だけ止まる**（`ps` にプロセスは出る。`/health` だけが無応答になる）。

リハではカメラ C が挿さっておらず、30 分おきに 2 回止まった。電池は 74% あった。
⇒ **点検で見るのは残量ではなく「充電されているか」**:

```bash
adb -s <ip>:5555 shell "dumpsys battery | grep -E '^  (AC|USB) powered'"   # true が要る
```

⚠ **素材撮りの直前だけは逆に抜く**（熱段を 0 にする）。挿すのは回しているあいだ、抜くのは撮る直前。

### 据え直したら較正を取り直す

リハでカメラ B が **7.9°** ずれたままだった（点検の「較正」行が名指しする）。CG 人形がその分ずれる。
⚠ **B の端末を人形視点の撮影に借りると、戻したとき較正が壊れる。** 借りるなら据え付ける前に撮る。

```bash

print(sorted(set(re.findall(r'pov_\d_t\d+_\d{8}_\d{6}\.mp4', s))))"
```

**5 本すべてが今日の日付**であること。1 本でも違えば、端末とファイル名を名指しして採り直す
（卓の `/shoot/pull` → `/shoot/adopt` に `host` と `name` を渡す）。

## ⚠⚠ 全部いっぺんに落ちたら、卓の PC を先に見る（2026-09-05 リハで踏んだ）

点検が **ルータ無応答 ＋ カメラ 3 台 NG** を同時に出した。実際にはルータもカメラも生きていて、
**卓の PC が有線の IP を失って `169.254.x` へ落ちていた**だけだった。

```powershell
ipconfig /renew "イーサネット"    # これだけで 192.168.10.10 が戻り、同時に全部 OK になった
```

⇒ **3 台が同時に落ちることは実際にはめったに無い。全滅は卓側を疑う方が当たる。**
点検は「卓から見えるか」しか測れないので、**卓が網から外れた姿と、現場が全滅した姿は同じ顔で出る**。

順に見る: `Get-NetIPAddress` で PC が `192.168.10.10` を持っているか →
持っていなければ `ipconfig /renew` → それでも駄目ならルータの電源とランプ。

| 症状 | 見るところ | 直し方 |
|---|---|---|
| **全部 NG（ルータも）** | **PC 自身の IP** | `ipconfig /renew "イーサネット"`（上の節） |
| 1 台だけ黒い / 砂嵐 | `/video` からバイトが出ているか | `fix cameras`（画面を起こす → アプリを起こし直す） |
| **1 台が 30 分おきに止まる** | **その端末が充電されているか** | **ケーブルを挿す**（下の「充電」） |
| 3 台が同時に周期的に途切れる | Quest の設定パネル | `fix panel` |
| 卓では映るのに Quest だけ映らない | 端末キャッシュ | `fix cache` → Quest を再起動 |
| 演出が出ない・別のカメラに出る | `check` の「カメラ本数」「名乗った ID」 | 端末画面の cameraId を直す |
| 卓が落ちた | `py -3.11 tools/onsite.py serve` | ⚠ **2 つ立てない**（互いの show.json を巻き戻し合う） |

⚠⚠ **Wi-Fi には 1 度も触らない。** 入れ直すと保存済みの別 AP が選ばれ、**全台が会場や
研究室の AP へ移る**（2026-08-30 に実演した）。しかも画面には何も出ない。
`onsite.py` はこの操作を 1 つも持っていない。

⚠ **卓が落ちても体験は続く**（焼き込みの値で完走する）。ただしその状態では
音・コントローラ・目の写真の失敗が**全部無音になる**ので、卓は立て直す。
