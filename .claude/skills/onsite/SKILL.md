## 開場前（設営が終わったら 1 回）

```bash
py -3.11 tools/onsite.py check --deep
```

`--deep` は heartbeat を 20 秒サンプリングする。**Quest を本番と同じ台数だけ起動してから**回す
（起動していないと音・コントローラ・目の写真の行が出ない。出ないのが正しい —
⚠ 卓は最後に受け取った heartbeat を何時間でも返すので、**古い値で判定させない**ためにこちらで捨てている）。

### この 4 つは check にしか出ない

1. **無線 adb が開いているか**（`<ip>:5555`）。閉じていると**当日その端末を 1 手も直せない**。
   開けるのは USB を挿して `py -3.11 tools/onsite.py adb-open`。⚠ **端末を再起動すると閉じる**
2. **傾きと較正の差**。40° ずれていた実績がある（そのとき CG 人形が盛大にずれた）。
   ⚠ 傾きが合っていても位置と左右の向きは分からない（[[camera_fleet]]）
3. **端末に入っている APK が焼いたものと同じか**。古い機に当たると「実装が効いていない」の顔で出る
4. **露出ロック**。素材を撮った時と本番で色が変わる。設営と照明が決まってから端末の 🔓 を押す

## 落ちたとき

**まず `check` で「どの台が」を確定する。** 症状から原因へ飛ばない。

| 症状 | 見るところ | 直し方 |
|---|---|---|
| 1 台だけ黒い / 砂嵐 | `/video` からバイトが出ているか | `fix cameras`（画面を起こす → アプリを起こし直す） |
| 3 台が同時に周期的に途切れる | Quest の設定パネル | `fix panel` |
| 卓では映るのに Quest だけ映らない | 端末キャッシュ | `fix cache` → Quest を再起動 |
| 演出が出ない・別のカメラに出る | `check` の「カメラ本数」「名乗った ID」 | 端末画面の cameraId を直す |
| 卓が落ちた | `py -3.11 tools/onsite.py serve` | ⚠ **2 つ立てない**（互いの show.json を巻き戻し合う） |

⚠⚠ **Wi-Fi には 1 度も触らない。** 入れ直すと保存済みの別 AP が選ばれ、**全台が会場や
研究室の AP へ移る**（2026-08-30 に実演した）。しかも画面には何も出ない。
`onsite.py` はこの操作を 1 つも持っていない。

⚠ **卓が落ちても体験は続く**（焼き込みの値で完走する）。ただしその状態では
音・コントローラ・目の写真の失敗が**全部無音になる**ので、卓は立て直す。

## 会期中

```bash
py -3.11 tools/onsite.py watch
```

20 秒ごとに全カメラから実際にバイトを引く。出ていなければ**自分で起こし直す**
（1 台につき 90 秒に 1 回まで。落ちている時にだけ動く）。記録は `logs/onsite/watch-*.log`。

⚠ **背景で走らせたら黙る。** 「監視中。」で turn を埋めない。次に喋るのは何か起きたとき。
