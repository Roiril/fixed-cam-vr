# 当日

**窓は 3 つ。役割を混ぜない。**

| 窓 | 誰が見る | 何をする |
|---|---|---|
| **当日の画面** `http://localhost:8099/`（スマホは `http://192.168.10.10:8099/`） | スタッフ | 開場できるかを見る・素材を撮って採用する・止まった台を起こし直す |
| **博士タブレット**（アプリ「廻リ視 博士」） | スタッフと体験者 | 体験者 1 人ごとの進行。卓からは体験を操作しない |

⚠ **画面を第一に案内する。** シュビーは外向きの回線が要るので、会場の回線が死ぬと消える。画面とタブレットは LAN だけで動く。
画面の作りと判定の決まりは [tools/web-compositor/README.md](../../../tools/web-compositor/README.md)「当日の画面」。画面の「困ったとき」とこのスキルの「落ちたとき」は同じ中身（`tools/web-compositor/ops/help.js`）。直すときは両方。

## 開場までの流れ

画面の「準備」の 8 行が、そのまま順番。上の見出しが「開場できます」になれば終わり。

| 行 | 済みの条件 | 人 | シュビー |
|---|---|---|---|
| 01 回線と卓 | PC が `192.168.10.10` を持つ | ルーターを先に起動・PC を有線・サインイン（卓が自動で立つ） | 立たなければ `onsite.py serve` |
| 02 カメラ | A・B・C の映像の連番が進む | 据える・充電ケーブル・照明を決めて露出を固定 | 無線で直す口を開ける `adb-open`（USB） |
| 03 Quest | 応答あり・位置合わせ済み | 被って位置合わせ（右トリガー 2 秒 → ×印の上で右 A 0.5 秒 → 線を見て B） | `setup` で起動 |
| 04 博士タブレット | 送った設定が Quest に届く | アプリを開き、スタッフ設定で α / β を選び、言語と軽減を 1 度送る | アプリが無ければ `tablet/README.md` の手順で入れる |
| 05 会場の素材 | 人形視点 5 本・無人の写真 3 枚・人の確認 2 つ | 撮る・見る・採用する | 尺と形式の検査・切り出し |
| 06 アプリの版 | 採用中の素材と同じ版が使う Quest に入っている | 入れたあと被って確かめる | `unity.ps1 build fixedcam` → `quest-fleet.py sync` |
| 07 詳しい点検 | NG と未確認が 0 | 画面のボタンを押す | `check --deep` |
| 08 人が確かめること | 6 つの印 | 歩く場所・構図・各 Quest を被る・タブレットの音・左グリップの撮影 | — |

状態は 4 つ（済み／注意／まだ／対処）。**注意は開場を止めない。**止めるのは「まだ」と「対処」。

### 今日使う機材

- **予備の機は判定から外す。** `tools/web-compositor/operations-fleet.json` の `quests[]` の該当行に `"standby": true` を書き、卓を起動し直す。画面は「予備」と出し、開場の判定・アプリの版の照合・`check`・`watch` から外れる。**外すのは人が「使わない」と言ったときだけ**（欠けた機を成功にするために使わない）
- **登録の無い Quest は「まだ」のまま。** 画面の Quest の行に応答した ID が出る。「登録の依頼文をコピー」の文面どおり `deviceId` と `shortId` を書く
- **博士タブレットは登録のある分だけ数える。** 1 台で両方を回すなら、スタッフ設定で接続先を切り替える

### この 4 つは詳しい点検にしか出ない

1. **無線で直す口（`<ip>:5555`）が開いているか。** 閉じていると当日その端末を 1 手も直せない。開けるのは USB を挿して `py -3.11 tools/onsite.py adb-open`。⚠ **端末を再起動すると閉じる**

   ⭐ **PC を再起動しただけなら USB は要らない。** 切れているのは PC の adb の接続だけ:

   ```bash
   for ip in 192.168.10.21 192.168.10.22 192.168.10.23; do adb connect $ip:5555; done
   ```

   `adb devices` に `offline` で残っていたら `adb disconnect <ip>:5555` してから繋ぎ直す
2. **傾きと較正の差。** 40° ずれていた実績がある。傾きが合っていても位置と左右の向きは分からない（[[camera_fleet]]）。位置は画面の「無人の写真」で、いまの映像と重ねて見る
3. **端末に入っている APK が焼いたものと同じか。**
4. **露出の固定。** 照明を決めて数秒待ってから端末の錠の印を押す

### ⚠⚠ 配信スマホは 3 台とも充電ケーブルを挿す

**画面が消えると配信が止まる。**「画面を消さない」設定は充電中しか効かない。挿していない端末は 30 分で画面が落ち、**アプリは生きたまま配信だけ止まる**。見るのは残量ではなく充電されているか:

```bash
adb -s <ip>:5555 shell "dumpsys battery | grep -E '^  (AC|USB) powered'"   # true が要る
```

⚠ **素材撮りの直前だけは逆に抜く**（熱段を 0 にする）。

## 当日撮った素材を反映する — ⚠ 押しただけでは入っていない

会場で撮るのは **人形視点 5 本**（手持ちのスマホ）と **無人の写真 3 枚**（カメラ A・B・C）。シミ・手形・人形の動画は前もって同梱してある。目の写真は 0152 で廃止（撮ってきたと言われても画には出ない）。

順番は **人形視点 → カメラを本番の位置へ戻す → 無人の写真**。B の端末を人形視点に借りるなら、据える前に撮る（戻したとき較正が壊れる）。

**採用は結果を数えるまで終わらない。** リハで 2 通り外した。卓で「採用」を押しても入らない本がある（端末に残ったまま回収されていない）。`takes --adopt` が古い日の録画を採ることがあった（直した。ただし全部 ✅ で出る）。

```bash
py -3.11 tools/onsite.py takes           # 端末に残っているものを見る
py -3.11 tools/onsite.py takes --adopt   # 回収して採用する
curl.exe -m 6 -s "http://127.0.0.1:8099/shoot/plan?cam=A"   # shots[].adoptedName を数える
```

**5 本の `adoptedName` が意図した録画であること。** 違えば端末とファイル名を名指しして採り直す（`/shoot/pull` → `/shoot/adopt` に `host` と `name`）。

無人の写真は画面の「素材 → 無人の写真」で撮って採用する。**前の日の写真を使い続けるなら撮り直さなくてよい。**同じ画面で「いまの映像を重ねる」を押し、壁と床の線が合うのを人が見る。

⚠ **写真を替えると、その写真に合わせて作った素材がずれる。** A は左の幕のシミ・右の幕・4-A の人形、B は壁の手形。各カメラの札の下に「この写真に合わせて作った素材」が出て、替えたあとは「作り直し」と作り方を出す（準備の 05 は「注意」。開場は止めない）。台帳は `tools/web-compositor/plate-dependents.json`。

### 右の幕（2-A のしみと膨らむ顔・人形）は必ず作り直す

全員に見せる演出なので、A の写真を替えたら毎回やる。**「この写真に合わせ直す」を押すだけ**（1 分ほど・外の回線は要らない）。卓が採用中の写真へ動画を位置合わせして組み直し、台本の cue と台帳の `plate` を替える。札が「合っている」になったら焼き直す。

断られたら、カメラの位置か幕の並びが変わっている。**まずカメラを採用中の写真に合わせて戻せないかを見る**（戻せれば何も作り直さずに済む）。戻せなければ動画を生成し直す（外の回線と 20 分〜）:

1. 卓は断った時点で、Flow に渡す首尾フレームを `Logs/gen-plate/stain2A_right_video_20261115/build/flow_inputs_<写真の日時>/` に書いている（メッセージの末尾にも出る）
2. Flow（Omni 1.2 Flash・360p・6 秒）に `start_16x9.png` → `end_16x9.png` を渡して生成する。`end_16x9.png` が無ければ最後のフレームを Codex で描き直す
3. `py -3.11 tools/gen-plate/stain3/build_flow_right.py --plate tools/web-compositor/captures/<採用中の写真> --from-flow <返った mp4> --dry` → `build/sheet.png` を開いて見る → `--dry` を外して走らせる（新しい動画が `stain_A_right_flow.json` の `source` に残る）
4. もう一度「この写真に合わせ直す」を押す。今度は新しい動画から組み、台本と台帳を替える

詳しくは `tools/gen-plate/stain3/README.md`「当日に作り直す（右の幕）」。

**会場で部屋ごと変わり、生成し直す時間が無いとき**は、全部の素材を射影で写し替えるつなぎがある（`tools/gen-plate/replant.py`。手順は `tools/gen-plate/stain3/README.md`「当日に作り直す」）。
写した名前へ cue を替えるのは `POST /state` ではできない（準備の卓は 403）。卓を止めて `show.json` の cues を直し、`onsite.py serve` で起こし直す。

### ほかの素材

作り直すかは、札の「元にした写真と重ねる」でいまの映像と重ね、ずれで決める。作り直しは Codex の画像生成か動画の生成が要る（外の回線と 15 分〜）。作り直したら台帳の `plate` を新しい写真の名前に書き換え、焼き直す。
**カメラを据え直すときは、採用中の写真に合わせて戻すのが一番安い**（素材も写真もそのまま使える）。

**そのあと焼き直す。** 実機は焼いたアプリの素材だけで動く。

```powershell
.\tools\unity.ps1 build fixedcam
py -3.11 tools\quest-fleet.py sync
```

画面の 06「アプリの版」が済みになるまで見る（`/ops/content` の `ready`）。

## 落ちたとき

**まず「どの台が」を確定する。** 症状から原因へ飛ばない。

## ⚠⚠ 全部いっぺんに落ちたら、卓の PC を先に見る

実際にはルータもカメラも生きていて、**卓の PC が有線の IP を失って `169.254.x` へ落ちていた**だけ、が実績。画面は 01「回線と卓」を「対処」にし、ほかの行を「卓が網に戻るまで分かりません」にまとめる。

```powershell
ipconfig /renew "イーサネット"
```

| 症状 | 見るところ | 直し方 |
|---|---|---|
| **全部 NG** | **PC 自身の IP**（画面の 01） | 上の `ipconfig /renew`。駄目ならルーターの電源 |
| 1 台だけ黒い / 砂嵐 | 画面のそのカメラ | 「起こし直す」（1 台ずつ・90 秒に 1 回）。押せなければ端末で配信アプリを前に出す |
| **1 台が 30 分おきに止まる** | その端末が充電されているか | ケーブルを挿す |
| 3 台が同時に周期的に途切れる | Quest の設定パネル | `fix panel` |
| 卓では映るのに Quest に出ない・演出が古い | 画面の 06 | 焼いたアプリを入れ直す（`quest-fleet.py sync`） |
| Quest が固まった・途中でやめたい | 博士タブレット | 「困ったとき → 体験を中断してやり直す」1.5 秒。⚠ **固まった Quest の電源ボタンを押さない**（休止に入る）。右 A 2 秒は被っていないと読まれない |
| 展示を止めたい | 博士タブレット | スタッフ画面の右上「展示を一時中止する」。戻すのは右下「スタッフ専用（長押し）」→「展示を再開する」 |
| 博士タブレットが応答しない | 画面の 04 | 「廻リ視 博士」を開き、スタッフ設定で接続先を選ぶ |
| 端末が別の Wi-Fi に居る | 端末の設定 | 保存済みの `kougaku-lab-exp-a` を手で選び直す |
| 朝、全機が Wi-Fi に戻らない | [[no_internet_autojoin_kill]] | 各端末で 1 度だけ手で選び直す → USB で `adb-open`（予防） |
| 卓が落ちた | `py -3.11 tools/onsite.py serve` | ⚠ **2 つ立てない**（互いの show.json を巻き戻す） |

⚠⚠ **Wi-Fi は入れ直さない・保存済みの網を消さない。** 入れ直すと保存済みの別の網へ全台が移る（2026-08-30 に実演した）。`onsite.py` はこの操作を持っていない。

⚠ **卓が落ちても体験は続く**（焼いた値で完走する）。ただし音・コントローラの失敗が無音になるので、卓は立て直す。

⚠ **画面が「卓に届いていません」と出たら、まず `curl -s -m 20 http://127.0.0.1:8099/ops/status` を直接叩く。** 応答が空なら卓の中で例外が出ている（`logs/onsite/desk.log`）。2026-11-15 まで、届かないカメラが 1 台あるだけでここが落ちていた（[[onsite_day_ops]]）。

## 会期中

```bash
py -3.11 tools/onsite.py watch
```

20 秒ごとに全カメラの連番を見る。2 巡続けて止まっていたら自分で起こし直す（1 台につき 90 秒に 1 回。画面の「起こし直す」と記録を共有）。記録は `logs/onsite/watch-*.log` で、画面の「本番」に末尾が出る。動いていなければ画面が「見張りは動いていません」と言う。

画面の「本番」は体験の段で重みを変える。体験中に左コントローラが見えていなければ「対処」。待機中の右コントローラは見ない。

## 体験者 1 人ごと

**博士タブレットの画面が案内する。**スキルにも卓にも手順を二重に持たない（ずれる）。流れと証拠の決まりは [[staff_setup]]。

- 入力: 体験者は左の X / Y だけ。スタッフは右（A 2 秒 = 予備のリセット、B = 押しているあいだ状態、トリガー 2 秒 = 位置合わせ）。[[controller_input_final]]
- Quest を外すと休止する。休止中は応答が止まり、画面の Quest の行が「対処」になる。電源ボタンを 1 度押すと戻る
