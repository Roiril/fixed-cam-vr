# ツインで回す 1 周

ツインは 2 つの役をする。**回帰の門**（前は通っていたものが壊れていないか）と、**体験者の目の代わり**
（何が何秒見えたか）。どちらも実機の代わりではない（`reference/why.md`「代理を厚くしない」）。

**1 周 = 1 つ直して、同じ走り方で走り直す。** 終わりの判定は「新規の判定が消えたか」と「左右に並べたコマで変わったか」。

## 0. 読む

- `memory/twin_verify.md` — ツインの都合で出る見え方（黒い服・明るい床・A の下端の段々・立ち止まりの 1 コマ）
- `tools/twin/known.json` — 毎回出る判定と、その理由
- `MEMORY.md` の「いま開いている指摘」と、触る場面の `canon/NOW.md` の行

## 1. 走る

```bash
py -3.11 tools/twin-verify.py --calib twin --tag <何を見る走行か>     # 見る走行（動画あり・10 分）
py -3.11 tools/twin-verify.py --no-video --nomark                     # 報告しない（人形 End）
py -3.11 tools/twin-verify.py --no-video --relief                     # ホラー軽減
py -3.11 tools/twin-verify.py --no-video --speed 0.45 --dwell 2       # 速く歩く人
```

- 見る走行は `--calib twin`（人形が画に合う）。既定の `show` は APK と同じ値で、人形はツインの画に合わない
- 判定だけの 3 本は、本編の進行（Director・報告・終幕・エージェント画面）を触ったときに回す。速い走行は既定で出ない FAIL を出す
- 背景で走らせて通知を待つ。同時に 2 本は走らない（錠が断る）。別のセッションが Unity を使っていたら `SendMessage` で順を決める
- 走行と撮影のあいだに C# を書き換えない（判定は古いコード・動画は新しいコードになる。変わっていたら WARN が出る）

**2 本同時に回す**（検証用の木 `Projects/Unity/fcv-twin-tree`。作り方と罠は `tools/twin-tree.py` の頭）:

```bash
py -3.11 tools/twin-tree.py sync                                   # いまの作業ツリー（未コミットごと）を向こうへ写す
py -3.11 tools/twin-tree.py run -- --no-video --nomark --tag tree-nomark
py -3.11 tools/twin-tree.py sync --ref HEAD                        # 直す前の側を向こうに置く（前後を同時に走らせる）
```

- 走行の組は、動画ありの 1 本をこちら、判定だけの 3 本を向こうへ振る
- 向こうの木で編集しない（`sync` のたびに捨てる）。`sync` は向こうの走行が終わってから

## 2. 新規の判定を仕分ける

`twin-verify.py` は判定を**新規**と**既知**に分けて出す。新規の FAIL・WARN は 1 行ずつ、次のどれかへ送る。残さない。

| 行き先 | 条件 |
|---|---|
| 直す | 本編か計器が壊れている |
| `memory/` に 1 本（`MEMORY.md` の「いま開いている指摘」へ） | 壊れているが、この周では直さない |
| `tools/twin/known.json` | 同じ走り方で 3 走行続けて出て、原因が走り方か計器の制約だと分かった WARN。FAIL は入れない |

「3 走行続けて出ていない既知」と出たら、その行を `known.json` から消す。

## 3. 見る

```bash
py -3.11 tools/twin-look.py cut <走行>                 # look/scenes.md（場面の時刻表）と場面ごとの PNG
py -3.11 tools/twin-look.py cut <走行> --scene 3-A --crop
```

`look/scenes.md` を読み、場面ごとに**個別の PNG を開く**（`sheet_*.jpg` は索引）。場面の順に、体験者として
「何が見えたか・何が起きたと思ったか・次に何を待ったか」を追う。

**所見は測れる形で書く。** 「無い」「N 秒しか出ない」「N px」「読めない」「順が逆」。形容（弱い・良い・見応え）は書かない。
1 件ごとに、**何に依存してそう見えたか**を次の語から 1 つ付ける。付けられない所見は、まだ見方が足りない。

| 依存 | そう見えた理由 | シュビーが自分でやること |
|---|---|---|
| 時刻表 | Director・cue・報告・終幕の順と秒。ツインでも実機でも同じに出る | 壊れ（出るはずが出ない・順が違う・`NOW.md` と食い違う）は直す。演出の変更は 4 の「演出」 |
| 計器 | 判定が黙った・偽の FAIL・時計のずれ・コマが切れない | 直す。観測は C# の `ShowTelemetryHost` と `analyze-xp-log.py` を対で |
| 歩き方 | 自動走行が省く・速い・立ち止まる（名乗りと練習は出ない） | 走り方を足す。本編は変えない |
| ツインの見た目 | 黒い服・明るい床・廃墟風の部屋・圧縮の無い画 | 本編は変えない。ツインを直すか `memory/twin_verify.md` に書く |
| 大きさと立体 | 小さい・遠い・近い・怖い・酔う | 判定しない。`canon/OPEN.md` の Q4（被るときにまとめる）へ |
| 音 | 聞こえ・音量・定位 | 鳴ったかは `ev=sfx` の数で見る。聞こえは実機（`rules/sound-design.md` §7） |

⚠ **ツインの見た目に依存する所見で本編を変えない。** 作品をツインの部屋に合わせ込むことになる。
2026-11-11 の感想 4 件のうち 2 件（別れの写真の暗さ・3-A の人形の埋もれ）は黒い服と明るい床が効いていた。

## 4. 1 つ直す

**壊れ・計器（時刻表 / 計器 / 歩き方）**

1. 落ちる判定かテストを先に足す（`.\tools\unity.ps1 test` か `py -3.11 tools/test-tools.py`）。足せないなら、何で確かめるかを 1 行書く
2. 直す
3. 見つけたときと同じ引数で走り直す。新規の判定からその行が消えたかを見る
4. `py -3.11 tools/twin-look.py pair <新しい走行>`（同じ走り方の直前の走行が左に並ぶ）。`pair.md` の「数が違う出来事」に、直した所以外が出ていないかを読む

**演出（体験者に見えることを変える）**

- `skills/work-round` の 0 段を通す（`canon/ROUNDS.md` に賭け 1 文と予測 3 行）。ツインの走行は「安い門」で、焼いた実機の代わりにしない
- **本編の既定は変えない。**（2026-11-11 ユーザー判定。問い「演出の自己改善は、本編の既定まで変えてよいですか？」に「版まででいい」）
  切り替えられる版として作り、既定の走行と版の走行を `pair` で並べ、`skills/direction-round` で 1 点訊く。
  焼いた APK の既定へ入れるのは、ユーザーが採ったときだけ
- 切り替えの旗は、判定が出たら既定にするか消す。**開いている版は 3 つまで**（旗の掛け算で走行の組が増える）
- `NOW.md` で未判定の行でも同じ。未判定は「訊く所」であって「変えてよい所」ではない

## 5. 置く

新しい台帳は作らない。

| 何 | 置き場 |
|---|---|
| 直した壊れ | コミット。罠が残るなら `memory/` |
| 直さなかった壊れ | `memory/` に 1 本と `MEMORY.md` の「いま開いている指摘」 |
| ツインの都合の見え方 | `memory/twin_verify.md` |
| 毎回出る判定 | `tools/twin/known.json` |
| 演出の案・作った版 | `canon/OPEN.md` の「案」「実装済み・未判定」。走行の名前と `_pair/` のフォルダを書く |
| 被らないと分からないこと | `canon/OPEN.md` の Q4 |
| 演出の賭けと差 | `canon/ROUNDS.md`（壊れの直しは書かない） |

## 体験者役のサブエージェントを使うとき

走行を別の目で見させてよい（2026-11-11 のユーザー依頼「シュビーが遊んで見て、VRの体験者視点で」）。渡すもの:

- `look/scenes.md` と場面ごとの PNG のフォルダ
- `memory/twin_verify.md` のツインの都合（指摘から外すもの）と、`known.json` の「歩き方」の行（名乗りと練習は走行に出ない）
- 返す形: 場面・秒・見えたこと・依存の語

返ってきた感想は**案**で、`canon/OPEN.md` へ置く。初めて被る人の代わりにはならない（`reference/why.md` §3）。

## 止まる所

- 同じ直しが 2 回外れたら、3 回目の前に `advisor` に諮る
- ツインの PASS で `canon/OPEN.md` の項目や「実機は未確認」を閉じない。閉じるのは実機の走行（`quest-record.py --walk`）かユーザーの言葉

## やってはいけないこと

- ❌ 既知の判定を読み飛ばす癖で、新規も読み飛ばす → だから分けて出している。新規は 0 にしてから終える
- ❌ コマを開かずに `scenes.md` の数だけで「出ている」と言う
- ❌ 走行ごとに引数を変えて前後を比べる（歩く速さが違えば区間の長さが変わる）
- ❌ 版の走行だけを見せる。必ず既定の走行と左右に並べる
- ❌ 所見に点数を付ける（`reference/why.md`「品質を採点しない」）
