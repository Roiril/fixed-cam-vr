# 展示ネットワークの設営（自前 AP ＋ 固定 IP）

**使う機材**: NEC Aterm WG2600HP（研究室の実験用・SSID `kougaku-lab-exp-g` / `-a`）

**これで消える問題**: 会場の DHCP で配信スマホの IP が変わって接続先が外れる／AP のクライアント
アイソレーションで端末どうしが通信できない／2.4GHz の混雑で受信 fps が落ちる。

**⚠ この 3 つは設営の順序が決まっている。** ルータ → 端末 → コード。飛ばすと次が確認できない。

---

## 0. アドレス設計

```
LAN            192.168.10.0/24     ゲートウェイ 192.168.10.1（Aterm 本体）
DHCP 配布      192.168.10.2 〜 .10  ← 来客・一時的な機器だけ
```

**展示の機材は全部、端末側で静的 IP を設定する**（下の理由）。配布範囲を `.10` までに狭めてあるので、
静的に振った `.11` 以降とは<b>構造的に衝突しない</b>。

| IP | 機材 | 備考 |
|---|---|---|
| `192.168.10.11` | **PC（オペレータ卓）** | `ShowServer.asset` / 卓の `serve.ps1` |
| `192.168.10.21` | カメラ **A**（Phone01） | `cameraId: A` |
| `192.168.10.22` | カメラ **B**（Phone02） | `cameraId: B` |
| `192.168.10.23` | カメラ **C**（Phone03） | `cameraId: C` |
| `192.168.10.24` | カメラ **D**（Phone04・演出専用） | `cameraId: D`・使わない日は空でよい |
| `192.168.10.31` | Quest #1 | serial `2G0YC1ZF7S06BW` |
| `192.168.10.32` | Quest #2 | serial `2G0YC1ZF890864` |

サブネットマスク `255.255.255.0` ／ ゲートウェイ・DNS とも `192.168.10.1`。

### ⚠⚠ なぜ「ルータの DHCP 固定割当」ではなく「端末側の静的 IP」か

**Quest 2 台とも Wi-Fi の MAC がランダム化されている**（2026-08-30 実測）:

```
Quest #1  36:1e:88:ec:42:dd      ← 0x36 = 0011 0110（locally administered ビット = 1）
Quest #2  c2:14:15:b7:84:42      ← 0xc2 = 1100 0010（同じく 1）
```

MAC 固定割当は MAC を鍵にするので、**ランダム MAC のままでは効かない**。
端末側の静的 IP なら MAC に依存せず、ルータを別の機体へ替えても設定が生きる。

⚠ Aterm 側の固定割当（`詳細設定 → DHCP固定割当設定`・最大 20 件・MAC は `:` 区切り・
IP は配布範囲内であることが必須）を併用してもよいが、**その場合は先に各端末で
「デバイスの MAC を使う」へ切り替えてから MAC を採り直すこと**。切り替えずに採った MAC で
登録しても効かない。

## 1. ルータの設定（初回 1 回だけ・自宅や研究室で済ませておく）

1. [ ] **電源を切ってから**背面スイッチを **RT** にして、電源を入れ直す
   - ⚠ **BR（ブリッジ）では DHCP サーバ自体が動かない**。孤立 LAN では RT 固定
   - 起動は **2.4GHz・5GHz のランプが点灯するまで待つ**（本体に貼ってある注意書きのとおり）
2. [ ] PC を `kougaku-lab-exp-a`（5GHz）へ繋ぐ
3. [ ] ブラウザで `http://aterm.me/` → ユーザ名 `admin` ／ パスワードは研究室と同じ
4. [ ] 「詳細な項目を表示」を押す（これを押さないと下のメニューが出ない）
5. [ ] **DHCP の配布範囲を狭める** — `詳細設定 → DHCPサーバ設定`
   - リース範囲の開始 `192.168.10.2` ／ 割当数 **9**（＝ `.2`〜`.10` まで）
   - ⚠ 初期値は開始 `.2` ／ 個数 32（`.2`〜`.33`）。狭めないと静的 IP と衝突しうる
6. [ ] **5GHz のチャネルを固定** — `Wi-Fi設定 → Wi-Fi詳細設定(5GHz)`
   - **オートチャネルセレクトを OFF**、チャネルを **W52（36 / 40 / 44 / 48ch のどれか）** に固定
   - ⚠ **W53（52〜64ch）と W56（100〜140ch）は DFS 対象**。レーダーを検出すると通信が一時的に
     切れて、そのチャネルが 30 分使えなくなる。**本番中に起きると映像が全部止まる**
   - W52 は屋内使用限定（本体ラベル記載）。屋内展示なら問題ない
7. [ ] **ネットワーク分離機能が OFF であることを確認** — `Wi-Fi設定 → Wi-Fi詳細設定(2.4GHz)/(5GHz)`
   - オーナー SSID の初期値は OFF。**ON にすると端末どうしが直接通信できない**
     （しかも 2.4GHz と 5GHz を跨ぐ通信まで切れる）＝ 会場の AP で踏む事故と同じものを自分で作ることになる
   - ⚠ **ゲスト SSID（`-gx` / `-ax`）は使わない**。あちらは分離が前提
8. [ ] WAN 側は**何も繋がなくてよい**（体験はすべてローカル通信）

## 2. 端末側の設定（端末ごとに 1 回だけ）

### 配信スマホ（Pixel 7a ×3〜4）

1. [ ] `kougaku-lab-exp-a`（5GHz）へ接続
2. [ ] ネットワークの歯車 → **詳細オプション → IP 設定を「静的」** → 上の表の IP を入力
   - IP `192.168.10.21`（A の場合）／ ゲートウェイ `192.168.10.1` ／
     ネットワークプレフィックス長 `24` ／ DNS `192.168.10.1`
3. [ ] **「モバイル ネットワークに自動で切り替える」を OFF**
   - `設定 → ネットワークとインターネット → 接続の自動調整`
   - インターネットの無い Wi-Fi でデータ経路がモバイルへ逃げる。SIM を入れていない機なら実害は無いが、
     入っている機では確実に切る
4. [ ] 配信アプリ（fixed-cam-streamer）を起動し、**画面に出ている cameraId が表の割当と合っているか**見る
   - ⚠ IP と cameraId の対応が入れ替わっていると、演出が別のカメラに出る

### Quest（2 台）

1. [ ] `kougaku-lab-exp-a` へ接続
2. [ ] Wi-Fi 設定でそのネットワークを開き、**IP 設定を静的**にして `.31` / `.32` を入力
   - ⚠ **メニューの正確な名前は未確認**（Meta 公式に記載が無く、確定した一次ソースが取れなかった）。
     実機で `設定 → Wi-Fi → 接続中のネットワーク` を開けば 1 分で分かる
   - 静的にできない版なら、代わりに Wi-Fi 詳細で **「Use device MAC」** へ切り替えてから
     `adb shell ip addr show wlan0` で MAC を採り、Aterm の固定割当に登録する

### PC（卓）

1. [ ] `kougaku-lab-exp-a` へ接続し、アダプタの IPv4 を静的 `192.168.10.11` に
2. [ ] `serve.ps1` を起動して `http://192.168.10.11:8099/` が**他の端末のブラウザから開けること**を確認
   - ここが開かなければ端末間通信が通っていない（＝ ネットワーク分離が ON）

## 3. 疎通の確認（設営のたび・3 分）

**上から順に。1 つでも欠けたら次へ進まない。**

1. [ ] 全端末が `192.168.10.x` を持っているか
   - スマホ: 配信アプリの画面に出る ／ Quest: `adb shell ip addr show wlan0` ／ PC: `ipconfig`
2. [ ] **PC から各カメラの映像が見えるか**（これが端末間通信の証明）

   ```bash
   curl.exe -m 4 -s -o NUL -w "%{http_code}\n" http://192.168.10.21:8080/health
   ```

   `200` が返ればよい。⚠ Git Bash で `MSYS_NO_PATHCONV=1` を立てている場合は `-o NUL`
   （`/dev/null` と書くと exit 23 で 0 バイトになり「落ちている」ように見える）
3. [ ] **卓の 🩺 疎通診断**を押す — PC→カメラ HTTP ／ beacon ／ Quest heartbeat の 3 経路が ✅ になるか
4. [ ] Quest でアプリを起動し、卓のライブ状態で **カメラ本数・音・コントローラ**が ✅ か
   （2026-08-30 に足した行。音とコントローラは画にも録画にも出ないのでここでしか分からない）

## 4. コード側の更新（IP を固定した後・1 回だけ）

⚠ **この 4 つは同じ値でなければならない。**片方だけ直すと「卓では正しいのに実機が違う」になる。

| 何 | どこ | どうやって |
|---|---|---|
| 焼き込み（卓が居なくても繋がる） | `Assets/Settings/Cameras/Phone0*.asset` の `host` | Unity の Inspector で直接 |
| 卓サーバの接続先 | `Assets/Settings/ShowServer.asset` の `host` | 同上（`192.168.10.11`） |
| ライブ設定 | `show.json` の `cameras[].host` | **卓の UI から**（⚠ ディスクを直接書くと、動いている卓のメモリが上書きして巻き戻る） |
| 端末キャッシュ | Quest の `show_config.json` | APK を焼き直せば自動で捨てられる（`buildGuid` 照合）。手で消すなら `py -3.11 tools/quest-fleet.py reset-config <serial>` |

- [ ] `.asset` 4 本 ＋ `ShowServer.asset` を上の表の値へ
- [ ] 卓の UI で `cameras[].host` を同じ値へ（📌 手動固定の印が付く）
- [ ] `show.json` の **`control.discoveryEnabled` を `true` へ戻すか決める**
  - 現在 **`false`**（＝ Quest 側の自動張り替えが止まっている。サーバ既定は `true` なので誰かが切った）
  - IP を固定すれば発見機構は普段使われない。**端末を 1 台入れ替えたときや静的 IP を入れ忘れたときの
    保険**として戻す価値はある。切ってある理由に心当たりがあるなら、そのままでよい
- [ ] APK を焼き直す（`.\tools\unity.ps1 build fixedcam`）→ 両方の Quest へ入れる

## 5. 困ったとき

| 症状 | まず見る |
|---|---|
| 端末が `192.168.10.x` を取れない | ルータが **RT モード**か（BR だと DHCP が動かない）。ランプが 2 つとも点いてから繋いだか |
| PC からカメラが見えない | ネットワーク分離が ON になっていないか。ゲスト SSID（`-gx` / `-ax`）に繋いでいないか |
| 映像が数十秒おきに全部止まる | 5GHz のチャネルが **W53 / W56** に落ちていないか（DFS の瞬断）。W52 へ固定する |
| 卓では映るのに Quest だけ映らない | Quest の IP と `.asset` / `show.json` の値がずれていないか。端末キャッシュが古くないか（`reset-config`） |
| 受信 fps が配信の 2/3 くらいしか出ない | 2.4GHz に繋がっていないか。**5GHz（`-a`）へ寄せる** |
