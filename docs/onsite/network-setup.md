# 展示ネットワークの設営（自前 AP ＋ 固定 IP）

**使う機材**: NEC Aterm WG2600HP（研究室の実験用・SSID `kougaku-lab-exp-g` / `-a`）

**これで消える問題**: 会場の DHCP で配信スマホの IP が変わって接続先が外れる／AP のクライアント
アイソレーションで端末どうしが通信できない／2.4GHz の混雑で受信 fps が落ちる。

**⚠ この 3 つは設営の順序が決まっている。** ルータ → 端末 → コード。飛ばすと次が確認できない。

---

## 0. アドレス設計

```
LAN            192.168.10.0/24     ゲートウェイ 192.168.10.1（Aterm 本体）
DHCP 配布      192.168.10.2 〜 .10  ← 来客・一時的な機器 ＋ PC の固定割当
静的（端末側）   192.168.10.11 以降   ← 配布範囲の外なので構造的に衝突しない
```

| IP | 機材 | 決め方 |
|---|---|---|
| `192.168.10.10` | **PC（オペレータ卓）** | **ルータの固定割当**（有線 MAC `D4:93:90:32:0F:B2`） |
| `192.168.10.21` | カメラ **A**（Phone01） | 端末側で静的 |
| `192.168.10.22` | カメラ **B**（Phone02） | 端末側で静的 |
| `192.168.10.23` | カメラ **C**（Phone03） | 端末側で静的 |
| `192.168.10.24` | カメラ **D**（Phone04・演出専用） | 端末側で静的。使わない日は空でよい |
| `192.168.10.31` | Quest（serial **`2G0YC1ZF890864`**） | 端末側で静的 |
| `192.168.10.32` | Quest（serial **`2G0YC1ZF7S06BW`**） | 端末側で静的 |

サブネットマスク `255.255.255.0` ／ ゲートウェイ・DNS とも `192.168.10.1`。

⚠ Quest の 2 台は**設計と逆の番号で入れてある**（2026-08-30 実測）。どちらの機でも体験は同じなので
入れ替えず、この表を実機に合わせた。**serial で見分ける**（IP では見分けない）。

### PC だけ決め方が違う理由

**PC 側の設定を 1 つも変えないため。** 有線を静的にすると、このルータを外して研究室の有線を使うとき
毎回 DHCP へ戻すことになる。有線の MAC は<b>ランダム化されない</b>ので、ルータ側の固定割当が確実に効く。

⚠ **固定割当の IP は DHCP の配布範囲内でなければならない**（Aterm の制約）。範囲を `.2`〜`.10` に
狭めたので、PC はその端の `.10` を予約する。範囲外の `.11` は指定できない。

### ⚠⚠ なぜ「ルータの DHCP 固定割当」ではなく「端末側の静的 IP」か

**Quest 2 台とも Wi-Fi の MAC がランダム化されている**（2026-08-30 実測）:

```
Quest #1  36:1e:88:ec:42:dd      ← 0x36 = 0011 0110（locally administered ビット = 1）
Quest #2  c2:14:15:b7:84:42      ← 0xc2 = 1100 0010（同じく 1）
```

MAC 固定割当は MAC を鍵にするので、**ランダム MAC のままでは効かない**。
端末側の静的 IP なら MAC に依存せず、ルータを別の機体へ替えても設定が生きる。

#### ⚠⚠ 決め手はこれ — **MAC は「ネットワークを削除して入れ直す」と変わる**（2026-08-30 実測）

AOSP の公式ドキュメントは「WPA2/3-PSK では persistent randomization。**忘れて再登録しても同じ MAC が返り、
変わるのは factory reset のみ**」と書いているが、**Pixel 7a で実際に変わった**:

```
カメラ A の端末   d6:6c:20:af:eb:e6  →  96:fb:79:ea:f3:f6   ← 保存済みネットワークを整理しただけで変化
他の 2 台         変化なし（触っていないため）
```

**実機が正。** これで MAC 固定割当は脆いと確定した — 当日「繋がらないから一度削除して入れ直す」は
現場でやりがちな操作で、そのたびに予約が外れる。しかも**外れても画面には何も出ない**
（IP が違うだけで、繋がってはいる）。

⭐ 同じ実測で **SSID ごとに MAC が違う**ことも確認できた（研究室では `36:1e:…`、
`kougaku-lab-exp-a` では `56:21:…`）。**別の SSID で採った MAC を登録しても効かない。**

⇒ **端末側の静的 IP を正とする。** Aterm の固定割当は PC（有線・MAC はランダム化されない）だけに使う。
既に登録してしまった端末ぶんは、静的 IP が優先されるので**消さなくてよい**（害はない）。

## 1. ルータの設定（初回 1 回だけ・自宅や研究室で済ませておく）

1. [ ] **電源を切ってから**背面スイッチを **RT** にして、電源を入れ直す
   - ⚠ **BR（ブリッジ）では DHCP サーバ自体が動かない**。孤立 LAN では RT 固定
   - 起動は **2.4GHz・5GHz のランプが点灯するまで待つ**（本体に貼ってある注意書きのとおり）
2. [ ] PC を `kougaku-lab-exp-a`（5GHz）へ繋ぐ
3. [ ] ブラウザで `http://aterm.me/` → ユーザ名 `admin` ／ パスワードは研究室と同じ
4. [ ] 「詳細な項目を表示」を押す（これを押さないと下のメニューが出ない）
5. [ ] **5GHz を確認** — `Wi-Fi設定 → Wi-Fi詳細設定(5GHz)`
   - **使用チャネル = `W52`**。⚠ この機種は**チャネル番号ではなく帯域（W52 / W53 / W56）で選ぶ**
   - ⚠ **W53 と W56 は DFS 対象**。レーダーを検出すると通信が一時的に切れて、そのチャネルが
     30 分使えなくなる。**本番中に起きると 3 台のカメラが同時に落ちる**
   - W52 は屋内使用限定（本体ラベル記載）。屋内展示なら問題ない
   - ⭐ **2026-08-30 の実機は初期値のまま `W52` だった**（＝ たいてい変更不要。見るだけ）
6. [ ] **ネットワーク分離機能が OFF であることを確認** — 同じ画面と `Wi-Fi詳細設定(2.4GHz)`
   - **ON にすると端末どうしが直接通信できない**（しかも 2.4GHz と 5GHz を跨ぐ通信まで切れる）＝
     会場の AP で踏む事故と同じものを自分で作ることになる。`SSID内分離(セパレータ)` も OFF のまま
   - ⚠ **ゲスト SSID（`-gx` / `-ax`）は使わない**。あちらは分離が前提
   - ⭐ 2026-08-30 の実機は両方とも初期値 OFF だった
7. [ ] **DHCP の配布範囲を狭める** — `詳細設定 → `**`IPv4LAN側設定`**
   - ⚠ メニュー名は「DHCPサーバ設定」ではない。LAN 側 IP と DHCP がこの 1 画面にまとまっている
   - **アドレス割当パターン → 手動設定**（初期値は「自動設定」で、先頭アドレスが入力できない）
   - **割当先頭アドレス** `192.168.10.2` ／ **割当数** **9**（初期値 32 → `.2`〜`.10` になる）
   - 触らない: IPアドレス/ネットマスク（`192.168.10.1` / `24`）・DHCPサーバ機能（ON）・リースタイム（24）
   - ⚠ ［設定］で**再起動が入り有線が一瞬切れる**。Wi-Fi 経由で作業しているなら切断される
8. [ ] **PC を固定割当に** — `詳細設定 → DHCP固定割当設定`
   - MACアドレス `D4:93:90:32:0F:B2` ／ IPアドレス `192.168.10.10`
   - ⚠ **コロン区切りで入れる**（Windows の表示はハイフンなので直す）。MAC は
     `Get-NetAdapter -Name "イーサネット" | Select MacAddress` で採る
9. [ ] WAN 側は**何も繋がなくてよい**（体験はすべてローカル通信）
10. [ ] **設定値をファイルに保存** — `メンテナンス → 設定値の保存＆復元`
    - ルータが初期化されても数分で戻せる。**展示の保険としていちばん効く 1 手**

⭐ **2026-08-30 に実機で通した。**5〜6 は初期値のままでよく、実際に変えたのは 7 と 8 だけ。
`ipconfig /renew` で PC が `.2` → **`.10`** を受け取ることまで確認済み。

## 2. 端末側の設定（端末ごとに 1 回だけ）

### 配信スマホ（Pixel 7a ×3〜4）

1. [ ] `kougaku-lab-exp-a`（5GHz）へ接続
2. [ ] ネットワークの歯車 → **詳細オプション → IP 設定を「静的」** → 上の表の IP を入力
   - IP `192.168.10.21`（A の場合）／ ゲートウェイ `192.168.10.1` ／
     ネットワークプレフィックス長 `24` ／ DNS `192.168.10.1`
3. [ ] **「モバイル ネットワークに自動で切り替える」を OFF**
   - `設定 → ネットワークとインターネット → 接続の自動調整`
   - インターネットの無い Wi-Fi でデータ経路がモバイルへ逃げる。SIM を入れていない機なら実害は無いが、
     入っている機では確実に切る
4. [ ] **`kougaku-lab-exp-a` 以外の保存済みネットワークを削除する**（配信スマホは展示専用なので消してよい）
   - ⚠⚠ **これをやらないと、Wi-Fi が入り直ったときに別の AP へ勝手に移る。** 2026-08-30 に実演した —
     全 5 台の Wi-Fi を入れ直したら、**5 台とも研究室の AP へ移った**。会場で強い AP があれば同じことが起き、
     **体験が丸ごと止まる**。しかも画面には何も出ない（繋がってはいるので）
   - Quest は開発でも使うので削除せず、**研究室のネットワークの「自動的に接続」を OFF** にする
   - ⚠ 削除・再登録は **MAC を変える**（上の実測）。固定割当を併用しているなら、**削除は必ず先にやってから
     MAC を採り直す**
5. [ ] **画面が消えない設定にする**（`stay_on_while_plugged_in` / `screen_off_timeout`）
   - ⚠⚠ **画面が消えると配信が止まる。** 2026-08-30 の実測でカメラ B が画面ロックのため
     `totalFrames=3` / `encodeIdle=true` で止まっていた（IP は正しく入っていたので、
     ネットワークの問題に見えて 10 分溶かした）
   - 3 台の設定が**バラバラだった**（A だけ `stay_on=15` / 30 分、B と C は `0` / **30 秒**）。揃える:

   ```bash
   for s in <serial> <serial>; do adb -s $s shell settings put global stay_on_while_plugged_in 15; adb -s $s shell settings put system screen_off_timeout 1800000; done
   ```

6. [ ] 配信アプリ（fixed-cam-streamer）を起動し、**画面に出ている cameraId が表の割当と合っているか**見る
   - ⚠ IP と cameraId の対応が入れ替わっていると、演出が別のカメラに出る
   - ⚠ **アプリが起動していなければ 8080 は開かない**（当たり前だが、IP が正しいと
     「ネットワークの問題」に見える）。`adb shell monkey -p com.fixedcamvr.streamer -c android.intent.category.LAUNCHER 1` で起こせる
   - ⚠ **`encodeIdle=true` は異常ではない**。需要駆動 encode なので、誰も見ていなければ止まる。
     `/video` を引けば動き出す

⭐ **QR で繋げる**（2026-08-30 実測）。`WIFI:T:WPA;S:<SSID>;P:<pass>;;` を QR 化すれば Android の標準カメラで読める。
**Quest 3 も読めた。** 既に繋がっている Android の `設定 → Wi-Fi → ネットワーク → 共有` から出すのが一番早い。
⚠ 誤り訂正を `h` にすると version 6 まで密度が上がって**検出器が拾えなくなる**。`q`（25%）で焼くこと。

### Quest（2 台）

1. [ ] `kougaku-lab-exp-a` へ接続
2. [ ] Wi-Fi 設定でそのネットワークを開き、**IP 設定を静的**にして `.31` / `.32` を入力
   - ⚠ **メニューの正確な名前は未確認**（Meta 公式に記載が無く、確定した一次ソースが取れなかった）。
     実機で `設定 → Wi-Fi → 接続中のネットワーク` を開けば 1 分で分かる
   - 静的にできない版なら、代わりに Wi-Fi 詳細で **「Use device MAC」** へ切り替えてから
     `adb shell ip addr show wlan0` で MAC を採り、Aterm の固定割当に登録する

### PC（卓）

**PC 側の設定は無い。** ルータの固定割当（§1-8）で `192.168.10.10` が来る。LAN ケーブルを Aterm の
**LAN ポート**（WAN ではない）へ挿すだけ。

1. [ ] `ipconfig` で `192.168.10.10` を持っているか見る（違えば固定割当の MAC を確認）
2. [ ] `serve.ps1` を起動して `http://192.168.10.10:8099/` が**他の端末のブラウザから開けること**を確認
   - ここが開かなければ端末間通信が通っていない（＝ ネットワーク分離が ON）

⭐ **有線で Aterm、Wi-Fi で研究室のネットワーク、を同時に持てる**（実測済み）。卓サーバは
`0.0.0.0:8099` で待つので両方から届く。**設営中に卓を止めずにルータを設定できる。**

## 3. 疎通の確認（設営のたび・3 分）

**上から順に。1 つでも欠けたら次へ進まない。**

0. [ ] **まず 1 本流す。** 在席端末・MAC・cameraId・フレームの状況が 1 画面で出る

   ```bash
   py -3.11 tools/net-scan.py
   ```

   ⚠ **接続には触らない**（読み取りだけ）。⚠ **この PC 自身は ARP に載らないので出てこない** —
   PC の IP は `ipconfig` で見る。⚠ Quest は ICMP に応答しないことがあるので、出なくても異常ではない
   （`adb shell ip addr show wlan0` で確かめる）

1. [ ] 全端末が `192.168.10.x` を持っているか
   - スマホ: 配信アプリの画面に出る ／ Quest: `adb shell ip addr show wlan0` ／ PC: `ipconfig`
2. [ ] **PC から各カメラの映像が見えるか**（これが端末間通信の証明）

   ```bash
   curl.exe -m 4 -s -o NUL -w "%{http_code}\n" http://192.168.10.21:8080/health
   ```

   `200` が返ればよい。⚠ Git Bash で `MSYS_NO_PATHCONV=1` を立てている場合は `-o NUL`
   （`/dev/null` と書くと exit 23 で 0 バイトになり「落ちている」ように見える）
3. [ ] **卓の 🩺 疎通診断**を押す — PC→カメラ HTTP ／ beacon ／ Quest heartbeat の 3 経路が ✅ になるか
4. [ ] Quest でアプリを起動し、卓のライブ状態で **カメラ本数・音・コントローラ**が ✅ か
   （2026-08-30 に足した行。音とコントローラは画にも録画にも出ないのでここでしか分からない）

## 4. コード側の更新（IP を固定した後・1 回だけ）

⚠ **この 4 つは同じ値でなければならない。**片方だけ直すと「卓では正しいのに実機が違う」になる。

| 何 | どこ | どうやって |
|---|---|---|
| 焼き込み（卓が居なくても繋がる） | `Assets/Settings/Cameras/Phone0*.asset` の `host` | Unity の Inspector で直接 |
| 卓サーバの接続先 | `Assets/Settings/ShowServer.asset` の `host` | 同上（`192.168.10.10`） |
| ライブ設定 | `show.json` の `cameras[].host` | **卓の UI から**（⚠ ディスクを直接書くと、動いている卓のメモリが上書きして巻き戻る） |
| 端末キャッシュ | Quest の `show_config.json` | APK を焼き直せば自動で捨てられる（`buildGuid` 照合）。手で消すなら `py -3.11 tools/quest-fleet.py reset-config <serial>` |

- [ ] `.asset` 4 本 ＋ `ShowServer.asset` を上の表の値へ
- [ ] 卓の UI で `cameras[].host` を同じ値へ（📌 手動固定の印が付く）
- [ ] `show.json` の **`control.discoveryEnabled` を `true` へ戻すか決める**
  - 現在 **`false`**（＝ Quest 側の自動張り替えが止まっている。サーバ既定は `true` なので誰かが切った）
  - IP を固定すれば発見機構は普段使われない。**端末を 1 台入れ替えたときや静的 IP を入れ忘れたときの
    保険**として戻す価値はある。切ってある理由に心当たりがあるなら、そのままでよい
- [ ] APK を焼き直す（`.\tools\unity.ps1 build fixedcam`）→ 両方の Quest へ入れる

## 5. 困ったとき

| 症状 | まず見る |
|---|---|
| 端末が `192.168.10.x` を取れない | ルータが **RT モード**か（BR だと DHCP が動かない）。ランプが 2 つとも点いてから繋いだか |
| PC からカメラが見えない | ネットワーク分離が ON になっていないか。ゲスト SSID（`-gx` / `-ax`）に繋いでいないか |
| 映像が数十秒おきに全部止まる | 5GHz のチャネルが **W53 / W56** に落ちていないか（DFS の瞬断）。W52 へ固定する |
| 卓では映るのに Quest だけ映らない | Quest の IP と `.asset` / `show.json` の値がずれていないか。端末キャッシュが古くないか（`reset-config`） |
| 受信 fps が配信の 2/3 くらいしか出ない | 2.4GHz に繋がっていないか。**5GHz（`-a`）へ寄せる** |
| **IP は正しいのに 8080 が開かない** | **配信アプリが起動しているか**（`adb shell ps -A \| grep streamer`）。**画面が消えていないか** — ロック中はカメラが止まる（`totalFrames` が増えない）|
| **急に全台が繋がらなくなった** | **別の AP へ移っていないか**（`adb shell cmd wifi status`）。Wi-Fi が入り直ると保存済みの別ネットワークが選ばれる。§2-4 の削除をやったか |
| `encodeIdle=true` で止まって見える | **異常ではない**。需要駆動なので誰も見ていなければ止まる。`/video` を引けば動く |
