# 電源を入れるところから設営する

2026-10-03。設営の入口をこの順に固定する。素材撮影の内容は [当日チェックリスト](../onsite-checklist.md) を使う。

## 1. 機材と配置

Quest α と β。それぞれ左右のコントローラー。博士タブレット。カメラ A/B/C。PC。展示ルーター。充電器と通信できる USB ケーブルを用意する。
ルーターを先に起動する。PC は有線で `192.168.10.10`。端末は `kougaku-lab-exp-a` の 5GHz へ接続する。インターネットは不要。
IP が違うときは [ネットワーク設営](network-setup.md) を参照する。保存済み Wi-Fi やパスワードを復旧のために消さない。

固定カメラは本番位置へ取り付ける。移動したカメラは配置を確認して位置合わせをやり直す。置いたまま較正値だけを書き換えて正常表示にしない。
本番の照明で露出とホワイトバランスを固定する。熱段が上がった端末は充電を外して冷ます。撮影後に位置を変えた場合も再確認する。

## 2. 起動

Quest と博士タブレットを USB 接続する。初回は端末側で USB デバッグを許可する。
PC のプロジェクト直下で実行する。

```powershell
py -3.11 tools/onsite.py setup
```

登録したUSB serialの端末だけを操作する。PCの卓を起動する。接続中の配信カメラを起動して実フレームの進行を確認する。Questのアプリを起動する。博士タブレットは導入済みの「廻リ視 博士」を起動する。アプリが未導入なら成功にせず導入手順を出す。
Questは登録した端末IDと固定IPと新しい受信情報を照合する。登録済み端末が初回のUSB列挙から欠けた場合は一度再観測する。欠落が続けば起動成功にはしない。
博士UIはAndroidの独立アプリ。画面と動画はタブレット内にある。ホーム画面の「廻リ視 博士」からPCなしで起動できる。横向きと全画面と前面中の画面維持はアプリが行う。ビルドと導入は [博士アプリの手順](../../tablet/README.md)。
タイトルの「スタッフ設定」でクエストα／βを選ぶ。本体ラベルを確認して「接続を確認する」を押す。通信先だけが切り替わる。IP入力とQuestのページへの移動は不要。注意書きでの待機と未開始設定を確認する。博士の音声を試聴する。「説明を確認する」は未接続でも使える。この確認はQuestへの反映に数えない。実機の音と左コントローラーは装着して確認する。
`setup` はアプリのActivityと画像と新しい読み込みログを確認する。Chromeのタブは使わない。再実行では保存済みの接続先を維持する。
PIN のロック画面が出た場合は本体で解除する。解除前は起動成功にしない。PIN はツールにもチャットにも入力しない。
起動結果とタブレットの画像は `logs/onsite/setup/`。このコマンドの成功は起動確認であり開場許可ではない。

α だけを試験する場合は明示する。

```powershell
py -3.11 tools/onsite.py setup --quests alpha
```

| 対象 | USB serial | 博士アプリの接続先 |
|---|---|---|
| Quest α | `2G0YC1ZF890864` | α（`192.168.10.31:8090`） |
| Quest β | `2G0YC1ZF7S06BW` | β（`192.168.10.32:8090`） |
| α の Redmi Pad SE | `122d7871` | スタッフ設定でαを選ぶ |

β の端末 ID とタブレットは未登録。現物を接続して実測値を `tools/web-compositor/operations-fleet.json` に登録する。別の Quest が同じ IP を取得しても正常には扱わない。
手動起動はホーム画面のアプリアイコンを使う。URLを入力しない。PCは博士UIの起動に不要。

## 3. 準備と開場判定

PC は `http://localhost:8099/` を開く。既定は撮影準備用。点検だけなら `tools/web-compositor/serve.ps1 -Inspect`。
接続を確認する。本番の照明で撮影する。素材を検分して採用する。演出を変えたら APK を再ビルドして両 Quest に導入する。
博士 UI で言語とホラー軽減を送信する。選択したクエストに「反映しました」と出るまで待つ。クエストの返答と送信内容の照合はUIが行う。装着したQuestの言語と設定も照合する。
別のページで設定を変更すると説明は停止する。Quest の再起動後は選択を確認して再送信する。再読み込みによる説明位置の復元は同じ起動と同じ送信が有効な場合だけ行う。

```powershell
py -3.11 tools/onsite.py check --deep
py -3.11 tools/onsite.py watch
```

点検は必須の未確認を成功にしない。機器の欠品を外して成功にするために `--quests alpha` を使わない。1 台試験時だけ使う。
実際に装着する。A/B/C の映像切替を歩いて確認する。左右のコントローラーを接続する。音が聞こえることを確認する。較正と安全な歩行範囲を確認してから開場する。

## 4. 止まった場合

| 症状 | 復旧 |
|---|---|
| 黒い画面・画面が消えた | 充電を確認する。USB 接続して `setup` を再実行する |
| 博士アプリが閉じた | ホーム画面の「廻リ視 博士」を開く |
| 旧Chromeの博士 UI がある | 旧ページを閉じる。独立アプリのスタッフ設定で接続先を確認する |
| 設定が反映されない | Quest の起動と展示 Wi-Fi を確認する。送信番号と反映番号を見る |
| 配信アプリの応答がない | 端末で配信アプリを開く。UUID が確認できる端末だけ卓の復旧操作を使う |
| 映像はあるが動かない | 連番が増えない故障として監視が通知する。復旧後も実フレームで再確認する |
| 別の Wi-Fi に接続した | 保存済み `kougaku-lab-exp-a` を選び直す。削除や再登録から始めない |
| 未確認が残る | 行に出る具体手順を実施する。欠品や設置ずれを正常と見なさない |

画面設定を戻す場合は、最初の実行と同じ証拠保存先を指定する。

```powershell
py -3.11 tools/onsite.py setup --quests alpha --restore-tablet 122d7871
py -3.11 tools/onsite.py wifi-restore
```

後者は `wifi-guard` が保存した接続チェック設定を復元する。Wi-Fi のパスワードを読む操作はしない。
タブレットの復元には卓サーバーは不要。復元に成功した保存値は証拠フォルダ内の履歴へ移す。次の `setup` はその時点の変更前値を保存する。復元途中で失敗した場合は元の保存値を残す。
