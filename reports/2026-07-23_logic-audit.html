CRITICAL

① timeline の present-flag が Unity 側で全て true に化ける（契約不整合）

ShowControlClient.cs:848 ⇄ tools/web-compositor/timeline.js:476-485 ｜ 検証 2/2 確定
何が起きるか
Web 卓は hasPost / hasInsert / hasOverride が false でも既定オブジェクトを常に非 null で書き出す。Unity の NormalizeTimelinePresentFlags は受信した bool を捨てて obj != null から再導出するため、全セグメント・全 cue で present-flag が無条件 true になる。
実害
(1) 幽霊 exit インサート（カメラ 0 へ 4 秒差し込み）が全区間に発生 (2) カメラ別グレーディングが中立値で上書き (3) cue の authored フェード / trim が既定値で全置換。ライブ・焼き込み両経路で発生し、Web 検証モードでは正しく見える（実機でのみ発症）。
修正の方向
Unity 側で Web 送信の has* bool を信頼する（ライブパース直後は bool が正しく届く）か、Web 側を CameraDef と同じ「未使用キーは出力しない」方式に揃える。
証跡
timeline.js:478-483  override: a.hasOverride ? {...} : defaultOverride() / post: s.hasPost ? {...} : {...FX_DEFAULT} / insert: ... : defaultInsert()（false でも非 null）
ShowControlClient.cs:848-853  seg.hasPost = seg.post != null; seg.hasInsert = seg.insert != null; c.hasOverride = c.@override != null（bool を破棄）
消費側: InsertController.cs:57（幽霊 insert 登録）/ TimelineDirector.cs:104（中立 post 適用）/ CueScheduler.cs:293-300（override 全置換）
CameraDef.hasPost が動くのは Web が未使用 cam.post キーを削除するから（app.js:143）。timeline はキーを常に出すため同手法が破綻。

HIGH

③ HMD 着脱後に _suspended が固着し、自己回復機構が全停止する

CameraStream.cs:253（resume-gap フォールバック）｜ 検証 2/2 確定 + 親 grep 照合済み
何が起きるか
_suspended の解除は OS の resume コールバック（OnApplicationPause(false) 等）経由のみ。だが resume-gap フォールバック自体が「Quest/Link はこのコールバックを確実に配送しない」前提で書かれており、その経路で復帰すると _suspended=true が恒久残留する（書き手は SetSuspended のみ・grep で確認済み）。
実害
表示は復帰して見えるが、以後 stall watchdog・砂嵐（SignalLostFx）・discovery 自動張替の 3 つが全部無効化。その後にカメラが本当に停止しても砂嵐が出ず、フリーズした最終フレームが露出したまま自己回復しない。
修正の方向
resume-gap 発火時に _suspended=false も揃えて解除する（registry 側から呼ぶなら全 stream 一括）。
HIGH

④ Web override 中に古いゾーン保留が commit し、固定カメラが外れる

ShowControlClient.cs:748 / CameraSwitchDirector.cs:100,419 ｜ 検証 2/2 確定 + 親 grep 照合済み
何が起きるか
ゾーン境界を跨いだ直後（dwell 計時中）にオペレータが cameraOverride を発火すると、tracker は無効化されるが Director 内の保留は _pendingZone == override先 の時しか消えない。別カメラの保留は生き残り、約 cooldown+dwell（既定 1 秒）後に SwitchSource.Zone として commit される。
実害
オペレータの固定が勝手に破れてゾーンカメラへ切り替わり、さらに LapCounter が周回を誤進行（Zone commit のため算入される）。既存テスト T5 は保留ゼロの条件で通るため未検出。
修正の方向
override 適用時に Director の保留を無条件クリア（CancelPending 相当を追加）。
MEDIUM

⑤ 動画 cue の Prepare 失敗で _current が残留し、ゾーン自動切替がデッドロック

ScreenOverlayController.cs:200 ｜ 検証 1/1 確定
何が起きるか
動画パスは Prepare 前に _current=data を立てるが、DL 失敗→ストリーミング URL フォールバック→Android で Prepare 失敗（既知の NuCachedSource2 -1）のとき errorReceived はログのみで _current を戻さない。静止画パスは安全（非対称）。

修正の方向
errorReceived / Prepare タイムアウトで StopOverlay 相当のクリーンアップを走らせる。
MEDIUM

⑥ 位置合わせのキャンセル退場が、未確定のプレビュー変換を元に戻さない

CourseRegistrationController.cs:437 / CourseFrame.cs:115-122 ｜ 検証 1/1 確定
何が起きるか
残差ガード通過時点で SetRegistration(save:false) が CourseFrame をプレビュー値へ書き換え（ゾーン再配置 + 要再登録警告も解除）。トリガー長押しキャンセルはこれを退避・復元しない。

修正の方向

MEDIUM

⑦ stall watchdog が _lastFrameTime を汚し、砂嵐が約 10 秒毎に点滅消灯

CameraStream.cs:369 ｜ 検証 1/1 確定
何が起きるか
強制再接続時にフレーム未受信のまま _lastFrameTime=now を代入。SignalLostFx はこの値を配信断の真実源として読むため、10 秒毎に 0.6 秒だけ「復旧した」と誤認して砂嵐が消える。
実害
真の信号断中、砂嵐が周期的に消えてフリーズフレームが露出（「信号ロスト」演出が壊れて見える）。throttle は別変数で担保済みなのでこの代入は不要。
修正の方向
_lastFrameTime = now の行を削除（再発火抑止は _lastReconnectTime が既に担う）。

⑧ streamer: カメラ自動復旧後、/info が 0x0 に固着

CameraController.kt:314（fixed-cam-streamer）｜ 検証 1/1 確定
何が起きるか
bind() が info を widthPx=0 で再構築するのに変化検知用 lastInfoW/H をリセットしない。復帰後に同一解像度でフレームが来ると再設定がスキップされ 0x0 が恒久固着。deviceRotationDeg も同様に 0 へ戻る。

修正の方向
bind() で lastInfoW/H = -1 にリセット。
