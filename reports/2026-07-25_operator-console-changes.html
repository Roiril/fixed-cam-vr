新しく増えた仕組み — 実測滞在時間

「進入 +20 秒」の演出は、体験者が 20 秒その区間にいることが前提です。緊張した人は 8 秒で抜けます。 リボンは「そこに演出がある」と描き続けるので、作者はそれに気づけません。そこを見せるための一次データを作りました。

Quest SegmentDwellLog（純ロジック・テスト 7 本） ← CueScheduler.CameraEntered ＝ ショーの時計（ZoneCommitted 由来） ※ 手動 A・Web 固定・インサートの画面切替では動かない ＝「体験者がそこに居た時間」 → heartbeat の dwell[]（送信失敗ぶんは次回へ戻す・上限 64） 卓 capture-server が dwell_stats.json へ集計 → GET /dwell/stats ・ POST /dwell/reset Web 2 秒ごとに引き直し → 区間フッタ「実測 平均 8.2s（最短 6.2s / 5 回）」 → 開始位置が滞在を超える演出に ⏱ 警告（ヘッダ・インスペクタ・tooltip）
  • スタッフ介入中（カメラ固定・演出の手動再生）とラン開始では計時を捨てる（滞在の水増しを防ぐ）
  • 異常値（1 秒未満・600 秒超・lap<1）は卓側で落とす（時計飛びで平均を壊さない）
  • 集計は dwell_stats.json に永続。会場が変わったらリボンの「⟲ 実測クリア」でリセット

実機（Quest）で最初にやること

ここから先は卓では確認できません。段 B（時計と画面の分離）は v3 と無関係に既存の挙動を変えているので、まず 1 ビルドで確かめてください。
  1. 卓サーバを再起動（serve.ps1）— 新しい /dwell/stats と /scenarios/save は再起動後に効きます
  2. APK をビルドして 1 周歩く。演出中に歩いても周回が進むこと・cue / インサートの後にゾーン切替が戻ることを確認
  3. 歩いた後、卓のリボンの区間に 実測 平均 が出ることを確認（出れば Quest → 卓 → UI の経路が生きている）
  4. v3（演出・カット）を使うなら、リボンの 「⇪ v3 に変換」→ 💾 保存。押すまで show.json は v2 のままで、実機は従来経路で動きます（＝退避路は生きている）
