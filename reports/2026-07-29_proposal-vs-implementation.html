企画書の要求と、いま動いているもの

旧版の企画書（docs/archive/）を実装と突き合わせた結果 ／ 2026-07-29 午前

⚠ この文書は古い。 突き合わせの相手が旧版の企画書で、同じ日の午後に 企画書が学会論文版（3 区間を 3 周・導入を含め 3 分以内・1 周目の録画を 3 周目の背景に・映像の乱れ）へ 差し替わった。企画書の正は docs/proposal/ の 1 本だけ。

ここで「無い」と判定した項目のうち、体験の終端・3 分の時計・導入・映像の乱れ・遅延の観測は その後に実装した（.claude/plans/2026-07-29_proposal-v3-implementation.md）。 逆に空間音響・しゃがみ / 振り向き / 着座・監視カメラ風 UI・90Hz は新しい企画書には無い要求なので、 ここでの「重い順」はもう当てにならない。調査のやり方の記録として残す。

企画書の要求を 33 項目に分けて実装と照合しました。映像を受け取って画面に出すまでは、ほぼ動く形であります。演出を著作する道具も揃っています。

足りないのは、体験を成立させる条件です。3 分で終わること、暗転して終わること、始める前に立ち位置を確かめることは、どれも実装がありません。恐怖の演出として企画書が名指ししたもののうち、画角外から鳴る音と、しゃがみ・振り向き・着座の検知もコードが 1 行もありません。

読み方

判定を 2 列に分けました。コードがあるかと、Quest 実機で確かめたかです。この作品はほぼ全機能が実機未検証なので、1 列にまとめると実態より進んで見えます。

ある要求を満たすコードが本番経路にある
一部仕組みはあるが要求の一部だけ／素材や配線が欠けている
無い該当するコードが存在しない

実機列の「確認済」は、Quest 3 の実機で動いた記録が残っているものだけに付けています。EditMode テストの通過や、ブラウザでのオペレータ卓の操作確認は「未確認」に含めます。

位置で動かす、体験を進める

企画書が求めたものコード実機実態
ゾーンを移動するとカメラが切り替わるある未確認頭の位置でゾーンを判定し、滞在 0.5 秒で確定して暗転付きで切り替える。ゾーンの形は卓で床タイルを塗って決める
特定の場所を通ったことを演出のきっかけにするある未確認床に引いた線を横切ると発火する。線は担当カメラに紐づき、別の領域の線を踏んでも何も起きない
体験者の入れ替えある未確認卓の「ラン開始」が周回・発火済み・カメラ固定・演出・素材の束縛をまとめて戻す。PC が居なければ右グリップ 2 秒長押し
屈む・しゃがむを演出のきっかけにする無い—頭の高さを演出の判定に使っている箇所が 1 つも無い。ゾーンの箱は高さ 2m を一律に貼るので実質いつも真。線の判定も高さを見ない
振り向きを演出のきっかけにする無い—頭の向きを読むのは表示物の配置（スクリーン追従・ステータス表示・CG 人形の体の向き）だけ。演出の開始条件は「進入して t 秒」「離脱時」「線の通過」の 3 つのみ
着座（シーン 3：椅子に座り正面カメラに大きく映る）無い—座位を扱うコードが存在しない。「その区間のカメラが正面を向いている」という設置の問題としてしか表現できない
線形の 3 シーン（廊下 → 角を曲がる → 部屋）を通す一部未確認進行モデルは「何周目の、どのカメラの区間か」の 2 キー。順路を 3 ゾーンにして 1 周目として書けば、企画書の 3 シーンはそのまま著作できる。ただし進行に前後の向きが無く、終端の概念も無い
約 3 分で終わる無い—体験全体の経過時間を持つ仕組みが無い。時間を持つのは演出 1 本の尺（既定 45 秒の打ち切り）と区間の滞在計測だけ。進行は完全に位置で駆動する
暗転して終了する無い—起動時の黒フェードは起動専用で、解除後に自分を破棄する。終わりを告げる暗転も、終了という状態そのものも無い

周回モデルの落とし穴

順路の最後のゾーンからスタート領域へ戻ると、周回が 2 に上がります。1 周だけの構成で全演出を 1 周目に置いていると、そこから先はすべての演出が沈黙します。逆走では上がりません（順路の次のゾーンに一致したときだけ前進するため）。上がるのは最後まで行ってから最初に戻ったときだけです。

迷った体験者、怖くて引き返した体験者ほど、何も起きない画面を見続けることになります。

スクリーンが頭に追従することについて

本番シーンのスクリーンは頭に追従する設定です（左右のみ・10° の不感帯・0.3 秒の減衰）。2026-07-19 の計画で、追従することを前提に緩急を設計しています。

映像の中身は固定カメラのままなので、企画書の「振り返ってもカメラは動かないので自分の後頭部しか見えない」は成立します。一方で「正面の固定カメラに自分が大きく映る」の「正面」は、スクリーンが常に視界の中央にあると意味を失います。あの位置から見られている、という空間的な参照が消えるためです。追従を切ればワールドに据えられたモニタになります。どちらで行くかを企画書の被観測感と突き合わせた記録は残っていません。

企画書が求めたものコード実機実態
空間音響で画角外から音を鳴らす無い—プロジェクト内の AudioSource は 3 つだけで、すべて spatialBlend = 0 の 2D 再生。定位の指定も spatializer の使用も 1 箇所も無い
環境音（通気口・ハム音・遠くの足音）一部未確認再生器は BGM の 1 レーンのみ。音源は HorrBGM.mp3 の 1 本だけで、環境音の素材が無い。卓で URL 音源を足せば BGM として流せるが、曲と重ねられない

埋まっている場所と、空いている場所

偏りには理由があります。7 月の 215 コミットは、ほぼすべてが演出を作れるようにすることに向いていました。オペレータ卓、show.json の契約、演出とカット、通過ライン、CG 人形と較正、実機なしの検証シミュレータ。

道具は揃いました。残っているのは 2 つです。ひとつは道具で作られる中身（血痕・落書きの素材、環境音、効果音、演出の本番データ）。もうひとつは、体験を体験として成立させる外側の枠です。始まりと終わり、時間、姿勢。これらは道具の問題ではないので、演出面をいくら磨いても埋まりません。

重い順に並べたギャップ

  1. 体験が終わらない — 進行が完全に位置で駆動し、時間による前進も終端もありません。動かない体験者、固まる体験者、引き返す体験者に出口がない。しかも順路の最後からスタートへ戻ると周回が上がり、以後の演出が全部沈黙します。展示では必ず起きる動きです
  2. 90Hz を要求していない — 企画書が技術的チャレンジとして名指しした数値に対し、設定するコードが 1 行もなく既定の 72Hz で動いています。共有設定に触る変更なので、同居アプリへの影響を見てから行う必要があります
  3. 空間音響がゼロ — 「見えない方向から音がする」は企画書の恐怖設計の柱のひとつです。実装が無く、著作する面も無い
  4. 姿勢が読めない — シーン 2 の「屈む・覗き込む」とシーン 3 の「着座」を発火条件にできません。「覗き込む位置に踏み込む」は通過ラインで代替できますが、しゃがむこと自体は取れません
  5. 監視カメラ風 UI が無い — カメラ番号とタイムスタンプは、90 年代の見た目を一目で伝える記号です。映像の説得力に直結します
  6. 色収差が卓と実機で食い違う — 卓のプレビューで見えているものが実機で出ません。オーサリングの信頼を損なう種類の乖離です
  7. 遅延を測る手段が無い — 100ms 目標に対して、撮影から表示までを測る方法がありません。現在測れているのは受信側の指標だけです
  8. 導入の欠落 — 立ち位置を確認させてから始める流れがありません。開始位置に居ない状態で始まると、スタート領域の演出が出ないまま進みます
  9. ほぼ全機能が実機未検証 — 上の 8 項目を埋めても、Quest で通しで動かした記録が無い状態は変わりません

この調査のやり方

企画書 2 本から要求を 33 項目に分け、5 つの視点で並列に実装を調べました（映像の取り込み / 映像の演出 / 位置と進行 / 音と運用 / 体験構造の設計批評）。「実装されている」の判定にはすべてファイルと行番号の根拠を求め、主要な指摘は自分で grep して裏を取っています。

裏取りしたのは次の 4 点です。Assets/ 全体に targetFrameRate と displayFrequency が 0 件であること。ScreenComposite.shader にビネット・グレイン・走査線があり色収差とピクセル化が無いこと。AudioSource が 3 つですべて 2D であること。姿勢・着座・ラン経過時間のコードが存在しないこと。

コードは変更していません。この文書は突き合わせの結果だけを述べています。／ 廻リ視（Assets/Scripts/・FixedCamVr.*）のみを対象とし、同居する別アプリは調査範囲に入れていません。
