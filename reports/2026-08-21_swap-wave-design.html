黒い波の設計

かっこよく・アートチックに・インタラクティブに ／ 2026-08-21 シュビー

美学の柱を 3 本立て、その下に設計を 8 本置く。骨子は「波は揺れずに走る」 「ほつれが墨の質感を作る」「応答するのは黒（呪い）だけ」。 実装は 3 段階に分け、1 段ごとに白地の動画で判定する。隠し切り（芯 ∪ 棒の構造・0091・0100）は 1 ビットも触らない。

1. 美学の柱 — 全部の判断をここから導く

縦は機械、横は生き物

帯の格子（48 行の等間隔）は装置の走査線で、縦は絶対に揺らさない。 有機的な動きはすべて横方向（端の波・ほつれ・走り）に置く。 機械の規則の上で黒だけが生きて動く、という対比が「アートチック」の正体。 帯を回す・行の高さを揺らす・縦に曲げる、は全部この柱に反するので却下。

装置は正直、呪いは応答する

インタラクティブにするのは黒だけ。映像・post・カメラは 1 ビットも 反応しない。作品の恐怖は「装置は正直に映している」という信頼の上に乗っているので、 装置側を反応させた瞬間に壊れる。呪いだけが体験者に応える、という分離が インタラクティブ性と正直さを両立させる唯一の形。

黒だけで組む

明るい線・色・白は使わない（0091）。かっこよさは形と時間（緩急）だけで作る。 参考画像の美しさは「太い筆致 ＋ かすれ ＋ 余白」＝ 書の語彙であって、色の語彙ではない。

2. 「かっこいい」の分解 — いまの波に足りない 4 つ

いまの波は対称な sin の重ね合わせ ＝ 振り子。連続で読めるが穏やかで、 「ゆらゆらした切り絵」に寄っている。動きのかっこよさの文法に照らすと、足りないのは:

文法いまあるべき形
緩急sin ＝ 立ち上がりも減衰も同じ速さ 立ち上がりは速く、減衰は遅く（attack–decay の非対称パルス）
方向全帯がその場で伸縮するだけ。山が移動しない 波の山が体を走る。向きは段の物語と結ぶ
対比太い棒だけ。密度が一様 太い芯と細く長い針の対比。密な帯群と疎な帯群の呼吸
キメ差し替えの縁に画の変化が無い（乱れパルスだけ） 物語の縁（justSwapScreen）に視覚の最大の一拍を置く

3. 設計 8 本

A. 走る波（背骨）

何: 波の山（crest）が体を駆け抜ける成分を 1 本足す。形は sin ではなく 非対称パルス — 山の前縁は 0.05 体高で立ち上がり、後ろへ exp で減衰して尾を引く。 山の間隔は体高の 1.2 倍（画面にいつも 1 つだけ山がある）。

向きは段の物語と結ぶ:

段山の走り方なぜ
ほどける前線と同じ向きに、前線より約 1.5 倍速く 波が前線の先触れになる。「これから食われる場所」を波が先に舐める
縮む / 育つ行き先（人形の足元 / 人の背丈）へ向かって収束 / 湧き上がる 吸い込み・成長に方向の証拠が付く
晴れる最後の 1 本が走り抜け、その後ろから帯が消える 波が体を「離れていく」。終わりに因果が付く

骨子: SwapWaveExt に crest 項を足す。 crest(rowN, t) = amp · pulse(frac((rowN − c(t)) / 間隔))、c(t) は段の進みから導く （時計は既存の _SwapCover / _SwapThread / _SwapSeed で足りる）。

B. 細いほつれ（質感）

何: 帯の中の細い帯（15px の行のうち縦中央 5px）が、棒の先からさらに伸びる針。 長さは裾の重い分布 — 短いのが大半、ごく稀にすごく長い。参考画像の実測 （中央値 13px / 最大 257px）をそのまま設計値にする。行ごとの長さは hash(行) で固定。

時間の繋ぎ方が要点: 針の長さを時間で乱数的に変えるとパチパチする（0098 で 階段を廃した理由と同じ）。⇒ 針は A の山に引きずり出される — crest が通っている行だけ針が伸び、通り過ぎると縮む。時間は連続のまま、 「波が体から糸を引き抜いていく」という因果が画に出る。

縮む段だけ向きを持たせる: 針が行き先へ向かって流れる ＝ モーションライン。 吸い込みの方向性は A と B の二重で効かせる。

C. 稀に跳ぶ帯（アクセント）

何: hash(行) 上位 10% の行だけ、段あたり 1〜2 回、一瞬だけ大きく突き出して戻る （立ち上がり 0.15 秒・減衰 0.3 秒）。規則的な波の上に事故のような棘が乗り、信号の乱れらしくなる。

頻度を上げると全体がノイズへ戻って 0089（全画面の乱れの否定）に逆行する。 入れすぎの検査は「1 画面に同時に跳んでいる帯 ≤ 2」。

D. キメの一拍（物語の縁と視覚の縁を揃える）

何: justSwapScreen（画面が実際に差し替わる 1 フレーム）の縁から 0.25 秒、最大の山が全身を走り抜ける。振幅 2 倍・針 2 倍。既存の乱れパルス（0.55 × 0.20 秒）と 同じ縁なので、画・乱れ・音（sfx_glitch）が同じ瞬間に揃う。新しい音は足さない （sound-design 規約 — 装置の音はもう鳴っている）。

なぜ: 世界が実際に変わるフレームがそこ。いちばん大きい視覚の一拍を 物語のいちばん大きい縁に置くのが「キメ」の定義そのもの。

E. 全身のエネルギー（インタラクティブ第 1 層 — 歩速）

何: 体験者の歩く速さが波の全体エネルギーになる。 立ち止まると波が静かな呼吸に沈み、歩く・動くと荒れる。

項目設計
入力頭の XZ 速度（BodyInputHistory 由来。新しいセンサ無し）
平滑半減期 0.8 秒（純ロジック SwapEnergyLogic・dt 注入・テスト可能）
写像energy = clamp01(速度 / 1.2 m/s)。振幅倍率 0.55 + 0.45·energy ／ 山の速さ 0.7 + 0.6·energy
下限静止でも 0.55（完全に止めると死んで見える。静の怖さは「小さく蠢き続ける」こと）

なぜ効くか: 説明ゼロで「自分に反応している」を発見させられる。 体験者は本能的に足を止める → 波が静まる → また動くと目を覚ます。 行動のループが指示なしで生まれる。これが「インタラクティブ」の本体。

規律: 変わるのは見た目だけ。総尺・段の進行・差し替えの縁は 1 ミリも動かさない（動かすと「歩かない体験者で演出が終わらない」を作る）。

F. 局所のホットスポット（インタラクティブ第 2 層 — 手）

何: 手が速く動いた場所の周辺だけ、帯の振幅・針・跳びが増える。 腕を振るとその腕のあたりの波が毛羽立つ。

項目設計
入力既にある ShowBodyInput（頭＋両手のワールド位置）。CG と同じ較正で画面へ投影（TryActorFocus と同じ流儀）
uniform手 2 点 ×（uv + 半径 + エネルギー）＝ 2 本。テクスチャ読み増ゼロ
結合弱く（ゲイン 0.2〜0.4）。平滑の遅れ 0.3 秒は消さない — 遅れて反応することが「気づかれた」と読ませる演出そのもの
退化手が取れない（コントローラ持ち・トラッキング切れ）→ エネルギー 0 → A〜D の絵に自然に落ちる。切り分けの分岐を増やさない

G. 追従そのもの（インタラクティブ第 3 層 — 既にある。軸として明文化）

差分マスクはライブの本人を毎フレーム追う（腕を上げれば黒も上がる — 0091 の 「黒いものが自分の腕などに合わせて動くことで分かる」はここで既に成立している）。 人形 → 人の育つ塊はいまの立ち位置に付いてくる（CG follow）。 横へ一歩ずれると黒が付いてくる — これが第 3 層。新規実装ゼロ。 設計上の指示は 1 つだけ: BodyInputHistory の 0.15 秒の遅れを「ずれ」として 消しにいかない。あの遅れが生き物性そのもの。

H. 余韻（終わり方が上品さを決める）

人 → 人形: 晴れた後、人形の輪郭に針が 2〜3 本だけ 0.5 秒残ってから引く （呪いが食事を終える）。人形 → 人: 最後の帯が人の肩から上へ剥がれて終わる。 どちらも「消える」ではなく「離れる」。A の晴れ方（最後の山の後ろから消える）と同じ原理の適用。

4. やってはいけない側（この設計の外周）

  • 進行を入力にしない。 入れ替わりは体験者が何をしても必ず完走する （watchdog の思想）。入力が変えてよいのは見た目だけ
  • 報告ボタンを読まない（0050。読んでよいのは untilMark の 1 か所だけ）
  • 乱数を使わない。 hash（行・周期番号）と体の入力だけ。同じ入力 → 同じ絵
  • フレーム履歴を持たない。 残像が欲しければ「同じ波を 0.1 秒前の時刻で再評価して 薄く引く」で決定論のまま作れる（ただし薄い黒は体の外にしか置けない — 隠し切りは常に全黒）
  • 明るい線を出さない（0090・0091）。かすれ・針・山、全部黒
  • 映像側を反応させない。 post・露出・乱れの育ち（GlitchEscalation）に 体の入力を混ぜない — 応答するのは呪いだけ

5. 判定の設計（作る前に決めておく）

  • 静止画では判定できない（走る波・エネルギー応答は動画でしか見えない）。 門は白地の動画: menu swap -Set plate=white → make-preview-video.py
  • 層を 1 つずつ入れて焼く。 -Set フラグで A〜F を個別に 切れるようにする。まとめて入れると「どれが効いたか」が消える（troubleshooting の教訓）
  • 機械の門 3 つ: ①隠し切り不変（白地 covered の人の灰色 ≤ 現行 3% 台） ②山の移動が時系列で観測できる（行ごとの端 x を抽出 → 山の行位置が単調に動く） ③針の長さ分布（中央値 / 最大の比が参考画像 13/257 のオーダー）
  • E / F はプレビューに「台本の動き」が要る。 代役が 静止 1 秒 → 歩行 1 秒 → 手を振る、を演じる台本を ShowSwapPreview に足す。 これが無いと応答の層は絵で判定できない（実機頼みになる）
  • 最終判定は実機で人が被って歩く。 自動走行はカメラの前に誰も居ないので 覆いが 1 画素も出ない（20260821_052102 で確定済み）。機械で取れるのは mask / rect / vis / 被覆まで

6. 実装の段階

  • 第 1 段A ＋ B ＋ D（かっこよさの背骨） 入力なし。シェーダ（SwapWaveExt / mixBar）と SwapMorphFx の uniform 1 個（キメの経過秒）だけ。 白地動画で判定して赤入れをもらう
  • 第 2 段E ＋ G の明文化（全身の応答） 純ロジック SwapEnergyLogic ＋ uniform 1 個 ＋ プレビューの台本。実機で被って確かめる価値が 初めて出る段
  • 第 3 段F ＋ C ＋ H（局所応答・アクセント・余韻） 1・2 段の赤入れを見てから量を決める（特に C は入れすぎが下品）
  • 保留視線への反応（判定待ち） 画面を見つめると波が一瞬静まる＝「見られていることを呪いが知覚する」。強いが、 呪いの性格（世界観）を新しく決める話なので OPEN.md の案に置いた。ユーザーが口にするまで実装しない

7. コストと危険

何見立て
GPU全部 ALU のみ（新しいテクスチャ読みゼロ）。既存の箱棄却の内側 ＝ 画面の 1〜2 割 × 2.6 秒。 隔離殻の 90→39fps の型（全画面で毎画素の重い数式）には当たらない
決定論入力駆動になるほど「プレビュー ＝ 台本、実機 ＝ 本人」の差が広がる。 台本を実機のテレメトリ（実走行の頭・手の軌跡）から作れば埋まる — 将来の手として記録
過剰化E・F のゲインを上げすぎると「呪い」ではなく「エフェクトのデモ」になる。 結合は弱く・遅れは残す、が保険。数値は全部 1 か所（SwapWaveExt と SwapEnergyLogic の const）に置く
実機の見かけ実機では人型が画面のごく一部（100〜300px）。針の細さは行の 1/3（5px）が下限で、 それ以下は符号化と mip で消える。白地動画は必ず実寸でも確認する
