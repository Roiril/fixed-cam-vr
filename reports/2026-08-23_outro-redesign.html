終幕の再設計 — ちかちかをやめ、電源断で終わる

canon/LEDGER.md 0111 ／ 2026-08-23 実装 ／ 独立した設計批評 2 体の収束を根拠に採った

ちかちか 6 秒を、管が縦に潰れて横一本の線になり、点になって消える 0.9 秒に置き換えた。 体験全体が浴びせてきた「異変の語彙」（明滅・乱れ・劣化）と正反対の、 一方向で戻らない一回性の事象だけが「終わった」と読める。 報告の 1 文字目は 7.2 秒後 → 2.1 秒後、 打ち終わりは 10.6 秒 → 5.5 秒。反復する明滅はゼロ。 実装済み（EditMode 1632/1632・menu outro の 31 コマで確認・白飛び 0 px）。 実機で被る検証だけが残っている。

1. 診断 — なぜテンポが悪く、なぜ終わったと読めないか

現状の終幕は Flicker 6.0 秒 → 黒 1.2 秒 → 報告の打鍵 3.4 秒。 「終わった」と確定できるのは報告が読めてからなので、 体験の終了から約 11 秒間、体験者は何が起きているのか分からないまま待つ。

分かりづらさの原因は長さではなく語彙にある。体験者は 3 分間 「画面が変になる ＝ 異変」と学習させられ続けた直後にいる。 ちかちかしながら消えていくスクリーンは、その文法の中では「また何か起きた」としか読めない。 明滅は往復する動きなので、原理的に終端に見えない（まだ戻るかもしれない、を常に残す）。

加えて安全の問題がある。現状の明滅は 6〜24Hz （OutroLogic.FlickerRateLo/Hi）で、 光過敏性発作の危険帯（3〜30Hz）のただ中にある。VR で視界の中心を占める面の明滅としては、 「目に悪い」は感覚ではなく実害の指摘として正しい。

2. 動かしていないもの

  • パススルーへは戻さない。背景は黒のまま（LEDGER 0048 — この部分は不変）
  • 報告 4 行の文言・1 字ずつの打鍵・12 字/秒・左寄せ（0048 / 0063）
  • 終幕の合図の機構（run.outro.afterTakeId / EndingCueLogic）
  • 報告は次のランまで出したまま（OPEN の既定）
  • 新しい音源・一撃は足さない（sound-design「終幕に足す一撃は 1 つも無い」）
  • 時刻 OSD で嘘をつかない（巻き戻し・停止・加速の禁止）

3. 設計 — 「記録終了」（装置が自分で落ちる）

段尺何が起きるか
Collapse0.9s ブラウン管の電源断。画（映像・砂嵐・時計・粒、発光しているものすべて）が 縦に潰れて横一本の線になり（0.35s）、 線が中央へ縮んで点になり（0.3s）、残光が消える（0.25s）。 単発・一方向・戻らない。明滅は 1 度も無い
Dark1.2s 何も無い黒。間。（現状のまま — 問題にされたのは 6 秒の側で、 この間は報告に重みを与える）
Report1.5s〜 報告の 4 行が 1 字ずつ打鍵音つきで打たれる（従来どおり・3.4s で打ち切る）
Done—文字だけが黒に残る。次のランまで

なぜこれが「終わった」と読めるか

  • 体験がまだ一度も見せていない身振りだから。 3 分間の語彙はすべて「揺れる・乱れる・劣化する」＝ 往復と漸進。 潰れて線になって点で消えるのは、秩序だった一方向の一回性の事象で、その対比だけが終端を作る
  • 「壊れた」ではなく「切れた」の記号だから。 テレビの電源が落ちる画は、ブラウン管を知らない体験者にも「画が消えた」としては必ず読める。 知っている体験者には「電源断」として一段強く効く。二層で、どちらか一方に賭けていない
  • 意味は「装置が自分で仕事を終えた」。 誰かが外から切った、にはしない — 外部の意図を示唆すると「まだ何かいる」と読まれ、 死んだ装置が直後に報告を打つ矛盾も立つ。調査が完了したから装置が閉じた、 という筋なら直後の「調査完了です。」へまっすぐ繋がる

音

新しい音は 1 本も足さない。装置の声（唸り）を潰れの頭で引き切り、 3 分間鳴り続けた音が消えること自体を終幕の音にする。 部屋の音は現行どおり前へ出て、最後の 1 字が打たれた縁から約 1 秒で無音へ落とす。 現状は打鍵 3.4 秒の途中（段 Done ＝ 1.5 秒）で部屋の音が切れており、この欠陥も同時に直る。 ⚠ 音のランプは段の尺から切り離す（下の罠 3）。

4. 実装の作用点と、潰した罠

批評 2 体が実コードを読んで挙げた指摘。9 件すべて実装で潰してある （この節は、次に終幕を触る人が同じ穴に落ちないための記録）。

#何どうする
1uv 変形の作用点 潰すのは発光面のサンプル座標だけ。ScreenComposite.shader の frag 冒頭（screenUv 導出・961 行付近）で逆写像する。 末尾の col には潰す材料がもう無い。 管のガラス（角丸 _CrtRound・縁 _CrtEdge）は元の uv のまま計算する — 潰れた uv を CrtSdf に渡すと fwidth が発散して線そのものが黙って消える
2OSD（時計） 潰れの頭 0.1 秒で _OsdOpacity を 0 へ。潰した uv で OSD を引くと 暗黙微分でミップが飛んで灰の帯になるため、一緒に潰すのではなく先に消す （装置が落ちる話と矛盾しない）
3音のランプ ShowSoundDirector は StageProgress01（段相対）を読んでいるので、 段を 6.0s → 0.9s にすると部屋の音のせり上がりが黙って 6.7 倍速になる。 装置の声・部屋の音のランプは段の尺から独立した固定尺（1.5〜2.0s）へ切り替える。 SoundBedLogic は OutroStage.Flicker を名前で分岐しているので、 段名の変更と同じコミットで直す（片方だけだと終幕が黙って無音になる）
4効果の実在の観測 _ScreenCollapse を書けなくても既存判定は全部 PASS する （画は「0.9 秒ライブ → 黒へ瞬断」になりログは OK と言う）。 ev=outro に cl=（材質へ実際に書いた潰れ値）を足し、 analyze-xp-log.py の終幕節と対で直す。 「状態は進んだが効果が出ていない」をこの codebase は繰り返し踏んでいる
5線の明るさ 輝度補償はエネルギー保存にせず上限を置く — linear で潰れ直前の画面平均の 2〜3 倍・絶対 0.5 以下、縮む段では減衰させる（残像対策）。 確定値は menu outro プレビューの実測と、実機で被る 1 回で決める （見かけの明るさの机上見積もりは 2 回続けて外した前歴がある）。 ⚠ 線が育つ向きの動きは 1 フレームも入れない — 逆向きは「起動しかけ」に反転する
6show.json のキー flickerSec → collapseSec に改名し、Sanitized の許容を 0.4〜2.0 秒に絞る（現行 Pick は 0.01〜60 なので、古いキャッシュの 6.0 が 「6 秒の崩壊」として通ってしまう）。旧キーは読み捨て。 既定は C# / 卓 / capture-server.py の 3 者で揃える（既存の流儀）
7畳む経路 ResetScreen() 1 本に集約 — power=1 / collapse=0 / OSD 不透明度=1 を 必ず一緒に書き戻す。終幕を畳むすべての経路（終わった / ラン開始 / 相変化 / OnDisable）が通る。 「凍結が解けない」を 4 回踏んだ型を新しい uniform で再生産しない
8_ScreenPower との分担 _ScreenPower が「死んだ」の唯一のスイッチ（Collapse 中は 1・Dark 以降 0）、 _ScreenCollapse は Collapse 段以外 0。二重に暗くしない。 writer はどちらも OutroDirector だけ
9死んだコードの掃除 FlickerPower / Hash01 は使わなくなったらテストごと消す （死んだ決定論コードを残さない）

6. 判定を待つもの（既定つき・どれも未実装）

線の明るさは暗所で眩しくないか
上限 1.25 は「白飛びさせない」から実測で決めた値で、暗所の VR で被るまで確定しない。 眩しければ下げる（1.0 にすると「潰れても明るくならない」）。 見かけの明るさの机上見積もりはこのプロジェクトで 2 回続けて外している。
時計を残して止める版を入れるか
独立設計側の案：画だけ先に消えて時計だけが黒い管に残り、最後の 1 秒を刻んで止まってから管が潰れる。 「3 分間刻み続けた唯一の不動点が止まる」は作品自身の言葉で書いた終了宣言になる。 ただし rules/streaming.md の「時刻で嘘をつかない（停止も嘘）」に終幕の例外を書き足すことになり、 時計に気づいていなかった体験者には効かない。 既定：入れない（いまの実装は潰れの頭 12% で時計を消す — 潰れた座標のまま引くと 暗黙の微分が飛んで灰色の帯になるため。装置ごと落ちるので筋は通る）。
打ち終わった後の終端の記号は要るか
報告を打ち終わると以後は永久に無変化・無音で、「まだ続くのか」と待つ体験者が残る可能性がある （分かりづらさの残り 1 つ）。既定：このまま — 4 行目「装置を外してください。」が指示そのもので、打鍵音が止まることが音の終端になる。
「電池が切れかけ」という比喩ごと置き換えてよかったか
0111 で否定されたのは逐語では「ちかちか」まで。ただし切れかけの表現手段（明滅）が消えたので、 比喩だけ残しても画にする手が無い。「装置が調査を終えて落ちる」に置き換えた。 比喩を戻したいなら別の判定が要る。
報告の数字を最後に打つか
既存の案（2026-08-19）。いまは 1 行目の数字が最初に出る。順を変えると「集計してから答えた」ように見える。 文言は 1 字も動かさない。既定：今回は触っていない（本件と独立に判定できる）。

7. 退けた代案

案退けた理由
砂嵐で終わる信号断＝異変の語彙。終端に読めない
ゆっくりフェードだけ安全だが、漸進は劣化（異変の語彙）と区別できず「終わった」の記号性が無い
破片を吐き出して現実へ帰す（導入の逆）0048 が「パススルーへ戻さない」で棄却済み
報告を先に出し、背後で画面が死ぬ（並列化）テンポは最速だが、打鍵音と装置の死ぬ音が重なり、 点いたままの画面の上に文字が乗って「黒の中の掲示」の構図が壊れる
画を凍らせてから消す（記録終了の Seal 段）凍結は 3 周目 A で使った異変の語彙。 終幕に持ち込むと最後の 1 手がまた曖昧になる
物理スイッチの「カチッ」を鳴らす外部の意図＝「誰かが切った」を示唆する。 新しい一撃を足さない規約にも反する

8. 検証（3 つ通過・1 つ残り）

  • ✅ 安い門：EditMode 1632/1632。「潰れの進みが 1 度も戻らない（明滅ゼロ）」 「決定論」「潰れ中に電力を二重に落とさない」「報告の 1 文字目まで 2.2 秒以内」 「音が段名に依存しない」「旧キーの 6.0 秒を新キーへ写しても通さない」を固定
  • ✅ 絵の門：menu outro の 31 コマ。潰れ → 線 → 縮む → 点 → 消える の各段を目視確認。管の角丸・縁の暗さは潰れておらず、時計は潰れの頭で消えている
  • ✅ 数値の門：白飛び全コマ 0 px（素の画と同じ）。 尖頭は素の 1.11 倍まで。平均は単調減少で往復なし
  • ⬜ 被る門：線の明るさが暗所の VR で眩しくないか、電源断が「終わった」と 読まれるかは実機で被る以外に確かめる手が無い。次の被り検証に混ぜる （visual-verification の「溜めて 1 回」）

走行時の観測は ev=outro の cl= と ev=sum の clMax=。analyze-xp-log.py が「潰れ切ったか / 途中で止まったか / 1 画素も出ていないか」を判定する。この観測が無いと「潰れなかった」を誰も検出できない — 段は正しく進み pw も Dark 以降 0 になるので、他の判定は全部 PASS してしまう。
