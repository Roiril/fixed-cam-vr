体験者を覆う黒いマスクの仕様

2 周目 C の末尾 / 3 周目 A / 4 周目 A ／ 実装とプレート素材の実測

黒い覆いは作り方が 2 つある。2 周目 C の末尾と 3 周目 A の前半は、カメラの映像と無人プレートの差で人の形を引く。3 周目 A と 4 周目 A の入れ替わりの段は、体験者の位置に立てた CG の人型の形をそのまま使う。前者は映像に写った当人そのものなので位置も腕も一致する。後者は較正を通した投影で、腕は手のトラッキングから追う。

周囲の光が変わって人以外が黒くなることは起きるが、少しの揺れでは起きない。画の明るさを一律 +10%（露出 +0.3EV 相当）振っても、差分を引く範囲の 2.6% しか黒くならなかった。カメラが動いた場合も全体が黒くなることはない — 黒くなるのは輪郭だけで、4° 回しても 19% で頭打ちになる。それより頻繁に起きるのは逆で、暗い服の体験者が拾われず体が透ける。いまのプレートで測ると、黒っぽい服は範囲の 29% しか覆えない。

差分が使えるのは映像の中に当人が写っている間だけ。3 周目 A の入れ替わりは覆い切った縁で画面が無人プレートへ差し替わり、4 周目 A は人形から人へ育つあいだずっと画が無人プレートなので、差分を引く相手が居ない。その判断はシェーダに入っている（_SwapFromTop > 0.5 && hand < 0.999 のときだけ差分を引く）。持続の覆いから引き継ぐカットは cover が 1 のまま始まるので hand が即 1 になり、差分と CG が混ざる区間は事実上無い。

2. 体験者の位置に出るか

差分の区間（2 周目 C 末尾・3 周目 A の入り）
映像に写っている当人そのものの形。カメラが固定なら原理的にずれない。
CG の区間（3 周目 A・4 周目 A の入れ替わり）
HMD の頭の位置 → コース座標 → カメラ較正 → 画面。映像の遅延ぶん過去の位置を読む。背丈も HMD の高さから推定するので、身長の違う体験者に追従する。

ただし差分を引く範囲そのものが CG の人型から作られる。シェーダは人型の周り（人型の高さを 1 とする空間で横 ±1.25・縦 ±1.35）の箱の外を 1 画素も触らない。CG が立てられないと RectResolved=false になり、覆いは 1 画素も出ない。

この箱は広い。カメラ A で 3 周目 A の凍結点に立つと、箱は映像の 83% を占め、人が占めるのはそのうち 17% だけ。残り 83% は背景で、そこで差分が立てば黒くなる。

3 周目 A は swapMinX 0.5 で映像の右半分だけに効かせている。凍結点（枠 UV 0.685）に立てば体は右側に写るので成立する。ただし体験者が映像の左半分に写る位置に居ると、覆いは出ない。左半分はもともと鏡映しなので当人も写っていない。

3. 腕はついてくるか

差分の区間は、腕も含めてそのまま拾う。実写の差なので、腕が上がっていようが伸びていようが関係ない。拾えないのは服と背景の明るさが近いときで、それは §6。

CG の区間は、手の位置を肩基準で人型へ写して IK で解く。手のトラッキングが切れたら idle ポーズへ 0.35 秒で減衰合流する。首だけ振ったときに手が振り回されないよう、体の向きは頭の向きを鈍らせた値を使う。

どちらの場合も、覆いの最終的な形は「芯 ∪ 棒」— 差分または CG の人型（芯）に、行ごとに横へ引き伸ばした黒い棒が重なる。腕の輪郭がそのまま黒く出るわけではない。腕の位置に芯が立ち、その行の棒が横へ泳ぐ。

4. 周囲の光の変化で、人以外が黒くなるか

差分は linear 空間の RGB 最大チャネル差を smoothstep(0.060, 0.20) に通した値。この空間の選び方が効いていて、明るい面は敏感・暗い面は鈍い。

画全体の露出が振れただけでは出ない。linear で 1.05 倍（+0.07EV）ならどの明るさでも閾値に届かず、1.10 倍（+0.14EV）で sRGB 203 より明るい画素だけが拾われ始める。

効くのは光の揺れではなく、プレートと現場の食い違い。同じ設営で 18 分しか空けなければ 2.8%、2 日空けると 22.7%、設営を組み替えると 52.6% が黒くなる。いま show.json が指す plate_A_20260816_182100.jpg は 8 月 16 日の設営で撮ったもので、8 月 5 日・7 日のものとは部屋の作りが違う。

5. カメラの位置がずれたら

全体が黒くなることはない。黒くなるのは輪郭だけ。平らな面は何画素ずらしても同じ値が読めるので差が出ない。差が出るのは値が急に変わる所 — パイプの縁、幕の折り目、棚の段 — に限られる。だから面積はずれの量に比例せず、輪郭の総量で頭打ちになる。

周回で画が痩せるのがここでは効く。同じ 5 px のずれでも、1 周目の頭の鮮明さ（800 ブロック）なら 14.9%、3 周目 A の粗さ（267 ブロック）なら 9.5%。細かい模様が先に潰れるので、後半ほどずれに強い。上の表は 3 周目 A の粗さで測った値。

ただし面積が小さくても形が悪い。散らばった輪郭の線それぞれから、覆いの「棒」が横へ泳ぐ。人型としては読めない黒い帯が、人の居ない場所に何本も出ることになる。

そしてカメラが本当に動いたなら、狂うのは覆いだけではない。較正がずれるので、CG 人形の立ち位置・影・差分を引く範囲の位置・3 周目 A と 4 周目 A の入れ替わりの人型が全部同じだけずれる。覆いの誤検出はその症状のひとつにすぎない。端末の傾きセンサーと保存した較正を突き合わせれば「カメラが動いたか」は判定できる（.claude/memory/camera_fleet.md）。

6. 実際に起きやすいのは逆

いまの plate_A の右半分（覆いが効く側）は暗い。sRGB の中央値が 49 で、下位 25% は 35。この前に黒っぽい服の人が立つと、差分は体を見つけられない。

拾えなかった画素は CG の形へ落ちない。シェーダは sil = silDiff < 0 ? silCg : lerp(silDiff, silCg, hand) で、プレートを掴めなかったとき（−1）だけ CG へ縮退する。プレートはあるが人を見つけられなかった（0）ときの受け皿は無い。持続の覆いは _SwapDiffHold で CG への受け渡しも 0 に潰しているので、穴はそのまま素通しになる。

2 段の mip で穴を埋める仕掛けが入っているが、いまの値では 2 段になっていない。MaskDiffLod = 0.6 に対して粗い段が lod + 0.6、細かい段が lod + max(0.6 − 2, 0) = lod で、差は 0.6 段ぶんしかない。コメントが意図している「粗い段が人の中の穴を埋める」は、この差では効かない。

7. 気づいたこと

  • 差分が何を拾ったかを観測していない。 ev=swap の mask= はプレートを掴めたか（0/1）だけで、誤って背景を拾ったことも、人を拾えなかったことも実機ログに出ない。
  • Editor プレビューは理想条件しか焼いていない。 Preview Swap Morph はプレートに人を焼き込んだ画を「現在の画」にするので、プレートと現場が 1 画素も違わない前提。照明のずれもカメラのずれも入れた版が無い。
  • プレートの鮮度を誰も見ていない。 撮影時刻はファイル名にあるが、実行時に古さを判定する経路が無い。

測り方: シェーダの SwapDiffAt と同じ式（linear 空間・RGB 最大チャネル差・smoothstep(0.060, 0.20)・lod + 0.6 と lod の 2 段の max）を Python で再現し、tools/web-compositor/captures/ の無人プレートに当てた。mip は 1/2lod へ縮小してから戻して模した。実効 lod は ScreenDecayLogic のブロック数（800 → 267）と CoarseLod() から算出し、断りのない数値は 3 周目 A の粗さ（267 ブロック・lod 1.68）で測ってある。差分を引く範囲と swapMinX の位置は show.json の cameras[].calib と layout.lines.line_freeze の中点から計算した（投影式は卓の doll-math.js と同じ）。
限界: 実写の人が写ったカメラフレームが手元に無いので、人がどれだけ拾われるかは実測していない。§6 は「その画素にその明るさの服が来たら」の仮定計算で、実際には人の影・服の折り目・髪が加わる。§4 の露出の振れも、実カメラの自動露出ではなく画像への一律の掛け算で模した。§5 のずれは平行移動と画像中心まわりの回転で模したもので、実際のカメラの移動は遠近も変わる。
