ルータを持ち込む方式に変えた

仕組み ／ 当日の手順 ／ 2026-08-31 の実測

会場の Wi-Fi を使うのをやめて、自分のルータを持ち込んで住所を自分で決める方式にした。会場がどこであっても同じ番号のネットワークが立ち上がるので、当日ネットワークについて調べることは何も無い。置いて電源を入れるだけ。

今日いちど全部を実測した。土台は繋がっている — PC・カメラ 3 台・Quest 2 台がそろって所定の番号を持ち、端末どうしも通信できていた。要対応が 3 件ある（Quest の電波掃引・カメラ B の電波・APK が古い）。

1. 何をしたのか

この作品が通信していること

体験の間、機械どうしが交わしているのは 3 種類だけで、どれも建物の中で閉じている。インターネットは 1 バイトも要らない。

  • 配信スマホ 3 台 → Quest（カメラの映像）
  • PC の卓 → Quest（設定・演出の合図・録画した動画・当日の写真）
  • PC の卓 → スマホ（撮影の指示・状態の確認）

会場の Wi-Fi を使うと壊れる 3 つ

住所が毎回変わる会場の Wi-Fi は繋いだ順に番号を配る（DHCP）。昨日 .34 だったスマホが今日 .51 になる。Quest は .34 を見に行くので黒いまま
端末どうしが喋れない公共の AP は端末を互いに隔離するのが既定。同じ Wi-Fi にいるのにスマホと Quest が直接通信できない。会場の設定なので直せない
混んでいる来場者のスマホが数百台。受信の駒が落ちる

とくに 1 つ目は実際に起きていた。方式を変える前の焼き込み値は 192.168.11.34 / .3 / .12 というバラバラな番号で、これは会場ではなく研究室の Wi-Fi が配った順にすぎない。

やったこと — 自分の LAN を持ち歩く

研究室の実験用ルータ（NEC Aterm WG2600HP）を持ち込んで、会場の回線に一切繋がない孤立したネットワークを自分で立てる。住所は全部こちらで決めて、端末に書き込んでおく。

Wi-Fi は飛んでいる。ルータの仕事は「電波を出して端末をつなぐ」と「外のインターネットへ中継する」の 2 つで、切ってあるのは後者だけ。カメラも Quest も kougaku-lab-exp-a という 5GHz の Wi-Fi にぶら下がっている（実測: 5180MHz / WPA2 / 866Mbps）。この Wi-Fi にスマホで繋ぐと電波は強いのに Web は開かない — それで正しい。

体験はもともと建物の中だけで完結していて、外へ出る通信が 1 つも無い。PC は有線で、Quest とカメラは Wi-Fi で、同じルータの中にいる。

自動で配る範囲は .2〜.10 の 9 個に狭めてある。だから .11 以降に手で書いた番号は、自動配布とぶつかりようがない。来客の PC が繋いでも、取れるのは .2〜.9 だけ。

なぜ「端末側に書く」のか

ルータには「この機械にはいつもこの番号」と覚えさせる機能（MAC 予約）があり、最初はそれで済ませるつもりだった。8/30 に実機で測って、この方式は当日壊れると分かった。

覚える鍵になる MAC が、そもそも偽物
Quest 2 台とも Wi-Fi の MAC がランダム値だった（36:1e:88:… / c2:14:15:…）。予約は MAC を鍵にするので、鍵が毎回変わると効かない。
しかも「ネットワークを削除して入れ直す」と MAC が変わる
公式の資料には「再登録しても同じ MAC が返る」と書いてあるが、Pixel 7a で実際に変わった（d6:6c:20:… → 96:fb:79:…）。当日いちばんやりがちな操作がこれ。
外れても画面には何も出ない
番号が違うだけで Wi-Fi には繋がっている。人からは正常に見えたまま、Quest だけが黒い。

端末側に書いてあれば MAC に依存しないし、ルータを別の機体に替えても設定が生きる。PC だけ例外にしたのは、PC 側の設定を 1 つも変えないため — 有線の MAC はランダム化されないので予約が確実に効くし、このルータを外して研究室の有線に戻すとき何もしなくていい。

ルータの中で実際に変えたのは 2 つだけ

8/30 に実機で一通り通した。設定画面で触ったのは次の 2 つで、あとは初期値のままでよかった。

  • 自動で配る範囲を .2〜.10 の 9 個に狭めた（初期値は 32 個）
  • PC の有線 MAC を .10 に予約した

見て確認しただけで変えなかったもの：背面スイッチが RT（BR だと番号を配る機能そのものが動かない）／5GHz のチャネルが W52（W53・W56 は気象レーダーを検出すると通信が切れて 30 分そのチャネルが使えない。本番中に起きるとカメラ 3 台が同時に落ちる）／ネットワーク分離が OFF（ON にすると、会場の AP で踏む事故を自分で作ることになる）。

2. 当日、別の会場でどうするか

会場のネットワークについて調べることは何も無い。 Wi-Fi の名前も、パスワードも、繋がるかどうかも関係ない。ルータが「持ち歩けるネットワークそのもの」なので、コンセントさえあれば同じ 192.168.10.x が立ち上がる。

設営（10 分）

順序が決まっている。ルータ → 端末 → 確認。飛ばすと次が確かめられない。

  1. ルータを置いて電源を入れる。 2.4GHz と 5GHz のランプが両方点くまで待つ。WAN ポートには何も挿さない
  2. PC の LAN ケーブルを LAN ポートへ（WAN ではない）。ipconfig で 192.168.10.10 が来ていること
  3. スマホ 3 台の電源を入れる。 Wi-Fi は自分で kougaku-lab-exp-a に付く。配信アプリを起動して、画面の cameraId が A / B / C と表の割り当てで合っているか見る
  4. Quest 2 台の電源を入れる
  5. 1 本流して全部を一望する。 在席している端末・cameraId・フレームの状況が 1 画面に出る
py -3.11 tools/net-scan.py

ここで .1（ルータ）・.21・.22・.23（配信 3 台）・.31・.32（Quest）が並べば土台は完成。PC 自身はこの一覧に出ない（ipconfig で見る）。Quest は応答しないことがあるので、出なくても異常ではない。

  1. 卓の 🩺 疎通診断を押す。 PC→カメラ・卓の呼びかけ・Quest の生存の 3 経路が ✅ になるか
  2. Quest でアプリを起動して、卓のライブ状態でカメラ本数・音・コントローラを見る。 音とコントローラは画にも録画にも出ないので、ここでしか分からない

当日やってはいけないこと

やりがちな操作何が起きるか代わりに
繋がらないので Wi-Fi を削除して入れ直す手で書いた番号が消える。MAC も変わるまず net-scan.py。番号は生きていることが多い
端末の Wi-Fi を切って入れ直す保存済みの別の AP へ勝手に移る。8/30 に 5 台とも研究室の AP へ移った触らない。移ったかは net-scan.py に出なくなることで分かる
ゲスト用の SSID（-gx / -ax）に繋ぐ端末どうしの通信が切られる。会場 AP と同じ事故kougaku-lab-exp-a だけを使う
スマホを放置して画面が消える配信が止まる。 番号は正しいので「ネットワークの問題」に見える充電しながら画面が消えない設定にしてある。伏せない
2.4GHz（-g）に繋ぐ受信の駒が配信の 2/3 くらいまで落ちる5GHz（-a）へ寄せる

要対応 1 — Quest が 10 秒ごとに電波を掃引していた

Quest 側の受信が配信の 2/3 ほどしか出ておらず、3 台が同時に落ち込む波が周期的に出ていた。原因は映像経路ではなく、Quest の設定パネル（Wi-Fi の画面）が終了しないまま残っていて、10 秒ごとに Wi-Fi の全チャネルを掃きに行っていたこと。掃引の間は電波が別のチャネルへ出ているので、3 本の映像が一緒に途切れる。

設定パネルを終了させたら、45 秒あたりの掃引が 8 回から 1 回に減り、受信も戻った。

要対応 2 — カメラ B の電波が弱い

掃引を止めても、カメラ B だけ他の 2 台より 7 fps 低いまま残った。PC（有線）から引くと B も 29.8 fps 出るので、スマホと配信アプリは正常。弱いのは ルータと B の間の電波。

PC からの応答（10 回）カメラ Aカメラ Bカメラ C
平均7 ms25 ms4 ms
最大15 ms61 ms13 ms
届かなかった回0 / 101 / 100 / 10

200 秒の走行でも同じで、B だけ受信 19.3 fps、取りこぼしは 2094 枚（A は 482 枚、C は 642 枚）だった。

見る順番は 3 つ。① B が 5GHz（-a）に繋がっているか — 2.4GHz に落ちているとちょうどこの症状になる。② ルータと B の間に金属や人体、距離があるか。③ B は 3 台でいちばん熱い（45.0℃）ので、置き場所を風の通る所へ。

要対応 3 — 両方の Quest の APK が、BGM 修正より古い

入っている APK は 8/30 19:50 に焼いたもの。BGM の取得に失敗したとき諦めずに 4 回試すようにした修正は 20:12 のコミットなので、まだ端末に入っていない。[Bgm] クリップ取得に失敗 は 8/30 の走行でも、今日の走行でも同じように出た。

.\tools\unity.ps1 build fixedcam

焼き直して 2 台とも入れ直す。片方だけに入れない — 古い APK の機に当たると「直したはずの不具合がまだある」という顔で出る。

まだ決めていないこと・確かめられなかったこと

件いまの状態判断の材料
