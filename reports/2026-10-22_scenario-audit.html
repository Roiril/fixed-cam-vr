現行シナリオの監査 — 4-A の「止まってください！」が人形 End に追い越される

2026-10-22 ／ 対象: ブランチ feature/tablet-ui-motion（8a25a895）、配布中の show.json rev 1283、LEDGER 0207〜0286

体験が止まって抜けられなくなる経路は見つかりませんでした。いちばん重いのは 4-A です。3-A を位置合わせ版にしたとき凍結の線が台本から消えたので、「止まってください！」は入ってから 3 秒の時計でしか出ません。人形 End の判定は 1 カット目から有効なので、その 3 秒のあいだに画面の左半分へ歩いた人は警告を見ないまま人形 End になります。

見たものと見方

体験の流れを 3 つの視点で通しました。正規ルートの物語と時系列、体験者の逸脱、スタッフ運用と来場者の入れ替わりです。視点ごとに独立したサブエージェントがコードを追いました。重い指摘はわたしが該当行を開いて照合しています。

確度は 2 段階で書きます。「確定」はコードと設定で経路を追えたものです。「推定」は起きる頻度や見え方を実機でしか確かめられないものです。実機は走らせていません。

現行の流れ

  1. 準備博士タブレットで言語・注意・説明 → スタッフへ渡す → HMD 装着
  2. 導入左 X/Y の練習 → 「報告できました。装置は正常です。」→ スイが名乗る → 題字（短押し）→ 床の矢印と円まで歩く → 現実が割れてスクリーンへ
  3. 1 周目A 演出なし ／ B 手形（報告で消える）／ C 演出なし
  4. 2 周目A 幕の顔の染み ／ B バックルームズへ飛ぶ ／ C 予備動作 → 線を越えると人形視点 4 カット → 追いつき → 乗っ取り
  5. 3 周目A 2-A の録画を位置合わせで出し、中央の線で早送り → 人形が残る ／ B・C 1 周目の録画 ＋ 人形 → 無人の部屋
  6. 4-A大量の人形 → 「止まってください！」→ 催促 → 報告すれば帰還、しなければ帰還不能 ／ 人形が左半分へ入れば人形 End
  7. 終幕砂嵐 → 電源断 → エンドロール冒頭（結末・報告数・写真）→ 15 秒で閉じる。帰還なら台車が動く

高 — 4-A の順序

1. 「止まってください！」より先に人形 End が成立する

場面。4-A に入った体験者が、それまでの周と同じように歩き続けたとき。

起きること。締めの線は台本から導いています。「左半分を凍らせるカットの直前に待っていた線」です（ShowTakeSchema.cs:578）。3-A を位置合わせ版（0274）にしたとき凍結のカットが無くなったので、この関数は空を返します。配布中の show.json に splitFreeze: true のカットは 1 本もありません。そのため③a は「4-A に入ってから 3 秒」の時計でしか出ません（CommsCueLogic.cs:448）。起点はゾーン確定なので、実際に入ってからはおよそ 3.5 秒です。

一方、人形 End の判定は催促の全文表示を待ちません（EndingDecisionLogic.cs:55）。4-A の 1 カット目から人形が体験者の位置に立つので、足が画面の左半分に入った時点で成立します（TakeRunner.cs:246）。画面の中心線は L 字の角の近くを通り、0.5 m/s で歩くと 2.2 秒で届きます。報告は催促を読み切るまで受け付けないので、押して逃れることもできません。

根拠。0247「凍結線を踏むもしくはそこに入ってから 3s」。0233「止まってくださいは凍結点の場所で出す」。0178「止まってください！以降の流れは全員に見せる」。2026-09-25 の人形 End は催促を待たない、と show-design に書いてありますが、当時は凍結線が先に③a を出していました。

直す方向。締めの線を台本の推論に頼らず、明示のキーで指せるようにします（既存の line_freeze を当てられます）。あわせて、左半分の判定を③a を表示した後に限ります。

中 — 物語の前提が崩れるもの

2. 乗っ取りを見ていない人に「呪いから戻った」姿が出る

2-C の接近は policy: yield なので、線を越えて 4.1 秒以内に C を出ると追いつきのカットが自然完了しません。乗っ取りは起きず、劇伴も替わりません（TakeRunner.cs:1505、:1596）。線は C の出口まで 0.7 m ほどの所にあり、2-C の実測滞在は約 7 秒なので珍しいルートではありません。それでも 4-A の③a では復帰の表示が無条件に始まります（CommsPanel.cs:1161）。弱った起動・顔に残る人形・赤字が、呪いを一度も見ていない人に出ます。

0270 は「呪われていた状況から何とか戻ってきた姿」です。乗っ取りを見なかった人に何を出すかは決まっていません。復帰の表示を乗っ取りが届いた回だけにするのが筋です。

3. 乗っ取り後の砂嵐が 3-A の頭 5 秒を覆う

追いつきの最後のカットが終わると砂嵐が始まり、乗っ取りの警告が消える約 7 秒後まで続きます（CameraFeelFx.cs:150）。10-20 の自動走行では 3-A の滞在 9.2 秒のうち 5.0 秒が砂嵐の下でした。そのあいだも位置合わせの録画は裏で進んでいます。0279 で「違和感なく再生された」と判定された中央の線の手前の部分が、多くの人には砂嵐で見えないことになります。重ならないには 2-C に約 12.6 秒とどまる必要があります。

直す方向は 2 つあります。砂嵐のあいだは 3-A の進み具合の最大値を据え置き、見せ始めを砂嵐の後へずらす方法。あるいは乗っ取りの尺と 3-A の関係をユーザーの判定に回す方法です。

4. 引き返すと 1-B の手と 2-A の染みが出し直されない

報告せずに 1-C → 2-A → 1-C → 2-A と戻った場合です。染みの演出は hold で、尺は「次にカメラが切り替わるまで」です。ゾーンが変わると尺が閉じて完走扱いになり、once なので戻っても武装されません（TakeRunnerLogic.cs:756、:464）。出し直しの仕組みが効くのは yield の演出だけで、テストもそこしか見ていません。streaming.md にあるユーザーの例「報告済みでない限りはもう一度出す」に反します。

5. A に居るのにカメラ B のライブが最長 41 秒映る

2-B に入って 4 秒以内に 2-A へ戻った場合です。バックルームズの演出は hold で、前の 2 カットは秒の尺なのでゾーンが変わっても続きます。3 カット目は「カメラ B のライブを次の切り替わりまで」なので、体験者が A に居るあいだ無人の B が映ります。止まるのは次のゾーン変化か、watchdog の 45 秒です。固定視点が自分を映すという前提が崩れます。3 カット目のカメラを「いまのゾーン」にすれば消えます。

6. 1 周目に逆走すると、3 周目に逆向きの録画が流れる

1-A から B を通らずに C へ出た場合、一度も居たことのない区間なので区間の周は 1 になり、(1, C) が録られます（LapCounter.cs:107）。一度録れた区間は録り直さないので（SegmentRecorder.cs:510）、正しい順で通った 1-C は残らず、3-C はその逆向きの断片を流します。「前へ進んで次のカメラへ出た試行だけ使う」は 2-A にしか掛かっていません。1-B と 1-C にも同じ条件を掛けるのが筋です。

7. 4-A で左コントローラが切れると、報告できないまま帰還不能になる

締めの判定は報告の入力が使えるかを見ていません（EndingDecisionLogic.cs:61）。HMD 内の再接続案内は題字の段にしか出ず、タブレットに出るだけです。切れているあいだは 15 秒を数えないか、「調査中断」側に倒すのが筋です。

8. 結果に分母が出ず、外した判定の記録も無い

エンドロール冒頭に出るのは結末名と「報告数 N」の 2 行です（OutroReportText.cs:22）。異常総数 8 件は計算されてログにも出ていますが、画面には出ません。0247 のユーザーの言葉は次のとおりです。

異常の本当の数を分母にし、報告した回数を分子にし

show-design の 2026-09-25 節に「旧報告書の説明文と分母とタイプ打ちは廃止」とありますが、LEDGER に対応する発話がありません。ユーザーが分母を外すと言ったのかを後から追えません。分母を戻すか、判定を聞いて逐語で記録します。memory の ending_result.md と MEMORY.md の索引は、まだ分母が出ている前提で書かれています。

中 — 運用と来場者の入れ替わり

9. タイトルを組めない構成ではリセットが完了しない

リセットの完了は「タイトルの番号が進み、かつ段が Wait」で判定しています（OvrControllerBridge.cs:760）。タイトルの実体を組めないとき（シェーダの剥がれ・版の欠落）は、BeginTitle が番号だけ進めて段を Off に落とします（TitleScreen.cs:305）。すると毎回 NewVisitor() へ落ちて「リセットが要る」のまま残り、来場者を始められません。タブレットは「準備を始められませんでした」を出し続けます。show-design は「タイトルが壊れると二度と始まらない、は構造的に作らない」と書いています。完了の判定を「相が導入へ戻った」に替えれば、タイトルに依存しなくなります。

10. 完了したリセットをタブレットが「失敗」と読む

リセットの最初に新しいセッション ID を公開します。要求 ID を書くのは、録画の全削除を含む重い処理が終わった後です（VisitorPortal.cs:225、:707）。そのあいだ HTTP は中間の状態を返し、タブレットは押した直後に問い合わせます。「セッションが変わったのに要求 ID が無い」状態を受け取ると、通常リセットは失敗、強制リセットは別の操作に追い越されたと表示します（index.html:3793）。Quest 側は実際にはリセット済みです。要求 ID をセッション ID と同じロックの中で書けば消えます。

11. 前の人の台車の失敗が、次の人の本編中に警告で出る

台車の最後の合図と結果はリセットで戻りません（RomiCartLink.cs:50）。前の人の終幕で合図が届かなかった場合、次の人の本編中ずっと「台車へ合図が届きませんでした」がタブレットに出ます（index.html:3343）。スタッフが本編中に台車を触りに行きかねません。内部エラーの件数には体験者ごとの基準値の取り直しがありますが、台車にはありません。

低 — 軽い取りこぼし

  • 12. 報告が受理された後の帰還カット 7.1 秒の途中で本編の上限 300 秒に達すると、帰還の結末が「調査中断」に上書きされます（ShowRunDirector.cs:541）。
  • 13. 3 周目の区間に 120 秒とどまると watchdog が演出を畳み、人形化した区間に生身のライブが戻ります。
  • 14. 受付前から押し続けた人は、一度離すまで数えられません。案内は出ないので、押しっぱなしのまま 15 秒で帰還不能になります。推定です。
  • 15. コントローラが切れている間に来た振動の予約がリセットで落ちず、次の人がつないだ瞬間に 1 回鳴ります（OvrControllerBridge.cs:382）。
  • 16. 台車が動き出した後に強制リセットしても台車は止まりません。/stop はありますが、リセット経路から送っていません。推定です。
  • 17. 2-C の予備動作の 2 カット目が「カメラ B のライブ 0.6 秒」で、C に居る人に B が一瞬映ります。予備動作を 2-B から 2-C へ移したとき（0107）の名残に見えます。推定です。

文書のずれ

実装は正しく、文書だけが古いものです。次のセッションがこれを契約として読むので、直しておく価値があります。

  • rules/show-design.md の冒頭の節（優先される側）が「3-A の凍結カット」「凍結線 OR 3 秒」のままで、位置合わせ版の節と食い違っています。
  • 同じ節の「解除後は通常の異常検出結果を返す」は、0284 の「異変を取り除きました。お疲れ様です。」に置き換わっています。
  • rules/streaming.md の時計の節は 4-A を「最後」「LAST」と書いていますが、実装は 0247 どおり「終了」「END」「FIN」です。
  • memory/hmd_onboarding.md の導入の順番と完了文が古く、実装は練習 → 「報告できました。装置は正常です。」→ 名乗りの順です。

問題なしと確かめた点

  • 導入の順番は 0244 と 2026-09-24 の判定に一致します。
  • 分母 8 の数え方は配布台本の 9 本と一致します（2-C の 2 本を 1 件に数える）。対応表から漏れた演出はありません。
  • 正規ルートなら 2-A の位置つき録画は必ず作られ、3-A の録画カットに第 2 層は付いていません（0276 の対策は維持）。
  • 報告と帰還不能が同じフレームに重なると報告が勝ちます。テストがあります。
  • 帰りの A で引き返しても、終了判定は進行の周で数えるので体験は終わります。
  • HMD を外した休止は 15 秒の計時にも本編の時計にも入りません。
  • 2 人目以降の音・言語・ホラー軽減・録画・報告数・連絡の面の侵食は、本番のリセット経路から戻っています。
  • 終幕は報告の出始めから 15 秒で閉じます（0286）。0284 の返事は解除と同じフレームで切り替わります。

導入中の逸脱（歩行誘導の円へ行かない、箱の至近に立つ、位置合わせ中の操作）は深く追えていません。尺は 10-20 の自動走行で導入 47 秒と本編 86 秒でした。HMD の練習と人の歩く速さを足すと目安の 180 秒の近くになります。強制されている上限は 300 秒だけです。どの指摘もまだ直していません。
