# 実物の日本人形 → CG 人形（ShowActor）

買ってきた市松人形（高さ約 40cm・赤い着物・おかっぱ・白磁の顔と手）を、写真 4 枚から
CG 人形にする一式。成果物は `Assets/Art/Models/Doll/Ichimatsu.fbx` と
`Assets/Resources/ShowActors/Ichimatsu.prefab`。

## なぜこの作り方か

- **フォトグラメトリは使わない。** RealityScan を試して精度が出なかった。原理的にも、
  髪（画素以下の太さ＋半透明）は対応点が立たず、白磁の顔もつるつるで特徴が出ない
- **AI の画像→3D も使わない。** 実物が手元にあるのに学習分布から「市松人形らしいもの」を
  作ることになる。加えてこの PC は VRAM 16GB で TRELLIS.2（24GB 必須）が動かず、
  Hunyuan3D 2.1 も形状は通るがテクスチャ生成（29GB）が通らない＝色が出ない
- **正面写真のシルエットをそのまま前後へ押し出す。** 輪郭が写真そのものになる。
  合成先は 640×480 の暗い映像で人形は数百画素なので、前後の凹凸は観測されない
- **テクスチャは 4 枚から投影して焼く**（[bake.py](bake.py)）。アトラスの各テクセルから殻の
  表面点と法線を復元し、その面がどちらを向いているかで写真を混ぜる。写真をパネルへ
  引き伸ばして並べる方式は、**側面に実データが 1 画素も無い**（sideA/sideB は奥行きを
  測るのにしか使っていなかった）ため、横から見ると茶色い箱になっていた

## 走らせ方

```bash
cd tools/doll-model && cp photos/*.jpg .
python cutout2.py     # 4 枚から人形を切り抜く → mask_*.png
python profile.py     # マスクを仕上げて高さごとの寸法を出す → profile.json
python shell.py       # 殻の頂点・面・UV → shell.json
python texture.py     # 4 枚を殻へ投影して焼く → doll_albedo.png / doll_normal.png
"/c/Program Files/Blender Foundation/Blender 4.1/blender.exe" --background \
  --python assemble.py -- "$(pwd -W)"     # 腕・ボーン・FBX
"/c/Program Files/Blender Foundation/Blender 4.1/blender.exe" --background \
  --python export_web.py -- "$(pwd -W)"   # 卓用のメッシュ + 半分に縮めたアルベド
```

`export_web.py` は**オペレータ卓のカメラ合わせ**（`tools/web-compositor/align-ui.js`）が
人形を実メッシュで描くためのもの。glTF ではなく位置・法線・UV の生配列で出す
（卓に要るのは静止ポーズの 1 メッシュだけで、パーサを持ち込む理由が無い）。
⚠ **Blender 同梱の Python に cv2 は無い**（他の段はシステム側の Python なので入っている）。
テクスチャの縮小は Blender の画像機能で行う。

⚠ **`shell.py` と `texture.py` の順序はどちらでもよくなった**（2026-08-04）。旧実装は
`shell.py` が `texture.py` の出力（アルベド）を読んで髪の張り出しを決める**隠れた帰還路**を
持っていて、テクスチャを焼き直すたびに形が変わった。いまは髪の判定を写真から直に取る。

**幾何の式は [`geom.py`](geom.py) に 1 本だけ置く。** `shell.py`（メッシュを作る）と
[`bake.py`](bake.py)（テクスチャを焼く）が同じ関数を呼ぶ。テクスチャは「モデルのこの点が
写真のどこに写っているか」を知らないと焼けないので、両者が別々に式を持つと**沈黙して食い違う**。

確認用（どれも Blender・Play 不要）:

```bash
blender --background --python head_check.py   -- <dir>   # 頭だけフル解像度で 5 角度（判定用）
blender --background --python render_check.py -- <dir>   # 全身 8 角度
blender --background --python pose_check.py   -- <dir>   # 腕を振って袖が動かないこと
python compare_head.py side                              # 実物写真と横並び
```

⚠ **`head_check.py` のライトは距離の 2 乗で効く。** `render_check.py` の値をそのまま頭へ
寄せると約 19 倍明るくなり、**暗い髪が真っ白に飛んで何も判定できない**（実際にやった）。

Unity 側:

1. `Ichimatsu.fbx` と `doll_albedo.png` を `Assets/Art/Models/Doll/` へ置く
2. FBX の Rig を **Generic**（Humanoid にしない）
3. FBX を選んで `Tools/FixedCamVr/Setup/Build Show Actor Prefab`
4. できたプレハブを選んで `Tools/FixedCamVr/Diagnostics/Preview Show Actor`

## 押さえておくこと

- **腕は写真に写っていない**（白磁の腕は袖の外にあり、切り抜きで落ちる）。CG 側で作り、
  UV は顔の白磁の位置へ固定している。**手だけ断面を平たく**する（円柱のままだと棒に見える）
- **袖は腕に追従する。ただし剛体では付けない。** 付け根は腕に持ち上げられ、下端は垂れたまま
  ＝「腕の高さからの落差」で腕→Root へ滑らかに配分する（`SLEEVE_FALL`）。
  肩ボーンに 1.0 で付けると `ShowActorRig` が上腕を回すたび**袖が丸ごと回る**ので、そこは避ける。
  逆に Root へ 1.0 で固定すると袖が完全に不動になり、これも実物と違って見えた（両方やって確認済み）
- **腕メッシュは頂点グループの印で分離する**。座標だけで判定すると、前後に薄い袖の頂点が
  「腕の筒の中」に入って一緒に持ち上がる（実測で袖の上端が山形に引っ張られた）
- **顔と机は色で区別できない**（顔 H22 S25 V207 / 机 H40 S11 V210）。髪と黒シャツも同じ。
  確実に取れるのは赤い着物だけ（S217）なので、頭部は**形の式で塗る**（おかっぱ＝頭頂が丸く、
  頬から下はほぼ垂直）。GrabCut を頭に掛ける案は、矩形をわずかに動かすだけで
  「頭が消える／頭上に黒い柱が生える」を往復して収束しなかった
- **頭は縦長 close の対象から外す**。赤マスクの分断を繋ぐための縦 close を頭にも掛けると、
  丸い頭頂が縦へ膨張して**平らな箱**になり、画像の端では収縮で戻り切らず頭の上に柱が残る
- **最大連結成分だけ残してはいけない**。背面は帯（白い蝶結び）が頭と胴を分断するので、
  頭か袖の片方しか生き残らない
- **メッシュは格子で塗らない**。格子点の内外で四角を作ると輪郭が階段になり、
  頭と髪が箱・袖が長方形・裾が急に細って柱、という形で全部に出る。
  `shell.py` は**行ごとにマスクの実際の左右端を取り、その間を等分**している
- **断面は胴と袖で別々の楕円にする**。行の全幅（袖先から袖先）で 1 つの楕円を張ると、
  幅の狭い胴はその「てっぺん」だけを使うことになり、実測で胴の法線の傾きが
  **中央値 5.9 度**しか出ない ＝ どの向きから照らしても胴が 1 色の板に見える
- **行の左右端では深さを必ず 0 にする**。0 でないと前後が閉じず、側面から見て人形が縦に裂ける
- **上下の端にフタを張らない**。前後の頂点を直結する面は **u を 0.5 跨ぐ**ので、
  1 面にアトラス 1 枚が引き伸ばされる（見下ろしの角度で頭頂に円盤が出た）。
  端の深さを 0 へ落として自然に閉じる
- **UV をパネル境界（u=0 / 0.5）へ張り付けない**。テクスチャは Repeat + ミップなので、
  バイリニアが反対側のパネルを吸って袖先と頭頂で前後の絵が混ざる。半テクセル内側へ寄せ、
  Unity のインポートで **Wrap = Clamp** にする
- **側面プロファイルは補間の前に均す**。48 行を 144 行へ線形補間すると 8mm ごとに折れ、
  上から照らしたときに**横縞**として出る
- **マスクを数画素収縮してからテクスチャを焼く**。頂点の u は行の実際の左右端と一致するので、
  縁の「人形と背景が混ざった画素」をそのまま引いて輪郭に暗い線が出る
- **腕は袖の中を作らない**。袖は前後に薄いので、肩から作ると腕が布を貫通して見える。
  実物で見えるのは袖口から先だけ（ボーンは肩から張る）
- **袖の断面は端まで厚みを保つ**（`q ** 4`）。素の楕円（`q ** 2`）だと袖口へ向けて
  厚みが痩せるので、そこを通る腕が必ず布から出る。行の左右端で 0 へ落とすのは
  **ごく近く**（`edge * 7`）だけにする。腕の半径 6mm に対し、袖の半厚は袖口の手前で 12mm ある
  （数値は `shell.json` の頂点から測れる）
- 寸法の目測値は `cutout2.py` の `HEAD`（頭部の外形）だけ。ほかは写真から自動で測っている

### 髪が「角の丸い茶色い箱」に見えていた件（2026-08-04 に解消）

一度に 4 つ壊れていた。どれも**単独では直らない**ので、順に潰した記録を残す。

1. **`synth_hair()` が実写の髪を縦縞へ置き換えていた。** 「前後で同じ縞にすれば継ぎ目は
   原理的に消える」という理屈は正しかったが、前後のパネルは互いに位置合わせされていないので
   `hair[:, HALF_W:] = hair[:, :HALF_W]` が**幾何的に破綻**していた（実測: front 側の x=230 は
   「顔」、back 側の同じ x は「後頭部の髪」）。縞は**背景と額**に塗られ、本物の後頭部の髪は
   そのまま残っていた。合成した髪は明るい（gray≈156）ので、`make_normal` の髪の異方性
   （`g < 0.33`）も `gloss_mask` の髪（`v < 85`）も**一度も発火していなかった**。→ 削除
2. **前後の継ぎ目が頭ではブレンドされていなかった。** `blend_seam()` はパネルの端
   （列 0..72 / 440..512）を混ぜていたが、「front の u=0 と back の u=0.5 が同じ側面」が
   成り立つのは**袖が一番広い行だけ**。実測で頭のシルエットは列 167〜346 ＝**重なりゼロ**。
   → 焼き方を投影ベイクへ変え、真横で front:back = 50:50 に収束させた（縁で bit 一致）
3. **UV が平面投影だったので側面にテクセルが回っていなかった。** 実測（頭 t=0.12）:
   真横寄りの面は**弧長の 38% を占めるのに列は 3%**（一様配分の 0.07 倍）。しかもその行は
   パネル 512 列のうち 179 列しか使っていなかった。→ **断面の弧長で u を配る**
   （側面のテクセルが約 41 倍。顔も「捨てていた列」が回ってくるぶん得をする）。
   ⚠ 背面シートの u は**逆向き**にする。そうしないと u=0.5 に人形の反対側どうしが重なる
4. **頭の断面が本当に箱だった（テクスチャではなく形）。** 内側の楕円の半径に固定の
   `body_half`（54.0mm）を使っていたが、**頭の半幅は 42〜47mm** なので楕円の「てっぺん」しか
   使わない。実測で頭は半幅の 99% の地点でまだ深さの 56〜64% を保ち、最後の 1% で 0 へ落ちていた。
   README が胴について書いていた失敗が、そのまま頭で起きていた。
   → 半径を `min(body_half, その行の半幅)` にする（頭が真円に近い楕円になる）

あわせて直したもの:

- **`hair_at` が赤い着物を「髪」と判定していた**（アルベドを `gray < 88` で見ていたが着物は
  gray=55）。実測で**胴の奥行きが側面写真より 1.22〜1.26 倍に膨らんでいた**＝正面以外の
  どの角度でもシルエットが太かった。→ 彩度で切り分ける（髪 S<125 / 着物 S=216）。修正後 0.98〜1.03 倍
- **露出合わせを人形全体の統計で取っていた。** 写っている物の割合が違う（front は顔と着物が
  主・側面写真は髪が主）ので、露出差ではなく**中身の差**を補正してしまい、gain も shift も
  全チャンネルがクランプに張り付いて（0.850 / 1.180・赤に +14〜+22）**髪が赤紫に転んだ**。
  → 側面写真は「実際に使う場所」＝頭の髪の画素で合わせる
- **頭頂の放射状の筋。** 球で閉じるので行の半幅が 0 へ収束し、写真の数画素がパネル 1 枚ぶんへ
  拡大される。しかも頭頂を正面から見た写真は 1 枚も無い。→ 周方向にぼかす（`soften_crown`）
- **Unity の読み込みで 1024×1184 が 1024×1024 へ縮んでいた**（`npotScale=ToNearest`）。
  縦の解像度を 13.5% 捨てていた。→ importer を `None` にした

**残っている限界**（形の都合で、この作り方では消せない）: 横から見た顔の輪郭（鼻・唇）は
出ない — 殻は押し出しなので鼻が無い。毛先が輪郭からほつれる感じも出ない。
どちらも 640×480 の暗い映像では観測されない。

## 撮り直すときの条件

人形に触れない（ポーズが変わると同一形状として扱えない）／背景に模様のあるものを敷く／
影を消す（テクスチャに焼き込まれた影はシェーダの陰影と二重になる）／正面は T ポーズ。
