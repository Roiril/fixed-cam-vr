# 無人プレートへ異変を足す（生成素材の工房）

カメラで撮った無人の部屋（プレート）へ、生成 AI で人形・染み・手形などの**異変**を足して
cue の素材にする。4 周目 A の「左半分に大量の人形」がこれで作られている（`canon/LEDGER.md` 0050）。

## 三行で

**異変（何を足すか）は場所に依らない。場所（どの面のどこか）は当日 1 ファイル書くだけ。**
プロンプトはこの 2 つから機械が組む。手で書いた文面に部屋の事情が混ざると、当日そこが全部嘘になる。
**当たり外れは判定器で落とす。数値が緑でも `sheet.png` を開くまでが 1 周。**

---

## 1. 層（ここが全部の要点）

| 層 | 実体 | いつ書くか | 中身 |
|---|---|---|---|
| **契約** | `prompt/00-contract.md` | ほぼ書き換えない | 足す以外しない・寸法・塗り直さない |
| **なじませ** | `prompt/10-blend.md` ＋ `prompt/surfaces.md` | 品質を上げたいときはここ | 影・粒・縁・暗部・遠近・遮蔽。面ごとの追加 |
| **異変** | `anomaly/*.md` | 新しい異変を思いついたとき | 何を足すか。**どこにも依存しない** |
| **場所** | `sites/*.json` | **当日ここだけ** | どのプレートの、どの面が、画面のどこか |
| **伝送** | `--lap N`（機械が計算） | 出す周が決まったら | 何画素が潰れるか・色が残るか・明暗差の下限 |

**プロンプトの中で場所に触れているのは「この場所について」の節だけ**で、それは `compose.py` が
種を測って書く。人が場所について書くのは `sites/*.json` の**面の箱と一言**だけ。

⚠ **異変の本文に「左のカーテン」「木の合板の壁」と書かない。** それは場所であって異変ではない。
書いてよいのは「布の上に」「壁に」まで。どの布かは `sites` が決める。

## 2. 当日の手順（4 手）

```bash
# 0) その日のプレートを撮る（卓を開かなくてよい。配信中のカメラから 1 枚取る）
py -3.11 tools/gen-plate/grab.py --cam A
#    → tools/web-compositor/captures/plate_A_<日時>.jpg
#    ⚠ 撮る前に /info の tiltPitchDeg / tiltRollDeg を 2 回読んで、動いていないことを見る
#      （据え直しの途中の機を撮ると、素材だけ別の部屋になる）

# 1) 場所を作る（面の箱を下書きし、箱を描いた PNG を出す）
py -3.11 tools/gen-plate/site.py draft --plate <その日のプレート.jpg> --id A_20260901 --cam A
#    → logs/gen-plate/sites/A_20260901_surfaces.png を開いて、箱を sites/A_20260901.json で直す
#    → 直したら  site.py show --id A_20260901  で描き直して確かめる

# 2) プロンプトを組む（種を暗くする所まで込み）
#    出す周が決まっているなら --lap を付ける（伝送で何が失われるかを機械が節にする）
py -3.11 tools/gen-plate/compose.py --anomaly dolls-many --site A_20260901 --place left-half --lap 4

# 3) 生成 → 判定（印字されたコマンドをそのまま実行する）
#    codex-run.ps1 -Mode image ...
py -3.11 tools/gen-plate/judge.py   --run logs/gen-plate/<走行>   # 生成直後の作り
py -3.11 tools/gen-plate/deliver.py --run logs/gen-plate/<走行>   # ⭐ 体験者が見る画
py -3.11 tools/gen-plate/spill.py   --run logs/gen-plate/<走行>   # ⭐ 半分マスクの cue はこれも
```

⭐ **半分マスク（`split_left_half` / `split_right_half`）で出す素材は `spill.py` を必ず通す。**
`judge.py` の「置かない側」は `place` を基準に測るので、`--place` を狭めると数字の意味が変わる。
体験者に効くのは**合成マスクの境目 1 本**で、そこを跨いだ塊は**実機で縦に切れる**（`canon/LEDGER.md` 0120）。
⚠ **跨ぐ塊が 0 になるまで焼く。** 手元の 8 走行では `left-half` の 7 走行すべてが跨いでいた
（`left-40` へ狭めると 4 枚中 2 枚が 0 になる）。

合格したら明るさを戻して素材にする（`dim` と同じ指定で）:

```bash
py -3.11 tools/gen-tone.py undim <走行>/out.png tools/web-compositor/captures/<名前>.png --cam A
```

⚠ **生の生成物は `_raw.png` で残す。** cue の `hasMatch` / `matchGain` へ入れない
（卓が `bakeColorMatch` で書く場所なので、保存し直すと消える）。

## 2.5 顔の向き — 3 分の 1 がレンズ、残りは横顔と斜め（2026-09-04 に改訂）

**体験者は部屋を歩き、この 1 枚はスクリーンに出る。** レンズを見ている顔は、
**見る人がどこへ動いてもその人を見ているように見える**（肖像画の目が追ってくるのと同じ）。
体験者の実際の立ち位置を見させると、画面の中では**あさっての方を向いた人形**になる。

⚠⚠ **2026-09-04 にユーザーが「全部カメラを見ているのは不自然すぎる」と判定した**（`canon/LEDGER.md` 0135）。
8/17〜9/3 の「レンズを見るの 1 択」は、**同じ顔・同じ大きさの人形が隅に固まった集合写真**を作っていた。
いまの指定（`anomaly/dolls-many.md`）は **3 分の 1 がレンズ・残りは横顔と斜め・後ろ向きは 2〜3 体まで**。
横顔も明るい楕円として届くので数えられる。消えるのは後ろ向きだけ（黒い髪が床に溶ける）。
実測（09-04・n=2）: 届いた顔の粒 **28 / 21 個**（全員レンズ向きの 8/23 採用は 20 個以上）＝ 減っていない。
動画（集まる・居続ける）の作り方は `video/dolls-gather.md`。

指示は効く。**届いた画で数えた顔の粒**（足した面積で割った数）が、
レンズ **2.22** / ばらばら 1.14 / 別の一点 0.54（`survive.py`）。
後ろを向いた人形は黒い髪だけになるので、**居るのに数えられない**。
⚠ ばらばらと別の一点は、この n（条件ごとに 1 走行）では区別が付かない。

⚠⚠ **届いた顔に造作は 1 つも残らない**（帰りの A で 3.8 標本 ＝ 顔と襟が融合した明るい楕円）。
異変が言う「白目に対する黒目の位置が中央」は**体験者には届かない**。
外さないこと — それは**生成側で正面顔を作らせるための言い方**として効いている。
届いているのは「**顔の明るい面がレンズを向いている**」ことだけ。

確かめるのは 2 つ:

```bash
py -3.11 tools/gen-plate/heads.py   --run logs/gen-plate/<走行>            # 生成直後の顔を並べる
py -3.11 tools/gen-plate/survive.py --run logs/gen-plate/<走行> --lap 4    # ⭐ 届いた顔を数える
```

⚠⚠ **`heads.py` は背景を塗り直された走行では使えない**（顔を探す範囲が「種との差」なので、
部屋ごと描き直されると**壁を並べる**）。置く側の背景の保存が 35% 未満なら自分で止まる。
2026-08-17 の視線試験は、これに気づかず**2 条件とも壁の左右対称度を記録していた**（`runs.md`）。

## 3. 新しい異変を足す

`anomaly/<id>.md` を 1 枚書くだけ。頭書きが判定の線を兼ねる。

```
---
id: face-stain
title: 人の顔のように見えてしまう染み
surface: cloth        # floor / cloth / wall / furniture / ceiling
opaque: false         # false なら「下地が透ける」を判定する
min_area_pct: 0.5     # 足された面積（置く領域に対する %）
max_area_pct: 14
min_parts: 1          # 塊の数の下限
persp: false          # true なら「手前ほど大きい」を判定する
---
（本文＝プロンプトへそのまま入る。**場所に触れない**）
```

- **`surface` を持たない場所では、その異変は成立しない。** `compose.py` が
  「この場所に布の面が無い」と言って止まる（黙って画面全体へ広げない）
- 面ごとの描き方の注意は `prompt/surfaces.md` に足す（そこも場所に依らない書き方で）

## 3.4 ⭐⭐ 最後は「実機の経路を通した画」で見る（`screen.py`）

```bash
py -3.11 tools/gen-plate/screen.py --cue gen_dolls_A_left \
    --live tools/web-compositor/captures/<その日のプレート>.jpg --lap 4 \
    --out logs/gen-plate/screen.png
```

素材は post だけを浴びるのではない。**contain-fit → mip で痩せる → 色差をさらに 1 段落とす →
グレア → マスクでライブと混ぜる → post → 夜間モード**（`ScreenComposite.shader` が正本）。

⚠⚠ **帰りの A（この素材が出る唯一の場所）では画が完全な無彩になる。**
`_Mono` は劣化と同じ進みで、進み 1.0 ＝ 彩度 0。しかも輝度の重みが赤に寄る（0.52）ので
**赤い着物は暗くならず明るく写る**。⇒ **彩度の作り込みは本番の画に 1 ビットも出ない。**

⚠⚠ **継ぎ目は素材の中を見ても絶対に出てこない。** 半分マスクの本番では隣に実写が並ぶ。
合否は `deliver.py`（**4 以下**）。実測（2026-08-18 に枠への収め方を直して引き直した値）:

| | 継ぎ目の段差 |
|---|---|
| 恒等（素材＝プレートそのもの） | **0.0** |
| 同じ日のプレートから生成 | 1.6 / 2.2 |
| 読みやすさを上げた素材 | **4.0 ← 線ちょうど**（⚠ 逆を向くことは残っている — 1.6 → 4.0） |
| **別の日の部屋の素材**（現行 show.json） | **6.7** |

⚠ **段差は「素材を置かない画」との差で測る。** 生の値には「その列にもともとある縦の構造」が
下駄として乗っていて、**恒等の入力でも 5.1** 出た（2026-08-17）。下駄はプレートごとに違うので、
生の値では場所をまたいで比べられない。`screen.py` が出す勾配は**参考値**。

### どこで測るかの分担（3 段階の測り直しで決めた）

```bash
py -3.11 tools/gen-plate/deliver.py --run logs/gen-plate/<走行>          # ⭐ 届いた画の合否
py -3.11 tools/gen-plate/budget.py  --material <素材> --plate <プレート>  # 周ごとに何が届くか
```

| 何 | どこで測る | なぜ |
|---|---|---|
| 接地の影・遠近・背景の保存・面積・塊の数 | **生成直後**（`judge.py`） | 届いた画では塊が融合して測れない |
| 縁の鋭さ・粒・細かさ | 生成直後（参考） | **届いた画では差が出ない**（mip が実写も素材も同じだけなます） |
| 彩度・明るさ・暗部 | **post 後**（`posted.py`） | post が均す。帰りの A では彩度そのものが消える |
| **継ぎ目の段差** ＋ **読みやすさ** | **届いた画**（`deliver.py` が 1 コマンドで両方） | 隣に実写が並んだ瞬間にしか出ない／粒に埋もれないか |

⭐ **「暗がりへ沈めろ」の下限は測ってある** — 帰りの A では周りとの明暗差を **50%** まで、
1 周目は **35%** までしか落とせない（素材 3 本で測った最悪値。帰りの A は 3 本とも 50% で揃う）。
`limit.py` が素材を薄めながら検出限界を探す。判定は **Rose の基準（信号 ÷ 粒 ≥ 5）**。
実物の列は文脈として出すだけ（実物側は「そこに無ければ何が見えるか」を隣の平均で代用するので、
人形に厳しい側へ偏る）。

⚠⚠ **1 周目の旧値（10%）は 3.5 倍ゆるかった**（2026-08-18 に粒の刻みを実機へ合わせて判明）。
`compose.py` の式は **0.35 + 0.15 × 進み**。素材ができたら `limit.py` で実際に測る。

⚠⚠ **接地の影を届いた画で測ろうとして、順序が逆に出た**（影のある素材で 0.02・無い素材で 0.20）。
塊が融合して「直下の帯」が取れないため。**嘘をつく計器は載せない。**

## 3.5 ⭐ 追うべき欠点は 2 つだけ（実機の post を通すと半分消える）

素材は生映像の位置に入り、**ポスト処理を浴びてから体験者の目に入る**。
だから**生成直後の数値は、体験者が見る状態の数値ではない**（`posted.py` で 10 走行を測り直した）。

| 指標 | post で動く | どう扱うか |
|---|---|---|
| **縁の鋭さ** | 3% | ⭐ **素通しで届く。生成で直すしかない** |
| **接地の影** | 148%（符号すら変わる） | ⭐ 物理的な有無の話。**post 前で測る** |
| 彩度 | 49〜72% | post が均す。生成直後 1.0〜5.0 が post 後は**全走行 0.5〜1.4** |
| 暗部 | 89% | post が潰す |
| 明るさ | 32% | 均される |

⇒ **判定は指標ごとに見る場所を変えてある。** 作りの話（縁・接地・遠近・背景・面積）は生成直後、
体験者に届く見え方の話（彩度・明るさ・暗部）は post 後。

⚠⚠ **post の仕事をプロンプトにやらせない。** 異変に「着物は褪せて写る」と書いたら
post 後の彩度が 0.53 まで落ちた（＝ 背景より色が無い）。外したら 1.09〜1.42 に戻った。
これは `gen-tone.py` の「種に post を焼くとモデルが直そうとする」と同じ失敗の 3 度目。
**何かを直したくなったら、まず `posted.py` で「post を通しても残るのか」を測る。**

## 4. 判定の線（`judge.py`）

**どれも「種との比」で測る。部屋が変わっても引き直さない。**

| 見るもの | 線 | 何を捕まえるか |
|---|---|---|
| 寸法 | manifest と一致 | モデルは黙って拡大する（1448x1086 で返ってきたことがある） |
| 背景を塗り直していない | 触っていない画素が 置く側 35% / 反対側 90% 以上 | 似た別の部屋を描き起こす |
| 明るさを保つ | 0.95〜1.05 | 生成の露出ずれ |
| コントラストを保つ | sd 比 0.85〜1.20 | モデルは既定で「綺麗に」する |
| 置かない側を触っていない | 差 ≤ 8 / 足された面積 ≤ 0.5% | 半分マスクの反対側 |
| 継ぎ目に段差が無い | ≤ 4.0 | 境目に線が出ると装置が 2 台に見える |
| 足されている | 異変ごとの % | 何もしていない / 塗り替えた |
| 塊の数 | 異変ごと | 1 つの塊に潰れていないか |
| **粒が乗っている** | ≥ 0.45 | **つるつる ＝ CG っぽさの正体その 1** |
| **縁が刃物でない** | ≤ **1.00** | **切り抜きを貼った ＝ その 2**（2026-08-18 に 1.10 から下げた） |
| **暗部が沈む** | その場所の暗がり ×1.8 + 8 まで | **暗がりで光っている ＝ その 3** |
| **接地の影がある** | 直下が 1.5 以上暗い | **床に乗っていない ＝ その 4**（床の異変のみ） |
| 周りより明るくない | ≤ 1.45 | 足したものだけ露出が違う |
| **周りより鮮やかでない** | ≤ 2.2 | **彩度が高い ＝ その 5**（赤い着物が絵の具に見える） |
| 手前ほど大きい | 相関 ≥ 0.15 | 遠近に乗っていない（`persp: true` のみ）。⚠ **群れが密だと当てにならない** — 個体がくっついて 1 つの塊になるので、測っているのは塊の形。まばらな場面でだけ読む |
| 下地が透ける | 相関 ≥ 0.50 | 染み・手形が面の凹凸を消している（`opaque: false` のみ） |

### 線の出どころ（`selftest.py`）

計器そのものを、生成を待たずに試せる。種から 3 つの偽物を作って通す:

```bash
py -3.11 tools/gen-plate/selftest.py --run logs/gen-plate/<走行>
```

| 偽物 | 粒 | 縁 | 接地 | 期待 |
|---|---|---|---|---|
| 貼り付け（平らな色・硬い縁・影なし） | 0.00 | 1.08〜1.48 | 0.00 | 落ちる |
| 馴染ませ（粒・ぼけた縁・接地の影） | 5.00 | 0.56〜0.77 | 10.7 | 通る |
| 素通し（何も足さない） | — | — | — | 「足されている」で落ちる |

⚠⚠ **1 か所で回しても検査になっていない。** 偽物の強さは場所で変わる（塊の色が
「床の中央値 ＋ 50」なので、その明るさがありふれた場所では輪郭が生まれない）。
実際 A_20260816 では**貼り付けが門を素通りしていた**。**線を引くときは 5〜6 か所で回す**:

```bash
for r in q_A_20260816 g_dolls-many r1_dolls_B0816_new v_lap4 r1_dolls_B0807_new; do
  py -3.11 tools/gen-plate/selftest.py --run logs/gen-plate/$r | tail -1; done
```

⚠ **直すなら計器か線。検体をいじると狙っていない門が動く**（塊を暗くしたら粒の門が
馴染ませを誤って落とした・`runs.md`）。

⚠⚠ **縁は勾配の生の大きさで測らない。** 最初そう書いたら、50 階調の段差を 1 画素で切っても
種の強い縁より小さい値になり、**貼り付けを 1 度も捕まえられなかった**。
勾配をその場の明暗差で割ると「何画素かけて変わるか」だけが残る（1 画素なら約 0.5）。

## 5. 見る（数値の後）

判定のたびに走行フォルダへ **`sheet.png`** が出る。上段が 種 / 生成物 / 差 / 足された所、
下段が**塊を大きい順に切り出したもの**。

⚠⚠ **「20 体置いた」という数字を読んだだけで、中身を確認したことにしない。**
`~/.claude/rules/work-style.md` §2 の実践がこの 1 枚。過去に、
1.000 / 1.000 / 差 0.0 という完璧な数値の出力が、**人形が床に乗っておらず切り抜きを
並べたよう**に見えたことがある。

⚠⚠ **完璧すぎる数値は「生成していない」印のことがある。** 実際に 2 度あった。
1 度目は**緑背景で人形だけを描き、PowerShell でクロマキー合成**。
2 度目（2026-08-17）は**染みをガウス関数で計算して画素へ掛け算**していた（`make_stain.ps1` が置き土産）。
判定器は「置かない側の差が厳密に 0」を見つけたら警告を出す。出たら走行フォルダの中身も見る。

⚠ **薄い異変ほどプログラムで作られやすい。** 染み・汚れ・影は「掛け算 1 回」で作れてしまうので、
モデルは生成より計算を選ぶ。`prompt/99-output.md` で名指しで禁じてある
（「入力画像を直接編集して」とだけ書くと、**その編集をスクリプトでやってよいと読まれる**）。

## 6. なぜ種を暗くするのか

種を明るいまま渡すと**モデルは暗い画を一度も描かない**（種 122.9 に対し、体験者が見るのは 48.2）。
暗所の人形は暗いだけでなく陰影の付き方が違うので後段では作れない。ユーザー指摘
「明るい部屋で生成された人形はホラーっぽくなくリアルでもなく CG っぽい」（`canon/LEDGER.md` 0050）。

    プレート → dim（**露出だけ**）→ 生成 → undim → captures/ へ → 実機で post

⚠ **監視カメラらしさ（彩度・ヴィネット・コントラスト）を種へ焼かない。** それは実機の post の役目で、
種に入れると**モデルが「直すべき粗」と読んで画を作り替える**。`gen-tone.py` の既定が露出だけなのはこのため。
⚠ プロンプトで「粒を消さないで」と頼むのも同じ間違い……ではない。**足したものに粒を乗せろ**は
生成の側の仕事なので `10-blend.md` に書いてよい。禁じているのは**入力画像の粗を直させる**方向。

## 7. 落ち方は 3 種類（同じプロンプトでも回ごとに違う）

⚠ **1 回落ちただけでプロンプトを直しにいかない。** まず同じもので 1 回回す。

| 落ち方 | 判定でどう出るか | どうする |
|---|---|---|
| **部屋ごと描き直す** | 触っていない画素が 5% まで落ちる | 回し直す。**プロンプトのせいではない**（同じ文面が他の部屋では 80% を保つ） |
| **寸法を勝手に上げる** | 1448x1086 で返る | ⚠ **致命ではない。** 縮めても背景の保存は残る（実測 67〜95%）。判定が `out_fit.png` を書くので、素材にはそれを使う |
| **スクリプトで作る** | 置かない側の差が厳密に 0 ＋ `.ps1` の置き土産 | 生成ではなく計算している。回し直す |

⚠⚠ **この 3 つは互いに独立している。** 一度「寸法が上がったのは背景を描き直したからだ」と
まとめて読んだが、外れていた — **640x480 のまま部屋ごと描き直した回**（08-07・触っていない画素 5%）も、
**1448 で返ったのに背景を 95% 保っていた回**もある。症状を束ねて 1 つの原因を作らない。

## 8. 落ちたときの順序

1. **片側だけ暗い / コントラストが違う** → プロンプトの問題。種から post を抜き、
   左右で指示を分けるのをやめる（実測で 0.644/1.000 → 1.000/1.000 になった）
2. **粒・縁・接地で落ちる** → `prompt/10-blend.md` の該当項目を、**画面に現れる操作**で言い直す。
   抽象語（「自然に」「リアルに」）は効かない
3. **全体が一様にずれている** → ここで初めて倍率で合わせてよい。**オフセットは足さない**
   （黒が浮いて「薄い」画になる。gain 0.94 + offset +55 で最暗部が 40 → 73 に浮いた）
4. **絶対的な明るさをプロンプトで狙わない** → 数字で頼むと 0.64 → 0.88 → 1.75 と振れる

**同じプロンプトでも当たり外れがある。** 落ち方が毎回同じでなければ、直すより回す方が速い
（1 回 2〜4 分）。

```powershell
.\tools\gen-plate\autorun.ps1 -Anomaly dolls-many -Site A_20260901 -Tries 3
```

⚠⚠ **歩留まりはプロンプトでは動かない**（4 手試して全部だめ・`runs.md`）。**枚数で解く。**
⚠ **「1 枚良かった」を根拠に採用しない。** いちばん荒れる場所では 27〜79 と振れるので、
2 枚目で元へ戻る。条件を比べるなら `stats.py` で中央値を見る。

### ⚠⚠ 既定の 3 枚では足りない（2026-08-18 に手元の 25 走行で測った）

```bash
py -3.11 tools/gen-plate/yield.py        # 場所ごとの合格率と、9 割ほしいときの枚数
```

**全部の門を要求すると通るのは 4%（9 割ほしいなら 57 枚）。**
落ちている門の上位 3 つ（彩度 80% / 置かない側 76% / 寸法 64%）は
**この cue では体験者に届かない**（帰りの A は無彩・反対側はライブ・`out_fit.png` を使う）。
**その 3 つを外すと 28%（8 枚）** ＝ 届かない欠陥のために 7 倍焼いていた。

⇒ `judge.py` は落ちた門のうち**届かないものを名指しする**（合否は動かしていない。
3 つとも「描き起こした回」の印を兼ねているので、残りの門を見てから決める）。

⚠⚠ **異なる異変を同時に焼かない**（2026-09-04 実測）。`autorun.ps1` を 3 本同時に走らせたら、
手形の走行が**幕の顔の絵**を出し、染みの走行がそれを縮めて自分の出力にした（同じ絵が 2 走行に入った）。
8/23 の走行にも同じ組が 1 つあった（`195736_3`＝人形 と `195755_3`＝染み が byte 一致。
runs.md の「人形が 1 体も描かれなかった回」がそれ）。Codex の生成物は exec ごとの別フォルダに出るが、
同時に走る exec の間で絵が入れ替わる。**同じ異変の N 枚並列は構わない**（入れ替わっても同じ指示）。
**別の異変は 1 本ずつ**。並列で焼いたら `md5sum */out.png | sort | uniq -d` で重複を見る。
