# 無人プレートへ異変を足す（生成素材の工房）

カメラで撮った無人の部屋（プレート）へ、生成 AI で人形・染み・手形などの**異変**を足して
cue の素材にする。4 周目 A の「左半分に大量の人形」がこれで作られている（`canon/LEDGER.md` 0050）。

## 三行で

**異変（何を足すか）は場所に依らない。場所（どの面のどこか）は当日 1 ファイル書くだけ。**
プロンプトはこの 2 つから機械が組む。手で書いた文面に部屋の事情が混ざると、当日そこが全部嘘になる。
**当たり外れは判定器で落とす。数値が緑でも `sheet.png` を開くまでが 1 周。**

---

## 1. 層（ここが全部の要点）

| 層 | 実体 | いつ書くか | 中身 |
|---|---|---|---|
| **契約** | `prompt/00-contract.md` | ほぼ書き換えない | 足す以外しない・寸法・塗り直さない |
| **なじませ** | `prompt/10-blend.md` ＋ `prompt/surfaces.md` | 品質を上げたいときはここ | 影・粒・縁・暗部・遠近・遮蔽。面ごとの追加 |
| **異変** | `anomaly/*.md` | 新しい異変を思いついたとき | 何を足すか。**どこにも依存しない** |
| **場所** | `sites/*.json` | **当日ここだけ** | どのプレートの、どの面が、画面のどこか |

**プロンプトの中で場所に触れているのは「この場所について」の節だけ**で、それは `compose.py` が
種を測って書く。人が場所について書くのは `sites/*.json` の**面の箱と一言**だけ。

⚠ **異変の本文に「左のカーテン」「木の合板の壁」と書かない。** それは場所であって異変ではない。
書いてよいのは「布の上に」「壁に」まで。どの布かは `sites` が決める。

## 2. 当日の手順（3 手）

```bash
# 1) 場所を作る（面の箱を下書きし、箱を描いた PNG を出す）
py -3.11 tools/gen-plate/site.py draft --plate <その日のプレート.jpg> --id A_20260901 --cam A
#    → logs/gen-plate/sites/A_20260901_surfaces.png を開いて、箱を sites/A_20260901.json で直す
#    → 直したら  site.py show --id A_20260901  で描き直して確かめる

# 2) プロンプトを組む（種を暗くする所まで込み）
py -3.11 tools/gen-plate/compose.py --anomaly dolls-many --site A_20260901 --place left-half

# 3) 生成 → 判定（印字されたコマンドをそのまま実行する）
#    codex-run.ps1 -Mode image ...
py -3.11 tools/gen-plate/judge.py --run logs/gen-plate/<走行>
```

合格したら明るさを戻して素材にする（`dim` と同じ指定で）:

```bash
py -3.11 tools/gen-tone.py undim <走行>/out.png tools/web-compositor/captures/<名前>.png --cam A
```

⚠ **生の生成物は `_raw.png` で残す。** cue の `hasMatch` / `matchGain` へ入れない
（卓が `bakeColorMatch` で書く場所なので、保存し直すと消える）。

## 3. 新しい異変を足す

`anomaly/<id>.md` を 1 枚書くだけ。頭書きが判定の線を兼ねる。

```
---
id: face-stain
title: 人の顔のように見えてしまう染み
surface: cloth        # floor / cloth / wall / furniture / ceiling
opaque: false         # false なら「下地が透ける」を判定する
min_area_pct: 0.5     # 足された面積（置く領域に対する %）
max_area_pct: 14
min_parts: 1          # 塊の数の下限
persp: false          # true なら「手前ほど大きい」を判定する
---
（本文＝プロンプトへそのまま入る。**場所に触れない**）
```

- **`surface` を持たない場所では、その異変は成立しない。** `compose.py` が
  「この場所に布の面が無い」と言って止まる（黙って画面全体へ広げない）
- 面ごとの描き方の注意は `prompt/surfaces.md` に足す（そこも場所に依らない書き方で）

## 4. 判定の線（`judge.py`）

**どれも「種との比」で測る。部屋が変わっても引き直さない。**

| 見るもの | 線 | 何を捕まえるか |
|---|---|---|
| 寸法 | manifest と一致 | モデルは黙って拡大する（1448x1086 で返ってきたことがある） |
| 背景を塗り直していない | 触っていない画素が 置く側 35% / 反対側 90% 以上 | 似た別の部屋を描き起こす |
| 明るさを保つ | 0.95〜1.05 | 生成の露出ずれ |
| コントラストを保つ | sd 比 0.85〜1.20 | モデルは既定で「綺麗に」する |
| 置かない側を触っていない | 差 ≤ 8 / 足された面積 ≤ 0.5% | 半分マスクの反対側 |
| 継ぎ目に段差が無い | ≤ 4.0 | 境目に線が出ると装置が 2 台に見える |
| 足されている | 異変ごとの % | 何もしていない / 塗り替えた |
| 塊の数 | 異変ごと | 1 つの塊に潰れていないか |
| **粒が乗っている** | ≥ 0.45 | **つるつる ＝ CG っぽさの正体その 1** |
| **縁が刃物でない** | ≤ 1.10 | **切り抜きを貼った ＝ その 2** |
| **暗部が沈む** | その場所の暗がり ×1.8 + 8 まで | **暗がりで光っている ＝ その 3** |
| **接地の影がある** | 直下が 1.5 以上暗い | **床に乗っていない ＝ その 4**（床の異変のみ） |
| 周りより明るくない | ≤ 1.45 | 足したものだけ露出が違う |
| **周りより鮮やかでない** | ≤ 2.2 | **彩度が高い ＝ その 5**（赤い着物が絵の具に見える） |
| 手前ほど大きい | 相関 ≥ 0.15 | 遠近に乗っていない（`persp: true` のみ） |
| 下地が透ける | 相関 ≥ 0.50 | 染み・手形が面の凹凸を消している（`opaque: false` のみ） |

### 線の出どころ（`selftest.py`）

計器そのものを、生成を待たずに試せる。種から 3 つの偽物を作って通す:

```bash
py -3.11 tools/gen-plate/selftest.py --run logs/gen-plate/<走行>
```

| 偽物 | 粒 | 縁 | 接地 | 期待 |
|---|---|---|---|---|
| 貼り付け（平らな色・硬い縁・影なし） | 0.00 | 1.12 | 0.00 | 落ちる |
| 馴染ませ（粒・ぼけた縁・接地の影） | 5.00 | 0.63 | 10.7 | 通る |
| 素通し（何も足さない） | — | — | — | 「足されている」で落ちる |

⚠⚠ **縁は勾配の生の大きさで測らない。** 最初そう書いたら、50 階調の段差を 1 画素で切っても
種の強い縁より小さい値になり、**貼り付けを 1 度も捕まえられなかった**。
勾配をその場の明暗差で割ると「何画素かけて変わるか」だけが残る（1 画素なら約 0.5）。

## 5. 見る（数値の後）

判定のたびに走行フォルダへ **`sheet.png`** が出る。上段が 種 / 生成物 / 差 / 足された所、
下段が**塊を大きい順に切り出したもの**。

⚠⚠ **「20 体置いた」という数字を読んだだけで、中身を確認したことにしない。**
`~/.claude/rules/work-style.md` §2 の実践がこの 1 枚。過去に、
1.000 / 1.000 / 差 0.0 という完璧な数値の出力が、**人形が床に乗っておらず切り抜きを
並べたよう**に見えたことがある。

⚠⚠ **完璧すぎる数値は「生成していない」印のことがある。** 実際に 2 度あった。
1 度目は**緑背景で人形だけを描き、PowerShell でクロマキー合成**。
2 度目（2026-08-17）は**染みをガウス関数で計算して画素へ掛け算**していた（`make_stain.ps1` が置き土産）。
判定器は「置かない側の差が厳密に 0」を見つけたら警告を出す。出たら走行フォルダの中身も見る。

⚠ **薄い異変ほどプログラムで作られやすい。** 染み・汚れ・影は「掛け算 1 回」で作れてしまうので、
モデルは生成より計算を選ぶ。`prompt/99-output.md` で名指しで禁じてある
（「入力画像を直接編集して」とだけ書くと、**その編集をスクリプトでやってよいと読まれる**）。

## 6. なぜ種を暗くするのか

種を明るいまま渡すと**モデルは暗い画を一度も描かない**（種 122.9 に対し、体験者が見るのは 48.2）。
暗所の人形は暗いだけでなく陰影の付き方が違うので後段では作れない。ユーザー指摘
「明るい部屋で生成された人形はホラーっぽくなくリアルでもなく CG っぽい」（`canon/LEDGER.md` 0050）。

    プレート → dim（**露出だけ**）→ 生成 → undim → captures/ へ → 実機で post

⚠ **監視カメラらしさ（彩度・ヴィネット・コントラスト）を種へ焼かない。** それは実機の post の役目で、
種に入れると**モデルが「直すべき粗」と読んで画を作り替える**。`gen-tone.py` の既定が露出だけなのはこのため。
⚠ プロンプトで「粒を消さないで」と頼むのも同じ間違い……ではない。**足したものに粒を乗せろ**は
生成の側の仕事なので `10-blend.md` に書いてよい。禁じているのは**入力画像の粗を直させる**方向。

## 7. 落ち方は 3 種類（同じプロンプトでも回ごとに違う）

⚠ **1 回落ちただけでプロンプトを直しにいかない。** まず同じもので 1 回回す。

| 落ち方 | 判定でどう出るか | どうする |
|---|---|---|
| **部屋ごと描き直す** | 触っていない画素が 5% まで落ちる | 回し直す。**プロンプトのせいではない**（同じ文面が他の部屋では 80% を保つ） |
| **寸法を勝手に上げる** | 1448x1086 で返る | ⚠ **致命ではない。** 縮めても背景の保存は残る（実測 67〜95%）。判定が `out_fit.png` を書くので、素材にはそれを使う |
| **スクリプトで作る** | 置かない側の差が厳密に 0 ＋ `.ps1` の置き土産 | 生成ではなく計算している。回し直す |

⚠⚠ **この 3 つは互いに独立している。** 一度「寸法が上がったのは背景を描き直したからだ」と
まとめて読んだが、外れていた — **640x480 のまま部屋ごと描き直した回**（08-07・触っていない画素 5%）も、
**1448 で返ったのに背景を 95% 保っていた回**もある。症状を束ねて 1 つの原因を作らない。

## 8. 落ちたときの順序

1. **片側だけ暗い / コントラストが違う** → プロンプトの問題。種から post を抜き、
   左右で指示を分けるのをやめる（実測で 0.644/1.000 → 1.000/1.000 になった）
2. **粒・縁・接地で落ちる** → `prompt/10-blend.md` の該当項目を、**画面に現れる操作**で言い直す。
   抽象語（「自然に」「リアルに」）は効かない
3. **全体が一様にずれている** → ここで初めて倍率で合わせてよい。**オフセットは足さない**
   （黒が浮いて「薄い」画になる。gain 0.94 + offset +55 で最暗部が 40 → 73 に浮いた）
4. **絶対的な明るさをプロンプトで狙わない** → 数字で頼むと 0.64 → 0.88 → 1.75 と振れる

**同じプロンプトでも当たり外れがある。** 落ち方が毎回同じでなければ、直すより回す方が速い
（1 回 2〜4 分）。
