# revision02 静止画の観測

参照全体と原寸のコード・窓境界を開いてから、方向検出と細線保護の定数を固定した。元Bも全体とコードの原寸を開いた。以後、見た目の点数に向けたパラメータ探索はしていない。

下地はround11のraw RGBA。検出用にだけ平滑化した輝度を使う。出力はraw RGBとscalar deltaの和で、stage12・NLM・bilateral・光学処理・全面の階調変更を通さない。参照のRGBや物体patchは出力に使わない。round23の窓左右のscalar atlasだけを使い、モニタのatlasは使わない。

構造テンソルはcoherence>.60、勾配xのエネルギー比>.82。縦に近い境界を選ぶ。白・黒top-hatの直径15pxで細いridge/troughを拾い、その検出領域を四方2px拡げて追加量を0にする。縦方向を条件にしてコードを保護していない。輪郭ごとの残差は左右10pxに収める。

全候補のfull画像を開いた。Bは元・軟・標準・失敗比較の旧23版の原寸floor/edge/wireを並べて開いた。A/Cもfloor/edge/wireを原寸で開いた。旧23版は失敗の比較だけで、処理の下地には使っていない。

保護maskをA/B/Cとも原寸で開いた。Bでは床の繰り返し線が広く保護される。衣類や細いケーブルの近くも保護される。Aでは布の細かい明暗まで保護されるため、広い襞の境界にも処理しない部分がある。これは保守的な過保護で、可視領域の保護率はB41.00%、A61.83%、C34.79%。Bのgateを原寸で開くと柱や衣類の一部の縦境界だけが残り、delta単独画像もその範囲に限られる。参照と同じ量の加工が出たとは判断しない。

実画像の細線を全て意味的に識別した証明は無い。幅の太いコード、他の輪郭に重なるコード、コントラスト.028を下回る線には検出漏れの余地がある。細いtextureを保護することで加工領域が減る。B全体の変更は軟0.408%、標準0.431%。標準はA1.725%、C0.902%。Bのfloor ROIは追加前と完全一致。実画像については保護mask上の全RGBA一致を直接検証した。

30件の合成入力を両profileで検証した。平面・水平の広いstepは変更0px。縦の広いstepは軟3102px/標準3189pxに変化が実在する。2/4/6/12pxの水平・垂直・斜めの明線と暗線は追加前後のコントラストとFWHMが一致する。水平・垂直のFWHMは実際に2/4/6/12px。斜めは横断サンプル数で記録し、法線方向の幅と同一視しない。広い縦stepを水平・斜めの細線が横切るfixtureでも、その既知の細線と周囲2pxは完全一致し、残りの広い縦境界には軟2558px/標準2638pxの変更が出る。

RGBAのOFF完全一致・alpha・透明画素のhiddenRGB・開口内側2px・保護領域・delta0領域・再計算一致・入力SHA不変は全候補でassertした。source-snapshotに処理本体と生成コードを保存した。ブラウザのボタン操作は未検証。本編や動画や設定へは統合していない。自己採点と採用判断は行っていない。
