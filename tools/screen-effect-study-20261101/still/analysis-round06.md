# 追加加工・6版目：細部のある面を相対的な白黒へ写す

5版目の新規独立評価は56%。内訳は水平66、不規則58、白黒細片40、粒47、階調50、像62。親から受け取った要約であり、ユーザー発話ではない。以前の画像と記録は維持した。

5版目では方向の揃い方を条件にしすぎた。床の交差する細部まで弾き、境界の変位が主に残っていた。6版目はtextureの判定に方向coherenceを使わない。

## 細部のある面を相対的に分ける

まず3×3の中央値と小さい平均で孤立した粒を抑える。そのsmallと半径2、4、8pxの局所平均を作る。小さい幅で残るエネルギーと大きい幅のエネルギーの比をtextureの条件にした。等方的な細部と交差する線もこの条件を通る。

smallから半径4pxの平均を引き、その範囲の標準偏差で割る。暗い面でも、周囲より明るい筋は正の大きい値になる。textureと判定した場所だけを `0.43 + 0.42 × tanh(正規化値 × 2.2)` で明暗へ写す。暗い芯は約0.01、明るい芯は約0.85。画面全体の二値化ではない。

水平方向の±2pxの値も使い、細かな点だけが立つのを抑える。平坦と判定した面は従来の連続した階調を使う。元のgrainと構造を完全に区別できたとは扱わない。

## 面内の細片を増やす

面内の置換は16×4pxの区間を使い、実測runの長さと1〜4pxの高さで短く区切る。textureに反応する密度を5版目より増やした。境界の変位は0.35へ弱め、大きな縦の輪郭だけが波打つ状態を抑えた。

参照由来のlookupは4版目のものを使う。出所のhashとROIと抽出式を保持する。元参照のRGB、キャラ、室内の形を出力素材にしない。色相は付与しない。

## 同じ座標での確認

元ベースと6版目の床を原寸で並べて開いた。元の連続した灰色の筋が、白黒の短く切れた線と細片へ変わっている。元参照全体と候補全体も実際に開いた。

textureの強度0.35を超える画素は床ROIの63.16%、カーテンROIの42.32%、壁ROIの0%。これらは同じ座標で処理の有無を調べた値で、類似度ではない。別の部屋の白黒面積へ合わせる処理はしていない。

自分の観察では、一部の細片は参照の水平の筋より丸い穴のようにも見える。元のgrainをtextureとして拾う部分が残る。細片が増えたことと参照に近づいたことは分け、独立評価を待つ。

## 検証と出力

固定した `base.png` と `base.rgba` だけを入力にした。固定PNGのhashとRGBA再デコード一致を必須にした。alpha、全透明RGBA、OFF、同じ値での再計算はいずれも最大差0。曲面と画枠は固定。失われた細部を復元したものではない。

候補は `round-06-default.png`。独立比較用の不透明版は `round-06-default-on-black.png`。原寸前後全体と床と布と手すりと暗部の切り出しは `round-06-comparison-` で始まる。

処理値とROIの診断は `round-06-processing.json`。自己完結調整画面は `round-06-preview.html`。ブラウザ実表示は先のURL policy拒否により未検証。本編Unityと共用台帳は変更していない。
