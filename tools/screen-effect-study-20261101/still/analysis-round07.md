# 追加加工・7版目：行単位の水平処理へ変更

6版目の独立比較は44%。内訳は水平42、短長38、細片50、粒35、平面48、崩52。指摘は「丸い凹凸と全面粒が不一致」。親経由の評価要約であり、ユーザー発話ではない。以前の候補は残している。

## 生成画の役割

指定された生成画を実際に開き、元参照と固定ベースも開いて比較した。生成画は、広い布の陰影を残しながら水平の短い擦れへ変える方向を検討する資料として使った。

生成画のRGBや輝度はフィルタへ入力しない。生成画から固定した明るさの差分fieldを作る方法も使わない。独立評価へ渡すのは、現在ベースからフィルタで計算した実出力だけ。生成画の出所hashとdesign-onlyの用途をmanifestへ残した。

## 穴状の局所変換を撤去

前版の局所coherence、局所標準偏差、tanh、texture内部の白黒変換は7版目では使わない。広い面の中に丸い穴を作る変換をやめ、行全体に対する水平の変位へ置き換えた。

最初に縦方向5画素の中央値で細かな粒を整理する。二次元の大きな平均ではなく、同じx位置の縦5画素だけを使う。横方向の輪郭と布の広い陰影を読み続ける。

参照から測ったjitter系列は、さらに15行の移動平均を引いて遅い形を除く。その変位で行全体を同じだけ横へずらす。毎行で個別に境界を探して残差を配る処理は使わない。

横方向だけで輪郭を強め、実測run長から2〜8pxの短い読み位置を作る。その近傍差から明暗の細い複線と短い残像を作る。灰色が一定の面ではこの差が0になり、人工的な点や穴を発生させない。

## 少数の値を実画像で比較

restrained、default、roughの3つを保存し、全て実際に開いた。defaultを独立評価用の候補に固定した。生成画の見た目との一致を理由に合格とする判定は行っていない。

最後に元参照全体と候補全体を見る対象として維持し、床の原寸比較も開いた。曲面の輪郭とalphaは元ベースのまま。元の斜めのぼけは復元していない。

## 校正と検証

平坦な中間グレーを処理した出力は全画素で同じ値になり、平坦面へ線を生やさないことを数値で検証する。縦の明暗境界の試験では、行ごとに境界位置が変わることを検証する。これらは処理の校正であり、参照との類似度を表す値ではない。

入力は固定した `base.png` と `base.rgba`。PNGのhashとRGBA再デコード一致を検証した。alpha、全透明RGBA、OFF、同条件再計算は最大差0。

## 出力

`round-07-default.png` がRGBA実フィルタ出力。`round-07-default-on-black.png` が独立比較用。弱めと強めは `round-07-restrained.png` と `round-07-rough.png`。原寸全体と床と布と手すりと暗部の追加前後も保存した。

処理値は `round-07-processing.json`、調整画面は `round-07-preview.html`。ブラウザ実表示は先のURL policy拒否により未検証。本編Unityと共用台帳は変更していない。独立評価と採用判断は未実施。
