# 11版目：同じ追加フィルタを3カメラへ適用する

この比較は、入力を変えて合格を作るためのものではない。現行プロジェクトの3カメラへ同じ追加処理を適用し、場面にある細部の違いが加工の見え方へどう関係するかを調べる。構図と場面の一致は加工の一致と分けて評価する。

10版目の比較結果はB64、A55、C60。親から受け取った独立比較の要約であり、ユーザー発話ではない。9版目と10版目の画像とコードは変更していない。

## 入力は現行採用描画の固定コピー

入力元は `G:/マイドライブ/shubie/reports/2026-11-01_screen-adoption/gpu-complete/` の `A_adopted.png`、`B_adopted.png`、`C_adopted.png`。

`finalized-captures.json` は `changedSinceGpu=0` とimmutableの記載を持つ。GPU manifestの各写真のsha256と実ファイルを照合し、11版目の `base-A.png`、`base-B.png`、`base-C.png` へバイトコピーした。入力元のフォルダへは書き込まない。

GPU manifestにある採用形状、中心+0.12EV、色strength0.025、Mono0.5の比較条件を記録した。manifest自体を11版目へバイトコピーして残す。Unityは起動も操作もしていない。

## 同じ2プロファイルを適用

9-Aは既存のNLM、Wiener、信号処理をそのまま使う。10-Bは同じ光学処理の後、平坦面だけ追加で整理し、構造の近くへ独立した局所faultの群を置く。3カメラでパラメータを変えない。カメラごとの値の最適化はしていない。

10-Bのイベント位置は入力画像の細部エネルギーに反応する。したがって同じパラメータでも、配置される場所と重なりはカメラごとに変わる。これは値を別々に調整した結果ではなく、同じ適応フィルタを違う入力へ適用した結果。

生成目標画のRGB、輝度field、キャラや参照部屋の形は計算に使わない。参照由来の変位とrunの数値lookupは以前のものを共有する。

## 場面の違いとして分けて見る点

Aはカーテンの繰り返す縦の陰影が画面の多くを占める。床の細部が見える面積は下の一部。処理の乱れが縦の輪郭に集中して見えやすい。

Bは左側の平坦な壁と、手前で大きく写る床がある。平坦面の粒の整理と、床の繰り返す細部への追加処理を同じ全体画像で比べられる。Aと同じ量の処理でも、細片の多さを床の模様そのものから読みやすい構図。

Cは広い壁と斜めのカーテンと前景の大きな黒い形が中心。Aの垂直な繰り返しとは輪郭の方向が違う。短い水平欠けが斜めの輪郭でどう見えるか、広い平面で余計な模様が出るかを見る。

上の3点は入力場面の事実と、比較時に分けるべき観測対象。場面が参照に似ていることを類似度点の根拠にはしない。原寸の一部だけで完了とする判定もしない。

## 全6枚を開いた後の観察

元参照全体、3枚の元入力、6枚の追加加工結果を実際に開いた。自分の観察では、Bは絨毯が大きく写るため、同じ9-AでもAより床の白黒の細片が多く見える。これは素材に含まれる模様とその面積の違いを含むので、フィルタが強くなった証拠にはしない。

反対に、BとCの広い壁では9-Aの弱い周期的な模様がAより広い面積に見える。Aの布を中心に見ていたときより、平坦面に残る加工の問題が分かりやすい。10-Bでは壁がより平滑になる一方、Cの斜めの前景と紙の縁の細かい欠けが目立つ。

同じフィルタでも、素材の方向と細かさと平面の面積によって加工を読む場所が変わる。Aだけの布の見た目から「水平細片が不足している」と判断すると、フィルタの問題と布に元から少ない細部を混同する余地がある。ただしBへ変えて合格とする扱いもしない。平面の乱れと床の細片と輪郭の欠けを、3枚全体で評価するための6候補とした。

以前のA-only基準PNGと今回の現行採用Aはhashが違う。したがって以前の点数と今回の点数の差を、そのままフィルタ変更の効果へ帰属しない。今回の内部比較では、同じカメラの固定コピーに9-Aと10-Bを追加した結果だけを比較できる。
