# 画像を直接入力にしたCRTスクリーン

2026-10-30。先行の言語化による4案はユーザーが却下。
参照画像を画像生成へ直接渡して枠を抽出し、反射マップも同じ入力から生成した。

## 作業の順

1. 入力画像からFrameとReflectanceを生成し、プロジェクトのResourcesへ保存。
2. 著作の論理16:9を保ったまま、表示だけ参照の1280:1030へ変更。左右の黒帯は開口へ出さない。
3. 本番のScreenCompositeシェーダで無人写真を描画。
4. 毎回新規のサブエージェントへ参照と実描画の2枚だけを渡し、事情・過去の点数・目標点を知らせず採点する。
   室内と家具を除いた類似度96%以上がユーザー指定の完了条件。
5. 未達なら指摘を反映して再描画。座標・導入・終幕・反射の検証とビルドは途中でも行い、96%未達の版は確認用と明示する。

## 実体

- `Assets/Resources/CrtReference/Frame.png`: 画像を直接編集して得た透過枠。
- `Assets/Resources/CrtReference/CaseColor.jpg`: 元参照のバイトコピー。枠のRGBは再生成せずこの画素を読む。
- `Assets/Resources/CrtReference/Reflectance.png`: 同じ画像から生成した反射強度マップ。
- `CrtReferenceScreen`: 論理座標、開口、参照比率、材質の入口。
- `MjpegScreen`: 参照素材を構成できたときだけ物理比率を変更。CG・マスクの論理比率は16:9のまま。
- `ScreenComposite.shader`: 開口→論理UV→既存合成→参照筐体。最終alphaは1。

## 再描画

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools/unity.ps1 menu crt-reference
```

出力は `G:\マイドライブ\shubie\reports\2026-10-30_crt-reference\`。
各反復のPNG・元画像のハッシュ・材質ハッシュ・新規エージェントの判定をここへ保存する。
評価するのは実シェーダのPNG。画像生成AIが描いた完成予想図を実装の証拠にしない。

Gradeの曲線はDriveの`grade-fit.json`に全256値を保存。再生成は`fit-grade.py --replay <grade-fit.json>`。
再fitには`--source`と`--guide`の明示が必須。現在のA_ungradedは各描画で更新されるため、14時点の入力と同一とは扱わない。

初回の確認前の予測（描画処理起動後、PNGを確認する前に記録）:
- 枠の輪郭と微細な質感は画像からの抽出なので、先行の数式による枠より参照へ近づく。
- 見える映像に左右の黒帯は残らず、CGとマスクは同じ表示変換を受ける。
- 視点を変えたとき反射マップによる画素差が生じる。

採否と点数は評価結果に従う。96%はユーザー指定の主観評価の閾値であり、画像測定の精度ではない。
