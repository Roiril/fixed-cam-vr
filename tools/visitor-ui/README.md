# 来場者用タブレット UI

タブレットAPKに同梱するページは `tablet/app/src/main/assets/web/index.html`。
画面と素材はタブレット内から読む。外部フォントや CDN は使わない。
画面を変えた後はタブレットAPKの再ビルドとインストールが必要。
説明位置を復元した後も操作ボタンと案内は選択した言語に揃う。

起動時は全画面のスタッフ画面を表示する。「準備 → 来場者 → 装着 → 体験 → 回収」の現在地と主操作を示す。機器の異常はカメラ A・B・C ごとに直し方を添える。接続待ちでも Quest の位置合わせを始められる。
「準備を始める」の実完了後は「来場者の画面にする」で渡す。設定と博士の10文が終わるとスタッフ画面へ戻る。条件を確認して「長押しで装着へ進む」を1.2秒押す。Questの同じ説明版の受理後に装着案内2文を自動再生する。本編開始後はスタッフ画面へ戻る。終わりの演出中はリセットできない。完了後に回収して次の準備へ進む。

## スタッフ画面の描画確認

`node tools/visitor-ui/staff-mock-server.cjs --port 8108`でlocalhostだけに開発用サーバーを開く。`http://127.0.0.1:8108/`をブラウザで表示する。`POST /_scenario`へ`{"scenario":"setup"}`を送ると初回の準備に切り替わる。`confirm-problem`と`playing`と`outro`と`finished`と`asleep`と`wake`でも確認できる。`GET /_state`で値を確認できる。

mockはQuestへ接続しない。内蔵ブラウザの撮影が縮まないように開発用の応答だけ全画面要求を抑止する。APKのHTMLは変更しない。長押しの時間と要求IDと説明版の照合は`node tools/visitor-ui/verify-runtime.cjs`で検証する。mockの表示だけで実機の動作を合格にしない。

## Redmi の設営

ホーム画面の「廻リ視 博士」を開く。画面と素材はタブレット内にある。PCとQuestは起動に不要。来場者の設定を反映する場合はQuestで「廻リ視」を起動し、同じ展示Wi-Fiへ接続する。

起動時のスタッフ画面で本体ラベルに対応するα／βを選ぶ。「接続する」で応答を確かめる。保存済みの接続先は起動時に再確認する。「困ったとき」から接続先を変更できる。IPの手入力とQuestのページへの移動は不要。未開始の設定がある間は対象を変えない。

「博士の音声を確認する」と「説明を確認する」は同梱素材を使う。説明の確認ではQuestへ設定を送らず、反映成功にも数えない。タブレットの音量は本体のボタンで調整する。Questの音と左コントローラーは装着して確認する。

ビルドと導入は [tablet/README.md](../../tablet/README.md)。UIや動画を変えたときはタブレットAPKを更新する。Quest APKの再ビルドは不要。

## 通信

`POST /set` の成功は設定を受け取ったという通知。
反映済みの表示には `GET /status` の言語とホラー軽減の実値が必要。
さらに同じ `portalSessionId` と `tabletSessionId` で `appliedSeq == 送信時のseq > 0` を満たす必要がある。
`appliedSeq` は Quest が両方の設定を書いた後に更新する。タブレットは `/status` を2秒ごとに読み、これを Quest からの反映確認として扱う。設定を受け取った返答や900ms経過だけで完了を表示しない。Quest が本編中なら、次の注意書き画面で書かれるまで反映中を保つ。
設定の送信時に値を固定する。送信後に選択を変えても送信済みの値と混ぜない。

タブごとに `tabletSessionId` を作る。同じタブのリロードでは説明復元用に保持する。5 秒ごとに `POST /tablet/pulse` を送る。
クエストの切替前は固定した2 IPの `GET /status` を確認する。応答のIPとポートも確認する。不通や不正な応答では元の受付に留まる。成功したらAndroidの設定へα／βを保存する。ページは移動しない。以後の設定送信と反映確認と接続通知と取消は選択先へ送る。素材取得は常に端末内。任意URLは受け付けない。切替前の説明位置は破棄する。送信と復元に `targetId` を追加し、古い接続先からの応答を採用しない。
この通信は設定を変えない。`/set` と `/clear` にはページ ID と `/status` で得た Quest 起動 ID を必ず付ける。不足は400、古い Quest 起動 ID は409になる。
`/status` は `portalSessionId` と最後の送信 `lastRequest` を返す。古い起動 ID の `/set` は 409。
Quest が再起動したら以前の送信と説明位置を破棄する。選択中の言語とホラー軽減は保持して設定画面へ戻す。運用卓は Quest の heartbeat から待受・応答・反映を分けて表示する。
タブレットの応答が 30 秒以上途絶えた場合は未確認。バックグラウンドでブラウザが止まった場合も含む。
複数ページや別ページからの送信も確認済みにしない。説明中も照合を続ける。別ページで新しい設定が受理された場合は説明と媒体を止め、設定の確認を案内する。予約が体験開始時に消費された場合は別ページの変更として扱わない。PC から `/status` を読むだけでは接続証拠にならない。

失敗時の再送は来場者の操作で行う。自動で POST を繰り返さない。
通信できない間はヘッドセットの値を「—」と表示する。
受信件数が減った場合は再起動として扱う。
反映番号の減少は通常の体験の開始処理でも発生するため、再起動の根拠にしない。
反映後に予約が消費され、次の注意画面へ戻るまでを観測した場合も古い送信を破棄する。
次の注意画面へ戻った場合は次の来場者向けにタイトルへ戻す。Quest 再起動の場合は同じ選択を保って設定画面へ戻す。
旧 APK は起動 ID を持たない。今回の診断は新しい APK が必要。

### 検証用の応答

以下は代役サーバーだけのAPI。本番には存在しない。

| リクエスト | 用途 |
|---|---|
| `POST /_stage` 本文 `Wait` | 注意画面に進めて予約を適用する |
| `POST /_stage` 本文 `Done` | 反映を止める |
| `POST /_phase` 本文 `RUN` | 体験中の表示にする |
| `POST /_phase` 本文 `INTRO` | 導入中の表示にする |
| `POST /_consume` | 開始時の予約消費を再現する |
| `POST /_begin` | 次の注意画面を開始する。実値を既定に戻した後で予約を適用する |
| `POST /_reboot` | 初期値と連番に戻す。設定した通信障害も解除する |
| `POST /_fault` JSON本文 | 指定したリクエストの応答を遅らせるか失敗させる |

`/_fault` の本文例:

```json
{"path":"/set","delayMs":7500,"status":503,"count":1}
```

`path` は `/set`、`/status`、`/clear`、`/asset/briefing-v1.json`。
`delayMs` は0〜15000。`status` は200、400、503。
`count` は適用する回数。`-1`で継続する。`0`で解除する。
遅延は受信処理の前に行う。ブラウザがタイムアウトしてもサーバー処理は続く。

## スタッフの交代操作（2026-10-08）

初回はQuestのメインスクリーンで機器確認・位置合わせ。毎回はスタッフが回収して台へ置き、清拭・機器確認 → タブレットのスタッフ欄でリセットしQuestの実完了を待つ → 来場者が新しい設定・博士の説明 → スタッフが「装着案内へ」を一度押す → タブレットを置き両手で装着補助。右AリセットとB確定は予備操作。通常の確認のためにHMDを被り直さない。体験者の左X/Y練習と題字の明示開始を残す。 スタッフ専用操作は閉じたスタッフ欄からは受け付けず、来場者画面には置かない。初回の接続先と媒体確認、未開始設定の取消は折りたたむ。Questの`questTick`停止時は古い緑表示を外す。実表示は隔離したデスクトップEdgeの1097×686で確認し、模擬通信として記録する。実機通信・音声・着脱はこの確認の代わりにはならない。
