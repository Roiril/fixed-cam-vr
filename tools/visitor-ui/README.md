JSON から台本と SRT を再生成する。字幕を別の文面へ手編集しない。
音声制作後は `durationMs` を実際の音声へ合わせる。
全体の SRT はオートの説明開始を0秒とする。設定反映と手動で止めた時間は含まない。
台本には文ごとの場面内開始時刻と終了時刻を載せる。
媒体の開始時刻は同じ場面の先行する文の `durationMs` の合計。
手動では一文の終端で媒体を止める。文を送ると発話を中断し、次の文へ移る。
媒体制作時は文間の間を含めて尺を合わせる。

各場面に `audio` または `video` を追加すると、その言語の素材を使う。
値は `/asset/` 以下のファイル名だけを書く。
たとえば `"video": {"ja": "introduction-ja-v1.mp4"}`。
実ファイルは `Assets/Resources/Visitor/introduction-ja-v1.mp4.bytes` に置く。
音声付き動画を指定したら同じ音声を `audio` に重ねない。
未指定の音声と動画は取得しない。博士動画は既存画像と同じ人物と画角で作る。
日本語だけの素材指定も可能。素材がない言語は静止画と字幕で進む。
素材は APK に取り込まれる。差し替え時は版付きファイル名を変えて再ビルドする。

画像と動画は16:9を推奨する。現在の博士画像は顔の中心が画像幅の70%付近にあるため、各場面の `doctorAnchor` は `70`。新しく博士を中央で撮影した素材では `50` を指定する。`doctorImage` が博士素材を指定し、`image` は章の資料画像を指定する。`doctor-center` では両方に同じ博士画像を指定できる。
動画は章と言語ごとに分ける。たとえば `introduction-ja-v1.mp4`、`introduction-en-v1.mp4`、`subject-fr-v1.mp4`。音声だけなら `introduction-ja-v1.mp3` のように命名する。JSONには拡張子まで含むファイル名を書く。配信元の実ファイル名には `.bytes` を付ける。
音声や動画の尺は、場面内の `durationMs` の合計と一致させる。文間の無音もその尺に含める。音声付きの `video` と同じ内容の `audio` は同時に指定しない。
素材の取得や再生に失敗しても字幕は保持する。音声は来場者がミュートできる。取得や再生に失敗した場合は同じ文から再試行できる。

説明中の通信断は再生位置を保つ。
通信断とスタッフ情報の表示とタブの非表示ではオートを解除する。
元の画面へ戻った直後はその文で待つ。手動で送るか、オートを押すと再開できる。
同じタブをリロードした場合は、Quest の起動 ID、ページ ID、受理番号、反映番号、実値、未消費の予約がすべて一致したときだけ説明位置を復元する。復元後はオートをオフにし、保存した文で停止する。別タブは別のページ ID になる。予約の消費、新しい受理番号、Quest の再起動後は古い説明を復元しない。保存できないブラウザでも通常の設定と説明は続ける。

## 通信

`POST /set` の成功は設定を受け取ったという通知。
反映済みの表示には `GET /status` の言語とホラー軽減の実値が必要。
さらに同じ `portalSessionId` と `tabletSessionId` で `appliedSeq == 送信時のseq > 0` を満たす必要がある。
設定の送信時に値を固定する。送信後に選択を変えても送信済みの値と混ぜない。

タブごとに `tabletSessionId` を作る。同じタブのリロードでは説明復元用に保持する。5 秒ごとに `POST /tablet/pulse` を送る。
この通信は設定を変えない。`/set` と `/clear` にはページ ID と `/status` で得た Quest 起動 ID を必ず付ける。不足は400、古い Quest 起動 ID は409になる。
`/status` は `portalSessionId` と最後の送信 `lastRequest` を返す。古い起動 ID の `/set` は 409。
Quest が再起動したら以前の送信と説明位置を破棄する。選択中の言語とホラー軽減は保持して設定画面へ戻す。運用卓は Quest の heartbeat から待受・応答・反映を分けて表示する。
タブレットの応答が 30 秒以上途絶えた場合は未確認。バックグラウンドでブラウザが止まった場合も含む。
複数ページや別ページからの送信も確認済みにしない。説明中も照合を続ける。別ページで新しい設定が受理された場合は説明と媒体を止め、設定の確認を案内する。予約が体験開始時に消費された場合は別ページの変更として扱わない。PC から `/status` を読むだけでは接続証拠にならない。

失敗時の再送は来場者の操作で行う。自動で POST を繰り返さない。
通信できない間はヘッドセットの値を「—」と表示する。
受信件数が減った場合は再起動として扱う。
反映番号の減少は通常の体験の開始処理でも発生するため、再起動の根拠にしない。
反映後に予約が消費され、次の注意画面へ戻るまでを観測した場合も古い送信を破棄する。
次の注意画面へ戻った場合は次の来場者向けにタイトルへ戻す。Quest 再起動の場合は同じ選択を保って設定画面へ戻す。
旧 APK は起動 ID を持たない。今回の診断は新しい APK が必要。

### 検証用の応答

以下は代役サーバーだけのAPI。本番には存在しない。

| リクエスト | 用途 |
|---|---|
| `POST /_stage` 本文 `Wait` | 注意画面に進めて予約を適用する |
| `POST /_stage` 本文 `Done` | 反映を止める |
| `POST /_phase` 本文 `RUN` | 体験中の表示にする |
| `POST /_phase` 本文 `INTRO` | 導入中の表示にする |
| `POST /_consume` | 開始時の予約消費を再現する |
| `POST /_begin` | 次の注意画面を開始する。実値を既定に戻した後で予約を適用する |
| `POST /_reboot` | 初期値と連番に戻す。設定した通信障害も解除する |
| `POST /_fault` JSON本文 | 指定したリクエストの応答を遅らせるか失敗させる |

`/_fault` の本文例:

```json
{"path":"/set","delayMs":7500,"status":503,"count":1}
```

`path` は `/set`、`/status`、`/clear`、`/asset/briefing-v1.json`。
`delayMs` は0〜15000。`status` は200、400、503。
`count` は適用する回数。`-1`で継続する。`0`で解除する。
遅延は受信処理の前に行う。ブラウザがタイムアウトしてもサーバー処理は続く。

HTMLに含まれる実際のJavaScriptを使う19件の回帰検証。全画面要求、設定の実値判定、別ページ変更、説明位置の復元条件、媒体の文末停止、設定画面の分割と軽減曲の停止を含む。古い再生通知の無視も検証する。Node標準機能のみを使う。博士動画と新台詞の音声は未制作のため、口の動きと声の同期は素材制作後に確認する。
文末は媒体の再生位置から判定する。低頻度の `timeupdate` 通知に加えて文末近辺を確認するタイマーを使う。章の画面遷移による待ち時間は台本の媒体内時刻に含めない。

| 場面 | 確認する結果 |
|---|---|
| 初回表示とタイトルのタップ | 題字を表示する。タップ後の遷移で設定が現れる |
| 日本語・英語・仏語を選ぶ | 注意と操作名が切り替わる。選択位置が動かない |
| 軽減を素早く切り替える | 選択は1つ。説明とボタンが重ならない |
| `Wait`で送信 | 実値と反映番号が一致してから反映済みになる |
| `Done / INTRO`で送信 | 反映待ち。古い実値を反映済みとしない |
| `Done / RUN`で送信して`Wait / INTRO`へ | 次回待ちから自動で反映済みになる |
| `/set`が503、または6秒を超える | 再送と編集に戻れる。選択を保つ |
| `/status`を継続503にする | 実値が「—」になる。復旧したら再確認する |
| 送信後に`/_reboot` | 古い成功と説明位置を捨て、同じ選択で設定へ戻る |
| 説明中に別ページから送信 | 媒体を止め、3言語で設定確認を案内する |
| 説明中に同じタブをリロード | 完全一致時だけ同じ文へ戻り、オートOFFで停止する |
| 反映後に`/_consume`を観測し`/_begin`へ | 次の人のタイトルへ戻る。編集中の選択は保つ |
| スタッフの予約取消 | 成功・失敗が分かる。閉じると元の場所へフォーカスが戻る |
| 設定反映後の確認画面 | 人形の背景と実値を表示して待つ。自動で博士を出さない |
| 確認画面をタップ | 博士へ切り替わり、一文目を全文表示して待つ。pollで先頭へ戻らない |
| 画面タップと前後移動 | 一文ずつ移る。章を跨ぐと資料画像も変わる |
| オートをオンとオフにする | オンの間だけ次の文へ進む。オフにすると現在の文を保持する |
| 本文のスクロールと操作ボタン | スクロールでは文を送らない。ボタン操作を画面タップとして二重に処理しない |
| 動きを減らす設定 | タイトルと章の動きを省略する。文の順序と操作は同じ |
| 最後の字幕が終わる | 装着依頼を保持する。Unityの本編を自動開始しない |
| 説明中に通信断・スタッフ表示・タブ非表示 | 位置を失わず戻れる。非表示中に説明を飛ばさない |
| 説明中に設定へ戻り再送 | 新しい設定で説明を最初から開始する |
| キーボードのみ | ラジオを矢印で選べる。隠れた画面にフォーカスが入らない |
| 横1180×820、1024×768、縦820×1180、375×812 | 3言語の注意と操作が欠けない |

代役では Unity のスレッド処理や APK 内のリソース取り込みを検証できない。
実機側の同時送信順序と注意画面を離れる瞬間の予約消費は別の検証対象。

短縮前の2026-09-12の確認では3言語とも23文を順番に表示した。
タイトルから設定への移動、手動送り、オートの開始と解除、章を跨いだ前後移動を確認した。
スタッフ情報を閉じても同じ文を保持し、次の来場者ではタイトルとオートオフへ戻る。
横1180×820と1024×768、縦820×1180、小画面375×812で描画した。
任意媒体の遅延読込と文の終端での停止は処理単位で確認した。実音声と動画は未提供。
