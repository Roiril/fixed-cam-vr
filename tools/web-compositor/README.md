# web compositor — 廻リ視 のタイムライン・オーサリング卓 + マルチカメラ監視（1 ページ統合）

ブラウザから廻リ視（FixedCam）の体験を**タイムライン（周回×ゾーン区間）でオーサリング**し、カメラを監視する 1 ページ UI。
状態の正は `show.json`（このサーバ）。Unity（Quest 実機）は long-poll で追従し、端末ローカルにキャッシュして
**PC 不在でも前回設定で起動**する（設計 [.claude/plans/2026-06-16_web-config-to-quest.md](../../.claude/plans/2026-06-16_web-config-to-quest.md)）。

2026-07-19 に**タイムライン第一級**へ再設計（旧: カメラ列の下に cue がぶら下がる構造）。cue オーサリングをカメラ列から
切り出し、区間 1 個から cue・画像加工 post・インサートショットを一括編集できるようにした
（設計 [.claude/plans/2026-07-19_webui-timeline-authoring.md](../../.claude/plans/2026-07-19_webui-timeline-authoring.md)）。

## 作業の段（上部ナビで切替・2026-07-28 再編）

**並びは依存の順序**。場所が決まらないと区間が無く、較正が無いと CG 人形が出ない。上から順に進めば
必要なものが必要な順に出てくる。段の判定基準は「**会場でカメラと部屋が目の前にある時にしかできないか**」。

| 段 | 何をするか | 中身 |
|---|---|---|
| **📍 場所** | 会場でしかできないこと | フロアマップ（🖌 塗る / 📍 位置合わせ点 / 📏 通過ライン / 🧱 部屋 / 📐 カメラ姿勢）・カメラの接続と 🎯 較正・📡 発見済み端末・🩺 疎通診断 |
| **🧪 素材** | 合成の試写室 | 種フレーム → 指示 → 生成物 → 合成の見え（素材工房） |
| **🎬 演出**（既定） | 体験を組む正面 | 周回タイムライン・**⏺ 端末内録画**・🕹 シミュレーション・カメラ別の画質・🎵 BGM・🎭 CG 人形・📦 焼き込み |
| **🚨 本番** | 走らせる | ✅ 本番前チェック → ラン状態 → 監視列 → cue 手動発火 → 端末・診断。緊急操作は**画面下端に常駐** |

**カメラ列は段によって顔が変わる**（旧: 1 部品で 6 役を全モードに常時表示）。`data-col-role` で
監視 / 画質 / 設営 の 3 役を宣言し、📍 では画質を、🎬 では設営を、🚨 では両方を出さない。
これにより「触れるように見えて触れない」画質ロック（🔒）は不要になり撤去した
— **触らせたくないものは隠す（構造）方が、触れるが無効（状態）より強い**。

旧モード名（author / atelier / live）は place / material / show / live へ改称。
旧「生成プロンプト」節（`prompts.json`）は宣言どおり撤去した（サーバ API は参照用に残置）。

## 本番運用の安全装置（2026-07-25）

ショー中に「壊れていることが見えない」「前の体験者の状態が残る」を潰すための仕掛け。

| 仕掛け | 何を防ぐか |
|---|---|
| **● LIVE は「いまバイトが来ている」**（2026-07-28） | カメラが熱落ち / Wi-Fi 断しても**最後のフレームを表示したまま「✅ 全台 LIVE 受信中」**と言い続ける事故。旧判定は `<img>` の `load`/`error` 頼みで、(a) upstream 断は `/cam` プロキシが握り潰すので `error` が飛ばず、(b) multipart の各フレームで `load` が飛ぶかはブラウザ実装依存（実測で飛ばない環境あり）だった。**プロキシが upstream から実際に読めたバイトの時刻**を `GET /cam/liveness` で返し、2.5s 途切れたら `⏸ 停止 Ns`。本番前チェックも「未受信 / 未発見」と「停止」を区別する（現場の打ち手が違う）。あわせてプロキシを `read()` → `read1()` に（64KB 溜まるまで中継がブロックしていた＝低ビットレートで遅延の原因） |
| **ヘッダの 2 灯**（サーバ ● / Unity ●） | 卓サーバ（capture-server.py）が落ちても画面が最後の絵で生き続ける事故。断なら赤帯 + 画面をトーンダウン + 最終応答からの経過秒 |
| **「人の居場所」と「画面」を分ける**（2026-07-28） | heartbeat の `cam` は**画面に映っているカメラ**であって体験者の居場所ではない。演出のカットが別カメラを映している間、卓は「ゾーン D」と表示し、**その index で区間を引いていたので「このゾーン / 次の演出」まで別区間の内容**になっていた。Unity が `zoneCam`（ショーの時計が確定した担当カメラ）を別に送り、卓は区間の照会を必ずこちらで行う。あわせて `takeId` を送り、**「画面: 自律 / 演出〈id〉が再生中 / 卓が固定 / 手動 cue」**を 1 行で常時出す（本番中に「なぜ切り替わらないのか」へ即答するための行） |
| **ラッチの列挙は 1 関数が正**（2026-07-28） | 警告バー・本番前チェック・⛑・▶ ラン開始 が**独立に**`cameraOverride` と `activeCue` の 2 つだけを見ていたため、**素材スロットの束縛（前の体験者の顔で作った動画が次の演出に出る）・端末発見 OFF・IP 自動追従 OFF・📌 手動固定**はどこからも警告されなかった。`latches()` が単一の正となり 4 箇所が同じ配列を消費する（ラッチを増やしても見落としが構造的に起きない）。⛑ が解除するのは体験を壊すもの（固定 / 演出 / スロット）だけで、意図的な設定かもしれない 📌 と発見 OFF は**警告だけ**にして外さない（外すと配信が切れる）。`lap>1` のまま次を始める状態も本番前チェックが言う |
| **ラッチ警告バー**（ヘッダ直下・両モード） | `control.cameraOverride`（カメラ固定）/ `activeCue`（演出再生中）が残ったまま次の体験者を始めること。**show.json 由来なので Unity 未接続の準備段階でも見える**。⛑ ワンクリックで両方解除 |
| **▶ ラン開始 = フルリセット** | runEpoch++ に加えて**カメラ固定解除 + 演出停止**を同時に行う（旧: runEpoch のみ） |
| **✅ 本番前チェック**（ライブ・3 秒更新） | サーバ / Quest heartbeat + 同期 / カメラ受信 / **配信元の重複**（2 ゾーンが同じ IP＝同じ映像）/ **接続先の同一性** / ラッチ / タイムライン / 参照 cue の実在・素材 / 未保存 を 1 枚に集約 |
| **接続先の同一性照合**（PC が `/info` を 10 秒毎） | DHCP のリース移動や端末側の cameraId 付け替えで、**slot が別スロットの端末を掴んだまま HTTP 200・MJPEG も流れる**（＝ LIVE 判定が通ってしまう）事故。`cameraId` / `show` を突き合わせ、不一致ならカメラ列と本番前チェックに赤で出す。**警告のみ**で映像は止めず host も書き換えない（自動追従は beacon 経由だけ）。キルスイッチ `FIXEDCAM_IDCHECK=0` |
| **緊急操作の集約** | ▶ ラン開始・🚶 ゾーン自律へ戻す・■ 画面を取り返す をライブの 1 箇所に大きく。**2026-07-28 から画面下端に常駐**（fixed）— 監視列が主役で最上段のため、旧レイアウトでは緊急操作が初期表示の 2 画面先に落ちていた |
| **■ 画面を取り返す が Take にも効く**（2026-07-28） | 旧 `■ 演出を止める` は `stopCue` しか送らず、**タイムライン自動発火の演出を止められなかった**（Take は activeCue を使わず空のまま走るので Unity 側で状態変化が起きない）。`abortTake`（`control.takeAbortEpoch` の増分）を併送して確実に畳む。once・周回は保つので体験はやり直しにならない |
| **⏺ 端末内録画の照合**（2026-07-29） | 「前の周を録って後の周で流す」（`source:"rec"`）の設定 `record` に**卓の編集面が無く**、show.json を手で書くしかなかった。書き忘れても卓は何も言わず、**実機だけがそのカットを黙って飛ばす**（気づけるのは実機のログだけ）。⏺ パネル（ON/OFF・録る周・上限）を足し、「録画」カットが指す (周, カメラ) を録る設定かどうかを **⏺ パネル / 本番前チェック / カットの警告 / ▶ 検証**の 4 面で照合する。判定は [`record-model.js`](record-model.js) が単一の正（ラッチの `latches()` と同じ流儀）。⟲ ワンクリックで足りない周を録る対象に足せる |
| **ライブ中の画質ロック 🔒** | 本番中に画質スライダへ触れて体験者の見え方が変わる事故（ライブモードで既定 ON・🔓 で一時解除） |
| **未保存の可視化 + ガード** | ヘッダの `● 未保存` バッジ（ライブでも見える）/ タブを閉じる前の確認 / **未保存のまま 📦 エクスポートを実行させない** |
| **⟲ 元に戻す（Ctrl+Z）** | タイムラインの直前編集を 1 手戻す（30 手）。`－ 周回` は区間が残っている時だけ確認ダイアログ |
| **show.json の 1 世代バックアップ** | 保存のたびに `show.json.bak` を残し、tmp → `os.replace` で書く（書き込み中の電源断でも壊れない）。復旧は .bak をリネームしてサーバ再起動 |
| **📦 エクスポート結果に焼き込み先を表示** | 「いつ・rev いくつ・どの IP で焼いたか」+ 参照先が無い cue の警告（現地 DHCP の IP が APK に verbatim で入るため） |

## タイムライン・モードの画面構成

```
タイムライン … 周回（行）× ゾーン区間（course.order 順に横連結）。区間クリックで下にインスペクタ
  ▶ 検証     … 🕹 ショーシミュレーションへ移動（歩きで実時間検証。矢印キーの簡易シミュレーションは 2026-07-25 に廃止）
  区間インスペクタ（クリックで展開）
    ・演出の開始規則 … 進入 +t 秒 / 離脱時 / 📏 このラインを通過したら（フロアマップの線 + 通らなかった時の扱い）
    ・cue（進入 + 遅延で発火・複数可）… 既存 cue 割当 or ＋新規 cue 作成（素材 + マスク + フェード + trim）
                                        + 遅延秒 / 1 回のみ / 強度・フェード・trim の区間上書き
    ・🎨 このゾーンの画像加工 post 上書き … 9 スライダ（segment > camera > global の 3 段解決）
    ・⏢ インサートショット … 別カメラを N 秒差し込む（退出時 / 進入時・カメラ・秒・cue・1 回・insert 中 post）
    ・🎵 BGM … この区間で「▶ 曲を切り替える / ■ 止める / ― そのまま」。ループ範囲 in-out・音量・
               フェード・頭出し。試聴しながら「ここを in / ここを out」で範囲を取れる
  🎵 BGM 帯（区間セルの下）… その区間で鳴っている曲を carry-forward で表示。▶=切替 / ≡=同じ曲のまま調整 / ■=停止
BGM ライブラリ … audio/ の音源をトラック登録（ループ範囲・音量・試聴）+ ラン既定 BGM の選択
フロアマップ … マップ直上の 5 択（🖌 塗る / 📍 位置合わせ点 / 🚶 歩かせる / 📐 カメラ姿勢 / 📏 通過ライン）で操作が切り替わる
               担当カメラをタイル塗り + 周回コース（スタート/CW-CCW）+ 位置合わせ点 + 歩かせる
               + カメラ姿勢（CG 人形の視点）+ 📏 通過ライン（演出の発火点となる床の線分 = layout.lines）
               ※ ラインは**担当カメラに紐づく**（その区間の演出からだけ選べる）。一覧に担当・通過方向・
                 線が置かれているゾーン・使用中の演出数が出る
🕹 ショーシミュレーション … フロアマップの右隣。マップを 🚶 歩かせる にしてドラッグ = 体験者の歩き。ショーが実時間で進む（下記）
エクスポート … 📦 ビルド用エクスポート（show.json + 参照アセットを StreamingAssets/show/ へ焼き込み）
生成プロンプト … 画像/動画 AI 生成プロンプトを 📋コピー / 編集 / 削除（prompts.json）
マルチカメラ（常時・監視専用。列 = カメラ A / B / C。ライブ時はアクティブ列を大きく表示）
  ④ メタクエスト実映像 … 画質を当てた最終見た目（Quest と同じ絵）+ 📷1枚 / ⏺録画。ヘッダに 📺切替
  ③ 画像加工           … カメラ別 画質 9 スライダ（カメラ単位グレーディング。cue 編集は撤去 → タイムラインへ移設）
                         ↺ 画質を初期化 ／ ⇥ 他カメラにも適用（1 台で追い込んだ値を残り 2 台へ配る）
  ① 生リアルタイム映像 … 生 MJPEG + 📷1枚 / ⏺録画 / 配信元 IP・port・認証
```

- **🎥 全体グレーディング**（カメラ列の上・2026-07-26 追加）… `show.json` トップレベル `post`。
  **カメラ個別 post を持たない列は全部これ**＝列の「↺ 画質を初期化」の戻り先であり、起動時の見た目。
  ここを触る面が無かったので、既定の絵を現場で直せなかった。
  - **🎥 監視カメラ既定へ** = 出荷値（`common.js` の `FX_CCTV`）に戻す:
    露出 -0.72 / コントラスト 1.28 / 彩度 0.35 / 色温度 -0.18 / 色かぶり +0.16 / 黒浮き 0.065 /
    ヴィネット 0.45 / グレイン 0.065 / 走査線 0.20。**現場が明るくて見えない時に動かすのは露出だけでよい**
  - **◻ 加工なし** = 素の映像（数式の恒等元 `FX_DEFAULT`）
  - 同じ値を `capture-server.py` の新規 show.json 既定と Unity `ScreenMjpeg.mat` にも入れてある
    （卓が無い初回起動でも同じ絵で立ち上がる）
- **画質は 9 項目**（2026-07-26 に 2 つ追加）。追加分は監視カメラらしさに要る 2 軸:
  **色かぶり（tint）** = 緑↔マゼンタ（色温度と直交。蛍光灯 + 安物 CMOS の緑寄り）／
  **黒浮き（lift）** = コントラストの後に黒の床を上げる（締まらない黒。これが無いと暗部が真っ黒に潰れるだけ）。
  既定 0 なので旧データの見た目は変わらない
- カメラ列は**監視専用に格下げ**（生映像・Quest 実映像・接続・録画・カメラ単位 post）。**cue 作成はタイムラインの区間インスペクタ**で行う
- ライブ手動 cue 発火（演出 ON/OFF → `control.activeCue`）は**ライブ・モード**へ移設
- **① 生映像の 📷/⏺** … 生フレーム（`camA_…`）／ **④ 実映像の 📷/⏺** … Quest と同じ絵（`camA_quest_…`）。ビデオデモ用
- 合成済み静止画を撮るため WebGL は `preserveDrawingBuffer: true`（[gl.js](gl.js)）
- **合成ビューは画面に出ている時だけ描く**（[composite-view.js](composite-view.js)。モードで隠れている面・
  スクロール外は停止）。1 ページに合成ビューが 6 面以上あるので、全部を常時 25fps で回すと GPU が詰まって
  ページ全体が固まる。**録画中だけは画面外でも回し続ける**（`setForced`。止めるとコマが凍るため）

### 演出・カットのリボン編集（オーサリング面はこれ 1 つ）

2026-07-25 に**演出・カット（`schema:3`）へ一本化**した。旧グリッド（cue 割当・インサートショット）は削除。

- show.json が古い形式でも、読み込み時に演出・カットへ変換して表示する（バッジ「古い形式 → 保存で更新」）。
  **💾 保存で `schema:3` / `takes[]` として書き出される**
- **保存しなくても実機の動きは同じ**。Unity も読み込み時に同じ変換（`TimelineMigration`）をしてから
  `TakeRunner` で実行するので、古い形式のまま置いておいても新形式で保存しても挙動は変わらない
- 実装ごと戻したいときは一本化コミットを `git revert` する（データを戻すだけでは戻らない）

```
1周目  ┃▨ A ▨▨▨┃🎬 演出 6s┃▨ B ▨▨┃🎬 離脱時 4s┃▨ C ▨▨┃
        区間 = 斜線（伸縮＝体験者が決める時間）   演出 = 尺に比例した固定幅（こちらが決める時間）
```

- **開始位置**は 2 種のスナップだけ: 区間の中 = `進入 +t 秒` ／ 区間の右境界へ吸着 = `離脱時`。
  操作は**ドラッグ（マウス / 指）**か、演出ヘッダを選んで **← →（Shift で 2s）・Home（進入直後）・End（離脱時）**
- **区間フッタに実測の平均滞在時間**（`実測 平均 8s（最短 6.5s / 2 回）`）。実機の heartbeat 由来で、
  開始位置がそれを超える演出には ⏱ 警告が出る（`ifMissed` があるので出ないわけではないが、
  「山場が意図した所で出ない」ことに作者が気づける唯一の材料）。⟲ 実測クリアで集計をリセット
- **カットの尺**「素材の終わりまで」は**素材の実尺をブラウザで測って**表示する（測れない時だけ `≈` 推定）
- **素材の導線**: カット行の `↻`（撮った素材を読み直す）／`📂`（recordings/ を開く）。
  「⏺ 全カメラ録画(Quest)」で合成後の絵をそのまま録れるので、**録画 → ↻ → カットの素材に選ぶ**で繋がる
- **素材リストは 2 群**（2026-07-26）: 実素材（`captures/` `recordings/`）が先、
  末尾の optgroup **「動作確認用（testassets）」**が `testassets/` のダミー（「演出 A」等の文字だけ）。
  旧環境で撮って使えなくなった素材は `archive/` へ退避してあり**一覧に出ない**
- BGM（区間で切替・停止・ループ範囲）は v3 でも区間の属性。**試聴 + 「ここを in / out」も使える**
- **演出（インサート含む）にも BGM を持てる**（2026-07-26）。演出インスペクタに
  「🎵 この演出のあいだ: ◯◯」を常時表示 —— 何も設定しなければ**その区間の曲のまま**で、そう書いてある。
  変えた演出だけリボンのチップに `♪ 曲名` / `🔇` が出る。演出が終わると**いる区間の曲**へ中断位置から戻る
  （演出中に次のゾーンへ入っていれば、その区間の曲へ）

**画面の作法（2026-07-25 のデザイン修正で確定）**:

- **区間は「中身の幅」で置く**（画面いっぱいに伸ばさない）。伸ばすと空区間が広く見え、
  行末の「離脱時の演出」が画面外へ押し出されて読めなくなる
- **演出ヘッダは 2 段**（1 段目 = 名前 ／ 2 段目 = 開始位置と尺）。1 段だと最小幅で名前が潰れる
- **カットの最小幅は 110px**。ラベルは短く（`ライブ C` / `映像 01.mp4`）、詳細はツールチップ
- 各セクションの長い説明（`.hint`）は既定で 2 行に畳み、**▾ 説明** で全文（開閉は端末に記憶）

## 🧪 素材工房（カメラ別・合成の試写室・2026-07-26）

固定カメラ映像から切り出した 1 枚を種に、演出を足した動画（image-to-video）を作るための面。
旧「生成プロンプト」（`prompts.json`）はプロンプト本文しか持たず、**それを使って何が出たのかが分からない**ので
実質使えなかった。そこで**保存する単位を「プロンプト」から「生成」へ変えた**。

```
レシピ（場所に依存しない骨格・{{スロット}} を持つ）
   × 束縛値（そのカメラでの具体値）
   × 種フレーム（recordings/ の camX_*.jpg）
   = 生成 1 件（全文プロンプト・出力・採否・メモを丸ごと保持）
```

**この面の中心は記録ではなく合成の見え**（設計 [.claude/plans/2026-07-26_material-atelier.md](../../.claude/plans/2026-07-26_material-atelier.md)）。
素材の良し悪しは「動画単体の出来」ではなく**その構図の live に載せた時に破綻しないか**でしか決まらないので、
試写を出したまま作る。**列 = カメラ**で、1 列の中を上から **① 試写 → ② 種フレーム → ③ 指示 → ④ 生成物** と流す
（上ほど作業中よく見るもの。作業順ではなく重要度順）。

- **① 試写** … `composite-view.js`（= Unity ScreenComposite の再現）。背景は **種フレーム / ライブ**、
  マスクは **全面 / 動くところだけ**、画質は **本番（カメラ post 込み）/ 素の色** を切り替えられる。
  - 「動くところだけ」= 種フレームと素材の**差分の累積**。固定カメラ i2v は背景が入力画像と同一なので、
    差分がそのまま「足されたもの」になる。Quest 側は静的マスク PNG を使うので**瞬間差分ではなく累積**を取る
    （再生が進むほど収束する。`↺` で取り直し、閾値スライダで感度調整）
  - 「素の色」は判断用の逃げ道。ホラー用のグレーディング（露出 −1.4 等）だと素材そのものが見えないため
  - **💾 カットの素材にする** で `cue_<camId>_<n>` を作る（差分マスクは PNG に焼いて `masks/` へ）。
    そのままタイムラインの演出で選べる＝工房が行き止まりにならない
- **② 種フレーム** … **📷 いま撮る**は監視列の生映像から 1 枚切り出して `recordings/` に保存し、
  **リロードも面の往復もなしに**候補の先頭へ入る（監視列の 📷 で撮ったものも同様に届く）
- **④ 生成物** … カードのサムネを**クリックすると試写に載る**。棚には `captures/` の**未記録ファイル**も出るので、
  「先に作ってから記録する」順序でも扱える（棚へ直接ドロップすると素材だけ先に入る）
- **素材は構図に属する**。カメラ A のフレームから作った動画は A のカットでしか使えないので、UI もデータもカメラで分ける
- **レシピ側に `2/5 採用` が出る**ので、「どのレシピが当たるか」が貯まる
- **生成は外部ツール**（Dreamina 等）で行う。📋 でプロンプトをコピーすると同時に**送信待ちのレコード**ができ、
  できた動画をカードへドロップすると `captures/gen_camB_standing_20260726_1432.mp4` の規約名で入る
  （ファイル名だけで由来が読める。`01.mp4` のような名無しを作らない）
- **`atelier-index.md` が保存のたびに自動生成される**。カメラ別に「入力・レシピ・束縛値・条件・全文プロンプト・
  採否」が並ぶので、**このファイル 1 つ読めば素材の全体が分かる**（人間にも、次セッションのシュビーにも）
- `atelier.json` が正。`atelier-index.md` はその読み物版で、手で編集しない
- **⚠ 固定カメラ i2v の要点**（レシピの骨格に入れてある）:
  マスク合成が前提なので「人影を足す」より「**部屋を 1 ピクセルも変えるな**」を強く書く。
  暗さ・粒・走査線は生成側でやらず、Unity の post（区間ごとに上書き可）でかける。
  そうしないとライブ映像と色が合わず合成が破綻する

**ストアは `.gitignore` の例外で追跡する**（`scenarios/` と同じ判断）。IP も認証情報もバイナリも含まず、
プロンプトと採否だけの小さな JSON なので、機材が変わっても残す価値がある。

| メソッド | パス | 用途 |
|---|---|---|
| GET | `/atelier` | レシピ + 生成の全体（採用率はサーバで数え直す） |
| GET | `/atelier/frames` | `recordings/` の静止画をカメラ別に束ねたもの（i2v の 1 枚目候補） |
| POST | `/atelier/recipe` / `/atelier/recipe/delete` | レシピの upsert / 削除 |
| POST | `/atelier/gen` / `/atelier/gen/delete` | 生成レコードの upsert（部分更新）/ 削除 |
| POST | `/atelier/attach?id=&ext=` | 生成物のバイナリを `captures/` へ規約名で保存し、レコードへ結びつける |

## 🎵 BGM オーサリング（2026-07-25）

従来の BGM は「[Bgm] の AudioSource が 1 曲を起動中ずっとループ」だけだった。これを
**タイムラインの区間（周回×ゾーン）で切り替え・停止・ループ範囲指定できる**ようにした。

1. `tools/web-compositor/audio/` に音源（mp3 / ogg / wav / m4a）を置く
2. 「🎵 BGM ライブラリ」で **＋ トラックに登録** → 表示名・ループ in/out・音量を設定（🔊 試聴しながら
   「ここを in / ここを out」で範囲を取れる）
3. タイムラインの区間をクリック → **🎵 このゾーンで BGM を切り替える / 止める** で指示を書く
4. **ラン既定 BGM** = 体験開始時に鳴っている曲（未設定なら APK 同梱の既定クリップ = 従来の曲）
5. 📦 エクスポートで音源も `sa://assets/` へ焼き込まれる（現地 PC 不在でも鳴る）

セマンティクス（動画編集のオーディオトラックと同じ感覚）:

- **指示の無い区間では曲が途切れず続く**（区間ごとに鳴り直さない）
- **同じトラックを指す区間は再生位置を保ったままループ範囲・音量だけ更新**（`retune`）。
  「同じ曲のまま 2 周目だけループ範囲を狭める」が書ける
- **別トラックはクロスフェード**、**停止はフェードアウト**
- ラン開始（▶ ラン開始 / 右グリップ長押し）で**ラン既定 BGM へ戻る**
- 区間の値 `-1` は「トラック既定を継承」

> **⚠ Unity 側は `Tools/FixedCamVr/Setup/Setup Main Demo Scene` を 1 回再実行**して [Bgm] を
> BgmDirector 化する必要がある（旧 AudioSource だけのシーンでは BGM 指示が無視され、従来の
> 固定ループがそのまま鳴り続ける＝安全側に縮退）。

| POST | `/command` | `playCue` / `stopCue` / `setCameraOverride` / `setPost` |

| GET | `/cam?host=&port=&path=&auth=` | MJPEG プロキシ（Basic 認証肩代わり。別ポート 8100 で listen） |

## 既知の制約

- ビューはカメラ実寸比に追従（黒帯を出さない）。
- cue は `cues[]`（トップレベル・カメラ帰属は文字列 id）。1 カメラ複数 cue（id = `cue_<camId>_<n>`）。**タイムライン区間のインスペクタで割当 or その場で新規作成**。素材未選択で保存 or 未保存割当は警告。
- **周×カメラ区間ごとに** cue パラメータ上書き・画像加工 post 上書き・インサートショットを持てる（`timeline.segments[]`。詳細 [rules/streaming.md](../../.claude/rules/streaming.md) の「タイムライン第一級オーサリング」）。
- **境界ブレンド（色統計/ラプラシアン）は Web プレビュー専用**。Quest 実機は ScreenComposite のハード合成（フェザーだけは cue 保存時に PNG へ焼き込まれ Quest にも効く）。
- 動画 cue は Quest 側が UnityWebRequest でローカル DL してから再生する（Android ネイティブの HTTP ストリーミング相性問題回避。詳細 [TROUBLESHOOTING / rules/streaming.md](../../.claude/rules/streaming.md)）。
- フロアマップの ◇ HMD 位置は heartbeat の `headCourseX` / `headCourseZ` / `currentZone` を読む（**2026-07-25 修正**。旧実装は `hmdX` / `hmdZ` / `zoneLabel` という存在しないキーを見ていたため、Unity が繋がっていても ◇ が一度も出なかった）。
- 合成素材は既存 `captures/` から選ぶ（📷 でその場保存も可）。AI 生成素材は外部で用意して `captures/` に置く。スペース入りファイル名も URL エンコードで対応。
