# タイムラインをコードから組む（authoring/）

卓（ブラウザ）でクリックして作る演出データを、**node から組み立て・検証・書き込み**するための道具立て。
`mawarimi-show.mjs` が体験の設計そのもの（企画書 [docs/proposal/](../../../docs/proposal/) の構成を形にしたもの）で、
残りはそれを検証して卓へ流し込む配管。

卓の UI と競合しない。書き込みは卓と同じ `POST /state` を通るので、ブラウザを開いていれば即座に反映される。

## 使い方

```bash
node authoring/apply.mjs                 # 組み立てて検証だけ（書き込まない）
node authoring/apply.mjs --dwell 4       # 速く歩く人（1 区間 4 秒）で検証する
node authoring/apply.mjs --apply         # 退避コピーを取ってから卓へ書き込む
SHOW_API=http://127.0.0.1:8299 node authoring/apply.mjs --apply   # 卓のポートを変える（既定 8099）
```

出るもの: ①組み立てたタイムラインの全文（読める形）②実機で黙って落ちる条件の検査
③3 周歩かせたときの発火トレース ④演出ごとに出たか出なかったかの表。

| ファイル | 役割 |
|---|---|
| `mawarimi-show.mjs` | **体験の設計**。企画書の 3 周構成を演出・カットに落としたもの。直すならここ |
| `apply.mjs` | 組み立て → 検証 → 書き込みの入口（CLI） |
| `verify.mjs` | **いま卓に入っている現物**を読んで同じ検査をかける（卓でクリックして直したあとにも使える） |
| `check.mjs` | 実機が**黙って飛ばす**条件の検査（素材が無い / 録っていない / 姿勢が無い / ラインの担当違い …） |
| `sim.mjs` | 卓の ▶ 検証と同じ純ロジック（`scenario-engine.js`）で歩かせてトレースを出す |
| `walk.mjs` | 「外周を 3 周する歩き」を決定的に作る（毎回同じ条件で比較するため） |
| `show-api.mjs` | 卓の HTTP API（`/state` `/command` `/dwell/stats`）の薄いクライアント + 退避コピー |

**書き込みは必ず卓サーバ経由**。`show.json` を直に書くと、動いているサーバのメモリ上の状態に上書きされて消える。
`show.json` は git 管理外・サーバの `.bak` は 1 世代しか無いので、`--apply` は毎回
`G:\マイドライブ\shubie\fixed-cam-vr-backups\` へ日付つきの退避を取ってから書く（`SHOW_BACKUP_DIR` で変えられる）。

## 体験の設計（企画書との対応）

区間は `layout.course.order` の 3 つ（カメラ A / B / C）。周は 1〜3。**導入を含め 3 分以内 / 各周およそ 30 秒**
＝ 1 区間およそ 10 秒（立ち止まり 7.5 秒 + 移動 2.5 秒）で組んである。

| 企画書 | ここでの形 |
|---|---|
| 導入：区間 1 を歩いて固定視点に慣れる | `run.introEnabled` / `introMinSec: 20` / スタート区間に居れば自動で本編へ。導入中は演出も録画も走らない |
| 1 周目：差し替えなし + 行動を録画 | `record.laps: [1]`。演出は手形 1 本だけ |
| 1 周目：死角の壁が血の手形で覆われていたことに、視点が切り替わった瞬間に気づく | **1 周目 / カメラ B・進入 +0 秒**（＝カメラが切り替わる暗転に相乗り）。`inherit` に手形を `cut` で重ね、5 秒後に瞬時に消す |
| 2 周目：人形 → 怪物。歩行や切替に同期させ、前後に乱れ | **2 周目 / カメラ A・通過ライン「2週目初化け物」**。乱れ → カーテンの隙間の人影だけをマスクで差し替え（2.6s）→ 乱れ → 実写。演出のあいだだけ無音 |
| 2 周目：怪物が接近し襲いかかる | **2 周目 / カメラ C・進入 +3.5 秒**。乱れ → 画面いっぱいの全面差し替え 1.6 秒 → 乱れ → 実写（速く歩いた人には出さない） |
| 3 周目：1 周目の録画を背景に、操作できる CG 人形を重ねる | **3 周目の 3 区間すべて**。`rec`（1 周目・同じカメラ）6 秒 + `cg: doll` / `follow`、乱れで入って乱れで戻る。3 周目は無音・画像加工を記録映像寄りに上書き |
| 3 周目：最後の反転 | 最終区間（カメラ C）の演出の最後から 2 番目のカットに、床に立つ日本人形の 1 枚を 2.4 秒 |
| 乱れは継ぎ目の隠蔽にも使う | `control.switchGlitch: 0.25`（ゾーンが切り替わる継ぎ目に薄く重ねる。2 周目だけが乱れると乱れ自体が合図になるため） |
| 全体は 3 分以内 | 3 周で約 1 分 30 秒（検証トレース実測）+ 導入 20 秒 ≒ **1 分 50 秒** |

### 設計で意識的に決めたこと

- **2 周目は「居る」と「来る」の 2 拍だけ**。マスクを使う差し替え（人形が居る）は台車を確実に置ける区間でしか
  成立しないので A の 1 箇所に絞り、襲いかかりは全面差し替え（マスク不要）なので C に置いた。
- **3 周目の録画カットは秒指定**（6 秒）。「素材の終わりまで」にすると尺が体験者の滞在に従属し、
  「各周およそ 30 秒」を守れないうえ、遅れが累積して最後の区間の演出が消える。
- **3 周目の 2・3 区間目は `wait: "chain"`**。前の演出が終わるまで待てるようにする（速く歩く人への保険）。
- **締めを「離脱時」に置かない**。離脱の瞬間に画面が塞がっていると出ないため、最後の演出のカット列に入れる。
- **1 周目の手形は、本来は物理（壁に実物）が正しい**。企画書の「差し替え演出は行わず」と一致し、
  2・3 周目でも壁に残る。ここで組んであるのは会場を汚せない時の代替であり、いま検証できる唯一の形でもある。

## まだ埋まっていないもの（現場でやること）

1. **カメラ A / B / C の較正**。CG 人形は姿勢か較正が無いと実機で出ない。いまは**ゾーンの塗りから起こした
   概算の姿勢**が入っているだけなので、現地で卓の［🎯 姿勢を合わせる］をやり直すこと。
2. **素材は 2026-07-29 に現地の生映像から作った実素材**（`captures/gen_*.png`）。種フレームは同日 18:51 の
   `camcam[ABC]_*.jpg`、マスクは種との差分（`make-diff-mask.py`）。作り直すときは卓の
   **🧪 素材 → 🪄 Codex に生成させる**か、同じ CLI（`~/.claude/scripts/codex-run.ps1 -Mode image`）で。
   - 1周目の手形 = `gen_handB_01.png`（左のパーテーション面だけを ROI で切ったマスク）
   - 2周目の人影 = `gen_monsterA_01.png`（カーテンの隙間の人影だけのマスク）
   - 2周目の襲いかかり = `gen_closeC_01.png`（全面差し替え・マスク無し）
   - 締め = `gen_camC_doll_*.png`（卓の 🪄 経由で生成。床に置かれた日本人形そのもの）
   - **動く素材（i2v）はまだ無い**。Codex は静止画しか出せないので、動きが要る演出は外部ツールで作る
3. **色統計マッチング**は卓の［境界ブレンド］で cue に焼く（実映像が要るので現地でしかできない）。
4. **実測滞在**（`GET /dwell/stats`）を取ってから、演出の開始位置と尺を実測で詰める。
   いまの 7.5 秒は企画書の「各周およそ 30 秒」からの逆算にすぎない。
5. **実機未検証**。ここで通っているのは「この歩き方をしたら何が起きるか」だけで、
   VR のスケール感・dip の体感・MJPEG の遅延・位置合わせ・Quest の性能は分からない。
