廻リ視 — 電源を入れるところからの設営

会場は研究室ではなく、Wi-Fi も別。ルータを持って行くので、機材どうしのつながりは会場が変わっても同じように戻る。 会場側の Wi-Fi は体験に一切使わない。

会場の Wi-Fi に、配信スマホと Quest を繋がない 繋いだ瞬間にその端末が別のネットワークへ移り、映像が止まる。しかも画面には何も出ない。使うのは Aterm が出す kougaku-lab-exp-a だけ。
電源を入れ直した Android は、この網へ自動で戻らない ルータに上流が無いので、Android が「使えない網」と判断して自動接続を恒久的に切る。 繋がっている間は何も起きず、次に電源を入れた時だけ戻らない — つまり展示の朝に全機が同時に踏む。 Quest 2 台でも配信スマホ 3 台でも起きる。直すのは端末の Wi-Fi 設定で 1 度手で選び直すことだけ。
位置合わせは 2 台とも取り直す 部屋が変わるので、端末に残っている登録は使えない。登録は機ごとの物理的な事実なので、片方からコピーもできない。
当日はビルドしない APK は 9/4 22:52 のものが 2 台に入っている。当日焼くと端末の設定キャッシュが捨てられ、取り直しから始まることになる。

0持って行く

出る前に。ひとつでも欠けると当日どうにもならないものだけ。

  1. Aterm（ルータ）本体と AC アダプタ、LAN ケーブル 1 本
    これが体験のネットワークそのもの。会場の設備は使わない。
  2. PC と AC。電源タップ（口数は機材ぶん）
  3. Quest 2 台と充電ケーブル。配信スマホ 3 台と充電ケーブル、固定具
  4. USB ケーブル（配信スマホを PC へ繋ぐ用）
    工程 3 の無線 adb を開けるのに要る。これが無いと、当日カメラが落ちても遠隔で直せない。
  5. 白衣（体験者ぶん ＋ スタンドイン 1 着）、人形、養生テープ
目の写真は要らなくなった。9/4 に取りやめたので、人形の目線で写真を撮る仕事は消えている。

1電源を入れる

順番が決まっている。飛ばすと次が確かめられない。

  1. Aterm を先に立てる。背面スイッチが RT であることを見てから電源を入れる
    BR（ブリッジ）だと DHCP が動かず、誰も IP を取れない。
  2. 2.4GHz と 5GHz のランプが両方点くまで待つ。点いてから他の機材を繋ぐ
  3. PC の電源を入れて、サインインする
    サインインすると卓（オペレータ卓サーバ）が自動で立つ。サインイン画面で止めない — 自動ログオンは切ってあるので、そこで止まると卓は立たない。
  4. LAN ケーブルで PC と Aterm を繋ぐ。挿すのは LAN ポート（WAN ではない）
    PC 側の設定は何も要らない。ルータが有線の MAC を見て 192.168.10.10 を渡す。
  5. 配信スマホ 3 台の電源を入れ、配信アプリを起動する。画面に出る A / B / C が割当と合っているか見る
  6. Quest 2 台の電源を入れる
  7. Wi-Fi に戻っていない機を、端末の設定で手で選び直す
    どの機が戻っていないかは py -3.11 tools/onsite.py wifi-guard で出る。 配信スマホは画面に IP が出るので、192.168.10.2x になっているかを見る。
ここが今回いちばん危ない。ルータに上流が無いので、Android は NETWORK_SELECTION_DISABLED_NO_INTERNET_PERMANENT でこの網の自動接続を切る。 切られたことは、繋がっているうちは一切表に出ない。9/5 の実測では Quest 2 台とも既に切られていて、再起動したら 2 台とも戻らなかった。
解き方は端末の Wi-Fi 設定で 1 度手で選び直すことだけ（手で選ぶと解ける。adb からは戻せない）。 予防は入れてある（接続チェックを切ってある）ので、一度解けば以後は付かない。
Aterm はインターネットに繋がっていない。WAN 側には何も挿さなくてよい。体験は全部この中で閉じている。 外の回線が要るのはシュビー（Claude）に頼むときだけで、そちらは会場の Wi-Fi かスマホのテザリングを PC が別に掴む。 外が無くても体験は動く。

2つながりを確かめる

PC で 1 行。ここが通らないうちは先へ進まない。

py -3.11 tools/onsite.py check

結果は行ごとに「何が」「どう直すか」まで出る。スマホから見るなら、卓が立った後に当日パネルを開いて「点検する」を押す。

http://192.168.10.10:8099/onsite.html
ここで必ず見るもの。PC が 192.168.10.10 を持っているか。カメラ 3 台から実際にバイトが流れたか。 端末が名乗る A / B / C が割当と合っているか。名乗りがずれていると、演出が別のカメラに出る。

3無線 adb を開ける

配信スマホを USB で PC に挿して 1 回。設営のたびに要る。

py -3.11 tools/onsite.py adb-open
端末を再起動すると閉じる。閉じていると、当日そのカメラが黒くなっても遠隔で一手も打てない （画面を起こすのもアプリを起こし直すのも、この経路を通る）。いまは 3 台とも閉じている。

4据え付けと較正

カメラを置いて、向きを決めて、色を止める。

  1. カメラ A / B / C を据え付ける（レンズは超広角のまま。較正が 104.3° を前提にしている）
  2. 較正を取り直す。とくに カメラ C
    いま C は、端末の傾きと保存してある較正が 51° ずれている。前に動かして取り直していない。このままだと CG 人形が C の映像で盛大にずれる。
  3. 照明を本番の状態にしてから、3 台とも端末の 🔓 露出/AF ロックを押す
    押さないと露出が自動で動き、素材を撮った時と本番で色が変わる。照明を変えたら押し直す。
  4. Quest 2 台で位置合わせを取る（右トリガー 2 秒長押しから登録）
    部屋が変わったので、両方とも必須。片方で取った登録は、もう片方では使えない。

5当日の素材を撮る

人形を置いた後。10 分・2 人。

  1. スタンドインに白衣を着せる（体験者にも被せる前に着せる。「調査員の制服です」で通す）
  2. 人形視点を 5 本撮る。手順は撮る人が持つスマホの「🎬 撮影」が 1 ショットずつ誘導する
    高さ 40cm 固定。毎カット C の立ち位置へ正対する。録画ボタンを押した直後から本番なので、いちばん見せたい状態から撮り始める。
撮る前に配信スマホの充電ケーブルを抜いて冷ます。熱を持った端末で撮った素材は、本番の画と粗さが揃わない。 配信を止めるだけでは下がらない（実測で 8 分に 0.5℃）。

6開場前の点検

Quest を本番と同じ台数だけ起動してから。

py -3.11 tools/onsite.py check --deep

--deep は 20 秒かけて実機の報告を集める。これを付けないと、音・コントローラの行が出ない。どちらも画にも録画にも出ないので、ここでしか分からない。

NG が 0 になるまで開場しない。warn は読んで判断してよい。

7会期中

走らせっぱなしにする。

py -3.11 tools/onsite.py watch

20 秒ごとに全カメラから実際にバイトを引き、出ていなければ自分で起こし直す。卓が落ちていれば立て直す。記録は logs/onsite/ に残る。

体験者 1 人につき人がやることは 5 つ。これ以上は増やさない。

  1. 白衣を着せる
  2. 左コントローラを渡して、口で説明する
  3. ヘッドセットを被せる
  4. 右 A — タイトルを閉じて始める
  5. 終わったら 右グリップ 2 秒長押し — 次の体験者へ
④⑤ は卓の ▶ でも代われるが、現地の手だけで回る。卓が落ちても体験は止まらない。

8困ったとき

症状から原因へ飛ばない。まず点検で「どの台か」を決める。

1 台だけ黒い / 砂嵐
当日パネルの「配信端末を起こし直す」。画面が消えた端末とアプリが落ちた端末に効く。
3 台が同時に、周期的に途切れる
Quest の設定パネルが生きている。当日パネルの「Quest の設定パネルを閉じる」。
卓では映るのに Quest だけ映らない
端末の設定キャッシュが古い。onsite.py fix cache のあと Quest を再起動。
急に全台が繋がらない
別の AP へ移っていないか。Wi-Fi を入れ直さない — 入れ直すと保存済みの別のネットワークが選ばれ、事態が悪化する。
映像が数十秒おきに全部止まる
5GHz のチャネルが DFS 帯に落ちている。Aterm の設定で W52 に固定する。
卓（PC の画面）が落ちた
py -3.11 tools/onsite.py serve。⚠ 2 つ立てない。2 つあると互いの設定を巻き戻し合う。
シュビーに繋がらない
会場の回線の問題。体験には関係ない。当日パネルで回す。

  2. Aterm の電源を落とす前に、卓を止めなくてよい（勝手に落ちる）
  3. 次の日も同じ会場なら、機材の設定はそのままでよい。電源を落として、翌朝は工程 1 から
    ⚠ 端末を再起動すると無線 adb は閉じるので、工程 3 をもう一度。
