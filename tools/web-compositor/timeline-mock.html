1. 3 層モデル — 「①体験者の切替」と「②演出の切替」の両立

両立させるのではなく、同じ仕組みの既定値と上書きにする。体験者の位置が決めるのは「ショーの時計（何周目のどの区間か）」だけで、 画面に何を映すかは常にオーサリングの結果。既定の割当がたまたま「その区間のカメラのライブ」なだけ。

体験者が決める

人の層

  1. HMD 位置
  2. ゾーン判定（重なり / ヒステリシス）
  3. dwell（一瞬の通過を捨てる）
  4. 確定ゾーン進行
オーサリングが決める

ショーの層

  1. 周回・区間 = ショーの時計
  2. 区間に付いた演出を解決
  3. 映すべき Shot の要求
見せ方が決める

画面の層

  1. 優先度調停 卓 > 演出 > 既定
  2. 最小ショット長・dip / フェード
  3. registry / overlay / post

流れは一方向。画面が凍っていても時計は止まらない（＝周回が壊れない）。演出は必ず有界で、終わったら「元のカメラ」ではなく「いま体験者がいるゾーン」を映す。

2. リボン — 1 周 = 横 1 本

区間は伸縮（尺は体験者が決める・斜線ハッチ）、演出は秒に比例した固定幅。この対比がそのまま「①の時間 / ②の時間」の違いになる。 クリックすると下に中身が出ます。

区間（伸縮・体験者が決める尺） 演出（固定・秒で決まる尺） ⏵ 位置＝開始規則（進入から t 秒 / 離脱の瞬間）
クリックして選択
区間 or 演出を選ぶとここに中身が出ます。

3. 同じ内容を、今の UI / 新しい UI で書くと

今（区間の属性としてのインサート）

・cue と insert が別概念で別 UI
・区間 1 つに insert は 1 本だけ（hasInsert 単数）
・anchor: enter / exit という抽象を人間が覚える必要がある
・多段（D→映像①→録画B→録画C）は書けない

{ "lap":3, "camera":1,
  "cues":[ {"cueId":"cue_B_1","delaySec":20} ],
  "hasInsert": true,
  "insert": { "anchor":"enter", "camera":3,
              "delaySec":20, "durationSec":4 } }

新（タイムライン上の要素としての演出）

・cue と insert が「カット」1 語彙に畳まれる
・区間に演出を何本でも、順番どおりに置ける
・anchor は消え「リボン上の位置」になる（ドラッグ）
・多段はステップを並べるだけ

{ "lap":3, "camera":1, "takes":[
  { "start":{"at":"enter","offsetSec":20}, "policy":"hold",
    "steps":[
      {"source":{"live":3},          "durSec":4},
      {"source":{"clip":"pre_01"},   "dur":"untilClipEnd"},
      {"source":{"clip":"rec_lap1_B"},"overlay":"cg_doll", "dur":"untilClipEnd"},
      {"source":{"clip":"rec_lap1_C"},"overlay":"cg_doll", "dur":"untilClipEnd"}
    ] } ] }

4. 既定の挙動（覆せる）

・占有ポリシー既定 = hold：演出中に歩いても画面は演出のまま。終わったら現在地のカメラへスナップ。
・演出中に通過した区間の演出は捨てる（遅れて流さない）。
・「録画映像 + CG 人形」は 1 本の動画に焼き込む前提（リアルタイム合成にしない）。
