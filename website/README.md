# 廻リ視 Web

廻リ視の作品サイトです。黒い空間の立体題字 → キービジュアル → 予告動画 → 固定視点とは → 実世界×固定視点 → ストーリー → 演出一覧 → 展示履歴 → クレジットの順で構成します。予告動画はYouTube埋め込み、ほかの素材は自前配信です。フォームはありません。

2026-09-25のユーザー指示で、レトロテレビの3視点をgit `b2d9bce3` にあった架空の廊下へ戻しました。現在は同じバイナリを `camera-fiction-01.webp` 〜 `03` として使います。実際の撮影写真とその加工版は消していません。ストーリーの調査依頼には実写真由来の `camera-01-doll.webp` を使います。ヒーローは既存の作品キービジュアルを維持しています。出典は `assets/SOURCES.md` に記録しています。

## デザイン（2026-11-15 第 3 版「幕と壁」）

ユーザーの指示は「境界は必要だし、章ごとにくっきりした分かれ目があったほうがいい。しかし、その境界を超越して調和する」「画像生成を自由に使っていい」「アニメーションは、スクロール or ホバー（スマホではタップ）のみ」。参照は魔法使いの嫁のサイトほか 4 枚。逐語は `AGENTS.md`。第 1 版・第 2 版（同日）の格子と余白の 4 段は残し、地と境界を作り直しました。

公開前に見たユーザーの指摘は「キービジュアルの下から急に色が変わって監視カメラも少しキービジュアルにめり込んでいて、なんか違う。調和してない。境界の感じない境界、滑らかな境界、文脈の通った境界がいい。」。これを受けて、**色の段差だけの境界を作らない**ことにしました。明るい壁が現れてよいのは、幕の裾が終わった先だけです。壁は下の幕へ向かって暗がりへ落ち、レールはその暗がりから出てきます。

### ページは 1 枚の壁。手前に幕が掛かっている

| 地 | 章 | 文字 |
|---|---|---|
| 幕（キービジュアルと同じ布） | 予告動画・実世界×固定視点・演出一覧・クレジット | 生成り |
| 壁（調査対象の、古い漆喰の壁） | 固定視点とは・ストーリー・展示履歴 | 墨 |

幕と壁が交互に来ます。章の境界は 2 種類だけです。

- **レール**（まっすぐ）: 壁の章から幕の章へ入る所。黒い棒と輪。壁は下端へ向かって陰るので、明るい壁と暗い幕が色の段差でつながらない
- **裾**（波打つ）: 幕の章から壁の章へ出る所。裾は壁に影を落とす

幕は `drape-rail.webp` `drape-folds.webp` `drape-hem.webp` の 3 枚です。ひだは縦に伸ばしても形が崩れないので、章の高さに合わせて伸ばします。幕は画面より少し広く（116vw）、章ごとに切り出す位置（`--drape-x`）をずらして同じひだが並ばないようにします。幕の章は壁の章より手前に重ねるので、裾は次の章の上に垂れます。

### 境界をまたぐもの

| もの | どこからどこへ |
|---|---|
| 床 | キービジュアルの床がそのまま下へ続き、暗がりへ沈む。リード文はその床の上。暗がりから予告動画の幕のレールが出てくる |
| 監視カメラ | 「固定視点とは」の壁の、幕の裾のすぐ下に付いていて、ゲーム機を見下ろす。細いケーブルは幕の裏へ上がる |
| ケーブル | 「固定視点とは」の壁を、上の幕の裏から下の幕の裏へ這う。その先にテレビがある |
| 髪 | 「実世界×固定視点」と「演出一覧」の裾の下から壁へ伸びる。展示履歴では荷札の裏を通る |
| 染み | ストーリーと展示履歴の壁。垂れた跡が下の幕の裏へ入る |

下へ読み進めるほど、壁は汚れていきます（上の壁はきれい、ストーリーで染みと髪が出る）。

人形はキービジュアルだけです。髪と染みは生成した絵で、作品内の図像の複製ではありません（[assets/site-art-prompt.md](assets/site-art-prompt.md)）。

### 章の格子と余白

左の柱に章題を縦書きの筆文字で組み、頭に赤い短い線を置きます。章題は章の頭に置いたまま動かしません。720px 以下では章題を横書きにします。

余白は 4 段です（`--s-label` .6rem / `--s-part` 1.25〜1.75rem / `--s-group` 2.75〜4rem / `--s-chapter` 4.5〜7rem）。壁の章の上には裾の垂れる分、下にはレールの分を足します。

### 章

並びは「キービジュアル → 予告動画 → 固定視点とは → 実世界×固定視点 → ストーリー → 演出一覧 → 展示履歴 → クレジット」。

| 章 | 置いたもの |
|---|---|
| キービジュアル | 絵をそのまま。床の続きにリード文、受賞と展示予定 |
| 予告動画 | 幕の前のスクリーン |
| 固定視点とは | 壁に掛けたゲーム機と、それを見下ろす監視カメラ。操作部の真下に「歩く」「見回す」の凡例 |
| 実世界×固定視点 | テレビと、その右に 3 台のカメラ。選ぶとテレビの映像が替わる |
| ストーリー | 壁に墨で縦書きの 1 文。テープで留めた写真と、赤いピンで留めた依頼書 |
| 演出一覧 | 電源の切れたモニター。押すと点いて開く |
| 展示履歴 | 釘 2 本に渡した針金へ吊るした荷札 |
| クレジット | 最後の幕は裾を見せず、キービジュアルと同じ部屋の床（`room-empty.webp`）へ降りる |

揃えるもの：赤は題字の「視」の 1 色だけ（`--red` `#b02a32`、幕の上の小さい文字は `#e0574f`）。書体は 3 つ。壁の章では `--ink` などの変数を墨の色に差し替えるので、同じ部品が幕と壁の両方で使えます。

### 動き

きっかけはスクロールとホバー（指ならタップ）だけです。時間で勝手に進むものは置きません。

2026-11-16 のユーザーの指示：「何かを動かすときは、なぜ動かすのかをちゃんと説明できるところだけ、しかも、最初と最後をちゃんと決めて置き、その間も、ちゃんとイージングしてこだわること。ただ何となく動かした。じゃだれの心も動かない。」「逆に、理由の言える動きは積極的に足してほしい。」動きを足すときは、下の表に 1 行書けるものだけにします。

| 何が | なぜ動かすか | 最初 → 最後 | 間 |
|---|---|---|---|
| 髪 | 幕の裏に居るものが、こちらへ出てくる | 長さの 3 割 → 全部。自分の上端が画面の下端に入ってから、上から 2 割へ上がるまで | スクロールに連動。ゆっくり出てゆっくり止まる 3 次の緩急 |
| 染み | 調査対象の壁が、近づくほど侵されていく | 濃い芯だけ → 縁まで。区間は髪と同じ | 同上 |
| テレビの映像 | カメラを選んだから、その映像に替わる | 前の映像 → 選んだ映像。替わった瞬間だけ画面が乱れる | 180ms、2 段の階段 |
| 演出一覧の画面 | 押したのは電源だから、ブラウン管が点く | 横 1 本の光の線 → 絵 | 420ms、`cubic-bezier(.2, .7, .2, 1)`。頭の 35% は線のまま |
| 押せる箱の四隅 | 撮影枠が対象を捉える。押せることを示す | 外に浮いた角（-8px）→ 箱に寄る（-4px） | 180ms |
| 依頼書 | 押すと原寸で開く。手に取れることを示す | 傾き 1.4° → 0°、壁から 4px 浮く | 500ms |
| ヘッダー | 読んでいる間は絵を隠さない | 出ている → 上へ退く（PC 幅）。上へ戻すと出る | 320ms |
| ページの終わり | 体験と同じく、回ると最初の部屋に戻っている。3 周目の終わりで本当に終わる | フッター → 暗がり（画面の 4 割）→ 暗がりに沈んだキービジュアル → 本物と同じ明るさ。写しの上端が画面の下端に入ってから、上端に着くまで | スクロールに連動。髪と同じ 3 次の緩急 |
| 3 周目の終わり | 3 度目も頭へ戻ると思っている所へ、別のものが待っている | フッター → 暗がり → 暗がりに沈んだ人形の顔 → 画面を埋める顔。区間は上と同じで、ページはそこで終わる | 上と同じ |
| 色 | 廻るたびに狂う。1 周目には手を付けない | 2 周目の頭（素の色）→ 2 周目の終わり（色が 7 割抜け、赤みが差す）→ 3 周目の終わり（血の色に焼け、四隅が黒く沈む） | 読み進めた量を周で数えた値（1 周目の頭が 0・3 周目の頭が 2）に連動。各層は 3 次の緩急 |
| 髪と染み（周ごと） | 周を重ねるほど、幕の裏のものが出てきて壁が侵される | 髪は長さ 1 倍 → 1.45 倍 → 2.3 倍、染みは 1 倍 → 1.3 倍 → 1.9 倍 | 周が替わるのは頭を読んでいる間。替わる所は画面の外 |

外したもの：テレビを画面に留めてスクロールでカメラを切り替える演出（「スクロールしてるのにスクロールされない」）、章題が柱に留まる動きと上から現れる動き（「不安定感があっていや」）、物が下から浮かぶ現れ、写真と荷札のホバー。どれも理由を言えませんでした。`npm run check` が `position: sticky`・`setInterval`・繰り返しのアニメーション・現れの仕掛けを落とします。

カメラは 3 つのボタンで選びます。マウスを乗せている間はそのカメラを映し、押すと選んだままになります。動きを減らす設定では、髪は伸びきった姿、染みは広がりきった姿で止まり、映像の乱れと点灯を止めます。

ページは 3 周します（`main.js` の「3 周するページ」）。フッターの後ろに暗がりと、ページの頭（キービジュアルと予告動画）の写しを置きます。写しは本物と同じ組版なので、写しの中の位置と本物の同じ位置は同じ絵になります。写しへ入ったら、スクロールが止まったとき（慣性を切らない）か写しの絵が尽きる手前で、同じ絵の本物の位置へ瞬時に移します。本物の頭から写しの頭までは整数の画素に揃えます（端数があると移った瞬間に文字のにじみ方が変わる）。移った直後はヘッダーの出入りを変えません。3 周目に入ったら写しを外し、暗がりの先の人形の顔で終わります（下の段落）。スクロールバーは出しません（つまみが下から上へ跳ぶと、頭へ戻ったのが見える）。2026-11-16、ヘッドレス Chrome で 390・1280・1920 幅を撮り、写しの頭と本物の頭の画素差が最大 1/255 であること、ホイールで 2 回移って 3 周目のフッターで止まることを確かめました。指で弾いたときの慣性は実機で未確認です。

周ごとに狂っていきます（`main.js` の「周ごとの異変」、絵は `assets/anomaly-art-prompt.md`）。周は `main`・フッター・頭の写しが `data-lap` で持ち、写しは次の周の姿で待ちます。だから頭へ戻った瞬間にはもう次の周の絵になっていて、替わる瞬間は見えません。キービジュアルは 2 周目で人形が 1 体だけ群れを離れ、3 周目で全員がこちらを向いて迫ります（周の絵は重ねた `.hero-anomaly` を見せ替える。読み込みは前の周の半ばから）。テレビは 2 周目でカメラ 02 の奥に人形が立ち、3 周目で 3 台とも狂います（画面の外にあるので、その場で差し替える）。色は画面全体に重ねた 4 枚の層（色を抜く・血の色に染める・明るい所まで焼く・四隅から沈める）で、1 周目の頭を 0・3 周目の頭を 2 と数えた読んだ量に連動します。移る前と後でこの値は続いています。3 周目に入ると写しを外し、暗がりの先に人形の顔（`.loop-final`）を置きます。2026-11-16、ヘッドレス Chrome の 1280・390 幅で、周をまたぐ 2 回とも移る前と後の画素差が最大 2/255 であることを確かめました。

ヘッダーは下の色との差で描くので（`mix-blend-mode: difference`）、幕の上では白、壁の上では暗い色になります。

キービジュアルの右下には担当表記が焼き込んであります（絵の高さの 90〜96%）。床の続きは絵の下端 3.2% にだけ重ねて溶かし、担当表記には掛けません。

クレジットは左右5項目ずつ、白石担当を上3段にまとめています。中央に他の飾り線と同じ細い区切り線を置き、赤線は使いません。狭い画面でも縦書きの飾りを残し、役割と氏名が改行しない範囲で文字を大きくしています。連絡先は控えめな等幅書体にしています。

## 入口

`index.html` 先頭の同期bootstrapは、初回に本文を隠して黒い読み込み画面を出します。準備は最大15秒です。題字と音声の準備が終わった場合だけ入口を開きます。スキップ、Escape、URLのハッシュ移動、準備失敗では本文へ進みます。読み込みが遅れて完了しても入口へ戻しません。

`entrance.js` と `entrance.css` が黒い背景の立体題字を表示します。既存の `assets/title.png` の表裏と輪郭に厚みを付けてWebGLで描画します。案内はタッチ端末で「タップ」、マウス端末で「クリック」。画面全体が開始操作を受け付けます。追加ライブラリはありません。

`entrance-geometry.js` は `Assets/Scripts/Streaming/IntroFractureMesh.cs` の分割を移植したものです。15放射と10輪をもとにした267片（三角178片・四角89片）を使います。`entrance-glass.js` は `IntroFractureTime.hlsl` と `IntroFracture.shader` の5秒の時間式を移植しています。亀裂が走り、一撃で飛び、漂い、重さに応じて加速して戻ります。着地は進行率 .70〜.87、最後の3片は .90。現行HLSLの着地幅 .17 を正とします。旧記録の .13 は使いません。

凍結する像は入口の実際の3D題字と黒背景です。飛んでいる破片にも元の白い筆跡と赤い印を保ちます。本体の暗いガラス材質をそのまま掛けると題字が黒く潰れるため、ウェブ版は画像の色と明るさを保ち、反射を弱く重ねます。破片には本体と同じ薄い厚み、研磨した縁、反射帯、屈折を付けます。ウェブでは両眼の投影と周辺球殻を使わず、画面の縦横比に合わせた投影にします。帰還中も題字の断片を保ち、着地した部分から120msで背後の実HTMLへ変わります。最後の3片は進行率 .90 で中央へ着地し、その部分のウェブ表示も現れます。最後は縁が中央から消えます。別のヒーロー画像への置き換えや拡大フェードで終わらせません。

`scripts/sync-entrance.mjs` は `IntroFractureTime.hlsl`、`IntroLogic.cs`、`SoundCueLogic.cs`、`SfxPlayer.cs`、`show.json` から `entrance-timing.js` を生成します。さらにQuestの `sfx_shatter.wav` を無加工でコピーします。5秒の動きは既存実装と同じです。生成動画から採用した6.016秒の音を進行率0.02と35msの先読みを合わせた0.135秒で始めます。映像が終わっても音の尾は最後まで再生します。旧スクリーン音は重ねません。クリックまたはキーボード操作で音声を有効にします。

入口は画像の準備と音声の読み込み試行が終わってから開きます。音声だけを取得できない場合は無音で進めます。非表示中は動きと音を一緒に止めます。スキップとEscapeでは音も停止して本文へ移動します。動きを減らす設定やWebGL非対応では短い無音フェードにします。タブ内の初回だけ表示し、ページ内リンクからの訪問では表示しません。フッターから再表示すると先頭へ戻って開始します。終了時に描画資源とイベントを解放します。題字と破片の描画面は約207万画素・DPR 1.5を上限にします。ポインター移動による題字の描画は1フレームに1回にまとめます。

## 携帯ゲーム機の視点切り替え体験

`experience-config.js` の `gameUrl` は `perspective-game/?embedded=1`。ユーザー指定のローカル体験を同サイト内へ収めています。コピー元と版は `perspective-game/README.md`。元のゲームは編集していません。架空の古い携帯ゲーム機は画像生成した `assets/handheld.webp`。生成条件は `assets/handheld-prompt.md`。

ゲーム機が画面内に入り、入口の演出が終わった時点でiframeを生成して自動起動します。画面外・非表示タブ・入口の再表示中は3D描画を休止し、戻ると同じ位置から再開します。電源を切った後はスクロールしても起動せず、電源ボタンで再起動します。固定視点への切り替えが終わるまで画面を隠し、固定視点から遊べる状態で表示します。実描画が始まってから本体の十字キーと左右のスティックを有効にします。下の説明付き3ボタンで視点を選べます。拡大中は説明を隠して画面の高さを確保します。拡大表示はEscapeで戻れます。「電源を切る」でiframeを破棄し、画面内の「電源を入れる」で再起動します。別タブでは元の操作画面で遊べます。`handheld.js` と埋め込み側の `embed.js` は同一originと送信元を確認して操作を渡します。埋め込み中は隠した設定画面のショートカットを止めます。

キービジュアルの直下に独立した予告動画章を置きます。YouTube動画は `ipoU4gU9G4k` です。「この映像は2026.09.01時点で作成したものです。」「DCEXPOに向けた新しい予告動画を作成中です。」と明記します。YouTube埋め込みが使えない環境向けに元動画へのリンクも置きます。ヒーローの章リンクと「固定視点とは」直下の説明は置きません。

## 実機映像

予告動画と演出一覧には同じ短文「ネタバレを含みます」を表示します。`#footage-gate` の折り畳みを自分で開くまで、映像本体とネタバレを含むポスターを読み込みません。開いても再生は始まりません。3本の映像を選べます。閉じると停止してURLを除去します。タブを離れた場合も停止し、復帰時には再開しません。

| 映像 | 尺 | 収録 |
|---|---:|---|
| 現実がスクリーンになる | 14秒 | Quest 3の片目。冒頭4秒をカット |
| エラーの演出 | 11秒 | Quest 3の右目 |
| 目の演出 | 11秒 | Quest 3の左目。視界の周囲を含む |

すべて実機の検証録画です。原本に音声はありません。出典と切り出し時刻は `assets/FOOTAGE.md`。再生成は `py -3.11 scripts/prepare-footage.py`。単独の再生成は `py -3.11 scripts/prepare-footage.py fracture` のようにIDを指定します。写真は `py -3.11 scripts/prepare-photos.py` で原本からWebPへ変換します。

記録は生成りの地に黒で刷った荷札2枚、クレジットは黒い金属の銘板1枚として組んでいます。IVRC2026は総合優勝と表示します。展示日は月までを表示しています。荷札のバーコードは `IVRC2026` と `DCEXPO2026` を Code 128 B で符号化したものです。クレジットにQRやURLの図案は置きません。

クレジットは2026-09-15のユーザー指定の10項目です。役割と「白石」「五島」「チーム」の表記をそのまま表示します。行番号01〜10はCSSのカウンタで描くので、本文の選択やコピーには混ざりません。

スマホでも左右5項目ずつを保ち、各項目の役割と氏名を同じ行に置きます。スマホでは行番号を隠して氏名だけが下段へ落ちないようにします。氏名の右側には余白を設けます。制作名 `チーム：Roil Studio` の直下に `白石大晴 / Kim Hyunmin / 堀越 康平 / 五島 慶人` を置きます。連絡先は `rinkyouaoi@gmail.com` のメールリンクです。その下に[ポートフォリオ](https://my-portfolio-ruby-delta-87.vercel.app/)を置きます。

固定視点の架空の廊下3視点は既存の `crt.webp` 内に表示します。CSSで走査線とブラウン管の周辺陰影を重ねます（止まっています）。調査依頼は実写真から作った `camera-01-doll.webp` を使います。

装飾に見える文字列は実在の事実から導いたものだけです。`REC 01` は記録の通し番号、`ivrc.net` と `dcexpo.jp` はリンク先のホスト名、`5EFB-30EA-8996` は「廻リ視」3字のUnicodeコードポイント、`MAWARIMI` は構造化データの別表記です。

見出しの右に出る更新日 `data-updated` は `sitemap.xml` の `<lastmod>` と同じ値にします。片方だけ直すと `npm run check` が落ちます。

## 書体

```powershell
npm run fonts
```

日本語の2書体は `index.html` の画面に出る文字だけを収録したサブセットです。**文言を変えたら走らせ直します。** 走らせないと新しい字が抜けたままになり、`npm run check` が「どの字が足りないか」を名指しで落とします。`npm run fonts -- mincho yuji` のように書体名で絞れます（キーは `mincho` `yuji` `plex`）。欧文の書体は印字できるASCII全部と、`fetch-fonts.mjs` の `LATIN_EXTRA`（`×` やキーの刻印の矢印 `↑←↓→` など）を持つので、それ以外の記号を等幅で組まない限り取り直しは不要です。

| 書体 | 使う場所 |
|---|---|
| Yuji Boku | 章の見出し、サイト名、銘板の背の「廻リ視」 |
| Shippori Mincho | 本文、役割名、人名、受賞と展示予定、ボタンの文字 |
| IBM Plex Mono 400 / 500 | 欧文と数字だけの表記（`CAM 01`、キーの刻印 `W` `1` `↑`、`REC 01`、荷札の題、更新日、メール） |

等幅は日本語を持たないので、日本語が混ざる札（`カメラ 01` など）は明朝で組みます。等幅で組む要素は `scripts/font-text.mjs` の `LATIN_CLASSES` と対にしています。2026-11-15 に Chakra Petch を外しました。

`npm run build` は公開に必要なファイルだけを `dist/` へ出力します。`dist/` は生成物です。

Vercelでは `vercel.json` により同じビルドを実行し、`dist/` だけを公開します。

Vercelプロジェクト `roilils-projects/mawarimi` はGit連携なしです。公開はこのディレクトリで `vercel deploy --prod --scope roilils-projects` を実行します。`--scope` を省くと "Not authorized" で止まります（2026-09-19 実測）。CLI を入れていなければ `npx --yes vercel@latest deploy --prod --scope roilils-projects` で同じことができます。`--prod` を付けなければプレビュー URL に出ます。プレビューは Deployment Protection が効いていて、Vercel にログインしたブラウザでしか開けません。初回は `vercel link --project mawarimi --scope roilils-projects` で既存プロジェクトへ接続します。`.vercel/` と `.env*` はローカル専用です。

Google Search Console の所有権確認には `google5081a8a413a7871f.html` を使います。確認状態を維持するため、公開後も削除しません。

公開URLは `https://mawarimi.vercel.app/` です。検索エンジン向けの正規URL・OGP・構造化データは `index.html`、巡回設定は `robots.txt` と `sitemap.xml` で管理します。構造化データでは「まわりみ」「廻り視」「マワリミ」「Mawarimi」を別表記として示します。ヘッダーにも作品名の読み「まわりみ」を表示します。
